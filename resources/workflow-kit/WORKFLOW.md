Прогон делится на **батчи** (кусок работы одного агента); параллельные батчи — **волна**;

рекомендация, этот файл их перекрывает.

## Марафон — в одном чате до конца (слово Элвиса 03.09.2026 утром)

- Марафон из нескольких воркфлоу идёт в ОДНОМ чате, пока не закрыт весь план. Никаких
  «следующая волна в новом чате», никаких предложений `/clear` — контекстом рулит харнесс.
- Пауза только на том шаге, где нужно слово Элвиса (одобрить макеты, дать домен, логотип).
  Всё, что от него не зависит, идёт дальше параллельно: другие волны, документы, ревизии.
  Остановиться целиком, когда есть независимая работа, — ошибка оркестратора.
- Документы для решения (концепции, макеты, списки на одобрение) готовятся заранее, пока
  Элвис спит, чтобы утром он только выбрал. Не откладывать их «до пятницы».
- Лимит посреди ночи — не финиш: после сброса resume и дальше по плану.

## Порядок прогона — всегда один

1. План — файлом в папке планов проекта: критик и resume должны читать одно и то же.
   У каждого батча в таблице — модель и эффорт; они же идут в коммит. **До плана
   планировщик обязан открыть run-файлы прошлых прогонов (стоп-маркеры, «исключено»),
   HANDOFF/_DEVLOG проекта и проверить каждую задачу по коду и git** — план по одному
   списку задач повторяет уже сделанное и воскрешает отменённое (WF53: три ошибки).
2. Критик плана — отдельный агент со свежим контекстом. Его задача — РАЗНЕСТИ план:
   (1) нужно ли вообще делать каждую задачу; (2) верен ли подход; (3) модель и эффорт
   каждого агента; (4) пересечения агентов по файлам; (5) что сломает существующие тесты;
   (6) какой батч владеет сборкой и dev-сервером. Запустить критика нечем — разнеси план
   сам и напиши в презентации: «критик недоступен, разносил сам».
3. Правки по находкам критика.
4. Презентация Элвису. Запуск — только после явного одобрения.
5. Сторож, точка отката, кодинг.
6. Проверка: сверка «сделано vs описано» по диффу, а не по отчётам исполнителей; verify
   по коду; полные тесты проекта. Красное чинится до отчёта; что не чинишь — заводи
   задачей в 🟣Trelvis.

Мелкая одиночная правка (одна задача, файл-два, без денег и чужих данных) идёт мимо
конвейера: без критика и без сторожа.

  Норма оркестратора — Fable `high`. Всё, что отличается (`xhigh`, `max`, `medium`,
  `low`, другая модель), — стоп и одна фраза Элвису: «Я на <модель, эффорт>, а норма —

  плевать» — тогда запускай и пиши в run-файл, на чём шёл.

  по плану. Простой инструмент Agent эффорта не задаёт — наследует эффорт сессии;

- `script_path` и `run_id` — в run-файл сразу после запуска волны: это точка подъёма.
  `Workflow({scriptPath, resumeFromRunId})` продолжает с первого незавершённого
  агента, готовые возвращаются из кэша.
- Агент завис или умер — сперва resume по runId; не поднялось — откатить огрызки батча
  и перезапустить один батч, не волну.
- Исполнитель возвращает отчёт ТЕКСТОМ (структуру — через `schema`); файлы вне
  репозитория и коммиты — оркестратор.

## Сторож лимита

Один сторож на каждый прогон, даже короткий; ставь до запуска. Крон — раз в 30 минут.

- **Крон только дисковый** (`scheduled-tasks`, `/Users/elvis/.claude/scheduled-tasks/`):
  сессионный умирает вместе с чатом. Имя: `watchdog-<проект>-<ДДММ>` — точки в id
  инструмент вырезает; в промпт сторожа пиши id таким, каким его вернул инструмент.
- **Состояние — файл рядом с планом**, тем же именем (`plan-wf5-2026-08-22.md` →
  `run-wf5-2026-08-22.json`), путь абсолютный. Внутри: `script_path`, `run_id`, ветка,
  next_steps, статус (`идёт`/`лимит`/`финиш`/`стоп`) и журнал «батч → суть отчёта,
  файлы, тесты → коммит». Не в scratchpad — он умирает вместе с сессией.
- Памяти у сторожа нет: каждый запуск читает файл заново. Прогон обновляет файл после
  каждого батча.
- **Подъём — сам, через `Workflow({scriptPath, resumeFromRunId})`** по данным
  run-файла: продолжает одобренный план с места остановки, нового не начинает. Сообщение
  в сессию оркестратора из фоновой задачи не доставляется — не пытаться. Элвиса ночью
  не будить.
- Resume отбило лимитом (пятичасовым, недельным) — это ожидание, а не упавший шаг:
  статус `лимит`, ждать отката хоть неделю, после отката resume и статус обратно `идёт`.
- Прогон умер посреди волны — часть батчей закоммичена, часть нет. Перед resume:
  git status, недокоммиченные огрызки умершего батча откатить (checkout своих файлов,
  новые файлы удалить). Проверенные хвосты ДРУГИХ прогонов (задокументированные в их
  файлах состояния) сперва закоммитить отдельно, потом откатывать мёртвое.
- **Стоп-условия**, любое: статус `финиш` или `стоп`; 6 возобновлений; один шаг упал
  дважды; файл состояния пропал; статус `идёт`, а файл не менялся 6 часов по записям
  ПРОГОНА (записи сторожа свежестью не считаются; `лимит` ждёт сколько нужно).
  Сработало — сторож пишет в файл, где встали, и снимает себя.
- Финиш — проверяемое состояние: крон снят тобой (глянь список), СВОЙ run-файл
  в `финиш`, и ни один другой run-*.json проекта не остался в `идёт`. Перед новым
  воркфлоу — та же проверка: снеси сторожей и выведи run-файлы мёртвых прогонов из `идёт`.

- До кодинга — точка отката: отдельная ветка и тег на текущем main. Каталог перед
  тегом чист: незакоммиченные хвосты прошлых прогонов сперва коммитятся.
- Коммит после каждого батча, а не в конце волны: иначе resume нечего продолжать.
- Деплой VkusnoffKz разрешён Элвисом насовсем (02.09.2026), сколько угодно — всегда
  со смоуком после. Пуш и внешние сервисы (iiko, Kaspi, Mobizon, TG-боты, DNS) —
  по явному разрешению на прогон. Всё это руками ОРКЕСТРАТОРА, исполнителям не
  поручать: защита харнесса режет у них эти действия и запись файлов вне репозитория.
- Прямые записи в чужие базы (sqlite Трелвиса и т. п.) защита тоже режет — только
  штатный CLI; нет команды — задача в 🟣Trelvis на команду, не обход.
- Деструктивное (`rm` и родня) — отдельным вызовом, не в цепочке `&&`: классификатор
  режет цепочку целиком.
- Один писатель на файл, общие (сторожевой тест, док) не исключение. Исполнитель,
  которого диагноз уводит в чужой файл, останавливается на диагнозе — правку делает
  гейт. Второй прогон по тем же файлам не запускай: перед стартом проверь кроны и файлы
  состояния в папке планов; занято — скажи Элвису.
