# Форма ответов

Как отвечать пользователю в чате оркестратора и в чатах проектов. Правила воркфлоу — `WORKFLOW.md` рядом.

## ⛔ ПРАВИЛО НОМЕР ОДИН — КОРОТКО

Важнее всего в этом файле: пользователь ведёт много чатов сразу, и простыни ему не выгрести. Каждый ответ — короткий,
по форме раздела «Короткий режим». Коротко — значит отобрать: выкинь то, что не меняет его решений, а оставшееся пиши
полными фразами, без обрывков и стрелок. Длину держи сам, по его сообщению: на длинную диктовку ответ может быть
длиннее; «подробнее», «распиши» — пиши подробнее, форма та же, блоков больше.

## Короткий режим — форма ответа

- Блок — `## Заголовок` обычным начертанием, без двоеточия, имена — как пишет владелец; капсом — только служебные
  блоки. Под заголовком одна–три коротких фразы.
- Блок на каждую тему или вопрос пользователя; без вступлений, пересказа по шагам и «почему так» — подробности по
  слову «подробнее». Главный блок — что нужно от пользователя прямо сейчас: одно-два действия, значения — в обратных
  кавычках.
- **Вопрос пользователю** — только где без его слова нельзя («Решай сам» в `WORKFLOW.md`): один на ответ, внутри блока
  темы, со своим вариантом «(рекомендую)» первым. Остальное реши сам и покажи в «🔘 ВЫБОР»; по решённому вариантов не
  предлагай.
- **`## 🔘 ВЫБОР`**, если в ходе были решения с вариантами: решения номерами, у каждого строка
  `- 🟢 выбранное — почему`; строка `- ⚪ …` с минусом — только если второй вариант почти так же хорош. Это не вопросы:
  работа уже идёт по 🟢; пользователь молчит или говорит «ок» — принято, иначе называет номер и что хочет.
- **`## 👤 СДЕЛАЙ`** — только если нужно его действие. Пункты 1, 2, 3 без букв и кодов (Э1, 🚦), через пустую строку,
  блокирующее — первым, с ⚠️. Первая строка — что сделать, ниже шаги подпунктами `- ` полными простыми фразами
  («Открой вкладку …», «Нажми „Сохранить“»), команда — отдельным блоком ```bash``` (кнопка Run). Пункт живёт, пока
  пользователь не сказал «сделал», «отменяю» или «не понял» (тогда объясни иначе — шагами, картинкой); незакрытые — в
  HANDOFF.md. Номер задачи — ссылкой в конце пункта. «Сделай» вопросом не считается.
- Задачи — одной строкой номерами-ссылками. Блоков «ЧТО ДАЛЬШЕ» и «ОТВЕЧАЮ» нет. Списки — markdown `- `: строки с «—»
  без пустых строк просмотрщик склеивает в абзац.
- Картинку или файл — файлом (`SendUserFile`) перед пунктом о нём, в тексте — «на картинке — …»; путей в чат не пиши.
- Порядок: «❗ Включи Accept Edits» / «❗ Верни режим Авто» → главный блок → «🔘 ВЫБОР» → темы → «👤 СДЕЛАЙ» → «🦾» / «🧩» →
  «🆕 ОТКРОЙ НОВЫЙ ЧАТ» или «❗ Скажи — и сделаю ❗» → служебные строки (каждая одной строкой; «🔥» — первой строкой
  ответа) → строка состояния.
- Совсем короткий ответ (подтверждение, «да/нет») — одна–три фразы без заголовков; строка состояния — только если идёт
  воркфлоу или ждём пользователя.

**Строка состояния** — шаблон дословно: `<маркер>[<Проект>](<путь к status.md>) · WF N из M · <слово> <значок>`,
значок один, в конце через пробел. Маркер — эмодзи проекта из паспорта или ⚪. `идёт` 💭 — есть что делать без
пользователя, даже при пунктах «сделай»; `жду` ❓ — без пользователя дальше некуда, в том числе всё сделано, но вопрос
к нему остался (решения из «🔘 ВЫБОР» ❓ не дают); `готово` ✅ — всё сделано, от пользователя ничего не нужно; `упал` 🛑.
Без процентов и названий. «WF N из M» — только воркфлоу этого чата (N — который идёт, M — сколько запланировано);
воркфлоу нет — кусок «WF» опускается. Имя проекта — ссылка на существующий status.md; его нет — маркер и имя без
ссылки, ради ссылки status.md не заводим. Пример: `⚪[MyApp](docs/status.md) · WF 1 из 3 · идёт 💭`.

## Служебные строки и блоки

- «🔥»: в начале чата проверь `echo $CLAUDE_EFFORT`; max без «да» пользователя на max — первой строкой ответа «🔥 чат на
  MAX, норма — Opus 5.5 EXTRA, переключи», и работай дальше.
- **Ступени усилия в тексте пользователю — заглавными**, **модель — всегда с версией**: LOW, MEDIUM, HIGH, EXTRA, 🔥
  MAX («Opus 5.5 EXTRA»); «xhigh» пользователю не писать. Код, коммиты и поля агентов — как были.
- **Волшебные фразы**: что ждёт слова пользователя («поехали», «включай комбо») — блоком `## ❗ Скажи — и сделаю ❗`:
  «фраза» жирным — что после неё будет.

## Новый чат

- **Контекст чата — забота оркестратора, не пользователя**: цифр контекста не докладывай и по цифре переход не
  предлагай; вместо компакта — новый чат; середину прогона не рви. Новый чат — на естественной границе (воркфлоу
  закрыт и выложен, HANDOFF свежий, следующая тема на прочитанное не опирается, ответы путают старое с новым) и перед
  марафоном из 2+ воркфлоу или ночным прогоном (`WORKFLOW.md`, «Марафон»). Новый чат — только когда в нём есть что
  делать (продолжение воркфлоу, следующая задача): всё сделано и ждём пользователя — не предлагай.
- **Один проект — один чат**: второй чат по проекту рядом с живым не заводи и не проси открыть — новая тема идёт в чат
  проекта, а новый чат только сменяет старый.
- **Блок `## 🆕 ОТКРОЙ НОВЫЙ ЧАТ`**: фраза — что доделано и почему граница сейчас; строка `Модель: <модель · эффорт>` —
  минимальная, при которой качество переданной работы приемлемо (выше — по желанию пользователя); текст передачи в
  ```-блоке, 3–6 строк, копируется только он: «Режим коротких ответов.», проект и папка, задача одной фразой, что
  прочитать (HANDOFF, план, run-файл — путями), первый шаг. Самой последней строкой ответа — ещё раз
  `## 🆕 ОТКРОЙ НОВЫЙ ЧАТ`, чтобы пользователь видел его внизу; без пояснений «вставь текст выше».
- **Блок открывает новый чат сам**: Пимп через 15 с после конца ответа, если пользователь 30 с не трогает Claude,
  открывает новый чат с этим текстом и моделью из строки `Модель:` — пиши её как в меню («Opus 5.5 · EXTRA»); Fable и
  MAX — только по нажатию пользователя. Поэтому блок — только по правилу выше, не для примеров.
- **Огромный чат не будить**: после часа простоя кеш холодный, и ход стоит как весь чат. Уходя в новый чат, сними свои
  кроны и напоминания (`CronList` → `CronDelete`, `ScheduleWakeup` stop), нужные перенеси; команды с кнопкой Run давай
  только в живом чате.

## status.md — счёт воркфлоу

Счёт воркфлоу этого чата для пользователя и карточки Пимпа — рядом с планами (`docs/`); обновляй в тех же ответах, где
меняется строка состояния. Карточка читает файл построчно — перед первой записью прочитай форму — раздел «status.md —
форма» в `WORKFLOW.md`.
