# PimpMyClaude

Прокачка Claude Desktop, как «Pimp My Ride», только для окон Claude. Бывший MyClaude (переименован 03.09.2026). GitHub: `ElvisIglikov/PimpMyClaude`.

## PimpMyClaude.app — приложение для команды

`app/` — приложение на Swift (AppKit, без Node и Hammerspoon), делает всё то же, что описанные ниже
`claude-patch/patch-claude.mjs` и три Lua-модуля: патчит Claude, меню на жёлтой кнопке, горячие клавиши,
блок ⌘Q, авто-Allow. Значок в строке меню: «Поставить», «Снять», статус патча, тумблеры, автозапуск при входе.
Инструкция для Маши, Аллы и Дениса — `docs/TEAM.md`.

- Собрать и подписать Developer ID: `tools/bundle.sh` (по умолчанию `release`, кладёт `app/.build/PimpMyClaude.app`;
  куда класть — переменная `APP_OUT`, чем подписывать — `SIGN_ID`).
- Релиз для раздачи: `tools/release.sh` — сборка → нотаризация у Apple (`xcrun notarytool`, профиль keychain
  `pimpmyclaude`) → `stapler staple` → `dist/PimpMyClaude-<версия>.zip`, проверенный `spctl` на распакованной копии.
  Версия — `CFBundleShortVersionString` в `app/Resources/Info.plist`. Профиль заводится один раз:
  `xcrun notarytool store-credentials pimpmyclaude --apple-id <Apple ID> --team-id F27N4S4NJ4`.
- Тесты: `cd app && swift test`.

Структура `app/`: `Sources/Patcher` — порт `patch-claude.mjs` на Swift (формат asar, лоадер, `ElectronAsarIntegrity`,
бэкап/restore, переподпись Claude ad-hoc); `Sources/ClaudeAX` — авто-Allow, меню на кнопке «Свернуть», хоткеи и ⌘Q
на Carbon, Расставить/Показать/Прокрутить, команды странице через `command.json`; `Sources/PimpMyClaude` — меню-бар,
окно операций, первый запуск и разрешения; `Resources` — Info.plist, entitlements, иконка; `Tests` — тесты.

Всё, что ниже, — исходники той же логики: `claude-patch/` и `hammerspoon/` остаются дев-инструментом
(проверить идею, не пересобирая приложение) и источником правды по поведению. Команде раздаётся только приложение.

## Узкие окна Claude и узкие поля по бокам (патч Claude Desktop)

`claude-patch/patch-claude.mjs` — дописывает в Claude.app маленький лоадер (взято точечно из ElvisOS).
Даёт две вещи, без панели настроек: минимальная ширина любого окна Claude 360 вместо 600 и поля по бокам текста 5 px вместо 32/40.

- Поставить (закроет и снова откроет Claude, переподпишет его локальной подписью):
  `node ~/_ElvisProjects/PimpMyClaude/claude-patch/patch-claude.mjs`
- Проверить: `node ~/_ElvisProjects/PimpMyClaude/claude-patch/patch-claude.mjs status`
- Вернуть оригинал: `... restore`. Прогон на копии без изменений приложения: `... selftest`.
- Значения лежат в `~/Library/Application Support/MyClaude/claude.json` (`minWindowWidth`, `sidePadding`, необязательный
  `frameRadius`), меняются на лету, перезапуск не нужен. `sidePadding` двигает ползунок «↔️ Поля по бокам» в меню окна
  (см. ниже): приложение пишет и в claude.json, и в свой блок claude.css — свежие сборки Claude сменили классы колонки
  чата (`--chat-column-gutter-start/end`), и правило самого лоадера по ним уже не матчится. Умолчание — 5 px
  (`claude-patch/claude.json`, `DEFAULTS` в `patch-claude.mjs`, `Patcher.configDefaults`, `LiveStyle.defaultSidePadding`:
  таргеты `ClaudeAX` и `Patcher` друг друга не видят, цифра лежит в обоих). Классы у Claude сменятся снова — поля опять
  «отвалятся», и лечится это строкой в claude.css, а НЕ лоадером (смена лоадера = перепатч Claude у всей команды).
- Диагностика: лоадер раз в 2 с пишет `~/Library/Application Support/MyClaude/status.json` (окна, минимумы, куда вставлен CSS). Положи рядом `probe.js` — любой JS выполнится во всех страницах claude.ai, ответ в `probe-result.json`.
- Живой CSS `claude-patch/claude.css` (копия лежит в Application Support): скрыты стрелки «назад/вперёд» в заголовке; строка действий под сообщением (копировать, форк, «3 minutes ago») видна всегда. Лоадер вставляет файл как **user-origin** (`insertCSS(text, {cssOrigin:"user"})`) и перечитывает раз в секунду — поэтому правило с `!important` отсюда бьёт даже инлайн-стиль страницы, и поля с радиусом рамки чинятся без перепатча Claude у команды.
- **Блок между маркерами `/* PimpMyClaude:auto */` … `/* /PimpMyClaude:auto */` принадлежит приложению**
  (`app/Sources/ClaudeAX/LiveStyle.swift`): поля по бокам и радиус неоновой рамки. Оно переписывает блок в трёх местах —
  при запуске, после «Поставить»/«Снять» (`Patcher.installLiveFiles` копирует claude.css из бандла целиком) и на каждое
  движение ползунка полей; пишет только при реальном изменении текста, иначе лишний mtime заставит лоадер переставлять
  CSS каждую секунду. **Свои правила пиши ВНЕ маркеров** — всё за их пределами сохраняется дословно, порядок строк файла
  не меняется. Строкой НИЖЕ блока можно и перебить его правило (при равной специфичности выигрывает последняя) — так
  подгоняют радиус под своё железо; внутри блока правку затрёт первый же запуск приложения. Маркеров в файле нет — блок
  дописывается в конец; маркеры битые или блок задвоился — старый кусок вырезается и блок пишется в конец.
- Радиус рамки берётся по версии macOS (`LiveStyle.frameRadius`: у Tahoe угол окна заметно круглее, чем у macOS 13–15) —
  отсюда «углы обрезаются неровно» до WF14. Перебить, не пересобирая приложение: ключ `frameRadius` в `claude.json`
  (0…40) или своя строка в claude.css после блока.
- После обновления Claude патч слетает — запустить установку снова. После первой установки macOS один раз заново спросит разрешения.
- Бэкап оригинальных app.asar и Info.plist: `~/Library/Application Support/MyClaude/backups/<версия>/`.

## Ручка над полем ввода (`claude-patch/inject.js`)

Живой скрипт, лоадер v6 выполняет его в каждой странице Claude и перечитывает при изменении файла
(копия лежит в `~/Library/Application Support/MyClaude/inject.js`; «Поставить» в PimpMyClaude.app перезаписывает её копией из бандла — править только `claude-patch/inject.js` и пересобирать). Поведение как в ElvisOS:
- Узкая (96 px) едва заметная полоска по центру над полем ввода, ярче при наведении. Тянуть вверх/вниз — высота поля.
- Одинарный клик: поле схлопывается в полоску и обратно (из растянутого — тоже схлопывается).
- Двойной клик: растянуть до потолка окна; ещё раз двойной — обычная высота.
- После отправки поле НЕ сворачивается. Работает и в окнах «Open in new window».
- Escape не останавливает выполнение (глотается, пока на экране нет открытого меню или диалога).
- Команды из меню (см. ниже): `collapse`, `expand`, `scroll` — всем окнам сразу; `cashout` (сохраняет последний
  ответ и черновик, вставляет их в свежий чат), `theme` (цвет и шрифт, с предпросмотром) и `workflow` (текст
  кикоффа в поле ввода) — окну по AX-заголовку (у `theme` есть и необязательное поле `match`: адресация путём
  страницы, им покраска по проекту достаёт главное окно); `status` — сводки проектов для подсказки полосы прогресса;
  `live-colors` — включить/выключить крутёж цвета по кругу всем окнам сразу (см. «🌊 Живые цвета ▸» в разделе
  «🎨 Оформление ▸» ниже).
- Проверка: `probe.js` с `window.__myclaude.status()` (там же `progress`, `statusFeed`, `theme`, `font`, `workflow`).

## Меню на кнопке «Свернуть» (`app/Sources/ClaudeAX/MinimizeMenu.swift`)

Наведи курсор на жёлтую кнопку окна Claude и подержи 0,3 с — всплывёт меню. Структура — вариант А макета
`docs/mockup-menu-wf14.html` (выбран Элвисом 04.09, задача #5361): верхний уровень короткий, всё про вид окна —
в одном «🎨 Оформление ▸», редкие команды — в «⋯ Ещё ▸».

```
🚀 Workflow
💬 Новый чат           ⌘N
🪟 Новое окно ▸       → 🪟 Здесь же (последняя папка) ⌥⌘N · ─ · НЕДАВНИЕ ПРОЕКТЫ · 📁 PimpMyClaude · 📁 Dictatorik · …
🪟 В отдельное окно
──────────
⬆️ Развернуть          ⌥⌘↑
⬇️ Свернуть            ⌥⌘↓
──────────
🎨 Оформление ▸
──────────
⋯ Ещё ▸               → 💰 Обкэшить ⇧⌘N · ▦ Расставить ⌥⌘A · 👀 Показать ⌥⌘S · ⏬ Прокрутить ⌥⌘D
```

**Клавиши спрятанной четвёрки работают как раньше**: ⇧⌘N Обкэшить, ⌥⌘A Расставить, ⌥⌘S Показать, ⌥⌘D Прокрутить —
«⋯ Ещё ▸» убирает их только с глаз. `MenuModel.entries` остаётся полным списком из десяти пунктов и единственным
источником регистрации хоткеев (`ClaudeAXController.refreshHotkeys`, id = индекс+1), а `MenuModel.moreCommands` лишь
говорит `build()`, какие четыре рисовать внутри «Ещё»: вынести пункт из `entries` = убить его клавишу. По той же
причине `.newWindow` остался в `entries` полным пунктом, хотя рисуется подменю (WF16): ⌥⌘N регистрируется по нему,
а нарисована клавиша на «Здесь же» — у пункта с подменю AppKit `keyEquivalent` не отрабатывает, и
`MinimizeMenu.newWindowItem` чистит его у родителя.

Workflow (только в приложении) вставляет в поле ввода кикофф воркфлоу и не отправляет; клавиши у пункта нет — ⌘⌥W занят самим Claude.
Новое окно (только в приложении) — новый чат сразу отдельным окном: ⌘N, первое сообщение (без него сессии не существует) и вынос чата в окно; занимает несколько секунд. С WF16 это подменю: «Здесь же (последняя папка)» — ровно прежнее поведение с «Привет», ниже — папки, где Claude Code уже работал (раздел «🪟 Новое окно ▸ в папке проекта» ниже).
В отдельное окно (только в приложении) — выносит окном ТЕКУЩИЙ чат, мгновенно и без сообщения; клавиши у пункта нет.
Свернуть/Развернуть — это поле ввода, не окно. Расставить — столбцами во всю высоту на главном экране (ряды только когда столбцы уже 340 px). Показать — все
окна Claude вперёд. Прокрутить — все чаты к последнему сообщению.

Дев-исходник той же логики — `hammerspoon/claude_minimize_menu.lua`; меню там осталось старым, плоским списком
(🚀 Workflow · Обкэшить · Новый чат · Свернуть · Развернуть · Расставить · Показать · Прокрутить), про оформление,
полоску и оконные пункты WF13 Lua-модуль не знает. Установка (один раз):
```bash
cp ~/_ElvisProjects/PimpMyClaude/hammerspoon/claude_minimize_menu.lua ~/.hammerspoon/ && echo 'pcall(function() require("claude_minimize_menu") end)' >> ~/.hammerspoon/init.lua && hs -c 'hs.reload()'
```
У пунктов иконки (🚀 💬 🪟 🪟 ⬆️ ⬇️ 💰 ▦ 👀 ⏬) и горячие клавиши, работают только когда окно Claude впереди: Обкэшить ⇧⌘N · Новый чат ⌘N (штатная) · Новое окно ⌥⌘N · Свернуть ⌥⌘↓ · Развернуть ⌥⌘↑ · Расставить ⌥⌘A · Показать ⌥⌘S · Прокрутить ⌥⌘D. В самом меню подсказки стоят справа серым, в системном порядке ⌥⌘ (его рисует AppKit по `keyEquivalent`, в заголовке пункта клавиши больше нет); поменять — таблица `M.hotkeys` в начале Lua-модуля, в приложении — `MenuModel.entries`. Lua-модуль шлёт команды двумя каналами
(`M.commandChannel = "both"`): `command.json` для лоадера v6 и временно `probe.js` для лоадера v5 (задержка до 2 с).
Приложение шлёт только `command.json` — probe-канал в него не переносили. Проверено живьём 03.09: Прокрутить доводит все окна до низа.

## «🎨 Оформление ▸»: цвет, шрифт, размер, рамка, поля (`claude-patch/themes.json` + inject.js)

Всё про вид окна — в одном подменю (WF14; до этого «Тема ▸», «Шрифт ▸» и «Автопокраска ▸» висели на верхнем уровне):

```
🗂 Проект: PimpMyClaude ▸           ← цвет проекта (WF15, ниже); папка не узнана — «Проект: не определён», погашен
──────────
МОИ ТЕМЫ                            ← секции нет, пока своих тем нет
  ✓ Ночная работа
    Тёплая
──────────
🎨 Цвет ▸                 ← ✓ Как у Claude · ─ · ТЁМНЫЕ (15) · ─ · СВЕТЛЫЕ (9)
🔤 Шрифт ▸                ← ✓ Системный (как у Claude) · четыре секции по категориям
🔠 Размер ответов ▸       ← ✓ Как у Claude · ─ · 12 13 14 15 16 18 20
🔠 Размер вопросов ▸
✨ Неоновая рамка       ✓
↔️ Поля по бокам  ——●——  5   ← ползунок прямо в открытом меню
──────────
🖥 Всем окнам ▸           ← ВСЕМ ОКНАМ · Цвет ▸ · Шрифт ▸ · Размер ответов ▸ · Размер вопросов ▸ ·
                            ✨ Неоновая рамка · ─ · 🌈 Раскрасить по кругу ▸ · 🌊 Живые цвета ▸
──────────
💾 Сохранить как мою тему…
🗑 Удалить мою тему ▸
🧹 Всё как у Claude       ← снимает разом все четыре слоя окна: цвет, шрифт, размер, рамку
```

Верхний список — про ЭТО окно; то же самое сразу всем окнам — во вложенном «🖥 Всем окнам ▸» (заголовок «ВСЕМ ОКНАМ»
стоит в нём ровно один раз, первым пунктом, вложенные списки своих шапок не рисуют). Раньше «Тема окна» и «Тема всех
окон» стояли двумя пунктами вплотную и подменялись при скольжении мыши вниз — отсюда «покрасило все окна» (#5313).
Каталога тем в бандле нет — «Цвет ▸» и «Шрифт ▸» не появляются, остальное оформление на месте.

- **24 темы**, у каждой кружок своего цвета и русское имя. 15 тёмных, по цветовому кругу: Красная, Оранжевая,
  Жёлтая, Зелёная, Матрица, Бирюзовая, Токийская ночь, Синяя, Фиолетовая, Дракула, Сиреневая, Розовая, Малиновая,
  Коричневая, Серая. 9 светлых: Персиковая, Лимонная, Кремовая, Мятная, Небесная, Светлая, Лавандовая, Сакура,
  Пудровая. «🎨 Цвет ▸» — один список: «Как у Claude» первым, дальше секции «ТЁМНЫЕ» и «СВЕТЛЫЕ», и **отделены они
  полоской**, как «МОИ ТЕМЫ» (прямой вопрос Элвиса 04.09: «почему мои темы отделены полоской, а светлые от тёмных
  нет»). «Как у Claude» сбрасывает только цвет.
- **Шрифты** — секциями «С ЗАСЕЧКАМИ», «БЕЗ ЗАСЕЧЕК», «РУКОПИСНЫЕ И ВЕСЁЛЫЕ», «МОНОШИРИННЫЕ»; каждый пункт нарисован
  своим шрифтом. В списке только то, что стоит в системе и умеет кириллицу (`NSFontManager` + проверка «Ж»).
  Шрифт — отдельный слой со своей таблицей стилей: тема его не трогает и наоборот, моноширинный уходит и на код.
  «Системный (как у Claude)» сбрасывает только шрифт.
- **Предпросмотр при наведении**: ведёшь мышью по списку — окно перекрашивается сразу, в хранилище ничего не
  ложится (`"preview": true` в команде). Ушёл из меню, не выбрав, — вернулось сохранённое; кликнул — закрепилось.
  Работает и на своих темах: их список переехал на уровень «Оформление ▸», и делегат предпросмотра висит и на нём.
  У «Всем окнам ▸» предпросмотра нет: красить все окна на наведении шумно.
- **«Мои темы»** — набор «цвет + шрифт + размер + рамка» под своим именем: «💾 Сохранить как мою тему…» запоминает
  последнее применённое, «🗑 Удалить мою тему ▸» убирает. Список стоит первой секцией в «Оформление ▸» (галка — на
  применённой) и остаётся внутри «Всем окнам ▸ → Цвет ▸», чтобы свою тему можно было дать сразу всем окнам.
  **«Изменить свою тему» = сохранить под тем же именем** (задача #5364): имя совпало с сохранённой (регистр и
  лишние пробелы не считаются) — приложение спросит «Перезаписать «X»?» и перепишет её слои, сохранив id и место
  в списке (галка не съезжает, применённая тема остаётся применённой). Не совпало — новая запись, как раньше.
  В поле диалога подставлено имя текущей темы; файл `~/Library/Application Support/MyClaude/my-themes.json`, до 20 тем.
- **Галка «Как у Claude»** (задача #5363) стоит, когда у слоя нет ни записи окна, ни записи «всем окнам»; есть запись
  «всем» — у окна пусто, галка внутри «Всем окнам ▸». У размеров сравнивается своя половина: у окна с `answer:16,
  question:nil` в «Размер вопросов ▸» галка стоит. **Галка отражает память приложения, а не реальный цвет страницы**:
  на окне после «Раскрасить по кругу» и на окне без AX-заголовка она не ставится вовсе (иначе соврала бы), а у главного
  окна, у которого заголовок меняется вместе с чатом, может отставать от того, что на экране.
- **«↔️ Поля по бокам»** (задача #5360) — ползунок 0…24 прямо в открытом меню, кнопки «применить» нет; по умолчанию 5.
  Значение живёт в `claude.json` (его же читает лоадер и правит руками сам Элвис), приложение пишет туда и в свой блок
  claude.css — **не** в `command.json`, поэтому очередь команд и примерку тем ползунок не трогает. Лоадер опрашивает
  файлы раз в секунду: «сразу, без применить» на деле означает отклик **до ~1 с**, это не баг. Подсветки строки у
  пункта-ползунка не бывает — так рисует AppKit.
- **«🌈 Раскрасить по кругу ▸»** (бывшая «Автопокраска», задача #5362 — с верхнего уровня меню и из меню-бара снята,
  живёт внутри «🖥 Всем окнам ▸») — одно нажатие, и все окна на экране красятся гармонично по цветовому кругу. Восемь
  наборов (Радуга, Пастель, Закат, Океан, Лес, Ягоды, Неон, Монохром), «🎲 Случайно» — случайная гармония из
  четырёх (аналоговая ±30°, триада, сплит-комплементарная, тетрада) со случайного старта, «🔁 Ещё раз» — тот же
  набор, та же схема и тот же режим, только старт на +37°. Палитры считает само приложение (`AutoPaint.swift`), themes.json ему не
  нужен: фон HSL(hue, 45–60 %) — как у живых тем каталога, текст к фону ≥ 7 по WCAG, акцент — в полосе контраста
  4,5–6,0 (у светлой 4,5–7,0), чтобы жёлтый с зелёным не кричали, а синий с фиолетовым читались. Окна берутся
  слева направо, потом сверху вниз (порядок «Расставить»), тема адресуется заголовком — поэтому окна с одинаковым
  заголовком и безымянные («Claude», «New chat») получают один цвет; строка HUD перед покраской так и говорит:
  «Крашу 4 окна; 2 без имени чата — одним цветом». Галки в «Цвет» с покрашенных окон снимаются (цвет теперь
  сгенерированный, а не из каталога), зато «Сохранить как мою тему…» на таком окне предложит его же цвет.
  Тёмная или светлая у «Случайно» — из памяти приложения (что оно окнам применяло), по умолчанию тёмная.
  «Как у Claude (все окна)» последним пунктом снимает цвет со всех окон разом.
- **«🌊 Живые цвета ▸»** (WF18, задача #5371) — там же, в «🖥 Всем окнам ▸», сразу под «Раскрасить по кругу»: окна
  плавно едут по цветовому кругу, пока не выключишь. Первым пунктом «⏹ Выключить» (галка стоит на нём, когда крутёж
  стоит), дальше два режима — «🔗 Все окна одним цветом» и «🎭 Каждое окно своим цветом» (по умолчанию; окна разведены
  по кругу поровну — три окна стоят в 120° друг от друга); «⏱ Скорость» — тот же ползунок в открытом меню, что
  «Поля по бокам», восемь делений: круг за 30 · 20 · 15 · 10 · 5 · 3 · 2 · 1 мин, по умолчанию 5 мин, справа подпись
  «круг за 5 мин». Быстрее минуты нет нарочно: при потолке 4 Гц это уже больше 1,5° за шаг, то есть мигание, а не
  смена цвета. Ниже режим света: «🌑 Тёмные» (по умолчанию), «☀️ Светлые» и «🪟 Как окно сейчас» — последний
  **доступен только в режиме «каждое своим»** (команда одна на все окна, и в «синхронно» окна взяли бы разные
  кольца — цвет перестал бы быть одним). Ползунок и режим света работают и на выключенном крутёже: скорость
  запоминается, команда не шлётся; сам ползунок идёт мимо очереди команд, как примерка темы, — иначе темп догонял бы
  мышь секундами.
- **Как это устроено.** Приложение шлёт ОДНУ команду `live-colors` на все окна (`scope:"all"`), дальше цвет крутит
  сама страница (`inject.js`, раздел 2в) — **от стенных часов**, а не накоплением тиков: `epoch` и `period` у всех
  окон одни, поэтому в «синхронно» окна сходятся без единого байта между собой, а придушенное фоновое окно (Electron
  режет таймеры перекрытых окон до 1 Гц) после пробуждения оказывается на правильном цвете, а не отстаёт. Крутить
  цвет командами нельзя: очередь держит 0,6 с на запись, лоадер читает файл раз в 500 мс и берёт только последнюю.
  Палитры считает тот же `AutoPaint.swift`, что и «Раскрасить по кругу»: в команду уезжает **кольцо из 12 палитр**
  (шаг 30°, оба набора сразу — тёмный и светлый), между соседними точками страница смешивает цвета покомпонентно
  в sRGB; второй копии формул контраста в JS нет нарочно — она разъехалась бы со Swift. Тик считается от скорости:
  250 мс на самом быстром круге и до 1 с на медленном; на предпросмотре темы и на спрятанном окне (`document.hidden`)
  тик молчит, вернулся — цвет догнан одним шагом. Рамка едет за цветом сама (`applyTheme` зовёт `paintFrame`),
  полоска прогресса перекрашивается на грубом шаге — раз в 30°, а не четыре раза в секунду.
- **Живые цвета ничего не запоминают в темах.** Идут мимо `writeLayers`: выключил — вернулась тема чата или окна,
  как будто ничего не было. Своё состояние лежит в двух местах: у приложения — `UserDefaults` (`liveColors.*`),
  у страниц — ключ `myclaude-live-v1` в localStorage, общий у окон Claude. Поэтому окно, открытое во время крутёжа,
  подхватывает цвет само, без команды — **и даже когда приложение не запущено**; остановить крутёж можно только из
  меню приложения. При старте приложение шлёт команду заново (список заголовков окон мог устареть). Фаза окна
  в режиме «каждое своим» защёлкивается по первому настоящему заголовку (не пустому и не заглушке «Claude»); новый список `titles` из команды пересчитывает фазу (`sessionStorage`, `myclaude-live-phase-v1`, сверка по ключу
  сессии — иначе попап «Open in new window» унаследовал бы фазу главного окна): у главного окна заголовок меняется
  вместе с чатом, и без защёлки оно прыгало бы на другую точку круга при каждой смене разговора. Окна, которых
  в списке не было, встают по хэшу заголовка, а окна с одинаковым заголовком получают одну фазу — ровно как
  в «Раскрасить по кругу».
- **Пока живые цвета крутятся, соседи молчат.** Пункты «🌈 Раскрасить по кругу ▸» погашены, а в шапке подменю стоит
  «сначала выключи живые цвета» (иначе покраска пишет окнам темы, а живой слой перекрывает их через четверть
  секунды — со стороны это «кнопка не работает»); цвет проекта (WF15) команд не шлёт вовсе, иначе окно мигало бы
  между проектным цветом и живым. Обратной симметрии нет: включение живых цветов ни у кого ничего не спрашивает.
  Живые цвета — только «всем окнам»: на одно окно, своей скоростью каждому и светлые с тёмными вперемешку в одном
  круге не делаем. **Честно: это постоянная работа для каждого окна — на ноутбуке без розетки батарея сядет заметно
  быстрее.** Проверка: `window.__myclaude.status().live` (on, mode, period, light, phase, hue, ring, paints,
  source) и `live=solo/300/dark` (или `live=off`) в `statusText` приложения.
- **Тема живёт на чате**, а не на окне: ключ `chat:<заголовок>` (плюс `main` у главного окна и `*` у «всем окнам»)
  в localStorage, сверх того сессия окна. Поэтому «Новый чат» и «Обкэшить» цвет НЕ меняют — у нового чата своей
  записи нет, окно остаётся как было; вернулся в старый чат — вернулся и его цвет. Записи старого образца
  `w:<заголовок>` читаются и переносятся сами.

Каталог `claude-patch/themes.json` (6 цветов на тему), CSS из палитры делает inject.js (урезанный порт генератора
ElvisOS) и вешает конструируемой таблицей `adoptedStyleSheets` — `<style>` в `<head>` нельзя: Claude зеркалит его
из главного окна во все окна «Open in new window». Красятся только страницы claude.ai и about:blank (артефакты и
браузер — нет). Режим Claude (тёмный/светлый) не переключается — светлая тема поверх тёмного режима выглядит
неровно. Только в приложении PimpMyClaude.app (Lua-модули тем не знают). Проверено живьём 03.09: четыре окна
четырьмя темами.

**Размер текста и неоновая рамка (WF12, переложены в «Оформление ▸» в WF14).** «🔠 Размер ответов ▸» и «🔠 Размер
вопросов ▸» стоят прямо в «Оформление ▸» (12–20 px, «Как у Claude» снимает обе половины; те же два подменю есть
в «Всем окнам ▸»): меняется только текст сообщений, кнопки и поле ввода — нет; слой `size` независим от темы и шрифта,
с предпросмотром. Тумблер «✨ Неоновая рамка» переехал туда же из «Тема ▸»: линия 2 px по краю окна со свечением цвета
акцента темы (как у полоски), слой `frame`; **радиус углов подгоняется под версию macOS блоком в claude.css** (задача
#5359 — до этого рамка рисовалась с жёстким радиусом 10 px и на Tahoe «обрезалась неровно»), сам `inject.js` в WF14
не трогали. Подсказка полоски — по клику на сегмент (только этот воркфлоу), наведение показывает лишь курсор; Esc,
повторный клик или клик мимо прячут.

## 🗂 Цвет проекта: вид живёт в папке проекта (WF15, задача #5370)

Открыл в Claude Code чат с папкой `~/_ElvisProjects/Dictatorik` — окно само перекрасилось в цвет этого проекта;
перешёл в чат другого проекта — цвет сменился. Вид (цвет, шрифт, размер, рамка) хранится **в самой папке**,
файлом `.pimpmyclaude.json`, и едет вместе с ней к любому в команде. Пункт стоит первым разделом «🎨 Оформление ▸»:

```
🗂 Проект: PimpMyClaude ▸
      ~/_ElvisProjects/PimpMyClaude     ← подпись, не нажимается
      ✓ Красить чаты по проекту
      ──────────
      🎨 Взять цвет проекта
      💾 Записать этот вид в проект     ← файла ещё нет: «✍️ Завести настройки проекта»
      📝 Вписать строку в AGENTS.md
      🗑 Убрать настройки из проекта
```

**Где файл и что в нём.** `.pimpmyclaude.json` в корне проекта; порядок ключей, два пробела отступа и перевод
строки в конце — контракт (`app/Sources/ClaudeAX/ProjectSettings.swift`), приложение пишет файл в этом порядке ключей (вложенные объекты — по ключу на строку, как в `ProjectTests.canonical`):

```json
{
  "pimpmyclaude": 1,
  "name": "PimpMyClaude",
  "theme": { "id": "indigo", "name": "Индиго", "type": "dark",
             "palette": { "accent": "#7c8cff", "background": "#171a2b", "foreground": "#e8e9f5",
                          "sidebar": "#12142230", "panel": "#1e2238", "muted": "#9aa0c0" } },
  "font": { "id": "inter", "family": "Inter", "mono": false },
  "size": { "answer": 16, "question": 14 },
  "frame": true
}
```

- Слои независимы и читаются как поля команды `theme`: **ключа нет — слой не трогаем** (проект задал только цвет —
  шрифт и размер у окна остаются свои), `null` — сброс слоя («в этом проекте как у Claude»), значение — применить.
- Палитра копируется целиком, как в `my-themes.json`: файл переживёт смену каталога тем, `id` нужен только для галки
  в меню. Чужие ключи файла сохраняются, битый JSON читается «сколько смогли» и **сам собой не переписывается** —
  затереть его может только явный клик «💾 Записать этот вид в проект».
- **Корень проекта, а не рабочая папка чата**: от `cwd` поднимаемся вверх до первой папки с `.git` или `AGENTS.md`
  (потолок — `projectsRoot` из `claude.json` и домашняя папка, ничего не нашли — сам `cwd`). Claude Code, запущенный
  из `…/PimpMyClaude/app`, берёт настройки корня, и два чата одного проекта не разъезжаются по цвету.
- Правку файла руками приложение подхватывает само, без перезапуска: сменился файл — окно перекрасилось.
- В папку писать нельзя (нет прав, том только для чтения, отказ macOS в `~/Documents`) — вид уходит в реестр
  `~/Library/Application Support/MyClaude/projects.json`, и приложение честно говорит это плашкой. Минус реестра
  один, зато тяжёлый: **с папкой к команде такие настройки не поедут**.
- `.pimpmyclaude.json` — новый неотслеживаемый файл в чужих репозиториях: он попадётся на глаза проверке «каталог
  чист». Лечится строкой в `~/.config/git/ignore`; сам в настройки git приложение не лезет.

**Как завести.** «💾 Записать этот вид в проект» кладёт в файл ровно те слои, что применены к этому окну (выбрал
цвет и шрифт — их и запишет; окну ничего не выбрано — так и скажет плашкой). Файла ещё нет — пункт зовётся
«✍️ Завести настройки проекта». Можно и просто создать файл руками. «📝 Вписать строку в AGENTS.md» — **памятка
агенту проекта, а не хранилище**: одна невидимая в отрисованном markdown строка
`<!-- pimpmyclaude: {"theme":"indigo","font":"inter","size":{"answer":16},"frame":true} -->`, пишется по клику и
назад НЕ читается (прежняя такая же строка заменяется на месте, остальной файл не трогается). Настройки берутся
только из `.pimpmyclaude.json` — хранилище ровно одно.

**Как выключить.** Тумблер «Красить чаты по проекту» (по умолчанию включён) — одним щелчком, и он при выключении
**снимает с окон слои, которые ставил проект**, а не бросает их залипшими. «🗑 Убрать настройки из проекта» удаляет
файл и запись реестра, но строку в `AGENTS.md` НЕ трогает и окна назад НЕ перекрашивает: цвет остаётся, пока не
выберешь «Как у Claude».

**Ручной выбор сильнее проекта.** Фоновая покраска не трогает окно, которому вид выбрали руками из меню или
которое красила «🌈 Раскрасить по кругу»; задан цвет или шрифт «всем окнам» — покраска по проекту молчит целиком.
Пока открыто меню и 2 с после его последней команды она тоже молчит: иначе фоновая команда сбивала бы примерку темы
мышью. «🎨 Взять цвет проекта» — явная просьба и идёт мимо всех этих проверок. Сменил проект — слои прошлого сперва
снимаются, поэтому в проекте без настроек окно возвращается к прежнему виду, а не остаётся в чужом цвете
(речь об окнах, покрашенных в этом запуске приложения; после перезапуска — «Всё как у Claude»).

**Честно: это подглядывание во внутренние файлы Claude.** Папку чата приложение берёт из
`~/Library/Application Support/Claude/claude-code-sessions/<аккаунт>/<рабочее место>/local_<uuid>.json` (там рядом
лежат `cwd`, `title`, `lastFocusedAt`), а какой чат открыт в главном окне — из адреса страницы в `status.json`
лоадера. Путь и формат чужие: обновление Claude Desktop может сменить и то и другое. Тогда «папки не знаю» —
приложение молчит (ни команд, ни ошибок), пункт зовётся «🗂 Проект: не определён» и гаснет, остальное работает как
работало; весь разбор лежит в одном `ProjectIndex.swift`. Патч Claude и лоадер при этом НЕ меняются — переустанавливать
(«Поставить снова») ни Элвису, ни команде не нужно.

**Что ещё стоит знать (и это не баг):**
- Цвет догоняет чат за 2–4 с: `status.json` лоадер пишет раз в 2 с, очередь команд — 0,6 с на запись.
- Главное окно адресуется путём страницы — необязательное поле `match` в команде `theme` (`inject.js`, версия
  файла сейчас `wf18-a-1`, три строки в `addressed()`). По заголовку нельзя: у него заглушка «Claude», и такую же носят безымянные
  попапы — команда разлилась бы на все сразу. Вынесенные окна чатов адресуются заголовком, а **один и тот же заголовок
  в двух разных папках — окно не красим вовсе** (лучше не покрасить, чем покрасить чужим цветом); заголовки-заглушки
  («Claude», «New chat», «Новый чат») не сопоставляются.
- Покраска по проекту **галок не ставит**: `ThemeStore` она не трогает вовсе, поэтому на окне, покрашенном проектом,
  в «🎨 Цвет ▸» так и останется галка «Как у Claude». Врёт галка, а не цвет — та же оговорка, что у «Раскрасить по кругу».
- Память о ручном выборе привязана к заголовку окна: **переименовал чат — память потерялась**, и проект такое окно
  перекрасит своим цветом.
- Подсказка «у проекта нет своего вида» показывается **один раз на папку** (ключ по пути папки в UserDefaults).
  Отмахнулся — больше не появится; завести настройки всегда можно пунктом меню.
- Обычные чаты claude.ai папки не имеют — их проект не трогает. Индекса чатов нет вовсе (не Claude Code, старая
  сборка, чужая машина) — WF15 просто молчит.
- Живая проверка на гейте: в `statusText` приложения строка `project=<on|off>/<папка главного окна>/<сколько окон
  покрашено проектом>`.

## 🪟 «Новое окно ▸» в папке проекта (WF16, задача #5380)

исчезнувшие с диска каталоги — вон, потолок 8 (`MenuModel.newWindowProjectsLimit`). Своего сканера у пункта нет:
источник правды «папка ↔ сессия» в приложении один. Показываются **только папки, где Claude уже работал**, —
в незнакомой он поднимет своё окно доверия к папке, и автоматическая цепочка встанет на нём; поэтому пункта
«Другая папка…» нет вовсе. Индекса нет (не Claude Code, чужая машина, сменился формат файлов) — в подменю
остаётся один пункт «Здесь же», раздел «НЕДАВНИЕ ПРОЕКТЫ» не рисуется: пункт, молча открывающий окно не в той
папке, хуже отсутствия пункта.

**Что считает приложение, а что делает страница.** Приложение кладёт в команду `new-window` всё готовым: путь
папки (`folder`), уникальное имя чата (`name`) и слои вида — из `.pimpmyclaude.json` проекта, а нет их — как
у окна, из которого нажали (`ClaudeActions.newWindowLayers`, ответ Элвиса на вопрос 2 макета). Контракт —
`scope, title, x, y, text, folder, name` и дальше слои `theme/font/size/frame` по правилам команды `theme`
(поля нет — слой не трогаем, `null` — сброс); пустые `folder`/`name` = «не трогать», и страница ведёт себя ровно
как в WF13. Страница на домашнем экране выбирает папку в сторе claude.ai (`setLocalSelectedFolder` +
`setTrustedSelectedFolder` — второй вызов обязателен, иначе Claude спросит доверие к папке своим окном), **сверяет
выбор обратно** (значение в сторе и чип папки на экране) и только потом отправляет первое сообщение. Стор ищется
поведенчески — по набору полей, а не по имени экспорта: имя меняется с каждой сборкой claude.ai.

**Почему чат не «Привет».** Заголовок авто-сессии — это и есть текст первого сообщения, поэтому первым сообщением
уходит имя проекта (и ничего больше: ни команд, ни путей — в новой сессии работает авто-Allow). Дальше страница
**переименовывает** чат тем же именем через контекстное меню строки сайдбара: после переименования заголовок
становится «пользовательским», и Claude не перепишет его позже своей сводкой — а значит, не съедет и цвет,
привязанный к заголовку. Номер («PimpMyClaude 2») считает приложение по **всем** заголовкам индекса, а не
страница по хвосту сайдбара (`ProjectIndex.uniqueChatName`): два чата с одним заголовком делят ключ темы `chat:`
и путают адресацию `cashout`/`workflow` — этим WF13 и болел, когда все его окна звались «Привет». Уникальность
всё равно не абсолютная: переименуешь чат руками — совпадение снова возможно.

**Цвет сразу.** Перед `openPopout` страница пишет в `myclaude-themes-v1` **одну** запись — `chat:<заголовок>` со
слоями из команды: localStorage у окон Claude общий, попап читает ту же карту, и окно рисуется уже покрашенным,
без вспышки. Ключ берётся из **фактической** строки сайдбара (её же получает `openPopout`), а не из желаемого
имени: сперва до 2 с ждём, пока переименование доедет до строки. Ни `writeLayers`, ни `storeSessionLayers`, ни
`applyLayer` в этом шаге не зовутся — команду исполняет главное окно, и `writeKeys()` дописал бы к ключу чата ещё
`main` и сессию, то есть перекрасил бы окно Элвиса в чужой цвет.

**Когда что-то не вышло — отказы видимые:**
- Папку выбрать нечем или выбор не встал — плашка «Не смог выбрать папку — чат не создавал», **сообщение не
  отправляется, чат не создаётся**, главное окно возвращается на прежний разговор (статусы `no-folder-ui` и
  `folder-missing`). Чат в чужой папке хуже отказа: в новой сессии работает авто-Allow, и агент стартовал бы
  в чужом проекте.
- Переименовать не вышло (у claude.ai сменилась разметка меню, нет пункта «Rename») — цепочка идёт дальше и
  плашки нет: чат создан и назван правильно. Но имя осталось авто-заголовком, и Claude может позже заменить его
  своей сводкой — тогда цвет, привязанный к заголовку, с этого окна слетит (статус `no-rename`).
- Заголовок оказался заглушкой («Claude», «New chat») — слои не пишем вовсе (`no-title`): такая запись досталась
  бы каждому безымянному чату разом.
- Запись слоёв не удалась (квота, битая карта) — окно всё равно откроется, просто без цвета.

**Побочный эффект, о котором лучше знать:** выбор папки меняет у Claude «последнюю папку» — следующий обычный ⌘N
и пункт «Здесь же» откроются уже в ней.

⌥⌘N не изменилась и работает как раньше («здесь же»). Лоадер и патч Claude WF16 не трогает — перепатчивать
`app.asar` из-за него не нужно; новый `inject.js` (версия `wf16-a-1`) доезжает копией из бандла, её кладёт
«Поставить». Проверка живьём: `window.__myclaude.status().newWindow` — рядом со статусом прогона поля `folder`,
`chip` (нашёлся ли чип папки), `name`, `rename`, `title` и `layers`.

## Полоса прогресса воркфлоу (inject.js, раздел 2б)

На нижней кромке рамки поля ввода — тонкая светящаяся линия: сколько пройдено марафона воркфлоу. Ничего не
хранится, всё берётся из самого чата — по последней строке состояния в ответах
(`💭⚪[PimpMyClaude](docs/status.md) · WF 6 из 9 · 40%💭`). Сегментов столько же, сколько воркфлоу в марафоне:
готовые полные, текущий залит на свои проценты, будущие пустые; ✅ заливает все, ✋ красит текущий жёлтым, 🛑 —
красным, остальное берёт акцент темы окна. Строки состояния в чате нет — полосы нет вовсе. Наведи на линию (зона
10 px над ней) — своя подсказка: «Воркфлоу N из M · P %», а под ней строка на каждый воркфлоу из сводки проекта.

Сводки шлёт само приложение, страница файлов не читает: `StatusFeed` раз в 60 с и на каждый показ меню обходит
`<projectsRoot>/*/{docs,audit,work}/status.md` (`projectsRoot` — ключ в `claude.json`, по умолчанию
`~/_ElvisProjects`) и при изменении шлёт командой `status` (≤ 6 КБ на проект, 32 КБ на команду). Папки проектов
нет — не шлёт ничего, и в подсказке остаётся один заголовок. Проверка: `window.__myclaude.status().progress`
(сегменты, якорь, причина) и `.statusFeed`.

## ⌘Q не закрывает Claude (`hammerspoon/claude_noquit.lua`)

Пока окно Claude впереди, ⌘Q перехватывается и показывает подсказку; выход только через меню Claude → Quit.
Установка: `cp hammerspoon/claude_noquit.lua ~/.hammerspoon/`, в init.lua `pcall(function() require("claude_noquit") end)`, `hs -c 'hs.reload()'`.
Статус: `hs -c 'return require("claude_noquit").status()'`, снять: `…stop()`.

## Auto-Allow для окон Claude Desktop

`hammerspoon/claude_autoallow.lua` — модуль Hammerspoon, сам жмёт «Allow» в диалогах разрешений Claude Desktop.
Нужен потому, что часть инструментов (например, create routine) спрашивают в любом режиме, и хуками/настройками Claude это не отключается.

- Ставится: `cp hammerspoon/claude_autoallow.lua ~/.hammerspoon/`, в `~/.hammerspoon/init.lua` строка `pcall(function() require("claude_autoallow") end)`, потом `hs -c 'hs.reload()'`.
- Работает всегда: Hammerspoon стартует при входе в систему (autoLaunch в init.lua), модуль грузится вместе с ним.
- Жмёт любую кнопку «Allow…» во всех окнах Claude, не только для workflow. Исключения — список `M.blockHeadingPatterns` в файле.
- Признак что работает: вверху экрана, в строке справа рядом с часами и батареей, иконка 🤖✓ (может прятаться, если иконок много). Выключить/включить: зажать control+option+command и нажать A, на экране мелькнёт «Claude auto-allow: OFF/ON».
- Выключить из терминала: `hs -c 'require("claude_autoallow").setEnabled(false)'`, включить: то же с `true`.
- Проверено 2026-09-02: окно «Allow once» закрылось само, в history() две записи.
- Проверка: `hs -c 'return require("claude_autoallow").status()'`, история нажатий: `hs -c 'return require("claude_autoallow").history()'`.
- Диалог должен быть виден на экране: окно свёрнуто или сессия не открыта — не нажмёт.
