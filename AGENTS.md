## Как устроено (три слоя)

1. **Патч Claude.app** — `claude-patch/patch-claude.mjs` (Node, дев-инструмент) и его порт `app/Sources/Patcher`
   (Swift, боевой): в `app.asar` дописывается **лоадер v7** (строка `LOADER` в mjs / `Loader.swift`; номер —
   `Asar.loaderVersion` и `LOADER_VERSION`, сверять по коду), пересчёт
   `ElectronAsarIntegrity`, переподпись ad-hoc, бэкап в `~/Library/Application Support/MyClaude/backups/<версия>/`.
   «Поставить» с WF45: живой `claude.css` не затирается, а **сливается** — приложение владеет РОВНО одним блоком
   между маркерами `/* PimpMyClaude:auto */`, всё, что человек дописал вне блока, остаётся дословно
   (`Patcher.mergeCSS`); сорвались хэш или подпись — `app.asar` и `Info.plist` возвращаются из бэкапа
   (`Patcher.rollback`, плашка говорит, что нажать); статус верит `installed.json` только с НУЖНЫМ номером
   лоадера, иначе перечитывает `app.asar` — старый лоадер там значит «патч слетел», и значок у часов красный
   (`Patcher.state()`, до WF45 на старом лоадере горела зелёная галка).
   Лоадер НЕ ТРОГАТЬ без крайней нужды: его смена = перепатч Claude у всей команды («Поставить снова»).
   Папка `~/Library/Application Support/MyClaude/` — так и называется (лоадер смотрит туда), не переименовывать.
2. **Живые файлы в Application Support/MyClaude/**, лоадер перечитывает их по mtime без перезапуска Claude:
   `claude.json` (minWindowWidth, sidePadding, projectsRoot; умолчания ЧИСТОЙ установки — `minWindowWidth: 280`
   (WF45; было 360, и на нём две плитки раскладок из четырёх серые) и `sidePadding: 5`; готовый файл
   `Patcher.ensureConfig` не перезаписывает, так что у команды 280 приедет только с новой установкой),
   `claude.css` (user-стили, `insertCSS`), **`inject.js`**
   (исполняется в каждой странице Claude при dom-ready и при каждом изменении файла; обязан быть идемпотентным —
   `window.__myclaude.dispose()`), `command.json` (команды `{id, action, at, …}`; лоадер читает раз в 500 мс и берёт
   ПОСЛЕДНЮЮ запись — отсюда очередь в Swift), `probe.js` → `probe-result.json` (любой JS во все страницы, ответ в файл —
   главный инструмент гейта; **с WF29 этот канал делят агент и приложение** — правило владения в «Контрактах»),
   `status.json` (диагностика лоадера, имя занято), `themes.json`, `my-themes.json`,
   `installed.json`, `workflow/` (комплект KICKOFF.md + WORKFLOW.md). Рядом лежит **`window-themes.json`**
   (WF35) — копия карты тем окон; лоадер его НЕ читает, это файл самого приложения
   (`app/Sources/ClaudeAX/WindowThemeStore.swift`), см. контракт `themes-restore` ниже; с WF43 рядом с ним
   **`window-themes.backup.json`** — страховка: тело карты пишется туда ровно перед тем, как пустой ответ
   страницы обнулит файл (`backupBeforeClear`), а обнуляет его только ВТОРОЙ пустой ответ подряд
   (`emptyAnswersToClear`) — один ничего не доказывает. Там же файлы WF36,
   лоадеру тоже неизвестные: каталог **`pimp/`** — канал «Пимп» (`<id>.json` запрос, `<id>.taken` взят
   в работу, `<id>.result.json` ответ; права 0600, файлы старше часа приложение убирает на тике) и
   **`projects.json`** (`{"version":1,"projects":[{name,folder,lastUsed}]}` — свой список недавних проектов
   для меню «🪟 Новое окно ▸» и для канала; переживает переустановку Claude, пропавшие с диска папки
   не показываются, но из файла не удаляются). Голосовой Пимп (WF75) держит там же три файла, лоадеру и приложению
   неизвестные, — их читает и пишет только `tools/pimp.py say`: `pimp-voice.env` (ключ DeepSeek, 0600, не читать и не
   печатать), `voice-log.jsonl` (журнал фраз, 0600) и `voice-pasted.json` (отметка последней вставленной фотки). Рядом с ним — **`project-views.json`** (WF46) — запасной
   реестр видов проектов на случай, когда в папку проекта писать нельзя (`ProjectSettingsStore`); файл
   в папке всегда сильнее. До WF46 реестр делил имя с `projects.json`, формы у них разные — и запись
   реестра стирала список недавних проектов; старое имя теперь только читается, и только если там объект.
   Источник правды — `claude-patch/` в репозитории; «Поставить» и `bundle.sh` копируют оттуда. Живой `inject.js`
   руками не править — только репозиторный, потом `cp` в Application Support (лоадер подхватит).
3. **PimpMyClaude.app** — `app/` (SwiftPM, macOS 13+, Swift 5 mode). Таргеты: `Patcher`, `ClaudeAX`
   (AX-модуль: авто-Allow, меню на кнопке, Carbon-хоткеи, ⌘Q, Расставить/Показать, темы/шрифты/размер/рамка,
   автопокраска, StatusFeed, WorkflowKit, очередь `CommandChannel`, канал чатов `ChatProbe`), `PimpMyClaude` (меню-бар, окно настройки
   разрешений, уведомления, Поставить/Снять/Статус). Протокол `ClaudeAXControlling` в `ClaudeAX.swift` — контракт
   между модулями, менять только осознанно.

## Сборка, гейт, релиз

- **`bash tools/test.sh`** — один прогон всего (WF24): `node --test tests/` (страница гоняется в
  `node:vm` через люк `globalThis.__myclaudeTest` и стаб DOM `tests/dom.mjs`, путь к файлу — `MYCLAUDE_INJECT`) + сторожевые
  grep-проверки inject.js + `python3 -m unittest tests/pimp_cli_test.py` (CLI «Пимп», WF36; приложение подменяет
  ниткой, каталог — `MYCLAUDE_PIMP_DIR`) + `swift test`. Числа тестов в паспорт не вписываем — они из последнего
  прогона `tools/test.sh`, скрипт печатает их сам. Красное = гейт не проходит. Чеклист гейта и «проверка на
  своём Маке» для команды — `docs/CHECKLIST.md`.
- `tools/bundle.sh release` → `app/.build/PimpMyClaude.app` (Developer ID). **Подмена без простоя:** сначала bundle,
  потом `pkill -f PimpMyClaude.app/Contents/MacOS; rm -rf /Applications/PimpMyClaude.app; ditto …; open …` — Элвис
  дважды ловил «минус не работает», когда приложение лежало во время сборки.
- `tools/release.sh` → нотаризация (профиль `pimpmyclaude`) → `dist/PimpMyClaude-<версия>.zip`; версию поднять в
  `app/Resources/Info.plist` (CFBundleShortVersionString + CFBundleVersion) до запуска.
- Живой гейт без клика: `probe.js` → `window.__myclaude.status()` (поля theme/font/size/frame/progress/statusFeed/
  chat/chatKey/sessionKey/preview/workflow), команды руками в `command.json` (id обязан быть новым), скриншот
  `screencapture -x -R…`. Мышью водить через Hammerspoon (`hs -c`) можно, но `hs` иногда виснет — таймаут.
- **`probe.js` с WF29 не только твой**: канал делят агент на гейте и приложение (`ChatProbe`). Положил свой скрипт —
  приложение уступает и молчит (карта чатов замирает, попапы красятся по заголовку); **закончил — удали `probe.js`**,
  канал вернётся за 5–10 с. Кто держит канал, видно по `head -1 probe.js` (`// myclaude-chats v1 …` — приложение)
  и в `statusText` полем `chats=<own|busy|off>/<страниц>/<опознано>`; рядом `pimp=<запросов/ошибок>` — канал «Пимп» (WF36).
- **«Поставить» в приложении закрывает Claude** и с ним чат оркестратора — на Маке Элвиса делает он сам; патч у него
  уже стоит (v7). Живой «Снять → Поставить» новым Swift-патчером Элвис ещё НЕ делал (проверено только на копии
  Claude.app и старым mjs-ридером).
- Git: коммит с явным автором (`GIT_AUTHOR_NAME=Elvis GIT_AUTHOR_EMAIL=elvis@M4.local …`, иначе «Author identity
  unknown»), в конце сообщения `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Ветка на воркфлоу

## Кто чем владеет при параллельных батчах (правило одного писателя)

Полос четыре, по файлам они не пересекаются — волна идёт ими разом (так шли WF21+WF41 и WF43):

1. **Страница** — `claude-patch/inject.js` (всегда ОДИН агент на волну: файл растёт каждой волной, сверяй
   `wc -l`; разделы 2а темы и ключи чата, 2б полоска, 2в живые цвета, 12 «Обкэшить», 12а Workflow,
   12б новое окно, 12в «кто этот чат», 16 подписки) и её тесты `tests/*.test.mjs`, `tests/dom.mjs`.
2. **Swift** — `app/Sources/**` и `app/Tests/**`. Узкое место полосы не исходники, а два тест-файла, куда
   дописывает каждый Swift-батч: `app/Tests/ClaudeAXTests/ClaudeAXTests.swift` и `PimpChannelTests.swift`;
   пока они не разрезаны, двух Swift-батчей разом не запускать.
3. **CLI и его тесты** — `tools/pimp.py`, `skills/`, `tests/pimp_cli_test.py`, `tools/*.sh`.
4. **Документы** — `AGENTS.md` (он же `CLAUDE.md` симлинком: писать только по пути `AGENTS.md`, иначе симлинк
   заменится копией), `HANDOFF.md`, `README.md`, `docs/**`.

Эталоны канала `tests/fixtures/pimp/*.json` пишет один батч до старта, дальше они не меняются: на них стоят
оба конца — Swift и CLI. Контракт команды фиксируется в плане до старта, менять — только на гейте.
