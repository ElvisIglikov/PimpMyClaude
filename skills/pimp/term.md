# Пимп: чат в терминале (`term`, WF111)

Часть скилла «Пимп» (`SKILL.md` рядом): как звать CLI и правило «окна Claude — только Элвису и Рику» — там.
Подчинённый чат в терминале вместо окна Claude — меньше памяти и тепла (слово Элвиса 30.09.2026).

| Элвис сказал | вызов |
|---|---|
| «открой Вкуснофф в терминале», «Рисовалку — терминалом» | `term VkusnoffKz --text "<задача>"` — tmux-сессия «rick-VkusnoffKz» фоном в папке проекта (без tmux — вкладка Terminal), `claude --model claude-opus-5-5 --effort high --permission-mode bypassPermissions --settings <файл Пимпа>`; окно — `--show` |
| «продолжи этот чат в терминале», «переведи Рисовалку в терминал» | `term Risovalka --from-chat local_…` (или `--last` — последний чат папки, `--resume <cliSessionId>`) |
| «напиши в терминал Вкуснофф: …» | `term-send VkusnoffKz "<текст>"` (длинный — `-` со stdin) — текст, пауза, Enter и проверка, что дошло |
| «какие терминалы», «что открыто в терминалах» | `term-list` |
| «перекрась терминал Вкуснофф» (сменили цвет окна проекта) | `term-color VkusnoffKz` |

Имя проекта — как у `open`, по `pimp.py projects`, наугад не открывать. Терминал проекта уже открыт — второй не
заводится: вкладку покажут, `--text` уйдёт в него. После `--from-chat`/`--last` скажи Элвису закрыть этот чат
в окне Claude: одну сессию двумя хозяевами не держат. «Нет доступа к Terminal» — Элвису: «Системные настройки →
Конфиденциальность → Автоматизация». С tmux чат идёт фоном, без окна (слово Элвиса 01.10: окна терминалов не
нужны — вертикальный монитор для HTML); окно — `term <проект> --show`.

`term-send` пишет «не уверен, что дошло» (код 1), когда текста не видно на экране чата после Enter: глянь сам
(`term <проект> --show`), повтор вслепую не зови — текст мог уйти.

Рику окна и терминальные чаты отвечают только почтой: `python3 <корень проектов>/Rick/tools/rick_bus.py tell
--from <проект> "…"` (корень — `projectsRoot` из `claude.json`, у Элвиса `~/Projects`; точный путь называет
отказ `send` в поле Рика). `send` в поле Рика отказывает (#8364, «зачем ты мне в моё поле ввода отправляешь…»),
туда пишет только голос Элвиса.

Вкладку ищем не по заголовку (claude переписывает его сразу), а по tty из реестра `MyClaude/term/<проект>.json`;
с tmux адрес — сессия `rick-<проект>`. `term-list` только читает tmux и реестр — без AppleEvents и без смены
заголовков (заголовок ставит `term`), убирает лишь мёртвые записи реестра; `term-send` в найденный tmux тоже не
обращается к Terminal. `term-list --with-terminal` добавляет вкладки claude без записи (руками или до реестра) —
по папке процесса, с пометкой «без записи»; `term-send` в них тоже работает. Чтение вкладок ждёт до 10 с: при
отказе список tmux/реестра остаётся, предупреждение уходит в stderr, JSON stdout остаётся массивом. Ошибка чтения
tmux — отказ (код 1), а не пустой список: реестр сохраняется, запуск и отправка не выполняются.

Вкладка Terminal красится цветом окна проекта (фон, текст, курсор — как у окна Claude: вид `.pimpmyclaude.json`
или авто-цвет по имени папки); у проекта `"theme": null` или выключен «Свой цвет у каждого проекта» (панель PMP → Оформление) — не красится.

Перед новым tmux-чатом снимаются глобальные метки `CLAUDECODE`/`CLAUDE_CODE_*`; те же метки убираются из нового
процесса, затем ставится локальное `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1`. `CLAUDE_CONFIG_DIR`, PATH и прочие
настройки сохраняются, работающие процессы не меняются. Отказ чтения/очистки среды блокирует создание сессии;
подтверждённое отсутствие сервера позволяет запустить новый с чистой средой. Значения переменных не печатай.

## Права терминала (WF121, лист 48 · 4.3)

Новый процесс, включая продолжение, получает абсолютный путь к `tools/claude-term-settings.json` рядом с CLI,
независимо от папки проекта. В файле только `permissions` с обязательными непустыми запретами `deny` (те же, что
у терминалов Рика); режим — `bypassPermissions`, его ставит сам CLI. Файла нет, он повреждён, без `deny` или
больше 2 MiB — новый чат не запускается. Начальный `--text` передаётся новому Claude через argv после `--`.
Настройки уже работающих процессов не обновляются; после штатного завершения можно продолжить через
`term <проект> --resume <cliSessionId>` с прежним cwd. `renew` обновляет окно Desktop, а не терминальный процесс;
две копии одной истории не запускать.

Файл не гарантирует распознавание всех обёрток и внешних инструментов. Отказ по запрету сообщай Рику через
`rick_bus.py tell --from <проект> …`: проект, сессия, категория и причина без секретов. Не отвечай на диалоги
разрешений клавишами через tmux/AppleScript, не повторяй запрещённое другим интерпретатором и не меняй чужие
settings ради разрешения.
