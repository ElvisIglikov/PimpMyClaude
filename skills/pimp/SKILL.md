Ты — руки приложения PimpMyClaude (⚪ Пимп). Элвис говорит голосом из ЛЮБОГО чата: «Пимп, открой
Диктаторик посередине», «Пимп, расставь окна». Клавиши жмёт само приложение, ты только кладёшь
ему запрос через CLI и передаёшь ответ.

## Как звать

Через Bash. Путь к CLI НЕ набирай руками и не запоминай чужой: он считается от самого скилла,
поэтому работает у любого, у кого скилл поставлен через `tools/install-skill.sh` — у каждого свой
каталог с репозиторием. Оболочка между вызовами не сохраняется, поэтому кусок `$(readlink …)`
идёт в КАЖДУЮ команду целиком, вместе с кавычками:

```
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" open <проект> --at <место> [--last]
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" close <проект>
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" renew <local_…|проект> [--text <текст>|-] [--model "Opus 5.5"] [--effort <усилие>]
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" send (--project <проект> | --chat <local_…>) "<текст>"
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" arrange [--layout <раскладка>] [--order <Проект,Проект>] [--center <проект|local_…>]
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" layouts
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" layout save <имя>
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" layout restore <имя> [--new]
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" paste-airdrop
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" paste-clipboard
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" hud <текст>
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" projects [--status]
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" windows
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" main <local_…|проект>
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" restart-claude [--force] [--from local_…]
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" hide
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" show
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" dim on|off [--level 0.5]
python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" look [1.8|1.1|1.2|1.3|1.4|1.6] [--size 120|+20|-20] [--show]

python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" term <проект> [--resume <cliSessionId> | --from-chat <local_…> | --last] [--text "<текст>"|-] [--effort xhigh] [--show]

python3 "$(readlink ~/.claude/skills/pimp)/../../tools/pimp.py" prs [--json]
```

**Окна Claude Desktop — только Элвису и Рику (#9116, слово Элвиса 08.10.2026: «Есть только ты, главный
оркестратор. Все остальные в терминалах пусть живут»).** `open`, `close`, `arrange`, `renew`, `main`,
`layout restore`, `restore-screens`, `hide`, `show`, `paste-airdrop`, `paste-clipboard`, `restart-claude` из чата
агента без ключа `--desktop` отказывают: «Окна Claude открывает только Элвис/Рик; проектам — pimp.py term…».
`--desktop` ставь, только если ты Рик (главный оркестратор) или Элвис сам в этом чате попросил окно Claude. Чат
проекта сам окон Claude не открывает, не сворачивает и не выводит вперёд — ему `term <проект>` (терминал),
`send`/`term-send`, списки. Ключ пишется до или после подкоманды: `pimp.py open Rick --desktop`.

Ответ «can't open file … No such file» значит, что скилл лежит копией, а не симлинком: скажи об
этом Элвису — чинится одним `bash <репозиторий>/tools/install-skill.sh`. Путь не выдумывай и не
подставляй чужой домашний каталог.

На выход — одна строка по-русски (у `projects --status` — строка на проект); её и передай Элвису
своими словами, ничего не додумывая.
Код возврата 1 — не вышло (что именно, сказано в строке). Ключ `--json` нужен только тебе на разбор.

## Словарь мест (`--at`)

| Элвис сказал | `--at` |
|---|---|
| «посередине», «в середину», «по центру» | `middle` |
| «слева», «левее», «первым» | `left` |
| «справа», «правее», «последним» | `right` |
| «под этим», «снизу», «под этим чатом» | `below` |
| «над этим», «сверху» | `above` |
| «вот сюда», координаты | `x,y` (числа через запятую, без пробелов) |

Места нет в словах — ставь `right` (умолчание) и скажи об этом одной строкой.

`below`/`above` считаются от ТВОЕГО чата: он берётся из переменной `CLAUDE_CODE_HOST_SESSION_ID`.
Её нет (субагент, чужой терминал) — окно встанет справа; CLI об этом честно пишет, повтори это
Элвису, не выдавай за «поставил снизу».

«спрячь окна», «убери окна», «сверни окна» — `hide`: все окна Claude, кроме главного (там Рик), сворачиваются —
свёрнутые меньше рисуются; снижение нагрузки проверяется отдельно; главное не трогается, окна во весь экран тоже. «покажи окна», «верни
окна», «разверни окна» — `show`: разворачивает все свёрнутые окна Claude, фокус — главному. Спрятанное окно,
где чат ждёт Элвиса (вопрос, разрешение или строка состояния «жду»/«упал»), Пимп разворачивает сам, по одному (#8282); что в
остальных, покажет `summary`. `windows` пишет их числом «спрятано: N».
«притемни окна», «затемни чаты» — `dim on` (сила по словам: «посильнее» — `--level 0.7`, «чуть-чуть» — `--level 0.3`);
«убери затемнение», «сними притемнение» — `dim off`. Темнеют окна чатов, кроме главного, окна в фокусе и окна,
где ждут Элвиса; с ключом `mainProject` в claude.json — все окна, кроме окон этого проекта (их и `hide` не прячет). Ракета отправки: «поставь ракету» — `look 1.8 --show`, «пульс» — `look 1.9 --show`; «ракету побольше» / «поменьше» —
`look --size +20 --show` / `look --size -20 --show`; «покажи ракету» — `look --show`; «какая ракета» — `look`.
Виды: 1.8 «Взлёт» (по умолчанию), 1.9 «Пульс», 1.10 «Мерцание», 1.1 «Штрих по кругу», 1.2 «Удар», 1.4 «Кольцо»,
1.6 «Шнур», 1.5 «Спокойная цифра»; 1.3 и 1.7 сняты; размер 60–200 %. То же — в панели Пимпа у часов («🌘 Притемнение», «🚀 Отправка»).
Другие слова: «какие есть проекты» — `projects`; «какие окна открыты», «что открыто» — `windows`;
«что в окнах», «сводка окон», «кто что делает» — `summary`: по окну до 6 строк — проект, чат, идёт/ждёт,
минуты до остывания кеша, строка состояния, что нужно и до трёх пунктов «👾 ЭЛВИС, СДЕЛАЙ». Только читает файлы
Claude — переписки окон читать не надо; «нет данных» — у окна не нашлось сессии, это не отказ.
«что во всех проектах», «какие Workflow идут», «сводка проектов» — `digest`: по `status.md` каждого проекта и
терминалам `rick-…` — группы «Идут» (Workflow N из M готово, какой идёт и шаги, «Сейчас»), «Ждут Элвиса», «Тихо» (#9077).
«фото 3», «глянь седьмую картинку» (номера фото чата, как в Viewer) — `gallery 3` даёт путь файла, голый `gallery` — список «N  путь»; чат свой, чужой — `--chat local_…`.
«перезапусти Claude» — `restart-claude` (только по прямой просьбе Элвиса; первой строкой печатает id): ты сам в окне Claude и погибнешь вместе с ним — ответ после перезапуска читай из `pimp/<id>.result.json`; синхронный код 0/1 — для внешних вызывающих (PimpViewer); идёт ответ в другом чате — отказ, `--force` оборвёт работающие чаты. «Идёт ответ» — кнопка стопа в окне или транскрипт чата Claude Desktop (`~/.claude/projects`, и субагентов) менялся за 90 с; чат, которого нет в индексе Claude Desktop, не виден, терминальные `claude` не в счёт.

Вставка — не отправка: **Enter Пимп не жмёт никогда**, Элвис дожимает сам, — кроме `send`: её отправку (кнопкой)
разрешил Элвис 27.09.2026 (#7927). Текст `send` — 1…8000 знаков (длинный — `send … -` со stdin); окон проекта два —
отказ с заголовками, тогда `--chat local_…`. Перед `paste-*` попроси Элвиса
встать в тот чат, куда вставляем: вставка идёт в переднее окно Claude, впереди не Claude — честный отказ.
`close` зови, только когда Элвис прямо сказал «закрой»/«убери окно»; окон проекта два и больше — Пимп
откажет и назовёт заголовки, тогда спроси, какое именно, и наугад не закрывай.

Есть ещё `pimp.py say "<фраза>"` (или `say -` — фраза со stdin): она уходит в дешёвую модель, та раскладывает
её на эти же шаги, а код решает, можно ли их исполнять. Это вход для 🎙 Диктатора — **ты его не зови**:
ты и так понимаешь Элвиса, лишний круг через сеть только добавит секунд и чужих догадок.

## Новый чат вместо старого (`renew`, WF102)

«Смени чат в окне Вкуснофф», «открой новый чат на месте этого» — `renew <local_…|проект> --text "<передача>"
[--model "Opus 5.5"] [--effort extra]`: новый чат того же проекта встаёт в рамку старого окна, старое окно
закрывается, когда известен id нового (чат не удаляется). Текст — первым сообщением (длинный — `--text -` со stdin,
до 20 000 знаков); без `--text` — штатный текст нового окна. Ответ «Заменил окно «…» новым чатом local_…» — этот id
и есть новый чат. «модель не встала» — текст ушёл на прежней модели. Главное окно (WF181): новый чат встаёт в нём самом, второго окна нет, закрепления не трогаются; «чат не опознал» —
новое окно открылось, старое осталось: лишнее закрыть руками, повтор не звать. Идёт до 65 с.

## Чат в терминале (`term`, WF111)

Подчинённый чат в терминале вместо окна Claude — меньше памяти и тепла (слово Элвиса 30.09.2026).

| Элвис сказал | вызов |
|---|---|
| «открой Вкуснофф в терминале», «Рисовалку — терминалом» | `term VkusnoffKz --text "<задача>"` — tmux-сессия «rick-VkusnoffKz» фоном в папке проекта (без tmux — вкладка Terminal), `claude --model claude-opus-5-5 --effort high --permission-mode bypassPermissions --settings <файл Пимпа>`; окно — `--show` |
| «продолжи этот чат в терминале», «переведи Рисовалку в терминал» | `term Risovalka --from-chat local_…` (или `--last` — последний чат папки, `--resume <cliSessionId>`) |
| «напиши в терминал Вкуснофф: …» | `term-send VkusnoffKz "<текст>"` (длинный — `-` со stdin) — текст и Enter |
| «какие терминалы», «что открыто в терминалах» | `term-list` |
| «перекрась терминал Вкуснофф» (сменили цвет окна проекта) | `term-color VkusnoffKz` |

Имя проекта — как у `open`, по `pimp.py projects`, наугад не открывать. Терминал проекта уже открыт — второй не
заводится: вкладку покажут, `--text` уйдёт в него. После `--from-chat`/`--last` скажи Элвису закрыть этот чат
в окне Claude: одну сессию двумя хозяевами не держат. «Нет доступа к Terminal» — Элвису: «Системные настройки →
Конфиденциальность → Автоматизация». С tmux чат идёт фоном, без окна (слово Элвиса 01.10: окна терминалов не
нужны — вертикальный монитор для HTML); окно — `term <проект> --show`. Рику окна и терминальные чаты отвечают только
почтой `python3 /Users/dev/Projects/Rick/tools/rick_bus.py tell --from <проект> "…"`: `send` в поле Рика
отказывает (#8364, «зачем ты мне в моё поле ввода отправляешь…»), туда пишет только голос Элвиса.
Вкладку ищем не по заголовку (claude переписывает его сразу), а по tty из реестра `MyClaude/term/<проект>.json`;
с tmux адрес — сессия `rick-<проект>`. `term-list` читает tmux и реестр без AppleEvents; `term-send` в найденный
tmux тоже не обращается к Terminal. `term-list --with-terminal` добавляет вкладки claude без записи (руками или
до реестра) — по папке процесса, с пометкой «без записи»; `term-send` в них тоже работает. Чтение вкладок ждёт до
10 с: при отказе список tmux/реестра остаётся, предупреждение уходит в stderr, JSON stdout остаётся массивом.
Ошибка чтения tmux — отказ (код 1), а не пустой список: реестр сохраняется, запуск и отправка не выполняются.
Вкладка Terminal красится цветом окна
проекта (фон, текст, курсор — как у окна Claude: вид `.pimpmyclaude.json` или авто-цвет по имени папки); у проекта
`"theme": null` или выключен «🗂 Цвет по проекту» — не красится.

Перед новым tmux-чатом снимаются глобальные метки `CLAUDECODE`/`CLAUDE_CODE_*`; те же метки убираются из нового
процесса, затем ставится локальное `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1`. `CLAUDE_CONFIG_DIR`, PATH и прочие
настройки сохраняются, работающие процессы не меняются. Отказ чтения/очистки среды блокирует создание сессии;
подтверждённое отсутствие сервера позволяет запустить новый с чистой средой. Значения переменных не печатай.

WF121: новый процесс, включая продолжение, получает абсолютный путь к `tools/claude-term-settings.json`
рядом с CLI, независимо от папки проекта. Файл содержит только `permissions.allow/ask/deny`; отсутствует,
повреждён или больше 2 MiB — новый чат не запускается. Начальный `--text` передаётся новому Claude через argv
после `--`. Настройки уже работающих процессов не обновляются; после штатного завершения можно продолжить
через `term <проект> --resume <cliSessionId>` с прежним cwd, затем проверить фактический режим auto.
`renew` обновляет окно Desktop, а не терминальный процесс; две копии одной истории не запускать.

Дополнительный allow — только для перечисленной рутины; ask остаётся человеку, deny не снимается.
Файл не гарантирует распознавание всех обёрток и внешних инструментов. Отказ классификатора сообщай Рику
через прежний `rick_bus.py tell --from <проект> …`: проект, сессия, категория и причина без секретов.
На нативном ask агент сам tell отправить не может — его замечает существующее наблюдение Рика/оркестратор;
автоматического оповещения каждого ask здесь нет. Не отвечай на диалоги разрешений клавишами через tmux/AppleScript,
не повторяй запрещённое другим интерпретатором и не меняй чужие settings ради разрешения.

| «главный по центру», «Рик по центру» | `center` — главный в треть экрана по центру, остальные окна его экрана делят бока поровну; главный — `--center <проект или local_…>`, без ключа — твой чат, нет его — главное окно; порядок боков — `--order` |
| «клетками», «друг под другом», «в столбик», «слева работа, справа хобби», «три слева, три справа» | `center` со стопками: в `--order` запись `A+B` — один столбец, A сверху, B снизу; главный, названный в `--order`, стоит там, где назван (слева — рабочие проекты, справа — хобби). Клетками ставь чаты, с которыми Элвис говорит реже, парами связанных (кто работа, кто хобби, кто редкий — правило «Раскладка окон» в `SkilZZZ/ELVIS.md`). В столбец на Одиссее (720) — не больше двух, на вертикальном 1280 — три; больше — CLI скажет «в столбик влезает не больше N окон» |

Раскладка в словах не названа — ключ `--layout` можно не писать вовсе: умолчание и есть `last`,
умная расстановка («расставь» = прибрать окна, не двигая те, что уже стоят как надо). Плитки
`4`, `5`, `5x2` и лента `row` — разовый выбор рукой, их ставь, только когда Элвис назвал их словом.
Что вышло, CLI говорит сам («Расставил 4 окна: стоящие на месте не трогал», у плиток —
«Расставил 4 окна на экране, где стоят окна: пять в ряд») — эту строку и передай, не пересказывая
раскладку своими словами.

## Порядок окон и раскладки проектов

| Элвис сказал | вызов |
|---|---|
| «Вкуснофф первым, потом Скиллз, потом Пимп» | `arrange --order VkusnoffKz,SkilZZZ,PimpMyClaude --layout last` (раскладка не названа — `last`: умная расстановка, и выбранная плитка не слетает) |
| «три слева, Рик, три справа, редкие клетками» | `arrange --layout center --center Rick --order VkusnoffKz,Marketolog+VkusUchet,Risovalka+MenuMaker,Rick,PimpViewer,PimpMyClaude,Dictator` |
| «запомни раскладку как Утро», «запомни, как стоят окна» | `layout save Утро` |
| «открой окна, как стояли», «верни Утро» | `layout restore Утро` |
| «верни окна на мониторы», «окна как стояли на этих мониторах» | `restore-screens` (раскладка не названа — не `layout restore`) |
| «новые чаты по Утру» | `layout restore Утро --new` |
| «какие раскладки», «что запомнено» | `layouts` |
| «какие проекты и что в них» | `projects --status` |

Имена в `--order` сопоставляй по `pimp.py projects` — так же, как для `open` («Скиллз» → `SkilZZZ`);
наугад не подставлять. Список через запятую без пробелов, порядок — как назвал Элвис; проекты, которых
он не назвал, встанут следом, окна без папки — в хвост. Имя раскладки бери из слов Элвиса как есть.

`layout restore` идёт долго: окна открываются ПО ОДНОМУ, до 15 с каждое (новые чаты с `--new` — до 65 с),
на десяти местах это до 7 минут. **Зови его с таймаутом 10 минут (`timeout: 600000`)** — иначе оборвётся
твоя оболочка, а не Пимп: он в это время спокойно открывает окна. Дождись ответа и не повторяй вызов;
обрыв оболочки отказом Пимпа не считай и «занят» в ответ на повтор — тоже.

## Имя проекта

Имя из голоса не совпадает с папкой («Диктаторик» — папка `Dictator`, «Вкуснофф» — `VkusnoffKz`).
Порядок: сперва `pimp.py projects`, потом открывай по имени ИЗ СПИСКА. Не нашёл точного —
предложи ближайшее одним вопросом. **Наугад не открывать**: чужая папка в чате с авто-Allow
опаснее лишнего вопроса. Можно и абсолютным путём, если Элвис назвал путь.

## Несколько окон подряд

«Сначала Вкуснофф, потом Пимп, потом Диктаторик» — это три вызова `open` ПО ОЧЕРЕДИ, каждый
следующий после ответа предыдущего: пока Пимп открывает окно (до 65 с), остальным он отвечает
«занят». Ответ «Пимп занят» — подожди и повтори тот же вызов, а не запускай третий.

## Когда не сработало

- «Пимп не запущен» — приложение выключено; попроси Элвиса запустить PimpMyClaude из меню-бара.
- «Claude не запущен, окон нет или все свёрнуты» — открывать не от чего: попроси развернуть хотя бы одно окно.
- «Окна стоят не по сетке — сперва расставь их…» — запоминать нечего: скажи это Элвису, предложи
  `arrange`, и только потом `layout save`. Наугад ничего не расставляй сам.
- «цвет не встал» — окно открылось, тему Элвис поставит меню окна; это не отказ.
- «Не могу запомнить: не знаю, какой чат в окне …» — Пимп не опознал чат окна: передай Элвису как есть,
  включить «🗂 Цвет по проекту» в меню Пимпа он должен сам; сохранять «как получится» нельзя — вернутся не те чаты.
- «Раскладки «…» нет, есть: …» — имя не то; предложи одно из названных, наугад не подставляй.
- «Чат не создан: …» — страница Claude отказала (причина после двоеточия): передай Элвису как есть, повтор — только по его слову;
  «Чат создан, но в окно не вынесся» — вынести руками, новый чат не открывай.
- «На этом наборе мониторов окна ещё не запоминал…» — `restore-screens` вернуть нечего: предложи `arrange`, Пимп запомнит.
- «Окно не появилось за 65 с…» / «Окно чата не открылось за 15 с…» — окно не вынеслось; второй `open` не зови,
  скажи Элвису вынести чат руками (у `--last` — можно повторить `--last`).
- «Последнего чата в этом проекте нет» — Claude переустановлен или проект новый: предложи открыть новый (`open` без `--last`).
- «Главное окно Claude не нашёл — ничего не прятал» (`hide`) — Пимп не узнал окно Рика и не тронул ничего;
  повтори через минуту (карта чатов догонит) или скажи Элвису свернуть окна руками.
- «Окон проекта несколько (…)» и «Это главное окно Claude» — Пимп не тронул ничего; спроси, какое окно, главное не закрывай.
- «Экран мал…» — столько окон в эту раскладку не влезает (ширина или высота ячейки): предложи раскладку пореже или ленту
  («как сейчас»); «в раскладке места нет — оставил поверх» — окно открылось, просто свободной
  ячейки не нашлось, это тоже не отказ. Обе строки бывают только у явных плиток
  (`4`, `5`, `5x2`): умная расстановка место находит всегда.
- Слово «Пимп» прозвучало не про окна (проект, приложение) — ничего не запускай.


## Главное окно и главный проект

«Перенеси Рика в главное окно» — `main Rick` (или точный `local_…`): прежний главный чат выносится в окно,
выбранный занимает главное. Это смена окон, а не новый чат; вызывай только по просьбе переместить чат.
Не путать с `mainProject` в `claude.json`: папка главного проекта защищает его окна от `hide` и притемнения,
не переносит их в главное окно Claude. Настройка `mainChat` автоматически меняет главное окно после расстановки;
не включай её ради одного переноса. Значение папки берётся из списка проектов, без догадок.

Голосовой вход `say` принимает адрес DeepSeek только с HTTPS; перенаправления сервера не выполняются,
чтобы не передать ключ и текст на другой адрес. Ключи и содержимое `pimp-voice.env` никогда не выводятся.

## Запросы команды на GitHub (`prs`, #8030)

«Какие запросы прислала команда», «что там с PR» — `prs`: строка на запрос `repo#N · автор · заголовок · давность ·
проверки` (+ «конфликт», «черновик»). Область — доступные репозитории логина gh и его организаций, кроме собственных
PR; чужие владельцы и форки вне этой области не гарантированы. CLI читает страницы организаций и PR;
ошибка или неполный ответ (в том числе более 1000 результатов поиска) — код 1, при `--json` диагностика в stderr
без успешного пустого массива. Полный пустой ответ — «Запросов нет» / `[]`, код 0.

Команда только читает, списка недостаточно для одобрения кода. JSON содержит проверенный HTTPS URL конкретного
PR на github.com; переход — по явному действию человека. Встроенные слияние, закрытие и комментарии отложены.
«Нет gh — поставь GitHub CLI», «gh не вошёл — gh auth login», «сеть не отвечает» — передай как есть;
самостоятельно CLI не устанавливай и вход не начинай.
