# План WF7 — Полоска прогресса воркфлоу в поле ввода

Дата: 03.09.2026 23:20. Проект ⚪PimpMyClaude. Задача 🟣Trelvis #5318. Слово 👾 Элвиса: «в ElvisOS есть полоса внизу,
которая показывает протухание контекста; хочу, чтобы при запуске нескольких воркфлоу такая полоска росла — не внизу
экрана, а в нижней полосе поля ввода, над надписью Fable 5.1, и заполнялась по мере продвижения воркфлоу».
Одна задача, один файл — без критика (правило «мелкая одиночная правка»), но с verify. Оркестратор Fable high,
батч и verify Opus max. Стартует ПОСЛЕ волны 1 WF6 (inject.js — один писатель). Run-файл `docs/run-wf7-2026-09-03.json`.

## Образец в ElvisOS

`Resources/claude-chat-cleaner-inject.js:794-1130` — «полоса кэша»: `position:fixed; bottom:0; height:2px; width:0`,
цвет `var(--raduga-cache-bar,#8b5cf6)`, свечение двумя тенями (`0 0 18px` + `0 0 6px`), `transition: width linear`.
Меряет время с конца хода, не наш случай. Берём только вид: тонкая светящаяся линия, растущая слева направо.

## Решение

1. **Источник прогресса — строка состояния** последнего ответа в чате: `💭⚪[PimpMyClaude](docs/status.md) · WF 6 из 6 · 40%💭`
   (формат из SkilZZZ/AGENTS.md п. 5). Регэксп по тексту последнего сообщения ассистента: `WF (\d+) из (\d+)(?:\s*·\s*(\d+)%)?`,
   значок в начале/конце: ✅ → 100 %, 🛑 → полоса красная, ✋ → жёлтая, 💭 → цвет акцента темы (`var(--accent-brand)`
   / фиолетовый #8b5cf6 по умолчанию). Прогресс марафона = ((N − 1) + P/100) / M; строка вида `✅ · 5 из 5` без «WF»
   → 100 %. Строки состояния нет ни в одном сообщении → полосы нет (не рисовать пустую). Берётся ПОСЛЕДНЯЯ по DOM.
2. **Где рисуется** — внутри блока поля ввода, на границе между текстом и нижней строкой инструментов («Auto + 🎤 …
   Fable 5.1 High»): абсолютный `div` 2 px высотой, `left:0`, ширина = прогресс, поверх границы. Родитель — корень
   поля ввода, который inject.js уже находит (`data-myclaude-editor-root` / `state.shell`); строка инструментов —
   контейнер с кнопкой модели (текст «Fable», «Opus», «Sonnet», «Haiku» или `aria-label` c «model»). Если структура не
   найдена — полоса не рисуется, в `status()` `progress.reason`. Ручка над полем не задевается.
3. **Обновление** — на тик обновления времени сообщений (inject.js уже перечитывает DOM раз в ~10 с для «3 min ago»)
   и на MutationObserver ленты с троттлингом 1 с; при смене ширины — `transition: width 400ms linear`. Подсказка
   `title` на полосе: «Воркфлоу 6 из 6 · 40 %».
4. **Хранилище** — нет: полоса всегда считается из DOM. `status().progress = {wf, of, pct, total, state, reason}`.
5. **Во всех окнах** — каждое окно считает по своему чату (подчинённые окна тоже).
