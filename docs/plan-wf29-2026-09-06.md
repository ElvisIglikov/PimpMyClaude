## Решения

### 1. Причина у обеих задач одна — чинить надо опознание окна

`#5448` и `#5455` — не две работы. Механика «сменилась папка → перекрасить» написана и покрыта тестами (п. 12);
ей не хватает единственного — знать, какой чат в окне. Поэтому весь воркфлоу про **id чата**, а «смена директории»
закрывается сама собой. Отдельного слежения за «Change directory» не пишем: файл сессии и так перечитывается
по mtime раз в 2 с (п. 13).

### 2. Канал «страница → приложение» — probe.js, вежливо (вариант «а» из задания)

Других путей нет (п. 17): (б) localStorage приложение не читает — это LevelDB внутри работающего Claude;
(в) лоадер трогать нельзя; HTTP на localhost режет CSP; невидимая AX-метка в DOM (приложение читает узел через
Accessibility) требует живой проверки на упакованном приложении с выданным доступом и даёт шанс, что Chromium
выбросит невидимый узел из дерева, — записываем как возможное улучшение, но не в WF29.

Чтобы probe остался рабочим инструментом гейта, приложение владеет им **вежливо**:

- В первой строке своего скрипта приложение пишет метку `// myclaude-chats v1 <nonce>`.
- **Берёт канал**, если: `probe.js` нет вовсе; ИЛИ его текст побайтно равен тому, что приложение писало
  в прошлый раз; ИЛИ он начинается с метки `// myclaude-chats v1` (свой скрипт от прошлого запуска);
  ИЛИ файл не менялся дольше 10 минут.
- Увидело чужой свежий скрипт (агент на гейте) — **молчит 60 с и пробует снова**, карта чатов остаётся прежней
  и помечается «несвежей». Проверка стоит один `stat` (+ чтение файла, только когда `stat` изменился).
- **Тумблер выключен — канал не трогаем вовсе** (находка критика): `ChatProbe.tick` выходит первой строкой, если
  `projectPaintEnabled` (`ProjectPaint.swift:76`) стоит в `false`. Probe нужен ровно покраске; выключил
  «🗂 Цвет по проекту» — приложение не пишет `probe.js` и не читает `probe-result.json` совсем.
- **Новый круг не начинаем, пока не закрыт прошлый**: пишем `probe.js` только если на прошлый `nonce` уже пришёл
  ответ ИЛИ с записи прошло больше 30 с. Иначе (находка критика) круг лоадера — `probeStamp` ставится ДО обхода,
  дальше 41 страница последовательным `await` (`patch-claude.mjs:189-190`, тот же код `Loader.swift:64-66`) —
  не успевает закончиться, начинается второй, и поздно завершившийся СТАРЫЙ круг затирает `probe-result.json`
  свежего. Nonce-фильтр это поймает, но карта зря будет помечена несвежей.
- Ответ узнаёт по `nonce`: из `probe-result.json` берутся только записи, где `result.nonce` совпал с последним
  записанным; чужой ответ не разбирается вовсе. Файл читается только при смене `mtime+размер` (он весит 3,9 МБ —
  разведка п. 1), то есть один разбор на круг, а не на тик.
- Скрипт приложения — короткий и без побочных действий: одна строка отсева чужих страниц, один вызов
  `window.__myclaude.chats(...)`, `catch` → `{v:1,nonce,kind:"other"}`. Ничего не пишет и ничего не красит.
- Правило записывается в `docs/CHECKLIST.md`: «пользуешься probe.js на гейте — приложение уступает; закончил —
  удали probe.js, приложение заберёт канал обратно за 5–10 с».

### 3. Когда спрашивать (частота)

Своего таймера не заводим — работаем на общем тике 2 с `ClaudeAXController` (как покраска). **Пол — 15 с между
кругами** (правка по критику: круг стоит лоадеру обхода 41 страницы и записи файла на 3,9 МБ, разведка п. 1;
раз в 5 с это была бы постоянная нагрузка на чужой процесс). Спрашиваем только при включённом тумблере
«🗂 Цвет по проекту» и только по поводу:

1. первый тик после старта приложения;
2. изменился набор заголовков окон Claude (окно открылось, закрылось, переименовалось);
3. есть окно, чат которого мы не знаем, а спрашивали больше **60 с** назад (окно, которое не опознаётся
   в принципе — попап обычного чата claude.ai, — не должен дёргать канал каждые 15 с);
4. `indexRevision` вырос — **состав чатов изменился по кортежу `(sessionId, cwd, title)`**. Считает его
   `ProjectIndex`: отдельное поле `revision`, растёт в `reload()`, когда изменился набор этих кортежей.
   Возврат `reload() -> Bool` остаётся как есть — на нём висит `reloadIfNeeded`, и трогать его незачем.
   Полное равенство `ProjectSession` для триггера НЕ годится: в него входит `lastFocusedAt`, который Claude
   переписывает непрерывно (п. 13), и probe уходил бы почти на каждом тике, пока Элвис работает;
5. канал был занят чужим probe и освободился.

Пол 15 с покраску не замедляет: **перекраска после смены папки идёт по КЭШУ id и probe не ждёт** — id попапа
уже известен, изменился только `cwd` в индексе. Канал нужен ровно чтобы УЗНАТЬ id новой страницы.

`scan:true` (поиск стора) уходит только когда есть хоть один попап с неизвестным id; иначе `scan:false` — чистый
кэш. В покое вопросов НОЛЬ. Карта живёт в памяти приложения; перезапуск — спросим заново.

### 4. Что отдаёт страница: `window.__myclaude.chats(opts)`

Новая функция в api (и краткий слепок в `status().chat` — синхронный, только из кэша, для гейта):

```js
window.__myclaude.chats({ scan: true, nonce: "…" })  // → Promise<объект ниже>
{
  v: 1,
  nonce: "<строка из запроса или null>",
  kind: "main" | "popout" | "other",
  self: "local_…" | null,      // id чата ЭТОЙ страницы
  path: "/epitaxy/local_…" | "blank",
  row: "local_…" | null,       // id активной строки сайдбара — ТОЛЬКО сверка, поведение от него не зависит
  title: "<document.title>",
  popouts: [ { id: "local_…", title: "<заголовок окна>" } ],  // только главное окно, иначе []
  store: "ok" | "cache" | "busy" | "none" | "skip",
  at: <мс>
}
```

- `chats()` **никогда не бросает**: любая ошибка — `store:"none"`, `self:null`.
- `scan:true` пускает поиск стора, и то лишь если карта пуста или старше 30 с; без флага — только кэш
  (`store:"cache"` при попадании, `"none"` при промахе, `"skip"` на чужой странице).
- Скан идёт существующим `newWindowFindStore(newWindowToken)` (п. 16), токен берётся ТЕКУЩИЙ и не увеличивается:
  начался прогон «Новое окно» — скан сам бросит работу, вернём `store:"busy"` и прежнюю карту.
  Новых таймеров, наблюдателей и подписок раздел не заводит вовсе (иначе рушится идемпотентность).
- Одновременные вызовы `chats({scan:true})` (четыре попапа спросили родителя разом) складываются в ОДИН скан:
  промис держится в замыкании (`chatsScanInFlight`), остальные ждут его.
- **Импортёр модулей — сиденье замыкания** (правка по критику, без неё три теста не написать):
  `let moduleImporter = url => import(url);`, и `newWindowScanStores` зовёт `moduleImporter(url)` вместо
  `import(url)` напрямую. В бою поведение побайтно прежнее; тестовый люк (`inject.js:4809-4813`) получает
  `setModuleImporter` (и `newWindowScanStores`), чтобы стенд подставил фальшивый импортёр и посчитал вызовы.
  Причина: `tests/load.mjs:58` гоняет файл через `vm.runInContext(...)` БЕЗ опции `importModuleDynamically`,
  поэтому живой `import(url)` в стенде кидает `ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`, а его молча гасит
  `catch` на каждый адрес (`inject.js:3763-3765`): скан в тесте не нашёл бы ничего никогда, и «импортов ровно
  столько же» посчитать было бы нечем. Опция `importModuleDynamically` не нужна — сиденье дешевле и точнее.

### 5. Как страница узнаёт свой чат — `myChatId()`

- **Главное окно** (`claude.ai`): хвост `location.pathname`, если начинается на `local_`. Источник проверенный
  (п. 6). Активная строка сайдбара кладётся отдельным полем `row` — на гейте видно, расходятся ли они; поведение
  по `row` НЕ строим: `data-selected="focused"` — чужой атрибут, и «focused» может значить не «показан».
  Если гейт (п. 7) покажет расхождение — правка в одну строку: `self = row ?? pathTail`, и она описана здесь
  заранее, чтобы не планировать её отдельным воркфлоу.
- **Попап** (`about:blank`): спрашивает родителя — `window.opener.__myclaude.popoutChat(document.title, {scan})`.
  Функция живёт в главном окне, отдаёт **промис**: точное совпадение заголовка в карте попапов; ноль совпадений
  или два и больше — `null`. При `scan:true` и пустой/старой карте она сперва зовёт `chatsScan()` (тот самый
  единый промис), поэтому попап опознаётся уже в ПЕРВОМ круге probe, а не через круг.
- **Ответ кэшируется в `sessionStorage`, а не только в замыкании** (правка по критику): ключ `myclaude-chat-v1`,
  запись `{id, title}` — `sessionStorage` у попапа свой на окно (`about:blank` унаследовал origin claude.ai; так
  же живут `myclaude-theme-v1` и `myclaude-live-phase-v1`). Замыкание умирает при КАЖДОЙ перезаписи `inject.js`
  (лоадер перечитывает файл по mtime — это происходит на каждом гейте после `cp` и при обновлении приложения),
  и с пустым кэшем попап отверг бы команду с `chat` (решение 6, синхронность), а отпечаток в приложении был бы
  уже записан — окно осталось бы некрашеным до следующей смены папки. `sessionStorage` переживает перезапуск
  инжекта в том же окне. Кэш действителен, пока `document.title` равен сохранённому; заголовок сменился или
  записи нет — спросим родителя при следующем обращении. Обращения редкие (команда или probe), опроса по таймеру
  нет; запись — в тот же `track`/`dispose`, что и остальное (ничего не чистим при снятии: это память окна).
- Нет `opener`, нет `__myclaude` у родителя, стор не нашёлся, заголовок — заглушка (`claude`, `new chat`,
  `новый чат`) → `null`. Никаких догадок.

### 6. Контракт: у команды `theme` появляется необязательное поле `chat`

Порядок полей побайтно: `scope, title, match?, chat?, preview?, theme?, font?, size?, frame?` — `chat` встаёт
сразу после `match`, как `match` в WF15 встал после `title`.

- `chat` — строка `local_<uuid>`. Есть — страница сверяет со своим id (`myChatId()`) и заголовок не смотрит вовсе;
  свой id неизвестен — команда не наша.
- Порядок проверок в `addressed()`: сперва `match` (как было), затем `chat`, затем заголовок/фокус. Приложение
  никогда не шлёт оба поля разом.
- `myChatId()` в `addressed()` должен быть СИНХРОННЫМ: команда приходит событием и ждать промиса не может.
  Поэтому у попапа сверка идёт по КЭШУ id — `sessionStorage` `myclaude-chat-v1` (решение 5), он же переживает
  перезапись `inject.js`; кэша нет — команда не наша, и приложение на следующем тике пришлёт её заголовком
  (деградация ниже).
- **Поле `chat` уходит только той странице, которая сама назвала свой id в ПОСЛЕДНЕМ круге probe** (правка по
  критику): раз страница ответила `self:"local_…"`, её кэш заведомо тёплый и команду она возьмёт. Остаточную
  щель «страница потеряла id между кругом и командой» закрывает сброс отпечатка в решении 9.
- **Деградация по заголовку — на стороне приложения**: id окна известен → шлём `chat`; неизвестен → шлём как
  раньше, заголовком. Поведение на старом Claude и без probe не меняется.
- Другим командам (`workflow`, `cashout`, `new-window`, `popout-window`, `live-colors`, `status`) поле в WF29
  не добавляем: сейчас оно нужно только покраске, а лишние поля — лишний контракт.

### 9. Приложение: цели покраски — из ответов страниц, а не из заголовков окон

Это ключевая правка, она же убирает половину рисков.

- `ProjectPaint.targets()`: **главное окно** — как раньше (ключ `main`, адресация `match`), только сессия ищется
  по чату из решения 8. **Попапы** — по списку `ChatProbe.pages` (`kind == .popout`): у страницы есть свой id →
  цель с ключом `c:<id>`, полем команды `chat:<id>`, `title` из `document.title` (он же AX-заголовок окна — нужен
  для `isWindowBusy`, `themeEditorTitle` и `ThemeStore`), папка — `index.folder(for: id)` (`ProjectIndex.swift:129`).
- **Одинаковые заголовки перестают быть проблемой вообще**: страницы — разные объекты с разными id, каждая
  получает свою цель и адресуется по `chat`.
- **Неизвестный чат**: страница ответила, стор рабочий (`store:"ok"`), а `self:null` → окно «не определён»,
  команды нет, отпечаток не трогаем, папка главного окна НЕ подставляется никогда (комментарий со ссылкой на #5455).
- **Деградация без регресса**: карта несвежая (агент держит канал, приложение только стартовало) ИЛИ страница
  ответила `store:"none"|"busy"|"skip"` → для попапов работает СТАРЫЙ путь: заголовки из `paintableTitles()` +
  `index.folder(forTitle:)`, ключ `w:<заголовок>`. Так окно «Диктатор Workflow продолжение», которое красится
  сегодня, не перестанет краситься, если стор не найдётся. Запас «папка главного окна» не участвует ни в одном
  из путей.
- `ProjectPaint.writableFolder(for:)` и `target(for:)` (запись ручного выбора): сперва `ChatProbe.chat(forTitle:)`
  → `index.folder(for:)`, затем прежний `index.folder(forTitle:)`, и только у пустого заголовка и заглушки
  «Claude» — папка главного окна (это и есть само главное окно).
- Ключ отпечатка `c:<id>` переживает переименование окна: переименовали попап — повторной команды нет.
  У главного окна ключ остаётся `main` (он обязан пережить смену чата, комментарий `ProjectPaint.swift:37-39`).
- **Ключ на окно ровно ОДИН** (правка по критику). Отпечатки живут по ключу (`ProjectPaint.swift:226`, `:248`),
  и если ключ переключается между `c:<id>` (probe свежий) и `w:<заголовок>` (деградация), то на каждом переходе
  окно получает полную команду заново, а слои, поставленные под прошлым ключом, никто не снимает
  (`layer(...)`, `:285-288`) — на гейте, где агент десятки раз дёргает `probe.js`, это мигало бы. Поэтому при
  смене ключа отпечаток **переносится**, а не заводится второй:
  - `w:<заголовок>` → `c:<id>` (id появился): переносим как есть — `folder`/`digest`/`layers`/`title`/`match`
    сохраняются. Если папка по id отличается от папки по заголовку (это и есть баг #5455), тик увидит разницу
    сам и перекрасит.
  - `c:<id>` → `w:<заголовок>` (id потерян — страница перезапустила инжект, стор пропал, канал занят):
    переносим со слоями, но **`digest` обнуляем** — ближайший тик перешлёт вид заголовком. Это же и лечит
    щель решения 6: команда с `chat` могла уйти в никуда (в `commit(...)`, `:264-271`, отпечаток пишется, как
    только `send` вернул `true`, а `send` — лишь постановка в очередь `ClaudeActions.applyProject`,
    `ClaudeActions.swift:821`, не подтверждение, что страница команду взяла). Потеряла страница id — вид
    приедет заново заголовком; сохранила — она команду взяла.
  - Пара «заголовок ↔ id» для переноса берётся из `ChatProbe.pages` (там рядом лежат `title` и `chat`).
- `ProjectPaint.status` (строка `statusText`) дополняется: `on/PimpMyClaude/4/2` — тумблер / папка главного окна /
  покрашено / опознано попапов; рядом `ChatProbe.status` (`own/5/4`).
