## Что выяснено по коду (только чтение, 04–05.09; агенту заново не копать)

### Часть 1 — редактор

1. **Контракт `theme` менять не нужно, и `inject.js` тоже.** `normalizeTheme` (`claude-patch/inject.js:424`) берёт
   шесть ключей `THEME_PALETTE_KEYS` (там же :332), гонит каждый через `normalizeHex`, а `id`/`name` — через
   `themeText` (:419). Готовая тема из каталога и «своя» отличаются только строкой id.
2. **Предпросмотр уже ровно тот, что нужен.** `preview:true` со слоями красит окно, не касаясь хранилищ
   (inject.js:1261), `preview:false` без слоёв возвращает сохранённое (:1269), закрепляющая команда сама гасит
   примерку (`endPreviewExcept`, :1231). Со стороны Swift — `ClaudeActions.sendPreview`, `previewTheme`, `endPreview`.
   Примерка адресуется заголовком окна и фокуса не требует; **пустой заголовок → примерки нет вовсе**.
3. **Вся цветовая математика уже написана — в автопокраске.** `AutoPaint.palette(hue:light:strength:)`
   (`AutoPaint.swift:243`) отдаёт шесть цветов: фон с потолком насыщенности 60 % (`capped`), текст подтянут
   до контраста 7 (`pulled`), акцент уложен в полосу 4,5…6 (тёмная) / 4,5…7 (светлая) (`banded`). Ручкам нужен
   один новый параметр — **отдельный hue акцента**.
4. **Обратный ход из палитры в ручки приблизительный.** hue — из `background`, сила — из светлоты фона (тёмная
   `l = 16 − 4·сила`), сдвиг акцента — разница тонов. Светлота зажата в четыре пункта и квантуется 8-битными
   каналами: **шаг восстановления силы ≈5 %, тон ±2°**. Точного round-trip не проверяем.
5. **Файл своих тем расширяется без боли.** `MyThemesStore.parse` (`MyThemes.swift:111`) молча игнорирует незнакомые
   ключи, `json` (:135) пишет фиксированный порядок `id, name, type, palette, font, size, frame` — `knobs`
   дописывается последним, `contains`-проверки теста `testMyThemesSaveLoadAndLimit` остаются зелёными.
   `add` (:60) перезаписывает свою тему по имени (регистронезависимо), `appending` (:100) заменяет запись по id
   **на её месте** — значит `update(id:)` это пять строк поверх `appending`.
6. **Канал команд опрашивается раз в 500 мс и берёт ПОСЛЕДНЮЮ запись** (`CommandChannel.swift:37`), `.preview`
   пишется мимо очереди сразу. Ползунок без ограничения даст десятки записей в секунду — **троттлинг обязателен,
   шагом 0,5 с** плюс досылка последнего значения. Заодно каждая примерка двигает `lastWriteAt`, а `minInterval`
   = 0,6 с: пока ползунок таскают, очередные команды не пролезают вовсе.
7. **Пока идёт примерка, окно не перекрашивается при смене чата** (`syncChatTheme` выходит на `previewing`,
   inject.js:1188). Забытая открытой панель «замораживает» тему окна — отсюда сторож окна и обязательный
   `endPreview` на всех выходах.
8. **Окна в приложении уже делаются** — `HUD.swift` (NSWindow поверх всех, без фокуса, не ловит мышь),
   `SetupWindow`/`OperationWindow` в таргете приложения. Координаты Quartz→AppKit — `Screens.flip`
   (`ClaudeApp.swift:13`), обрезка по `Screens.mainUsableFrame` (:20).
9. **Протокол `ClaudeAXControlling` (`ClaudeAX.swift`) не трогаем**: редактор открывается только из меню окна.

### Часть 2 — меню

10. **Меню показывается из `MinimizeMenu.show(for:at:)`** (`MinimizeMenu.swift:135`), где `rect` — прямоугольник
    `AXMinimizeButton` в перевёрнутых координатах Quartz (его добывает `minimizeButton(of:)`, :117, с кэшем
    на полсекунды). Точка показа считается прямо перед `popUp` (:265–272) и сейчас звучит так: `point =
    (rect.minX, rect.maxY + 2)`, но если справа от окна влезает 280 пунктов — меню уезжает вправо
    (`frame.maxX + 6`, `rect.minY`), иначе влево (`frame.minX − 6 − 280`). Это слово Элвиса 04.09 21:20 (#5395):
    «открывать сбоку, чтобы примерка была видна». **Слово 05.09 10:40 его перекрывает** — правило «справа, если
    влезает» уходит.
11. **`popUp(positioning: nil, at:, in: nil)` ставит ЛЕВЫЙ ВЕРХНИЙ угол меню** в переданную точку (в координатах
    AppKit, отсюда `Screens.flip`). Значит «правый край чуть левее кнопки» — это `x = rect.minX − 2 − ширина меню`.
12. **Ширину меню до показа даёт `NSMenu.size`** (AppKit считает её лениво при первом обращении). У нашего меню
    есть пункты с кастомными `view` («↔️ Поля по бокам», «Скорость» живых цветов) — на них `size` может соврать,
    поэтому берём его только в разумных границах (120…600), иначе подставляем 280 — ту же константу, что стоит
    в коде WF19.
13. **`NSMenu` не анимируется в принципе.** Показ — блокирующий вложенный цикл событий внутри `popUp`; окно меню
    рисует сам AppKit (`NSCarbonMenuWindow`), доступа к его слою нет, API появления/исчезновения нет, `menuWillOpen`
    зовётся, когда меню уже на экране. Ни `NSAnimationContext`, ни Core Animation приложить не к чему — см. решение 2.2.

### Часть 3 — проект

14. **Цвет проекта уже ездит обычной командой `theme`.** `ProjectPaint.tick()` (`ProjectPaint.swift:206`) крутится
    на общем таймере 2 с `ClaudeAXController`, папку окна даёт `ProjectIndex` (главное окно — по `status.json`
    лоадера, попапы — по AX-заголовку), вид — `ProjectSettingsStore.settings(in:)`, отпечаток «окно → папка + хэш
    вида» не даёт слать одно и то же дважды. Менять этот каркас не нужно — меняются только источник вида
    и правила молчания.
15. **Ручной выбор пишется в одном месте** — `ClaudeActions.remember(scope:title:…)` (`ClaudeActions.swift:455`),
    и зовут его ТОЛЬКО закрепляющие команды: примерка (`sendPreview`) до него не доходит вовсе, автопокраска идёт
    мимо (`paint`, :607, пишет `commands.write` напрямую и снимает галки). Значит крючок «выбрал → это тема проекта»
    вешается на `remember` и сам собой не срабатывает ни на наведении мышью, ни на «Раскрасить по кругу».
16. **Защита «окно занято» сейчас работает против нас.** `ClaudeActions.isWindowPainted` (:793) объявляет окно
    занятым, если у него есть запись в `ThemeStore` ИЛИ его красила автопокраска, а `ProjectPaint.paint` (:238)
    на этом выходит. При новом правиле «ручной выбор = тема проекта» запись в `ThemeStore` больше не повод молчать
    (иначе окно навсегда осталось бы в цвете прошлого проекта), а автопокраска — по-прежнему повод.
17. **Файл проекта пишется безопасно.** `ProjectSettings.merged` (:100) сохраняет чужие ключи и **возвращает nil
    на битом файле** (тогда не трогаем вовсе); `ProjectSettingsStore.write` (:262) не переписывает файл тем же
    текстом (иначе дёргается mtime), а если в папку писать нельзя — кладёт вид в реестр приложения. Удаление —
    `remove(from:)` (:288). Контракт файла побайтный, порядок ключей `pimpmyclaude, name, theme, font, size, frame`.
18. **Плашки и подсказки уже есть**: `showNotice` + `hintsKey` («путь папки → true») — один раз на папку.
19. **Тумблер уже есть**: `ProjectPaint.enabledKey = "projectPaintEnabled"`, по умолчанию включён, выключение
    снимает поставленные слои (`setEnabled` → `clear()`). Новый пункт меню — это он же, только переехавший.

## Решения — часть 1. Редактор своей темы

### 1.1 Ручки (вариант А макета — панель)

Четыре ручки поверх существующего генератора: **Цвет** (hue 0…359), **Акцент** (сдвиг −180…+180° от тона фона),
**Сила цвета** (0…100 %), тумблер **Тёмная / Светлая**. Кнопки «Сохранить» / «Отмена».
**Поля имени в панели нет**: `LSUIElement = true` + `.nonactivatingPanel` означают, что клик делает панель
key-окном, не активируя приложение, — набранные буквы уедут в Claude. Имя спрашивает готовый рабочий путь
`MinimizeMenu.askThemeName` (`NSAlert` + `NSApp.activate(ignoringOtherApps:)` + `initialFirstResponder`).

Читаемость держится жёстко: `pulled`/`banded` никуда не деваются, нечитаемую тему ползунками не собрать.
**Диапазон «Силы цвета»**: 0…100 % сейчас двигают насыщенность фона всего 45 → 60 % (тёмная) и 40 → 60 %
(светлая) — на глаз ручка почти мёртвая. Расширяем **в `ThemeKnobs`, а не в `AutoPaint.palette`** (иначе поедет
автопокраска и пять её тестов): вниз по насыщенности расширять безопасно, читаемость всё равно держат
`pulled`/`banded`.

Шрифт и размер — вопрос 3 макета: если Элвис выберет «пять ручек», шрифт идёт **`NSPopUpButton`-списком, а не
ползунком** (сотни семейств, категории `FontCategory`), ползунки остаются только у кегля 11…24 (`Size.minPx/maxPx`).

### 1.2 Генератор: один новый параметр

`AutoPaint.palette(hue:light:strength:accentHue:)` — `accentHue` по умолчанию `nil` («как у фона»), поэтому
автопокраска и её пять тестов не меняются ни на строку. Ручки живут отдельной структурой
`ThemeKnobs {hue: Int, accent: Int, strength: Int, light: Bool}` (целые — `CommandValue` не придётся учить дробям)
с методами `palette()`, `theme(id:name:)` и `ThemeKnobs.from(palette:type:)` (приблизительный обратный ход, п. 4).

### 1.3 Панель (два новых файла + структура ручек)

**Логика — в чистой модели** `ThemeEditorModel`: ручки, троттлинг с подставленными часами и таймером (ровно как
`CommandChannel.init`), готовые команды на «сохранить»/«отмена». Тесты гоняют модель; `swift test` идёт без сессии
окна, и тест на живой `NSPanel` либо повиснет, либо проверит не то. `ThemeEditor.swift` — только проводка AppKit.

- `NSPanel`, стиль `[.titled, .closable, .utilityWindow, .nonactivatingPanel]`, `isFloatingPanel = true`,
  `level = .floating`, `hidesOnDeactivate = false`, `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`,
  заголовок «Своя тема». Встаёт слева от окна Claude (нет места — справа), координаты через `Screens.flip`,
  обрезка по `Screens.mainUsableFrame`.
- **Панель одна на приложение, ссылка СИЛЬНАЯ**: `static var current: ThemeEditor?` (слабая освободит контроллер
  сразу после выхода из обработчика пункта меню), `panel.isReleasedWhenClosed = false` (по умолчанию `true` —
  крестик дал бы обращение к освобождённой памяти), в `windowWillClose` сперва `endPreview`, потом `current = nil`.
  Открыли на другом окне — прежняя закрывается со своим `endPreview`.
- **Троттлинг примерки 0,5 с** — ровно шаг опроса лоадера; честная задержка от ручки до цвета 0,5–1,0 с. Ползунок
  `isContinuous = true`, пишется одно значение на интервал, последнее досылается всегда.
- **Открытие панели окно НЕ перекрашивает**: примерка не шлётся, пока не тронули ручку.
- **Заголовок окна перечитывается перед каждой записью** (`AX.string(window, kAXTitleAttribute)`): у главного окна
  он меняется вместе с чатом. Заголовка нет — примерка невозможна, панель пишет об этом строкой и остаётся рабочей.
- **Сторож окна**: раз в 1 с проверяем, что окно живо; исчезло — панель закрывается.
- **`endPreview` обязателен** на «Отмена», на крестик, на закрытие сторожем и в `stop()` контроллера.

### 1.4 Сохранение и «изменить»

- Новая тема: «Сохранить» зовёт `askThemeName(default:)`, дальше `MyThemesStore.makeID`, `add(name:…)`, затем
  `apply(myTheme:scope:"window", window:)` — обычная команда, она же гасит примерку. **В окне проекта эта же команда
  становится темой проекта** (часть 3) — так и надо: сохранил свою тему в окне проекта, она у проекта и осталась.
- «Изменить»: панель открыта с id существующей темы → `MyThemesStore.update(id:name:…)` поверх `appending`. Запись
  меняется НА МЕСТЕ (id и позиция в списке сохраняются), в том числе при переименовании. **Правило имени то же, что
  у WF14**: новое имя занято ДРУГИМ id → `NSAlert` подтверждения и слияние в ту запись.
- **`knobs` в `my-themes.json`**: `"knobs":{"hue":262,"accent":0,"strength":50,"light":false}` последним полем.
  Есть — панель открывается ровно там, где её оставили; нет — ручки восстанавливаются из палитры и панель пишет
  «ручки подобраны по цветам». **`knobs` пишутся ТОЛЬКО когда палитра получена этими же ручками**: для темы
  каталога ручки — догадка, и `ThemeKnobs.palette()` от них даст ДРУГИЕ цвета. Поле необязательное, `"knobs":null`
  не писать вовсе; «Сохранить как мою тему…» knobs не пишет.
- **Правка сохранённой темы не перекрашивает другие окна**: страница хранит в `myclaude-themes-v1` весь объект темы,
  а не ссылку по id. Окно, на котором правили, перекрашивается сразу; остальные возьмут новый цвет, когда тему
  выберут заново. Этой же строкой — в README и `docs/TEAM.md`.
- Слои шрифта/размера/рамки при сохранении берутся из уже применённых (`lastAppliedFont/Size/Frame`).

### 1.5 Меню редактора

В «🎨 Оформление ▸», в нижнюю группу: **«🎚 Своя тема…»** (открывает панель с ручками, подобранными по нынешней
теме окна) и **«✏️ Изменить мою тему ▸»** — список своих тем, пункт есть только когда они есть.
Порядок: 🎚 Своя тема… · ✏️ Изменить ▸ · 💾 Сохранить как мою тему… · 🗑 Удалить ▸ · 🧹 Всё как у Claude.
Предпросмотра по наведению у новых пунктов нет.

### 1.6 Кто владеет примеркой, пока панель открыта

Примерка в окне ровно одна, и пока панель открыта — она её хозяин:

- **Меню на жёлтой кнопке.** `MinimizeMenu.tick()` (8 Гц) блокируется только флагом `menuOpen`, живущим внутри
  `popUp`. Панель стоит вплотную к окну — курсор, задержавшийся 0,3 с на кнопке, поднимет меню, наведение на тему
  пошлёт `preview:true`, а закрытие меню без выбора — `endPreview`. **Правка:** `MinimizeMenu.editorOpen`
  (ставит и снимает `ThemeEditor`), `tick()` выходит на нём первым же `guard`, и `endPreview` после `popUp`
  не шлётся, пока примеркой владеет панель.
- **Цвет проекта и живые цвета.** Оба шлют обычные `theme`-команды на то же окно по таймеру, а любая такая команда
  вызывает на странице `endPreviewExcept(["theme"])`. **Правка:** флаг `ClaudeActions.themeEditorTitle: String?`
  и по строке-проверке в `ProjectPaint` и в отправку `LiveColors`.

## Решения — часть 2. Положение меню на кнопке и что с анимацией

### 2.1 Положение (слово Элвиса 10:40 — делаем)

Правило одно, без «если влезет справа»:

```
x = rect.minX − 2 − ширина меню      // правый край чуть ЛЕВЕЕ жёлтой кнопки
y = rect.maxY + 2                     // и чуть НИЖЕ её
если x < области экрана слева →  x = rect.minX,  y = rect.maxY + 2   // под левым краем окна, как было
```

- `rect` — прямоугольник кнопки «Свернуть» в перевёрнутых координатах, он уже приходит в `show(for:at:)`.
- Ширина меню — `menu.size.width`, но только в границах 120…600 пунктов; вне их берём 280 (константа WF19),
  потому что на пунктах с кастомными `view` `NSMenu.size` может соврать (п. 12 «Что выяснено»).
- Считает это **чистая функция** `MinimizeMenu.origin(button:menuWidth:area:) -> CGPoint` (перевёрнутые
  координаты), а `show` только зовёт её и переводит точку через `Screens.flip`. Так положение проверяется тестом,
  без экрана.
- Правило «справа от окна, если влезает» (WF19, #5395) **снимается**: слово 10:40 новее.

Побочные следствия, о которых надо знать заранее:

- Жёлтая кнопка стоит примерно в 26 пунктах от левого края окна, поэтому правый край меню окажется на эти же
  ~24 пункта ВНУТРИ окна. Это и есть «чуть левее значка», как просил Элвис.
- Каскад подменю AppKit раскрывает туда, где есть место, — теперь чаще ВПРАВО, поверх левого края окна
  (сайдбара). Примерку темы это закрывает сильнее, чем вариант WF19 «меню справа». Цена решения; вернуть
  «справа» — одна строка, если Элвису не понравится глазами.
- Панель редактора (часть 1) встаёт слева от окна тоже — при открытой панели меню всё равно не всплывает
  (решение 1.6), так что за место они не дерутся.

### 2.2 Анимация «вылет с минуса / влёт обратно» — разбор честно

**Штатный `NSMenu` анимировать нельзя** (п. 13 «Что выяснено»): показ — блокирующий вложенный цикл внутри `popUp`,
окно меню принадлежит AppKit, слоя и API анимации у него нет. Дальше — что вообще можно сделать:

| Вариант | Что это | Цена | Риск |
|---|---|---|---|
| **A. Без анимации (рекомендую)** | только новое положение из 2.1 | ноль | ноль |
| **Б. Вспышка у кнопки + мгновенное меню** | маленькое окно без рамки (готовый приём — `HUD.swift`): прямоугольник цвета акцента у жёлтой кнопки за 0,12 с уезжает туда, где встанет меню; после возврата из `popUp` — та же анимация обратно | ~70 строк, один новый файл, меню не трогается | низкий: окно не ловит мышь и не просит разрешений. | **В. скажет «хочу». Вариант В — **отдельный будущий воркфлоу** «своё меню» (там же оживёт и клавиатура, и анимация,
и произвольная вёрстка строк); втискивать его в WF20 нельзя: он один по объёму больше всех трёх частей вместе.

### 2.3 Что при этом ломается

Ничего из логики: пункты, галки, предпросмотр и клавиши от точки показа не зависят. Ломается один тест — его нет
(положение сейчас не проверяется вовсе), поэтому вместе с правкой заводим `testMenuOriginSitsLeftOfMinimizeButton`.

## Решения — часть 3. Цвет проекта без лишних действий

Цель словами Элвиса: «действий как можно меньше». Значит цвет должен быть у проекта СРАЗУ, а единственное действие
Элвиса — обычный выбор темы в меню, который он и так делает.

### 3.1 Цвет появляется сам — по имени папки

- `AutoPaint.hue(forName:)` — устойчивый тон из имени папки: **FNV-1a 64 над `name.lowercased()` в UTF-8**,
  `hue = Int(hash % 360)`. Именно свой хэш, а НЕ `hashValue`: у Swift он солится на каждый запуск процесса —
  цвет менялся бы после каждого перезапуска приложения и не совпадал бы у Элвиса с Машей.
- `AutoPaint.projectTheme(folderName:light:)` → `Theme(id: "project-<hue>", name: "<Имя папки> · <hue>°",
  type: …, palette: palette(hue:light:strength: 0.5))`. Читаемость держат те же `capped`/`pulled`/`banded`.
- **Тон — тёмный** (у Элвиса и команды рабочая тема тёмная). Хочешь светлый цвет проекта — выбери в окне этого
  проекта любую светлую тему: она станет темой проекта (3.2). Отдельного тумблера «светлые проекты» не заводим.
- Файл `.pimpmyclaude.json` при этом **не нужен и не создаётся**: авто-цвет живёт в голове приложения.
- Ключ отпечатка для авто-цвета — `auto:<hue>` (вместо хэша настроек), чтобы `paint` по-прежнему не слал одно
  и то же дважды.
- Галки в меню авто-цвет не ставит — как и покраска проекта сейчас.

### 3.2 Выбор темы в окне проекта = тема проекта (молча)

- Новый крючок `ClaudeActions.onWindowViewChanged: ((title, theme, font, size, frame) -> Void)?` зовётся в конце
  `remember` **только при `scope == "window"`**. Примерка и «Раскрасить по кругу» до `remember` не доходят
  (п. 15 «Что выяснено») — значит ни наведение мышью, ни автопокраска в файл проекта не пишут.
- `ClaudeAXController` вешает крючок на `ProjectPaint.noteManualChoice(title:…)`. Она:
  1. узнаёт папку окна тем же путём, что пункт меню сейчас (`folder(for:)`: индекс по заголовку, у безымянного
     окна — папка главного окна). Папки нет — **выходим молча**, выбор остаётся местным, как сегодня;
  2. берёт нынешние настройки проекта (`store.settings(in:)` или пустые) и накладывает пришедшие слои:
     `.set` — записать, `.reset` — убрать слой из файла, `.keep` — не трогать;
  3. остались слои — `store.write(settings, to: folder)`; не осталось ни одного — `store.remove(from: folder)`;
  4. забывает отпечатки этой папки, а окну-инициатору ставит свежий, чтобы не слать ему команду обратно;
  5. один раз на папку показывает плашку «Цвет записан в проект <имя> (.pimpmyclaude.json)» (ключ `hintsKey`
     переиспользуется — он и есть «путь → true»).
- Остальные окна этого проекта перекрашиваются ближайшим тиком (**≤ 2 с**).
- **Защита «окно занято ручным выбором» снимается** (п. 16 «Что выяснено»): она мешала бы окну взять цвет нового
  проекта после смены чата. Защита от автопокраски остаётся.
- Записывается ровно то, что выбрано: тема, шрифт, размер, рамка — каждый слой отдельно.

### 3.3 «Как у Claude» в окне проекта = снять тему проекта

- «🧹 Всё как у Claude» — это `apply(window, .reset, .reset, .reset, .reset)`, «Как у Claude» в подменю цвета —
  сброс одного слоя. По правилу 3.2 сброс убирает слой из файла проекта; ушёл последний — файл удаляется.
- Файла нет → у проекта снова **авто-цвет**. Чтобы окно не мигало голым Claude две секунды в ожидании тика,
  `noteManualChoice` после удаления **сразу красит окно авто-цветом** (тот же `paint`, мимо отпечатка).
- Совсем без цвета — это выключенный тумблер «🗂 Цвет по проекту» (3.4), а не «Как у Claude».

### 3.4 Меню: один тумблер вместо подменю

- В «🖥 Всем окнам ▸», сразу после разделителя и **перед** «🌈 Раскрасить по кругу ▸», появляется тумблер
  **«🗂 Цвет по проекту»** с галкой; по умолчанию включён. Он же `ProjectPaint.enabledKey`, выключение снимает
  поставленные слои со всех окон (`clear()`), включение — красит ближайшим тиком.
- Порядок «🖥 Всем окнам ▸»: ВСЕМ ОКНАМ · Цвет ▸ · Шрифт ▸ · Размер ответов ▸ · Размер вопросов ▸ ·
  Неоновая рамка · — · **🗂 Цвет по проекту** · 🌈 Раскрасить по кругу ▸ · 🌊 Живые цвета ▸.
- «🎨 Оформление ▸» лишается первого раздела: подменю «🗂 Проект: <имя> ▸» исчезает целиком, «Оформление»
  начинается сразу с «МОИ ТЕМЫ».

### 3.5 Что исчезает вместе с подменю (сказать вслух, чтобы не искали)

| Пункт | Куда делся |
|---|---|
| 🎨 Взять цвет проекта | не нужен: цвет и так стоит |
| 💾 Записать этот вид в проект / ✍️ Завести настройки проекта | заменён молчаливой записью при выборе (3.2) |
| 🗑 Убрать настройки из проекта | заменён «Как у Claude» в окне проекта (3.3) |
| 📝 Вписать строку в AGENTS.md | **пропадает совсем** вместе с кодом `writeAgentsLine`/`agentsLine`/`agents(file:line:)` и своим тестом. Памятку агенту проекта больше никто не пишет — если жалко, вернём отдельной задачей одним пунктом |
| Плашка «У проекта X нет своего вида» (`MenuModel.projectHint`) | не бывает: у каждого проекта цвет есть |

### 3.6 Конфликты — как разруливаем

| Что с чем | Как теперь |
|---|---|
| **Ручная тема vs проект** | Ручная тема В ОКНЕ ПРОЕКТА и ЕСТЬ тема проекта: пишется в файл, остальные окна проекта перекрашиваются. Старая защита «окно занято» снята |
| **Окно без папки** | Проект молчит: ни авто-цвета, ни записи. Выбор темы остаётся местным (как сегодня). Старые записи `ThemeStore`, сделанные до WF20, задним числом в проекты НЕ переносятся |
| **Автопокраска «по кругу»** | Проект такое окно не трогает (`autoPaintedThemes`) и в файл ничего не пишет: покраска идёт мимо `remember`. «Как у Claude (все окна)» — `scope:"all"`, тоже мимо |
| **Живые цвета** | Проект молчит целиком (`isLiveColorsOn`, уже так). Выбор темы во время крутёжа в файл ляжет (это ручной выбор), но на экране его перекроет живой слой — как и сегодня |
| **«Всем окнам ▸ Цвет»** | Как в WF15, проект молчит, пока задан вид всем окнам; снял «всем окнам» — цвет проекта вернулся. Отдельной строкой в README, иначе читается как поломка |
| **Два чата одного проекта с разными темами** | **Побеждает последний выбор**: он ложится в файл и перекрашивает второе окно за ≤ 2 с. Разных тем у двух чатов одного проекта больше не бывает — этого Элвис и хотел |
| **Панель редактора темы** | Пока панель открыта, проект это окно не трогает (`themeEditorTitle`, решение 1.6). «Сохранить» = ручной выбор → тема проекта |
| **Примерка мышью** | В файл не пишется никогда: `remember` у примерки не зовётся |
| **Чужая папка** (клиентский репозиторий) | Файл заводится молча — поэтому плашка один раз на папку и строка в README; `.pimpmyclaude.json` у Элвиса уже в `~/.config/git/ignore`. Писать нельзя (нет прав, том только для чтения) — вид уходит в реестр приложения, как в WF15 |
| **Битый `.pimpmyclaude.json`** | `merged` вернёт nil — файл не трогаем вовсе, плашка «файл проекта битый, не трогаю» один раз на папку. Перезаписи «на всякий случай» нет |

## Не делаем в WF20

Пипетку и шесть цветов вручную (вариант В макета — отдельно); **свою панель-меню и анимацию вылета** (решение 2.2,
