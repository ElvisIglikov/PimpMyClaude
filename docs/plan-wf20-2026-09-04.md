## Что выяснено по коду (только чтение, 04.09; агенту заново не копать)

1. **Контракт `theme` менять не нужно вообще, и inject.js тоже.** Страница принимает ЛЮБУЮ палитру:
   `normalizeTheme` (`claude-patch/inject.js:424`) берёт шесть ключей `THEME_PALETTE_KEYS` (там же:332), гонит каждый
   через `normalizeHex`, а `id`/`name` — через `themeText` (:419, срезает `<>{};*\/"'`, 80 знаков). Готовая тема из
   каталога и «своя» отличаются только строкой id. Значит **WF20 — чисто Swift**, лоадер и страница не трогаются,
   «Поставить снова» команде не нужно.
2. **Предпросмотр уже есть и ровно тот, что нужен.** `preview:true` со слоями красит окно, не касаясь хранилищ
   (inject.js:1261), `preview:false` без слоёв возвращает сохранённое (:1269), закрепляющая команда сама гасит
   примерку по слоям (`endPreviewExcept`, :1231). Со стороны Swift — `ClaudeActions.sendPreview`
   (`ClaudeActions.swift:429`), `previewTheme` (:384), `endPreview` (:422). Примерка адресуется **заголовком окна**
   и фокуса не требует (:436) — панель поверх Claude ничего не ломает; **пустой заголовок → примерки нет вовсе**
   (там же `guard !title.isEmpty`).
3. **Вся цветовая математика уже написана — в автопокраске.** `AutoPaint.palette(hue:light:strength:)`
   (`AutoPaint.swift:225`) отдаёт готовые шесть цветов: фон с потолком насыщенности 60 % (`capped`, :260),
   текст подтянут до контраста 7 (`pulled`, :271), акцент уложен в полосу 4,5…6 (тёмная) / 4,5…7 (светлая)
   (`banded`, :291). Ручкам не нужен свой генератор — нужен один новый параметр: **отдельный hue акцента**
   (сейчас акцент берёт hue фона). Контраст и насыщенность считаются по hex (`saturation(hex:)` :361,
   `contrast(hex:hex:)` :346) — тем же способом их проверяет тест `testAutoPaintPaletteIsValidAndReadable`
   (`ClaudeAXTests.swift:1231`), его и повторяем для ручек.
4. **Обратный ход из палитры в ручки — приблизительный, и это нормально** (правка М4; раньше здесь стояло «точно» —
   неправда). hue берётся из `background` (кап трогает только насыщенность, тон сохраняется), сила — из светлоты фона
   (тёмная `l = 16 − 4·сила`, светлая `l = 96 − 4·сила`), сдвиг акцента — разница тонов `accent` и `background`,
   тёмная/светлая — из `type`. Но светлота зажата в четыре пункта (тёмная 16 → 12 %) и квантуется 8-битными каналами:
   **шаг восстановления силы ≈5 %, тон ±2°**. Раз ручки всё равно пишутся в файл (решение 4), обратный ход нужен
   ТОЛЬКО чужим темам (каталог, правка руками) — там довольно «hue из фона, сила 50 %, тип из `type`» и честной
   строки в панели «ручки подобраны по цветам». Теста на точный round-trip не пишем.
5. **Файл своих тем расширяется без боли, а замена по id уже есть.** `MyThemesStore.parse` (`MyThemes.swift:111`)
   читает только знакомые ключи и **молча игнорирует незнакомые** — новое поле `knobs` старая версия приложения
   прочитает, потеряв только ручки. `json` (:135) пишет фиксированный порядок `id, name, type, palette, font, size,
   frame` — `knobs` дописывается последним, и `contains`-проверки теста `testMyThemesSaveLoadAndLimit` (:1153)
   остаются зелёными. **Правка В8:** после WF14 `add` (:60) перезаписывает свою тему по имени (регистронезависимо,
   id и место в списке сохраняются), а `appending` (:100) заменяет запись **по id на её месте** — значит
   `update(id:)` это пять строк поверх `appending`, а не новый механизм (прежняя формулировка «замены по id сейчас
   нет» устарела).
6. **Канал команд опрашивается раз в 500 мс и берёт ПОСЛЕДНЮЮ запись** (`CommandChannel.swift:37`), а `.preview`
   пишется мимо очереди сразу (`case preview` :59, сам `deliver` в конце файла :253 — ссылка поправлена по М7).
   Значит ползунок без ограничения даст десятки атомарных записей в секунду (temp + `rename`), из которых лоадер
   увидит одну на 500 мс. **Троттлинг обязателен — шагом 0,5 с** (ровно шаг опроса лоадера, правка В3)
   и обязательная досылка последнего значения. Заодно: каждая примерка двигает `lastWriteAt` в `deliver`,
   а `minInterval` = 0,6 с (:50) — пока ползунок таскают, очередные команды не пролезают вовсе.
7. **Пока идёт примерка, окно не перекрашивается при смене чата**: `syncChatTheme` выходит на `previewing`
   (inject.js:1188). Панель, забытая открытой, «замораживает» тему окна до конца примерки — отсюда сторож окна
   и обязательный `endPreview` при закрытии.
8. **Окна в этом приложении уже делаются** — `HUD.swift:57` (NSWindow поверх всех, без фокуса),
   `SetupWindow`/`OperationWindow` в таргете приложения. Меню знает и окно (`AXUIElement`), и его рамку
   (`MinimizeMenu.show(for:at:)`, :125) — панели есть куда встать; координаты Quartz→AppKit через `Screens.flip`
   (`ClaudeApp.swift:13`), обрезка по `Screens.mainUsableFrame` (:21).
9. **Протокол `ClaudeAXControlling` (`ClaudeAX.swift`) не трогаем**: редактор открывается только из меню окна,
   в меню-бар не выносится — иначе пришлось бы менять контракт между модулями.

## Решения

### 1. Ручки (вариант А макета — панель; окончательный выбор за Элвисом)

Четыре ручки, все — поверх существующего генератора: **Цвет** (hue 0…359), **Акцент** (сдвиг −180…+180° от тона
фона), **Сила цвета** (0…100 %), тумблер **Тёмная / Светлая**. Кнопки «Сохранить» / «Отмена».
**Поля имени в панели нет** (правка В1): `LSUIElement = true` + `.nonactivatingPanel` означают, что клик делает
панель key-окном, не активируя приложение, — набранные буквы уедут в Claude. Имя спрашивает готовый рабочий путь
`MinimizeMenu.askThemeName` (`NSAlert` + `NSApp.activate(ignoringOtherApps:)` + `initialFirstResponder`), который
WF14 как раз доучивает подтверждению перезаписи.
Гарантия читаемости остаётся жёсткой: `pulled`/`banded` никуда не деваются, нечитаемую тему ползунками не собрать
(вопрос 3 макета). **Диапазон «Силы цвета»** (правка М5): 0…100 % сейчас двигают насыщенность фона всего 45 → 60 %
(тёмная) и 40 → 60 % (светлая), светлоту 16 → 12 % — на глаз ручка почти мёртвая. Если Элвис по макету это
подтвердит, диапазон расширяется **в `ThemeKnobs`, а не в `AutoPaint.palette`** (иначе поедет автопокраска и пять
её тестов); вниз по насыщенности расширять безопасно — читаемость всё равно держат `pulled`/`banded`.
Шрифт и размер — вопрос 2: если Элвис выберет «пять ручек», шрифт идёт **`NSPopUpButton`-списком, а не ползунком**
(сотни семейств, категории `FontCategory` — листать ползунком нечитаемо, правка М11), ползунки остаются только
у кегля 11…24 (`Size.minPx/maxPx`), и «своя тема» начинает собирать все четыре слоя разом — структура `MyTheme`
это уже умеет (тема, шрифт, размер, рамка).

### 2. Генератор: один новый параметр

`AutoPaint.palette(hue:light:strength:accentHue:)` — `accentHue` по умолчанию `nil` (значит «как у фона»), поэтому
автопокраска и её пять тестов не меняются ни на строку. Акцент считается от `accentHue`, всё остальное — от `hue`;
`banded` работает как раньше. Ручки живут отдельной структурой `ThemeKnobs {hue: Int, accent: Int, strength: Int,
light: Bool}` (целые, чтобы `CommandValue` не пришлось учить дробям) с методами `palette()`, `theme(id:name:)`
и `ThemeKnobs.from(palette:type:)` — обратный ход из п. 4 «Что выяснено».

### 3. Панель (два новых файла: `ThemeEditorModel.swift` — логика, `ThemeEditor.swift` — проводка AppKit)

**Логика живёт в чистой модели** (правка В7): `ThemeEditorModel` держит ручки, троттлинг с подставленными часами
и таймером (ровно как `CommandChannel.init`) и отдаёт готовые команды на «сохранить»/«отмена». Тесты гоняют
модель; `swift test` идёт без сессии окна, и тест, который дёргает живую `NSPanel`, либо повиснет, либо проверит
не то. `ThemeEditor.swift` — только AppKit-проводка (ползунки, кнопки, позиция).

- `NSPanel`, стиль `[.titled, .closable, .utilityWindow, .nonactivatingPanel]`, `isFloatingPanel = true`,
  `level = .floating`, `hidesOnDeactivate = false`, `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`,
  заголовок «Своя тема». Встаёт слева от окна Claude (нет места — справа), координаты через `Screens.flip`
  и обрезку по `Screens.mainUsableFrame`, чтобы не уехать за экран.
- **Панель одна на всё приложение — и ссылка СИЛЬНАЯ** (правка В2): `static var current: ThemeEditor?` (не `weak`:
  слабая ссылка без единственного владельца освободит контроллер сразу после выхода из обработчика пункта меню),
  `panel.isReleasedWhenClosed = false` (по умолчанию `true` — крестик дал бы обращение к освобождённой памяти),
  в `windowWillClose` сперва `endPreview`, потом `current = nil`. Открыли на другом окне — прежняя закрывается
  (со своим `endPreview`), новая перенацеливается.
- **Троттлинг примерки**: `previewInterval = 0.5` с — ровно шаг опроса лоадера (правка В3: при 0,3 с лоадер всё
  равно видит не чаще двух записей в секунду, а честная задержка от ручки до цвета 0,5–1,0 с). Ползунок
  `isContinuous = true`, значения копятся, пишется одно на интервал, последнее значение досылается всегда (иначе
  окно застынет на предпоследнем цвете).
- **Открытие панели окно НЕ перекрашивает** (правка В5): примерка не шлётся, пока не тронули ручку; до первого
  движения на экране прежняя тема. Иначе на теме каталога один клик по пункту меню менял бы цвет — читается
  как поломка.
- **Заголовок окна перечитывается перед каждой записью** (`AX.string(window, kAXTitleAttribute)`): у главного окна он
  меняется вместе с чатом. Заголовка нет — примерка невозможна (п. 2 «Что выяснено»), панель пишет об этом строкой
  и остаётся рабочей (сохранить тему всё равно можно).
- **Сторож окна**: раз в 1 с проверяем, что окно живо; исчезло — `endPreview` уже некому, панель закрывается.
- **`endPreview` обязателен** на «Отмена», на крестик (`windowWillClose`), на закрытие панели сторожем и в `stop()`
  контроллера. Молчаливое залипание примерки — прямой запрет (п. 7 «Что выяснено»).

### 4. Сохранение и «изменить»

- Новая тема: «Сохранить» зовёт `askThemeName(default:)` (поля имени в панели нет — правка В1), дальше id
  `MyThemesStore.makeID`, `add(name:…)` (после WF14 совпадение имени = перезапись — так и надо), затем
  `apply(myTheme:scope:"window", window:)` — обычная команда, она же гасит примерку.
- «Изменить»: панель открыта с id существующей темы → **`MyThemesStore.update(id:name:…)` поверх `appending`**
  (правка В8: замена по id на месте уже есть, писать нужно пять строк). Запись меняется НА МЕСТЕ — id и позиция
  в списке сохраняются, галка в меню не съезжает, — в том числе при переименовании. **Правило имени то же, что
  у WF14**: новое имя занято ДРУГИМ id → тот же `NSAlert` подтверждения и слияние в ту запись. Так «две одинаковые
  строки в списке» становятся невозможны (риск из прежней редакции плана убран).
- **`knobs` в `my-themes.json`** (вопрос 4 макета, рекомендую «да»): `"knobs":{"hue":262,"accent":0,"strength":50,"light":false}`
  последним полем записи. Есть — панель открывается ровно там, где её оставили; нет — ручки восстанавливаются из палитры
  (п. 4 «Что выяснено») и панель пишет «ручки подобраны по цветам».
  **`knobs` пишутся ТОЛЬКО когда палитра записи получена этими же ручками** (то есть из редактора) — правка В4:
  для темы каталога или палитры, правленной руками, ручки это догадка, и `ThemeKnobs.palette()` от них даст ДРУГИЕ
  цвета — записав такие `knobs`, следующий «Изменить» молча перекрасил бы тему. Поле необязательное, `"knobs":null`
  не писать вовсе; «Сохранить как мою тему…» (`add` из меню) knobs не пишет.
- **Правка сохранённой темы не перекрашивает другие окна** (В6): страница хранит в `myclaude-themes-v1` весь объект
  темы (`runThemeCommand`: `all[layer] = value`), а не ссылку по id; Swift держит только id для галки. Значит окно,
  на котором правили, перекрашивается сразу (`apply(myTheme:)`), а остальные возьмут новый цвет, когда тему выберут
  заново. Этой же строкой — в README и `docs/TEAM.md` (батч D).
- Слои шрифта/размера/рамки при сохранении берутся из уже применённых (`lastAppliedFont/Size/Frame`,
  `ClaudeActions.swift:322`) — то же поведение, что у нынешнего «Сохранить как мою тему…».

### 5. Меню (поверх структуры WF14, вариант А)

В «🎨 Оформление ▸», в нижнюю группу к своим темам: **«🎚 Своя тема…»** (открывает панель с ручками, подобранными по
нынешней теме окна) и **«✏️ Изменить мою тему ▸»** — список своих тем, пункт есть только когда они есть (как
у «🗑 Удалить мою тему ▸»). Порядок: 🎚 Своя тема… · ✏️ Изменить ▸ · 💾 Сохранить как мою тему… · 🗑 Удалить ▸ ·
🧹 Всё как у Claude. Предпросмотра по наведению у новых пунктов нет (они открывают панель, а не примеряют).

### 6. Кто владеет примеркой окна, пока панель открыта (блокеры Б2 и Б3)

Примерка в окне ровно одна, и пока панель открыта — она её хозяин. Иначе примерку сбивают три чужих источника:

- **Меню на жёлтой кнопке (Б2).** `MinimizeMenu.tick()` (8 Гц) блокируется только флагом `menuOpen`, а тот живёт
  лишь внутри `popUp` (`MinimizeMenu.swift:36,70,216,243`). Панель стоит вплотную к окну — курсор, задержавшийся
  0,3 с на жёлтой кнопке, поднимет меню; наведение на любую тему пошлёт `preview:true`, а закрытие меню без выбора —
  `endPreview` (`show()`, ветка `previewed && !committed`). Окно прыгнет на сохранённую тему, а панель останется
  с ручками и будет думать, что примерка идёт. Плюс `app.focus(window:)` сразу после `popUp` уводит фокус с панели.
  **Правка:** `MinimizeMenu` получает `var editorOpen = false` (ставит и снимает `ThemeEditor`), `tick()` выходит
  на нём первым же `guard`, и `endPreview` после `popUp` не шлётся, пока примеркой владеет панель.
- **«Цвет проекта» (WF15) и «Живые цвета» (WF18) — Б3.** Оба идут ДО WF20 и оба шлют обычные `theme`-команды на то же
  окно по таймеру; любая такая команда вызывает на странице `endPreviewExcept(["theme"])` — примерка ползунка умрёт
  посреди перетаскивания, а сохранённую тему живой слой перекрасит через секунду после «Сохранить».
  **Правка:** флаг `ClaudeActions.themeEditorTitle: String?` (заголовок окна, которым владеет панель) и по одной
  строке-проверке в `ProjectPaint` (WF15) и в отправку `LiveColors` (WF18) — окно с этим заголовком тик пропускает.
- Тест `testMenuStaysClosedWhileThemeEditorIsOpen`; на гейте пункты (ж) и (и).

**Правка.** В решение 4 правило: «`knobs` пишутся ТОЛЬКО когда палитра записи получена этими же ручками (то есть
из редактора); поле необязательное, `"knobs":null` не писать вовсе; `add` из «Сохранить как мою тему…» knobs не
пишет». В V-E: «у каждой записи с `knobs` палитра побайтно равна `ThemeKnobs.palette()` от них».

### [важно] В5. Открытие панели не должно перекрашивать окно

Панель открывается «с ручками, подобранными по нынешней теме окна». Если она сразу шлёт примерку, то на теме
каталога окно поменяет цвет от одного клика по пункту меню — это читается как поломка.

**Правка.** Строка в решение 3: «примерка не шлётся, пока не тронули ручку; до первого движения на экране прежняя
тема». Гейт, пункт (а): «открыли панель — цвет не изменился, тронули ручку — изменился».

### [важно] В6. Правка сохранённой темы не перекрасит окна, где она уже стоит

Страница хранит в `myclaude-themes-v1` весь объект темы (`runThemeCommand`: `all[layer] = value`), а не ссылку по id;
Swift держит только id для галки. После `update(id:)` соседние окна останутся в старых цветах при верной галке.

**Правка.** В решение 4 и в батч D: «окно, на котором правили, перекрашивается сразу (`apply(myTheme:)`);
остальные возьмут новый цвет, когда тему выберут заново» — этой же строкой в README и `TEAM.md`. В гейт пункт (з):
«тема стоит на двух окнах, правим на первом — второе не меняется, это ожидаемо».

### [важно] В7. Три из шести тестов требуют живого AppKit-окна

`testThemeEditorThrottlesPreview`, `…SaveWrites…`, `…CancelEndsPreview` в нынешней формулировке гоняют саму панель;
`swift test` идёт без сессии окна, и тест либо повиснет, либо будет проверять не то.

**Правка.** Вынести логику в чистый `ThemeEditorModel` (ручки, троттлинг с подставленными часами и таймером — ровно
как `CommandChannel.init`, «сохранить»/«отмена» → готовые команды); тесты гоняют модель, `ThemeEditor.swift` остаётся
проводкой AppKit. В столбце «Файлы» батча E третий новый файл: `app/Sources/ClaudeAX/ThemeEditorModel.swift`.

### [важно] В8. `update(id:)` разъедется с перезаписью по имени, и его почти не нужно писать

WF14 уже приземлился в `MyThemes.swift`: `add` перезаписывает своё по имени (регистронезависимо, id и место
сохраняются), а `appending` (:100) заменяет запись **по id на её месте**. Значит `update(id:)` — это пять строк
поверх `appending`, а не новый механизм; п. 5 «Что выяснено» («замены по id сейчас нет») устарел — переписать.
Опасность в другом: `add` ключуется по имени, редактор — по id, и переименование темы в имя соседней даст две
одинаковые строки (план это принимает в рисках — зря, у Элвиса 20 тем и он их различает глазами).

**Правка.** `update(id:name:…)` применяет то же правило имени, что WF14: новое имя занято ДРУГИМ id → тот же
`NSAlert` подтверждения и слияние в ту запись. Риск «Одинаковые имена своих тем» из плана убрать. Тест
`testUpdateKeepsPlaceAndRespectsNameRule`.

### [важно] В9. Кто владеет сборкой — сказать жёстче

Формулировка «сборка волны у этого батча» верна, но волны тут нет: E → D → V-E идут цепочкой.

**Правка.** Строкой под таблицу: «`swift build` и `swift test` — только у батча E; D пишет документы и не собирает,
V-E только читает. Планировщик и критик сборку не запускают».

### Что нельзя без перепатча лоадера

Ничего из WF20. Перепатч («Поставить снова» у всей команды) нужен только на `Patcher/Loader.swift` и
