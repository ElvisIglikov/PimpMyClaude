# ⚪PimpMyClaude — контракты

Вынесено из `AGENTS.md` 18.09.2026 дословно (паспорт проекта читает каждый чат, он должен быть коротким).
Читать ПЕРЕД правкой всего, что ходит между страницей (`inject.js`), Swift и CLI: команды `command.json`, канал `pimp/`, localStorage, ответы probe, карточка и полоска. Новые контракты дописывать сюда, не в паспорт.

## Контракты (побайтно, страница и Swift обязаны совпадать)

- `theme`: `{"id","action":"theme","at","scope":"window"|"all","title":<AX-заголовок окна>,"preview":true|false?,
  "theme":{id,name,type,palette{accent,background,foreground,sidebar,panel,muted}}|null?,
  "font":{id,family,mono}|null?, "size":{answer?,question?}|null?, "frame":true|null?}` — поле есть → слой меняется,
  нет → не трогать, null → сброс; `preview:true` — только на экран, `preview:false` без слоёв — конец примерки.
  С WF43 (#5715) команду адресует и МЕНЮ — и закрепляющую, и примерку: `ClaudeActions.themeAddress` идёт по той же
  развилке `cashoutRoute`, что «Обкэшить» (главному окну `match`, вынесенному чату `chat`, неопознанному окну ничего,
  и он остаётся адресован заголовком); `scope:"all"` и пустой заголовок адреса не получают вовсе. Без адреса выбор
  цвета красил ВСЕ окна с таким же именем чата.
- `workflow`: `{…,"scope":"window","title","text"}` — вставить текст в поле ввода, не отправлять.
- `status`: `{…,"scope":"all","projects":[{name,text}]}` — сводки status.md проектов для подсказки полоски.
- `new-window` (WF13): `{…,"scope":"window","title","x":<число>,"y":<число>,"text":<первое сообщение>}` — главное окно: ⌘N (жмёт Swift),
  первое сообщение, чат выносится popout-окном (стор claude.ai `openPopout`, ищется поведенчески через `import()`
  чанков modulepreload), главное окно возвращается на прежний чат по строке сайдбара; `status().newWindow`.
  Текст первого сообщения один на все окна и живёт в `MenuModel.newWindowText` (с WF43, #5767 — «Окно открыто. Не
  читай правила и ничего не делай, жди задачу.»; до этого «Привет», а в окне проекта — имя проекта, и оно стоило
  полного хода модели). Имя чату ставит поле `name` и шаг переименования на странице; `name` пустое («Здесь же»,
  проект неизвестен) — переименования нет, и авто-заголовком чата становится весь этот текст. ⌘N Swift жмёт с WF43
  не от клика, а от `completion` записи файла (#5735): иначе клавиша обгоняла команду и главное окно уезжало на
  пустой `/epitaxy`. Эталоны `tests/fixtures/cashout/*` держат ПОРЯДОК полей и оставлены со старым текстом нарочно.
- WF16: `new-window` получил поля `folder` (абсолютный путь, "" — не трогать), `name` (имя чата) и слои `theme/font/size/frame`
  как у команды `theme` (порядок: scope,title,x,y,text,folder,name,[theme],[font],[size],[frame]); папка ставится через стор
  Claude (`setLocalSelectedFolder`+`setTrustedSelectedFolder`, поиск поведенчески), имя — через DOM-меню строки с деградацией.
- `popout-window` (WF13): `{…,"scope":"window","title","x","y"}` — вынести текущий чат главного окна в отдельное окно.
- Адресация окна (WF15): у любой команды с `scope:"window"` необязательное поле `match` — путь страницы
  (`/epitaxy/local_<id>`); есть строка → страница сверяет `location.pathname`, поля нет — по `title`/фокусу, как раньше.
  Главное окно так и адресуется (его заголовок «Claude» — заглушка).
- Адресация окна по чату (WF29): у команды `theme` необязательное поле `chat` — id чата (`local_<uuid>`).
  Порядок полей побайтно `scope, title, match?, chat?, preview?` + слои (`ClaudeActions.themeFields`,
  `ClaudeActions.swift:396`). Есть строка → страница сверяет её со своим id (`myChatId()`) и заголовок не смотрит
  вовсе; свой id неизвестен → команда не наша, и приложение пришлёт её заголовком на следующем тике
  (`addressed()`, `inject.js:1268`; порядок проверок `match` → `chat` → заголовок/фокус). Приложение шлёт `chat`
  только той странице, которая сама назвала свой id в последнем круге probe, и `match` с `chat` разом не шлёт
  никогда. Другим командам поле в WF29 не добавлено.
- Настройки проекта (WF15, правило записи WF20): файл `.pimpmyclaude.json` в корне проекта (`{"pimpmyclaude":1,"name","theme","font","size","frame"}`,
  ключ отсутствует → слой не трогать, `false` у frame → сброс), контракт побайтно — `ProjectSettings.swift`; индекс чатов
- WF20: подменю «🗂 Проект ▸» больше нет — остался тумблер «🗂 Цвет по проекту» в «🖥 Всем окнам ▸». Папки без файла
  красятся авто-цветом по имени (FNV-1a → тон, `AutoPaint.projectTheme(folderName:)`, отпечаток `auto:<hue>`, файла не
  заводит). Ручной выбор темы/шрифта/размера/рамки в окне проекта (`remember`, только `scope:"window"`) молча пишется в
  `.pimpmyclaude.json` (`ProjectPaint.noteManualChoice`); «Как у Claude» снимает слой, последний слой удаляет файл; битый
  файл не переписывается и не удаляется (плашка). «Своя тема…» — панель `ThemeEditor` (ручки `ThemeKnobs`: тон/сдвиг
  акцента/сила/тёмная), записи `my-themes.json` получили необязательное поле `knobs`, палитра записи побайтно =
  `ThemeKnobs.palette()`; `"knobs":null` не пишется. Меню открывается слева от минуса (`MinimizeMenu.origin`).
  Claude `~/Library/Application Support/Claude/claude-code-sessions/*/*/local_*.json` → `ProjectIndex.swift` (папка по
  sessionId/заголовку, главное окно по `status.json`). Индекс пропал — молчим, не красим. Покраска не трогает окна с ручной
  темой/автопокраской; файл в репозитории — в `~/.config/git/ignore`.
- **Кто этот чат (WF29, задачи #5448 и #5455)**: окно опознаётся id чата, а не заголовком — заголовок попапа это
  снимок имени чата на момент выноса в окно, и после переименования чата он с индексом Claude не сходится
  (у Элвиса так не опознавались три попапа из четырёх). Три части:
  - **Страница** — раздел «12в. Кто этот чат», `inject.js:4338-4541`. `window.__myclaude.chats({scan,nonce})` отдаёт
    промис `{v:1,nonce,kind:"main"|"popout"|"other",self,path,row,title,popouts:[{id,title}],store,at}` и НИКОГДА
    не бросает; `store` — `ok|cache|busy|none|skip`. Главное окно берёт свой id хвостом `location.pathname`, попап
    (у него путь `blank`) спрашивает окно-родителя: `window.opener.__myclaude.popoutChat(title,{scan})` ищет заголовок
    в карте `popoutWindows` стора claude.ai (тот же поведенческий скан, что у «Нового окна», токен не увеличивается;
    одновременные просьбы складываются в один промис `chatsScanInFlight`). Ноль совпадений заголовка или два и больше
    → `null`, заглушки заголовка не участвуют. Ответ родителя кэшируется в sessionStorage `myclaude-chat-v1`
    (`{id,title}`, годен пока `document.title` тот же) — кэш переживает перезапись `inject.js`, и по нему работает
    синхронный `addressed()`. Слепок без скана — `status().chat` (`kind/self/path/row/popouts/store/at`).
    Своих таймеров, подписок и наблюдателей раздел не заводит ни одного.
  - **Приложение** — `app/Sources/ClaudeAX/ChatProbe.swift`: пишет `probe.js`, читает `probe-result.json` и берёт
    из него только записи со своим `nonce`. Канал общий с агентом на гейте, поэтому владение **вежливое**: свой
    скрипт помечен первой строкой `// myclaude-chats v1 <nonce>`; канал берём, если файла нет, текст побайтно наш,
    начинается с метки или файла не касались дольше 10 мин; чужой свежий скрипт — молчим 60 с, карта помечается
    несвежей. **Тумблер «🗂 Цвет по проекту» выключен — probe не пишется и не читается вовсе.** Исключение —
    `ChatProbe.demand(at:)` (WF46): круг ПО ТРЕБОВАНИЮ. Спросивший открывает канал на 30 с
    (`demandSeconds`) даже при выключенном тумблере, ближайший тик спрашивает страницы мимо пола частоты
    (но не поверх незакрытого круга), карта забирается через `answered(after:)` и `pages`, дальше канал
    замолкает сам. Пол частоты 15 с,
    неопознанное окно переспрашиваем не чаще 60 с, незакрытый круг ждём 30 с, `scan:true` уходит только при
    неизвестном чате. Свой таймер не заводится — общий тик 2 с `ClaudeAXController`.
  - **Покраска** — цели `ProjectPaint.targets()` берутся из ответов страниц, а не из заголовков окон. Ключ окна
    `main` / `c:<id чата>` / `w:<заголовок>`, и ключ на окно ровно ОДИН: появился id — отпечаток переезжает из
    `w:` в `c:` со слоями, потерялся — обратно и с пустым `digest` (`ProjectPaint.moveMark`). Страница ответила при
    рабочем сторе, а чат назвать не смогла → окно «не определён»: команды нет, отпечаток не трогаем, папка главного
    окна не подставляется НИКОГДА (#5455). Ответа нет вовсе (канал занят, стор не нашёлся) → старый путь по
    заголовку, как до WF29. Чат главного окна: свежий (младше 10 с) ответ страницы сильнее адреса из `status.json`.
  - `ProjectIndex` при этом получил номер состава чатов `revision` (кортеж `sessionId+cwd+title`; `lastFocusedAt`
    в него НЕ входит — Claude переписывает файлы сессий непрерывно) и кэш разбора `status.json` по отпечатку
    (файл весит мегабайты, а спрашивают его дважды за тик). Отпечаток снимается со свежего `URL`:
    значения ресурсов кэшируются внутри объекта, и у долгоживущей ссылки mtime навсегда остался бы первым.
- `live-colors` (WF18): `{…,"scope":"all","on":true,"mode":"sync"|"solo","period":<с>,"epoch":<мс>,"light":true|false|null,
  "titles":[…],"ring":{"dark":[палитры…],"light":[…]}}` — порядок полей побайтно, числа числами, палитра в порядке
  `Theme.paletteOrder`; выключение — `{…,"scope":"all","on":false}`. Страница: раздел 2в inject.js, шаг кольца = 360/длина,
  память `myclaude-live-v1` (localStorage, общая — крутёж живёт и без приложения) и `myclaude-live-phase-v1`

  пересчитывает). `ClaudeCommand` не расширяется — команда пишется строкой (`LiveColors.swift`).
- WF19: в `size` половина может быть `null` — снимает только её (`{"answer":null}`), `"size":null` снимает обе; `new-window`/`popout-window`
  получили необязательное `match` после `title` (главное окно) — работают с любого окна; попап на `popout-window` — плашка «уже в окне».
- `themes-restore` (WF35): `{…,"scope":"all","entries":{<ключ>:{theme?,font?,size?,frame?}}}` — порядок полей
  побайтно `id, action, at, scope, entries`; `at` записей в команду НЕ идёт (он бухгалтерия файла), слои — те же
  объекты, что у `theme`, сброс — строкой `"none"`. Страница (`runThemesRestoreCommand`) свою память не заменяет,
  а **доливает недостающие СЛОИ**: что у неё есть, не трогает вовсе — отсюда идемпотентность, и спрашивать окно
  «ты пуста?» не нужно. Ключи только пяти видов (`*`, `main`, `id:`, `chat:`, `w:`; непустой хвост, не длиннее
  200 знаков), не больше 200 штук, мусор отбрасывается. Красит `restoreTheme(false)` и НЕ красит при примерке
  (`themeState.previewing`) и живых цветах (`liveState.on`). Обработчик стоит рядом с `status`/`live-colors` —
  **до** отмены примерки, иначе приезд команды гасил бы подменю под рукой. Диагностика —
  `status().restore = {at, keys, merged, painted}`.
- Кто шлёт `themes-restore` (`WindowThemeStore.swift`): понятие **поколения** — старт приложения
  (`ClaudeAXController.start()`) или перезапуск Claude (`ClaudeApp.onRestart`). В поколении не больше **трёх**
  команд: первая на первом тике, где окна Claude есть на экране, дальше только на смену набора AX-заголовков,
  зазор ≥ 5 с. Файл пуст или Claude не запущен — команд нет вовсе.

  `myclaude-themes-v1`, и отдаёт её **только главное окно** (`isMainWindow()`), а приложение берёт её только из

- **Канал «Пимп» (WF36)** — не `command.json`, а свой каталог `pimp/`: файл на запрос, ответ рядом. Эталоны
  побайтно — `tests/fixtures/pimp/*.json` (их читают ОБА конца: `tools/pimp.py` и `PimpChannel.swift`), там же
  README с порядком ключей. Запрос `{"id","at","action":"new-window"|"arrange"|"projects"|"windows","from",…}`
  (id = `<unix-мс>-<4 цифры>`, `from` — id чата агента из `CLAUDE_CODE_HOST_SESSION_ID`, пусто — «под этим»
  деградирует в `right`); ответ `{"id","at","ok","error","fromResolved","screen",…}` — `screen` с WF43 всегда

  `no-windows`, `project-missing`, `window-missing`, `too-small`, `not-arranged`, `bad-request`. Приложение на общем тике 2 с:
  берёт запросы без ответа по `at`, исполняет младше 30 с и по одному, пишет `<id>.taken`. CLI ждёт ответ до 60 с;
  нет `taken` за 5 с — «Пимп не запущен». Ожидания CLI переопределяются `MYCLAUDE_PIMP_WAIT`/`MYCLAUDE_PIMP_TAKEN`,
  каталог — `MYCLAUDE_PIMP_DIR` (нужно тестам). Правда об исполнении — ответ на диске, не память процесса.
