## Решения

### 1. Раскладки — режим у `ArrangeLayout` (чистая арифметика, её же гоняют тесты)

```swift
enum ArrangeMode: String { case ribbon, grid, projects }   // ribbon — сегодняшняя лента, умолчание

static func columns(count: Int, width: CGFloat, mode: ArrangeMode, minCellWidth: CGFloat = minCellWidth) -> Int
static func frames(count: Int, in area: CGRect, mode: ArrangeMode, minCellWidth: CGFloat = minCellWidth) -> [CGRect]
static func projectFrames(groups: [[Int]], in area: CGRect, minCellWidth: CGFloat = minCellWidth) -> [CGRect]
```

- `ribbon` — ровно то, что считается сегодня (существующие тесты должны пройти без правок).
- `grid` — «квадратом»: колонок `ceil(sqrt(n))`, но не больше, чем влезает по `minCellWidth`; при `n = 3…4` это и есть 2×2.
- `projects` — колонка на группу, окна внутри колонки рядами сверху вниз; групп больше, чем влезает колонок, — хвостовые
  группы сливаются в последнюю колонку. Порядок групп — по первому окну группы в `ArrangeLayout.order`; «без проекта» всегда
  последняя колонка.
- Границы ячеек считаются как сейчас (`floor(x + 0.5)`) — плитки без щелей.
- Старые сигнатуры остаются работать (параметр `mode` со значением по умолчанию `.ribbon`).

### 2. Последняя раскладка запоминается

`UserDefaults` ключ `arrangeMode` (строка). ⌥⌘A и первый пункт подменю применяют её; в подменю галка стоит на текущей.

### 3. Память позиций — новый `WindowMemory.swift`

Хранилище поверх того же протокола `ThemeDefaults` (тесты не пишут в живые настройки). Ключ `windowFrames`:
`{ "<заголовок чата>": { "x":…, "y":…, "w":…, "h":…, "at":… } }`, координаты перевёрнутые, лимит **60** записей
(лишние вытесняются по `at`, как в `MyThemesStore.appending`).

- **Запоминаем сами.** На тике 2 с (тот, что уже крутится в `ClaudeAXController`) читаем `ClaudeApp.onScreenFrames` —
  один вызов `CGWindowList`. Заголовок через AX спрашиваем ТОЛЬКО у окна, чья рамка изменилась и на следующем тике осталась
  той же (окно доставили и отпустили) — иначе AX-трафика нет вовсе и в память не попадает середина перетаскивания.
- Заголовок пустой или заглушка («Claude», «New chat») — не пишем: под таким ключом окно не опознать.
- **После «Расставить» не запоминаем** (решение по вопросу 3): `arrange()` помечает свои окна, и запись возобновляется,
  только когда окно сдвинули руками. Память — про то, как расставил Элвис, а не про сетку.
- **Возврат — пунктом «↩︎ Вернуть позиции»:** каждому видимому окну с известным заголовком ставим запомненную рамку.
  Рамка обрезается по видимой области экрана, который её содержит (монитор отключили — окно не должно уехать за край);
  два окна с одним заголовком — рамку получает переднее, второе не трогаем.
- **Автовозврат — только для НОВОГО окна:** id, которого на прошлом тике не было, в первые ~5 с жизни и только один раз.
  Главное окно при переходе по сайдбару НЕ двигаем: его заголовок меняется на каждом чате, и оно прыгало бы постоянно.
- «🧹 Забыть позиции» — чистит карту целиком.

### 4. «🙈 Спрятать все» и починка «Показать»

- «Спрятать все» — `NSRunningApplication.hide()`.
- «Показать» — перед `raise` вызывает `unhide()`; страховка, если не сработает: AX `kAXHiddenAttribute = false` у элемента
  приложения. Проверяется живьём на гейте.
- **Пока Claude спрятан** (`NSWorkspace.didHideApplicationNotification` / `didUnhideApplicationNotification`):
  - в меню-баре приложения появляется пункт «👀 Показать окна Claude» (`AppDelegate.buildStatusItem`, после «Статус…»),
    он же и есть гарантированный путь назад;
  - ⌥⌘S регистрируется, пока приложение спрятано, даже когда Claude не впереди (снять `claudeFrontmost` только для этой
    клавиши); как только Claude показался — обычный режим.
- Своей клавиши у «Спрятать все» нет: ⌥⌘H — системное «Скрыть остальные», а ⌘H у Claude и так прячет окна (вопрос 4).

### 5. «🗂 По проектам» — через probe (лоадер и inject.js не трогаем)

По клику Swift пишет в `probe.js` одноразовый снимок:

```js
(() => { try { const s = window.__myclaude?.status?.();
  return { title: document.title, project: s?.statusFeed?.project ?? null, path: location.pathname }; }
  catch (e) { return { title: document.title, project: null }; } })()
```

Дальше ждём в `probe-result.json` запись со свежим `at` (опрос 250 мс, потолок **3 с** — лоадер смотрит файл раз в 2 с),
сопоставляем `result.title` с AX-заголовками окон, группируем. Нет ответа, нет проекта, дубль заголовка — окно уходит в группу
«без проекта» (последняя колонка). На время ожидания — плашка HUD «Расставляю по проектам, пару секунд…» (`onNotice`, 3 с),
как у «Новое окно» в WF13. Файл пишется ТОЛЬКО по клику на этот пункт.

### 6. Меню (внутрь «⋯ Ещё ▸», структуру берём из WF14)

```
💰 Обкэшить                ⇧⌘N
▦ Расставить ▸            ⌥⌘A     ← сам не кликается (AppKit), клавиша работает
      ▦ Расставить как в прошлый раз
      ──────────
    ✓ Лентой (столбцами)
      Сеткой
      🗂 По проектам
      ──────────
      ↩︎ Вернуть позиции
      🧹 Забыть позиции
👀 Показать                ⌥⌘S
🙈 Спрятать все
⏬ Прокрутить              ⌥⌘D
```

Раскладки и позиции — замыкания в `MinimizeMenu.MenuConfig` (как `autoPaint`), а не новые команды страницы:
`arrange: (ArrangeMode) -> Void`, `arrangeLast: () -> Void`, `restorePositions: () -> Void`, `forgetPositions: () -> Void`.
В `ClaudeCommand` добавляется ровно один случай — `hideAll = "hide-all"` (нужен для пункта и для меню-бара приложения).

### 7. Контракты, которые НЕ меняются

`command.json` не получает ни одного нового действия: всё в WF21 — оконное и нативное. `inject.js` не трогаем вовсе
(ни один батч), лоадер тоже. Версию в `Info.plist` в этом воркфлоу не поднимаем — релизом марафона рулит гейт (WF17).

### 8. Не делаем в WF21

Раскладки на втором мониторе (как и сегодня — только главный экран); каскад и произвольные сетки; перетаскивание окон мышью
нашими руками; сохранение именованных раскладок; тему и настройки на проект (WF15); позиции по папке проекта (WF16);
позиции для окон, свёрнутых в Dock.

## Открытые риски

- **`activate` спрятанного приложения.** Что именно показывает окна — `unhide()` или `activate` — проверено не живьём;
  если оба промахнутся, страховка через AX `kAXHiddenAttribute`. Пункт в меню-баре обязателен в любом случае — это единственный
  гарантированный путь назад.
- **Глобальная ⌥⌘S на время «спрятано»** отбирает клавишу у других приложений. Снимать по `didUnhide` и по активации Claude;
  если наше приложение умрёт спрятанным, Carbon снимет регистрацию вместе с процессом.
- **probe — инструмент гейта.** Пункт «По проектам» перетирает `probe.js` и `probe-result.json`; если в этот момент кто-то
  ведёт живую диагностику, он потеряет свой ответ. Записать строкой в `AGENTS.md`.
- **Задержка probe до 2 с** (интервал лоадера) — отсюда плашка. Ответ не пришёл за 3 с — расставляем лентой и говорим об этом
  плашкой, а не молчим.
- **Имя чата меняется.** Claude переименовывает чат после первого ответа: запись позиции под старым именем осиротеет.
  Лечится вытеснением по `at` (60 записей), но «вернуть позиции» для только что созданного чата может не сработать — это ожидаемо.
- **Два окна одного чата** — один ключ на двоих: позицию получает переднее (та же грабля, что у тем в WF10).
- **Пересечение с WF15/WF16.** Если WF15 даст окну собственный проект (настройкой или по папке), «По проектам» должна
  переехать на этот источник и probe станет запасным путём. Проверить на гейте марафона, когда оба плана будут одобрены.
- **Перестановка меню ломает те же тесты, что и WF14** (`testMenuKeysMatchReadme`, `testMenuItemsCarryKeyEquivalents`,
  `testSkeleton`) — ожидания переписываются в батче A2, verify обязан убедиться, что переписаны, а не удалены.
- **Второй монитор.** Раскладки по-прежнему считаются по главному экрану: окно со второго монитора приедет на главный.
  Сегодня так же, но с раскладками это станет заметнее — если Элвис работает на двух экранах, это отдельная задача.
- **Критик плана — следующий шаг** (отдельный агент, Opus max, свежий контекст): его находки правятся до презентации.
