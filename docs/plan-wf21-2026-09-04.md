## Решения

### 1. Раскладки — режим у `ArrangeLayout` (чистая арифметика, её же гоняют тесты)

```swift
enum ArrangeMode: String { case ribbon, grid, projects }   // ribbon — сегодняшняя лента, умолчание

static func columns(count: Int, width: CGFloat, mode: ArrangeMode = .ribbon, minCellWidth: CGFloat = minCellWidth) -> Int
static func frames(count: Int, in area: CGRect, mode: ArrangeMode = .ribbon, minCellWidth: CGFloat = minCellWidth) -> [CGRect]
static func projectFrames(groups: [[Int]], in area: CGRect, minCellWidth: CGFloat = minCellWidth) -> [CGRect]
```

- `ribbon` — ровно то, что считается сегодня (существующие тесты должны пройти без правок).
- `grid` — «квадратом»: колонок `ceil(sqrt(n))`, но не больше, чем влезает по `minCellWidth`; при `n = 3…4` это и есть 2×2.
- `projects` — колонка на группу, окна внутри колонки рядами сверху вниз; групп больше, чем влезает колонок, — хвостовые
  группы сливаются в последнюю колонку. Порядок групп — по первому окну группы в `ArrangeLayout.order`; «без проекта» всегда
  последняя колонка.
- Границы ячеек считаются как сейчас (`floor(x + 0.5)`) — плитки без щелей.
- **У `mode` значение по умолчанию `.ribbon`** — иначе не соберутся сегодняшний вызов `ArrangeLayout.frames(count:in:)`
  в `arrange()` и три существующих теста.

**Один список окон на всю операцию (иначе окна уедут в чужие ячейки).** `groups` в `projectFrames` — это ИНДЕКСЫ, поэтому
раскладка и группировка обязаны идти по одному и тому же перечислению:

```
app.visibleWindows() → AX.frame каждому → ArrangeLayout.order → тот же массив AX-элементов
        ├── рамки  → ArrangeLayout.frames(count:in:mode:)
        └── заголовки AX.string(kAXTitleAttribute) у ТЕХ ЖЕ элементов → папка проекта → groups (индексы в этом порядке)
```

`ClaudeApp.onScreenFrames` (CGWindowList: только on-screen, `layer == 0`, ≥120 px) в раскладках **не участвует вовсе** —
множества окон у него и у `visibleWindows()` (AX, включая другие Spaces) не совпадают. Обход «рамки → `order` → AX-заголовок
→ схлопывание дублей → счётчики для HUD» уже написан в `ClaudeActions.paintableWindows()` — вынести из него общий помощник
и использовать в `arrange(mode:)`, а не писать третий обход. Вынос делает **батч A2** (единственный писатель
`ClaudeActions.swift`); A1 отдаёт только чистые функции: «список заголовков → папки → группы индексов».

### 2. Последняя раскладка запоминается

`UserDefaults` ключ `arrangeMode` (строка). ⌥⌘A и первый пункт подменю применяют её; в подменю галка стоит на текущей.

### 3. Память позиций — новый `WindowMemory.swift`

Хранилище поверх того же протокола `ThemeDefaults` (тесты не пишут в живые настройки). Ключ `windowFrames`:
`{ "<заголовок чата>": { "x":…, "y":…, "w":…, "h":…, "at":… } }`, координаты перевёрнутые, лимит **60** записей,
лишние вытесняются по `at` (в `MyThemesStore.appending` вытеснение по порядку вставки и поля `at` нет — за образец не брать).

- **Запоминаем сами.** На тике 2 с (тот, что уже крутится в `ClaudeAXController`; сегодня он рамок не читает вовсе —
  только `AX.isTrusted` + `refreshHotkeys`, чтение рамок появится в нём впервые) читаем `ClaudeApp.onScreenFrames` —
  один вызов `CGWindowList`. **AX опрашиваем только в тот тик, когда рамка изменилась** и на следующем тике осталась
  той же (окно доставили и отпустили): так в память не попадает середина перетаскивания. Полностью бесплатным это не будет —
  `CGWindowID → AX` идёт через `app.window(matching:)`, а он читает рамки всех AX-окон.
- Заголовок пустой или заглушка («Claude», «New chat») — не пишем: под таким ключом окно не опознать.
- **После «Расставить» не запоминаем** (решение по вопросу 3): `arrange()` помечает свои окна, и запись возобновляется,
  только когда окно сдвинули руками. Память — про то, как расставил Элвис, а не про сетку.
- **Возврат — пунктом «↩︎ Вернуть позиции»:** каждому видимому окну с известным заголовком ставим запомненную рамку.
  Рамка обрезается по видимой области экрана, который её содержит (монитор отключили — окно не должно уехать за край);
  два окна с одним заголовком — рамку получает переднее, второе не трогаем.
- **Автовозврат — только для НОВОГО окна:** id, которого на прошлом тике не было, в первые ~5 с жизни и только один раз.
  Главное окно при переходе по сайдбару НЕ двигаем: его заголовок меняется на каждом чате, и оно прыгало бы постоянно.
- **Окна, которые открыли мы сами (WF13 `newWindow`/`popoutWindow`), в автовозврат не попадают 15 с** — тем же маркером,
  что у `arrange()`. Иначе команда ставит окно по своим `x`/`y`, а через ≤5 с память сдвигает его на запомненную рамку,
  и окно прыгает на глазах.
- **Для только что созданного ЧАТА автовозврат не сработает никогда — и это ожидаемо.** У нового окна заголовок-заглушка,
  имя чата Claude ставит после первого ответа, а ключ памяти — заголовок; совпасть нечему. Реальная польза автовозврата —
  попапы уже названных чатов.
- «🧹 Забыть позиции» — чистит карту целиком.

### 4. «🙈 Спрятать все» и починка «Показать»

- «Спрятать все» — `NSRunningApplication.hide()`.
- **«Показать» переписывается по порядку операций.** Сегодня `showAll` начинается с `visibleWindows()`, а тот — с
  `guard running()?.isHidden == false`; `isHidden` у `NSRunningApplication` обновляется асинхронно, поэтому сразу после
  `unhide()` он в том же тике ещё `true`, список пустой и цикл `kAXRaiseAction` проходит вхолостую — «Показать» на спрятанном
  Claude не срабатывает с первого раза. Порядок такой: `running.unhide()` + `activate(options:[.activateAllWindows])`
  **сразу**, а перебор окон с `raise` и возврат фокуса — в `after(focusDelay)`; если список всё ещё пуст — второй заход
  через 0,4 с. Страховка, если и это промахнётся: AX `kAXHiddenAttribute = false` у элемента приложения. Проверяется
  живьём на гейте: «Спрятать все → Показать» **одним** кликом.
- **Пока Claude спрятан** (`NSWorkspace.didHideApplicationNotification` / `didUnhideApplicationNotification`)
  в меню-баре приложения появляется пункт «👀 Показать окна Claude» (`AppDelegate.buildStatusItem`, после «Статус…») —
  он и есть гарантированный путь назад, вместе с Dock и ⌘Tab.
- **Глобальную ⌥⌘S на время «спрятано» не делаем:** клавиша отбиралась бы у всех приложений, в макете её нет и Элвиса про
  неё не спрашивали, а путь назад уже есть. Если Элвис попросит отдельно — id хоткея обязан быть тем же, что у `.show`
  (индекс `.show`+1), иначе `CarbonHotkeys.apply` будет пере-регистрировать клавишу на каждом тике 2 с.
- Своей клавиши у «Спрятать все» нет: ⌥⌘H — системное «Скрыть остальные», а ⌘H у Claude и так прячет окна (вопрос 4).

### 5. «🗂 По проектам» — по `ProjectIndex` из WF15 (probe — только запасной путь)

Источник группы — **папка проекта** (`ProjectIndex`, приходит в `main` с WF15, идёт первым в очереди): у каждого окна
`cwd` сессии, у попапа — по AX-заголовку. Имя группы — последний компонент папки (`PimpMyClaude`, `Trelvis`, `VkusnoffKz`).
Заголовки берутся тем же обходом, что и рамки (см. решение 1), группы — индексы в этом порядке. Папку не знаем, заголовок —
заглушка или дубль → окно в группу «без проекта» (последняя колонка). Ничего ждать не нужно: индекс уже в памяти,
плашка и таймауты не требуются.

**Запасной путь, если WF15 почему-то не влился в `main`:** одноразовый снимок через probe — Swift пишет в `probe.js`
`(() => { try { const s = window.__myclaude?.status?.(); return { title: document.title, project: s?.statusFeed?.project ?? null }; } catch (e) { return { title: document.title, project: null }; } })()`,
ждёт в `probe-result.json` запись со свежим `at` (опрос 250 мс, потолок **4 с** — лоадер смотрит файл раз в 2 с; столько же
держится плашка HUD «Расставляю по проектам, пару секунд…»). Источник заведомо хуже: `statusFeed.project` есть только у чатов
со строкой состояния. Включать этот путь — решением гейта, отдельной строкой в run-файле; вместе с ним возвращаются и
обязанность записать в `AGENTS.md`, что пункт перетирает `probe.js`/`probe-result.json`.

Лоадер, `inject.js` и `command.json` не трогаются ни в основном пути, ни в запасном.

### 6. Меню (внутрь «⋯ Ещё ▸», структуру берём фактическую из `main`)

```
💰 Обкэшить                ⇧⌘N
▦ Расставить ▸            ⌥⌘A     ← сам не кликается (AppKit), клавиша работает
      ▦ Расставить лентой              ← заголовок по текущему режиму: «лентой» / «сеткой» / «по проектам»
      ──────────
    ✓ Лентой (столбцами)
      Сеткой
      🗂 По проектам
      ──────────
      ↩︎ Вернуть позиции
      🧹 Забыть позиции
👀 Показать                ⌥⌘S
🙈 Спрятать все
⏬ Прокрутить              ⌥⌘D
```

Первый пункт подменю не пишется как «Расставить как в прошлый раз» — он стоял бы рядом с галкой на том же режиме и
дублировал её; заголовок собирается по текущему режиму.

Раскладки и позиции — замыкания в `MinimizeMenu.MenuConfig` (как `autoPaint`), а не новые команды страницы:
`arrange: (ArrangeMode) -> Void`, `arrangeLast: () -> Void`, `restorePositions: () -> Void`, `forgetPositions: () -> Void`.
В `ClaudeCommand` добавляется ровно один случай — `case hideAll` **без rawValue** (rawValue у `ClaudeCommand` — это `action`
в `command.json`, а команда нативная и в `command.json` не уходит; в коде так и написать комментарием).

### 7. Контракты, которые НЕ меняются

`command.json` не получает ни одного нового действия: всё в WF21 — оконное и нативное. `inject.js` не трогаем вовсе
(ни один батч), лоадер тоже. Версию в `Info.plist` WF21 не пишет — её поднимает гейт **последнего** воркфлоу марафона.
⚠️ Оркестратору: WF17 (релизный) стоит третьим, к WF21 версия 1.4.0 уже уехала команде, значит после WF24 нужен ВТОРОЙ
релизный прогон — либо WF17 переносится в конец очереди.

### 8. Не делаем в WF21

Раскладки на втором мониторе (как и сегодня — только главный экран); каскад и произвольные сетки; перетаскивание окон мышью
нашими руками; сохранение именованных раскладок; тему и настройки на проект (WF15); позиции по папке проекта (WF16);
