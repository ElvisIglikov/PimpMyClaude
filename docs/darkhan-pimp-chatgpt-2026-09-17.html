Суть в трёх абзацах

Что такое эти приложения. И Claude Desktop, и ChatGPT для Мака — это Electron: браузер Chromium и Node.js в одной коробке, а сам «мозг» приложения — JavaScript, упакованный в архив app.asar внутри бандла. Окно чата — это по сути веб-страница. Значит, всё, что умеет браузер (вставить CSS, выполнить скрипт на странице), можно сделать и с ней — если добраться до главного процесса Electron.

Что мы делаем. Мы не переписываем приложение. В начало его главного скрипта дописывается маленький лоадер (80 строк). Он умеет три вещи: вставлять в каждую страницу наш CSS и наш JS из файлов на диске, читать команды из файла и писать в файл диагностику. Всё остальное — стили, ручка над полем ввода, темы, полоса прогресса — живёт в этих файлах и меняется без перезапуска и без нового патча. Цена: подпись Apple у приложения ломается, и мы переподписываем его локальной подписью. Отсюда почти все «камни» ниже.

Что снаружи. Рядом стоит второе, обычное приложение в меню-баре (Swift). Оно через Accessibility жмёт кнопки в диалогах, рисует меню на жёлтой кнопке окна, расставляет окна, ловит горячие клавиши, а лоадеру внутри шлёт команды файлом. Этот слой работает с любым приложением на Маке — даже если внутрь залезть нельзя.

Коротко про ChatGPT: он тоже Electron (в 2026 году это объединённое приложение ChatGPT + Codex), так что приём «дописать лоадер в архив» переносится один в один. Отличия и два серьёзных риска — в разделе «ChatGPT: что у него внутри».

Слой 1 — патч приложения: архив, лоадер, хэш, подпись

Шесть шагов, каждый простой. Приложение закрывается, сохраняются оригиналы, в главный скрипт дописывается лоадер, пересчитывается хэш, бандл переподписывается, приложение открывается снова. На Claude всё вместе занимает меньше минуты; у команды это одна кнопка «Поставить» в меню-баре.

  1. Закрыть приложение — и не из терминала внутри него самого.
  2. Сохранить оригиналы app.asar и Info.plist в папку с номером версии.
  3. Дописать лоадер в начало главного скрипта внутри app.asar и пересобрать архив (смещения файлов сдвигаются).
  4. Пересчитать хэш заголовка архива в Info.plist (ElectronAsarIntegrity).
  5. Переподписать бандл локальной подписью с нужным списком прав.
  6. Открыть и проверить: через 2 секунды лоадер пишет status.json.

После обновления приложения (Claude — через Squirrel, ChatGPT — через Sparkle) бандл перезаписывается целиком, патч слетает. Это норма: приложение снаружи замечает и просит нажать «Поставить» ещё раз.

🤖 Для нейронки: формат asar и алгоритм патча (код)

Архив Contents/Resources/app.asar — это не zip. Устройство простое, поэтому его можно править без сторонних библиотек (у нас — 60 строк на Node, и порт на Swift):

  • Первые 16 байт — «pickle»: четыре uint32 little-endian: 4, headerSize, headerSize − 4, jsonLength. Дальше jsonLength байт JSON-заголовка, добитого нулями до кратности 4.
  • JSON-заголовок — дерево {"files": {"имя": {"files": …} | {"offset": "123", "size": 456, "integrity": {…}, "unpacked": true?}}}. offset — строка, считается от начала блока данных, а блок данных начинается на 8 + headerSize.
  • После заголовка — просто конкатенация содержимого файлов. Файлы с unpacked: true лежат рядом в app.asar.unpacked/ (нативные модули .node) — их не трогаем.
  • integrity у файла: {"algorithm":"SHA256","hash":<sha256 всего файла>,"blockSize":4194304,"blocks":[sha256 каждого блока по 4 МиБ]}. При правке файла его нужно пересчитать.
  • Главный скрипт — не угадывать: читать package.json из архива, поле main (у Claude — .vite/build/index.pre.js, у ChatGPT — .vite/build/early-bootstrap.js; меняется от сборки к сборке).
  • Ловушка: asar дедуплицирует одинаковые файлы — две записи могут указывать на одно смещение. Перед правкой проверить, что никто не делит данные с главным скриптом.

Алгоритм патча: прочитать архив → найти main → если в его начале уже стоит наш маркер нужной версии, ничего не делать → снять старый лоадер (если есть маркер другой версии) → приклеить лоадер спереди → у записи обновить size и integrity → у всех файлов, чьё смещение больше нашего, сдвинуть offset на разницу длины → собрать заголовок заново (pickle + JSON + паддинг) → записать во временный файл и переименовать (атомарно) → перечитать и убедиться, что маркер на месте. Перед боевым прогоном — selftest на копии: после патча каждый файл читается по своему смещению и его SHA-256 совпадает с integrity.hash.

Код чтения и пересборки asar (patch-claude.mjs, дословно)

// ---------------------------------------------------------------- asar
function readAsar(archivePath) {
  const archive = fs.readFileSync(archivePath);
  const headerSize = archive.readUInt32LE(4);
  const jsonSize = archive.readUInt32LE(12);
  const headerJson = archive.subarray(16, 16 + jsonSize);
  return { archive, header: JSON.parse(headerJson.toString("utf8")), headerJson, dataOffset: 8 + headerSize };
}

function buildAsarPrefix(header) {
  const headerJson = Buffer.from(JSON.stringify(header));
  const padding = (4 - ((8 + headerJson.length) % 4)) % 4;
  const headerSize = 8 + headerJson.length + padding;
  const prefix = Buffer.alloc(16 + headerJson.length + padding);
  prefix.writeUInt32LE(4, 0);
  prefix.writeUInt32LE(headerSize, 4);
  prefix.writeUInt32LE(headerSize - 4, 8);
  prefix.writeUInt32LE(headerJson.length, 12);
  headerJson.copy(prefix, 16);
  return { prefix, headerJson };
}

function lookupFile(header, posixPath) {
  let entry = header;
  for (const component of posixPath.split("/")) {
    entry = entry.files?.[component];
    if (!entry) throw new Error(`в app.asar нет файла ${posixPath}`);
  }
  if (entry.files || entry.link || entry.unpacked) throw new Error(`${posixPath} — не упакованный файл`);
  return entry;
}

function walkPackedFiles(node, callback) {
  for (const value of Object.values(node.files ?? {})) {
    if (value.files) walkPackedFiles(value, callback);
    else if (!value.link && !value.unpacked) callback(value);
  }
}

function readEntry(parsed, posixPath) {
  const entry = lookupFile(parsed.header, posixPath);
  const start = parsed.dataOffset + Number(entry.offset);
  return { entry, content: parsed.archive.subarray(start, start + Number(entry.size)) };
}

// Главный сценарий берём из package.json внутри архива: в 1.40609.1 это
// .vite/build/index.pre.js, раньше был index.js — путь не хардкодим.
function mainEntryPath(parsed) {
  const pkg = JSON.parse(readEntry(parsed, "package.json").content.toString("utf8"));
  if (!pkg.main) throw new Error("в package.json нет поля main");
  return pkg.main.replace(/^\.\//, "");
}

function loaderVersionOf(source) {
  const match = source.match(/\/\* \[MyClaude:v(\d+):start\] \*\//);
  return match ? Number(match[1]) : 0;
}

function stripLoader(source) {
  const match = source.match(/^\/\* \[MyClaude:v\d+:start\] \*\/[\s\S]*?\/\* \[MyClaude:v\d+:end\] \*\/\n?/);
  return match ? source.slice(match[0].length) : source;
}

function fileIntegrity(buffer, blockSize = 4 * 1024 * 1024) {
  const blocks = [];
  for (let offset = 0; offset < buffer.length; offset += blockSize) blocks.push(sha256(buffer.subarray(offset, offset + blockSize)));
  return { algorithm: "SHA256", hash: sha256(buffer), blockSize, blocks };
}

Сам патч (patch-claude.mjs, дословно)

function patchAsarFile(archivePath) {
  const parsed = readAsar(archivePath);
  const mainPath = mainEntryPath(parsed);
  const { entry, content } = readEntry(parsed, mainPath);
  const source = content.toString("utf8");
  if (loaderVersionOf(source) === LOADER_VERSION) return { changed: false, mainPath, headerSha256: sha256(parsed.headerJson) };
  const clean = stripLoader(source);
  if (!clean.includes("require(") || !clean.includes("electron")) throw new Error(`${mainPath} не похож на главный сценарий Electron — патчить вслепую не буду`);

  const targetOffset = Number(entry.offset);
  const targetSize = Number(entry.size);
  // asar дедуплицирует одинаковые файлы: два входа могут делить одно смещение.
  // Если бы кто-то делил его с главным сценарием, его размер и хэш протухли бы.
  walkPackedFiles(parsed.header, (candidate) => {
    if (candidate === entry) return;
    const offset = Number(candidate.offset);
    if (offset >= targetOffset && offset < targetOffset + targetSize) throw new Error(`${mainPath} делит данные с другим файлом архива — патчить не буду`);
  });
  const replacement = Buffer.concat([Buffer.from(LOADER), Buffer.from(clean)]);
  const delta = replacement.length - targetSize;
  walkPackedFiles(parsed.header, (candidate) => {
    const offset = Number(candidate.offset);
    if (offset > targetOffset) candidate.offset = String(offset + delta);
  });
  entry.size = replacement.length;
  entry.integrity = fileIntegrity(replacement, entry.integrity?.blockSize);

  const { prefix, headerJson } = buildAsarPrefix(parsed.header);
  const data = parsed.archive.subarray(parsed.dataOffset);
  const rebuilt = Buffer.concat([prefix, data.subarray(0, targetOffset), replacement, data.subarray(targetOffset + targetSize)]);
  const temporary = `${archivePath}.${process.pid}.tmp`;
  fs.writeFileSync(temporary, rebuilt);
  fs.renameSync(temporary, archivePath);

  const verify = readAsar(archivePath);
  const after = readEntry(verify, mainPath).content.toString("utf8");
  if (loaderVersionOf(after) !== LOADER_VERSION) throw new Error("после пересборки лоадер в архиве не найден");
  return { changed: true, mainPath, headerSha256: sha256(headerJson) };
}

🤖 Для нейронки: хэш в Info.plist и переподпись (команды, права)

Хэш в Info.plist. В Contents/Info.plist лежит ключ ElectronAsarIntegrity → Resources/app.asar → hash. Это SHA-256 строки JSON-заголовка архива (не всего файла!). После пересборки заголовок другой — хэш пересчитать и записать:

/usr/libexec/PlistBuddy -c "Set :ElectronAsarIntegrity:Resources/app.asar:hash <sha256 заголовка>" /Applications/Claude.app/Contents/Info.plist

Проверяет ли Electron этот хэш — решает «предохранитель» (fuse) EnableEmbeddedAsarIntegrityValidation, зашитый в бинарник Electron Framework. У Claude он включён: не пересчитаешь — Claude падает на старте («ASAR Integrity Violation»). У ChatGPT выключен (см. раздел про ChatGPT) — но держать хэш верным всё равно стоит: включат при следующем обновлении, и патч, который «и так работал», перестанет.

Подпись. Мы изменили app.asar и Info.plist. Оба входят в печать подписи Apple (Info.plist — в хэш самого исполняемого файла, asar — в список ресурсов CodeResources). На Apple Silicon приложение с битой подписью либо не запускается, либо теряет доступ к микрофону, экрану, связке ключей. Поэтому переподписываем бандл локальной («ad-hoc», подпись -) подписью — сначала всё дерево (--deep: фреймворки, хелперы), потом ещё раз само приложение со своим списком прав:

function updateInfoIntegrity(appPath, headerSha256) {
  run("/usr/libexec/PlistBuddy", ["-c", `Set :ElectronAsarIntegrity:Resources/app.asar:hash ${headerSha256}`, path.join(appPath, INFO_RELATIVE)]);
}

function signAndVerify(appPath) {
  say("Переподписываю Claude локальной подписью…");
  run("/usr/bin/xattr", ["-cr", appPath]);
  run("/usr/bin/codesign", ["--force", "--deep", "--sign", "-", "--timestamp=none", appPath]);
  run("/usr/bin/codesign", ["--force", "--sign", "-", "--timestamp=none", "--entitlements", ENTITLEMENTS, appPath]);
  run("/usr/bin/codesign", ["--verify", "--deep", "--strict", "--verbose=2", appPath]);
}

Почему два прохода: --deep переподписывает вложенные бинарники, но права (entitlements) при переподписи не сохраняются. У главного приложения они нужны, иначе после патча пропадают микрофон и экран — это было проверено на живом Claude, отсюда файл entitlements.plist в проекте. Локальная подпись выключает hardened runtime, поэтому хелперам Chromium права на JIT не нужны — Claude так работает у всей команды.

В локальную подпись их класть нельзя: macOS либо убьёт приложение на старте, либо права просто не сработают. Какие оставить — в разделе про ChatGPT.

🤖 Для нейронки: лоадер дословно и что в нём менять для ChatGPT

Лоадер — единственное, что зашито внутрь приложения. Это одна строка-шаблон в патчере (Node) и её дословная копия в Swift-приложении (Loader.swift). Номер версии стоит в маркерах /* [MyClaude:v7:start] */ … end */: по нему патчер видит, что стоит, а что пора заменить. За две недели лоадер менялся семь раз, и каждый раз всей команде приходилось ставить патч заново — поэтому правило: в лоадер кладётся только «прочитать файлы и вставить», вся логика — в живых файлах.

Что он делает по порядку: (1) require("electron") — мы в главном процессе, всё доступно; (2) подменяет BrowserWindow.prototype.setMinimumSize, чтобы минимальную ширину окна прижимать к нашей (приложение само зовёт этот метод при смене экрана и при стыковке панелей — просто выставить один раз не помогает); (3) на web-contents-created → dom-ready вставляет CSS через insertCSS(text, {cssOrigin:"user"}) и выполняет inject.js через executeJavaScript(code, true); (4) fs.watchFile с интервалом 0,5–1 с на настройки, CSS, скрипт и файл команд; (5) раз в 2 с пишет status.json и, если изменился probe.js, выполняет его во всех страницах и кладёт ответ в probe-result.json. Весь код — в одном try/catch: что бы ни случилось, приложение стартует.

Что в нём поменять для ChatGPT

  • Папку: "MyClaude" → своя, например "PimpMyGPT"; имена файлов любые, но их же должно знать приложение снаружи.
  • Маркер [MyClaude:vN:start] → свой; версию считать с 1.
  • В cssText() убрать две строки со селекторами Claude (ps-[var(--chat-gutter…, .epitaxy-*, scrollbar-gutter) — у ChatGPT другой DOM. Оставить только чтение живого CSS-файла: поля и всё прочее — туда, после разведки через probe.js.
  • isClaudePage оставить как есть (он лишь отсекает devtools: и chrome-) — просто переименовать.
  • Минимальная ширина: у ChatGPT главное окно держит 480×600 (getPrimaryMinimumSize) и переустанавливает её через setMinimumSize — хук работает. Но тот же класс при сохранении и восстановлении рамки окна клампит ширину к 480 (persistPrimaryWindowBounds, clampPrimaryWindowBounds): после перезапуска окно откроется не уже 480, сузить снова можно. Лечится либо расстановкой окон приложением снаружи, либо текстовой правкой {width:480,height:600} в главном бандле тем же патчером (хрупко: меняется с каждой версией).
  • Строку с log("loader vN ready") оставить: по ней в логах видно, что лоадер вообще запустился.
🤖 Для нейронки: порядок «Поставить», откат, статус

Порядок «Поставить» в приложении (порт на Swift, Patcher.swift), с решениями, которые стоили ошибок:

  1. Отказаться, если нас запустили изнутри самого приложения (Claude Code в окне Claude): закрытие Claude убило бы и патчер. Проверка — цепочка родительских процессов до Claude.app/Contents/. Для ChatGPT это ещё важнее: у него встроенный агент с терминалом — нейронка Дархана может сидеть внутри него.
  2. Прочитать версию из Info.plist, найти entitlements.plist, создать папку живых файлов и claude.json с умолчаниями (готовый файл никогда не перезаписывать).
  3. Разобрать asar и посмотреть, что стоит. Лоадер уже нужной версии, хэш сходится, подпись валидна — обновить только живые файлы и выйти. Лоадер стоит, но хэш/подпись битые (прошлый прогон упал между записью архива и подписью) — дочинить: закрыть, записать хэш, подписать, открыть.
  4. Пробная запись в Contents/Resources/ до закрытия приложения: на macOS 13+ первая попытка поднимает системный запрос «Управление приложениями» (App Management). Без этого разрешения запись в /Applications/*.app даёт EPERM. Не администратор Мака — переустановить приложение в ~/Applications.
  5. Закрыть приложение: свои процессы искать по пути бандла, не по имени (копий с именем «Claude» бывает несколько); сначала мягко (terminate, 20 с), потом жёстко.
  6. Бэкап app.asar и Info.plist в backups/<версия>/ — только чистого архива; если в архиве уже чей-то лоадер, а чистого бэкапа этой версии нет, в бэкап его не класть (иначе «Снять» соврёт).
  7. Патч архива → хэш в Info.plist → подпись → проверка подписи. Осечка на любом из последних трёх шагов — вернуть оригиналы из бэкапа, подписать что есть и сказать человеку, что нажать. Между записью архива и удачной подписью приложение не запускается — это самое опасное окно.
  8. Скопировать живые файлы из бандла (CSS сливается по маркерам, чужие строки сохраняются), записать installed.json (версия, хэш, номер лоадера) — по нему меню-бар быстро показывает статус без разбора архива.
  9. Открыть приложение (open -a). Предупредить: macOS один раз переспросит разрешения.

Статус для значка: installed.json верим только если версия, хэш и номер лоадера совпадают; иначе разбираем архив. Лоадера нет — «приложение обновилось», номер старый — «старый лоадер», хэш не сходится — «патч слетел». Красный значок → человек жмёт «Поставить» снова.

«Снять» — вернуть оригиналы из бэкапа и подписать локально. Подпись Apple при этом не возвращается: настоящий откат только переустановкой с сайта.

Слой 2 — живые файлы: стили, скрипт и команды без перепатча

После патча внутрь приложения больше никто не лезет. Всё, что видит человек — узкие поля, ручка над полем ввода, цвета, шрифты, полоса прогресса, — это два файла на диске: claude.css и inject.js. Поменял файл — через секунду применилось во всех окнах, приложение не перезапускается. Третий файл, command.json, — команды от приложения снаружи («покрась это окно», «вставь текст в поле», «вынеси чат в окно»), четвёртый, probe.js, — «выполни вот это во всех окнах и покажи ответ». Через него нейронка смотрит на разметку чужого приложения, не открывая DevTools.

Главное правило этого слоя: скрипт в странице обязан уметь снять сам себя. Он выполняется заново при каждом сохранении файла, и без этого в окне копились бы дубли.

Правила для скрипта в странице (все выстраданы)

  • Идемпотентность. Скрипт выполняется заново при каждом изменении файла — значит первой строкой window.__myclaude?.dispose?.(): снять слушатели, таймеры, узлы, стили прошлого экземпляра. Иначе после десяти правок в окне десять ручек.
  • Никаких модулей и внешних скриптов. Это обычный скрипт в контексте страницы. executeJavaScript и insertCSS из главного процесса обходят CSP страницы, а вот <script src=…>, вставленный в DOM, CSP заблокирует.
  • Стили — через adoptedStyleSheets, не через <style>. Claude зеркалит <style> главного окна во все вынесенные окна — тема одного окна заезжала в остальные.
  • Чужие страницы — молчать. Скрипт прилетает и в file://…/main_window, и в окно логина: проверка «это страница чата?» первой, иначе ничего не делать.
  • Окно — это не заголовок. Заголовок окна меняется (переименовали чат) и повторяется (два чата с одним именем). Окно опознаётся id чата, который страница называет сама в ответ на probe.js; заголовок — запасной признак.
  • Селекторы ломаются каждым обновлением. Держать их в живых файлах, а не в лоадере; правило «сначала probe.js, потом CSS» — на каждое обновление приложения.
  • Канал probe.js общий. Им пользуются и приложение (спрашивает страницы, какой чат в окне), и человек/нейронка. Первая строка скрипта — подпись владельца; чужой свежий файл — не трогать; закончил — удалить свой.

Слой 3 — приложение снаружи: меню, кнопки, окна

PimpMyClaude.app — обычное приложение со значком у часов. Оно не лезет внутрь Claude: смотрит на его окна через Accessibility (то же, чем пользуются программы для людей с ограничениями), жмёт за человека «Allow» в диалогах, показывает своё меню, когда курсор задерживается на жёлтой кнопке окна, расставляет окна по экрану, ловит горячие клавиши и перехватывает ⌘Q. Внутрь оно передаёт команды через файл — и получает ответы тоже файлом.

Это самый переносимый слой: ему всё равно, Electron перед ним или нативное приложение. Для ChatGPT он повторяется без изменений — меняются только имя приложения и то, какие кнопки искать.

🤖 Для нейронки: что использовано в AX-слое и какие грабли там лежат

Приложение снаружи — Swift/AppKit, меню-бар, macOS 13+. Разрешений два обязательных: Accessibility (читать окна и жать кнопки чужого приложения) и App Management (писать в чужой бандл при «Поставить»); третье, уведомления, — по желанию. Что и как:

  • Окна и кнопки — AXUIElement: список окон приложения по pid, у окна AXPosition/AXSize/AXTitle, кнопки в диалогах по AXRole = AXButton и заголовку, нажатие AXPress. Авто-Allow — обход диалога раз в тик (2 с), нажатие «Allow…» кроме списка исключений (удаление, деньги, внешние сервисы; узор ищется в тексте команды целым словом).
  • Меню на жёлтой кнопке — по AX находится рамка кнопки «свернуть», наведение с задержкой открывает NSMenu. Перед popUp обязателен NSApp.activate(ignoringOtherApps: true) — на macOS 14+ кооперативная активация не работает, подменю закрывались.
  • Горячие клавиши — только Carbon RegisterEventHotKey: глобальный NSEvent-монитор не глотает ⌘Q и просит ещё одно разрешение (Input Monitoring). ⌘Q перехватывается, чтобы не убить сессию агента.
  • Процессы — свои искать по bundleURL, не по имени; Launch Services помнит все копии с тем же bundle id (бэкапы, огрызки обновлений).
  • Подпись самого приложения — Developer ID с первой сборки: у Accessibility разрешение привязано к «designated requirement», и при каждой ad-hoc пересборке macOS спрашивала бы заново.
  • Команды внутрь — очередь: одна запись в command.json за раз, следующая после паузы ≥ 0,5 с (лоадер читает раз в 500 мс и берёт последнюю). Адрес окна — id чата из ответа probe.js; заголовок — запасной вариант.
  • Раскладка окон — рамки считаются от экрана, где стоят окна; ячейка не уже minWindowWidth; окна двигаются через AX (AXPosition/AXSize), не через приложение внутри.

Этот слой не знает, Electron перед ним или нет. Если бы ChatGPT оказался нативным, меню на кнопке, авто-Allow и расстановка окон работали бы всё равно; не работали бы только стили и скрипт в странице.

ChatGPT: что у него внутри и чем он отличается

Хорошая новость. ChatGPT для Мака в 2026 году — тоже Electron: это объединённое приложение ChatGPT + Codex (внутри оно так и называется, Codex, bundle id com.openai.codex, Chromium 152). Ещё лучше. «Предохранители» Electron у ChatGPT открыты: проверка хэша архива выключена, разрешён запуск с отладчиком и запуск как Node. Значит патч даже проще, а разведку можно делать вообще без патча — запустить приложение с флагом --inspect и подключить DevTools к главному процессу.

Хуже. Подпись OpenAI несёт «ограниченные» права: push-уведомления Apple, общая с другими приложениями OpenAI связка ключей, группы приложений. И самое важное: приложение шлёт на сервер OpenAI токен Apple DeviceCheck («я настоящее приложение OpenAI»). После переподписи токена не будет. Код это переживает — пишет в лог и шлёт код ошибки вместо токена, — а примет ли такое сервер, узнать можно только пробой. Это первый тест после патча; не примет — откат из бэкапа, и остаётся слой 3 или DevTools.

Обновления. Sparkle перезапишет приложение целиком, патч слетит — как у Claude, ставить снова. Либо не сможет обновить из-за подписи — тогда обновляться вручную с сайта.

DeviceCheck — риск номер один

В main-*.js есть код, который через Resources/native/devicecheck.node получает токен Apple DeviceCheck («это настоящее приложение OpenAI на настоящем Маке») и прикладывает его к запросам на серверы OpenAI (attachDeviceCheckToken, attachIntegrityState, «Refusing to attach DeviceCheck token to non-OpenAI URL»). DeviceCheck работает только у приложения, подписанного сертификатом команды с профилем; после локальной подписи токена не будет. Код к этому готов: пишет в лог «DeviceCheck attestation unavailable/failed» и вместо токена шлёт error_code. Примет ли это сервер — из кода не видно. Поэтому первый тест после патча: войти, отправить сообщение, посмотреть логи в ~/Library/Logs/com.openai.codex/ на строки про DeviceCheck и ошибки авторизации (в коде встречается свой статус 432 — «Failed to retrieve authentication token»). Отказ сервера — откат из бэкапа и другой путь (слой 3 снаружи или DevTools без патча).

Подводные камни

Каждый из этих пунктов стоил нам хотя бы одного вечера. Заголовок — что ломается, ниже — как обойти.

Патч из терминала внутри самого приложения
Патчер закрывает приложение — и убивает себя. У ChatGPT встроенный агент с терминалом, нейронка может сидеть внутри. Запускать из Terminal.app; в патчере — проверка цепочки родительских процессов.
Разрешение «Управление приложениями»
Без него писать в /Applications/*.app нельзя (EPERM). Дать его Terminal или своему приложению; пробную запись делать до закрытия приложения, чтобы системный запрос не остался без ответа. Не администратор — ставить приложение в ~/Applications.
Бэкап до, откат при осечке
Между записью архива и удачной подписью приложение не запускается. Осечка — вернуть оригиналы из бэкапа той же версии. Бэкап только чистого архива; «Снять» подпись Apple не возвращает.
Главный скрипт — не угадывать
Брать из package.json → main внутри архива; у ChatGPT это 216-байтный бутстрап без слова «electron» — сторож «похож на Electron» переписать.
Смещения, дедуп, integrity
После вставки сдвинуть offset у всех файлов после нашего, пересчитать integrity (SHA-256 + блоки 4 МиБ), проверить, что никто не делит данные с главным скриптом. Прогон на копии с полной сверкой хэшей — обязателен.
Хэш заголовка в Info.plist
SHA-256 строки JSON-заголовка, не файла. У Claude проверяется (fuse включён), у ChatGPT нет — держать верным всё равно.
Подпись в два прохода и права
--deep локально, потом само приложение со своим entitlements.plist. Ограниченные права (application-identifier, aps-environment, team-identifier, keychain-access-groups, application-groups) в локальную подпись не класть.
После переподписи macOS спросит заново
Микрофон, запись экрана, Accessibility, уведомления — один раз. Связка ключей может спросить пароль. У ChatGPT возможен повторный вход; у него же — риск DeviceCheck на стороне сервера.
Обновления сносят патч
Squirrel/Sparkle заменяют бандл. Нужен индикатор «патч слетел» по маркеру в главном скрипте и кнопка «поставить снова». Обновление может и не пройти из-за подписи — тогда вручную с сайта.
Лоадер = перепатч у всех
Каждая правка лоадера — «Поставить» заново у каждого пользователя. В лоадере — только чтение файлов и вставка; вся логика в живых файлах.
Скрипт в странице должен снимать сам себя
Выполняется заново при каждом сохранении. Первой строкой — dispose прошлого экземпляра. Стили через adoptedStyleSheets, не <style> (Claude зеркалит <style> в вынесенные окна).
Следить за файлами опросом, не событиями
fs.watchFile с интервалом; fs.watch теряет атомарные перезаписи. Команды — «последняя запись побеждает», id всегда новый.
Селекторы живут до следующего обновления
DOM меняется с каждой сборкой. Держать CSS в живых файлах, после каждого обновления — probe.js и правка. Из Claude в ChatGPT не переносится ни один селектор.
Минимальная ширина — не одна точка
Приложение само зовёт setMinimumSize (Claude — при смене экрана, ChatGPT — syncPrimaryMinimumSize); подменять метод на прототипе, а не вызывать один раз. У ChatGPT ещё и сохранённая рамка клампится к 480.
Окно — не заголовок
Заголовки меняются и повторяются. Адресовать окна id чата, который страница называет сама; заголовок — запасной признак.
Имена внутри бандла не Electron-овские
У ChatGPT фреймворк «Codex Framework», хелперы «Codex (Renderer)». Не хардкодить «Electron Framework»; путь к архиву у всех один — Contents/Resources/app.asar.
Несколько копий приложения
Launch Services помнит бэкапы и старые копии с тем же bundle id. Бандл выбирать по пути, процессы закрывать по пути бандла, не по имени.
Права самого приложения снаружи
Accessibility и App Management — два разных разрешения. Dev-сборки подписывать Developer ID с первого билда, иначе macOS будет спрашивать Accessibility после каждой пересборки.

Порядок работы для нейронки

Девять шагов, в этом порядке. Первые два — только чтение, ничего не ломают. Патч — с пятого. Самый важный тест — седьмой: после него понятно, принимает ли сервер OpenAI переподписанное приложение.

  1. Сверить, что перед нами: есть ли app.asar, какой bundle id, версия, чем подписано.
  2. Прочитать fuses — нужен ли хэш, разрешён ли отладчик.
  3. Найти главный скрипт в архиве и убедиться, что это читаемый JS.
  4. Написать патчер по образцу PimpMyClaude и прогнать его на копии архива.
  5. Дать разрешение «Управление приложениями» тому, кто будет писать в бандл.
  6. Патч: закрыть → бэкап → архив → хэш → подпись → открыть.
  7. Проверить лоадер: status.json появился, страницы видны, CSS вставлен.
  8. Тест входа и сообщения — DeviceCheck. Не прошло — откат.
  9. Разведка DOM через probe.js, первый CSS, потом скрипт с командами, потом приложение снаружи.

Что переносится, а что нет

Переносится целиком: сам приём (лоадер спереди главного скрипта, хэш, локальная подпись, бэкап), код разбора и пересборки архива, лоадер почти дословно, устройство канала через файлы (настройки, CSS, скрипт, команды, разведка, статус), правила для скрипта в странице, архитектура приложения снаружи и все грабли из списка.

Не переносится ни строчки: содержимое claude.css и inject.js — это восемь тысяч строк, привязанных к разметке Claude (классы, структура ленты, поле ввода, внутренние сторы страницы, тексты кнопок «Allow»). У ChatGPT свой интерфейс, и его надо разведывать с нуля через probe.js. Не переносятся и контракты команд, которые опираются на устройство Claude (вынос чата в окно, «кто этот чат», настройка папки проекта).

Переносится с оговорками: список прав для подписи (у ChatGPT свои), сторож «похож ли файл на главный скрипт», хук минимальной ширины (у ChatGPT ещё клампится сохранённая рамка), и сама возможность залезть внутрь — она держится на том, что сервер OpenAI терпит приложение без DeviceCheck-токена.

Голосовой ввод

Внутри страницы это не сделать: распознавание речи браузера (Web Speech API) в Electron не работает — у него нет ключа Google, которым пользуется Chrome. Поэтому голос делается снаружи, и тут ChatGPT и Claude одинаковы. Два пути. Простой — диктовка самого macOS: она печатает в любое поле любого приложения, ничего патчить не надо. Свой — приложение снаружи записывает звук, отправляет в распознавание (Whisper или любая модель для речи) и кладёт текст в поле: либо через буфер обмена и ⌘V (у нас есть опыт: ⌘V ловится в любом месте окна и уводится в поле ввода), либо командой в command.json, которую скрипт в странице превращает во вставку текста без отправки — так у нас работает кнопка «Workflow».
