## Разведка живьём (probe 17.09 04:20–04:50, главное окно)

- **Мост открытия файла есть у самого Claude:** `window["claude.web"].LocalSessions.openSessionFileInDefaultApp(sessionId, path)`
  (имя окна-свойства с точкой — доступ только скобками). Проверено: `("local_a5599717-…", "/Users/elvis/…/mockup-wf66-composer.html")`
  → `{ok:true}`, Chrome открыл файл (браузер по умолчанию у Элвиса — Google Chrome,
  `window["claude.settings"].DesktopInfo.getDefaultBrowserName()`). `sessionId` — id чата `local_<uuid>`
  (тот же, что `myChatId()` раздела 12в). Форма с объектом `{sessionId, path}` — ошибка «Argument sessionId at
  position 0». `FileSystem.openLocalFile(session, encodeURIComponent(path))` — НЕ подходит: `INVALID_SESSION`
  (это сессии Cowork, не чаты Claude Code).
- **Карточка файла** — `button.font-sans.max-w-[min(100%,480px)].rounded-lg…` в ленте; у её React-волокна
  (`__reactFiber$…`, обход `memoizedProps` вверх по `return`) строковые пропсы `path` = абсолютный путь,
  `name` = имя файла, `title` = путь. Текст кнопки: «html mockup-wf66-composer.html 10.1kB».
- **Контекстное меню** — `div[role="menu"][data-cds="ContextMenu"]` (появляется в `body` как новый узел
  через ~кадр после `contextmenu`) → `div[data-cds-sheet-scroll]` → пункты `div[role="menuitem"]` с одним
  `span.min-w-0.flex-1.truncate` внутри: «Attach as context», «Copy» (с `aria-haspopup`), разделитель
  `div[role="separator"].my-1.h-px.bg-border`, «Show in Finder». Подсветка пункта — класс
  `data-[highlighted]:bg-fill-ghost-hover` по атрибуту `data-highlighted`, который ставит base-ui.

## Батч A — страница (Fable high; один писатель `claude-patch/inject.js`, `tests/`)

**Файлы.** `claude-patch/inject.js` (новый раздел 12г «Открыть в Chrome»; правка теней в 2б), новый
`tests/open-in-chrome.test.mjs`, `tests/idempotent.test.mjs` — только если появится узел с id (не нужен:
пункт живёт внутри меню Claude и умирает с ним).

**Устройство 12г.**
1. `contextmenu` на захвате (`on(document, "contextmenu", …, true)`, только `themable`): от `event.target`
   вверх не более 12 предков ищем React-волокно с пропсом `path` — строка, начинающаяся с `/` или
   `computer://` (снять префикс). Нашли → `openState.pending = { path, name, at: Date.now() }`; нет →
   `pending = null`. Никаких `preventDefault`: меню Claude открывается само.
2. Наблюдатель за меню — ТОЛЬКО пока ждём: `MutationObserver` на `document.body` (`childList, subtree`)
   ставится в момент `contextmenu` при найденном пути и снимается сам через 1500 мс или после вставки;
   в `track()` — снятие и таймера, и наблюдателя. Ищем среди добавленных узлов `[role="menu"][data-cds="ContextMenu"]`
   (сам узел или потомок), в котором есть пункт с текстом `Show in Finder|Show in folder|Show in Explorer|Show in file manager`;
   в чужие меню (без такого пункта) не лезем.
3. Пункт: клон узла «Show in Finder» (`cloneNode(true)` — без React-обработчиков и без id), текст
   `🌐 Открыть в Chrome`, `font-weight: 600` (слово Элвиса: «жирненькая, выделенная»), метка
   `data-myclaude-open-chrome`; ставится ПЕРВЫМ пунктом меню плюс клон разделителя после него.
   Подсветка — на `pointerenter/leave` ставим/снимаем `data-highlighted=""` (класс Claude сделает фон).
   Повторная вставка в то же меню — нет (проверка по метке).
4. Клик (`click` на нашем узле, `stopPropagation`, без всплытия в меню Claude): `sessionId = myChatId()`
   (раздел 12в: главное окно — хвост `location.pathname`, попап — кэш `myclaude-chat-v1`); бридж —
   `window["claude.web"]?.LocalSessions?.openSessionFileInDefaultApp`. Есть оба → вызов `(sessionId, path)`,
   результат в `openState.last = {path, ok, error}`; меню закрыть — `document.dispatchEvent(new KeyboardEvent("keydown",
   {key:"Escape", bubbles:true}))` ПОСЛЕ вызова. Нет чата (`null`) или бриджа → плашка `notice(...)`
   (существующая плашка страницы, как у «Обкэшить»): «Не знаю, какой это чат — открой через Finder» /
   «Claude не даёт открыть файл»; ошибка бриджа → плашка с текстом ошибки, обрезанным до 120 знаков.
5. `status().openInChrome = { pending: Boolean, path: pending?.path ?? null, inserted: <счётчик>, last }`.
6. **Свечение полосы (2б):** тени `0 0 9px/0 0 3px` (заливка) и `0 0 9px/0 0 5px` (слой свечения) → `0 0 6px/0 0 2px`
   и `0 0 6px/0 0 3px`; пульс не трогать.
7. `VERSION` → `wf67-a-1`.

**Тесты** (`tests/open-in-chrome.test.mjs`, стаб `tests/dom.mjs`; посмотреть, как стаб отдаёт
`MutationObserver` — разделы 9/12 им пользуются): (1) `contextmenu` на узле с волокном `{memoizedProps:{path}}`
(волокно подкладывается тестом как свойство `__reactFiber$test`) → `status().openInChrome.path`; (2) появление
меню с «Show in Finder» → в нём первый пункт с меткой и текстом «Открыть в Chrome», вставка ровно одна;
(3) клик → вызван подложенный `window["claude.web"].LocalSessions.openSessionFileInDefaultApp(chatId, path)`
ровно раз, `last.ok`; (4) без пути (правый клик по тексту) наблюдатель не ставится, меню не трогается;
(5) `dispose()` снимает слушатель и наблюдатель (второй прогон не удваивает вставку). Прогон:
`node --test tests/*.test.mjs`, `bash tools/test.sh --js`.

**Критерии готовности (живьём, гейт).** Правый клик по карточке файла в чате → первым пунктом жирный
«🌐 Открыть в Chrome»; клик → Chrome показывает файл, меню закрылось; правый клик по обычному тексту — меню
Claude как было; свечение полос заметно тише.

**Что не делать.** Не трогать меню Claude сверх вставки одного пункта; не перехватывать `contextmenu`;
не заводить постоянный наблюдатель; лоадер и Swift не трогать; `FileSystem.openLocalFile` не звать.
