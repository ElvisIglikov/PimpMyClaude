## Что выяснено по коду (проверено 06.09 чтением; агенту кодинга заново не копать)

### Часть 1 — почему примерка мгновенная

1. **`hoverSeconds = 0.3` (`app/Sources/ClaudeAX/MinimizeMenu.swift:15`) к пунктам отношения не имеет.**
   Это выдержка курсора на **жёлтой кнопке** окна перед показом меню: `tick()` сравнивает время с
   `hoverSince` и зовёт `show(for:at:)` (`:122-124`). К подсветке пунктов внутри меню он не подключён никак.
2. **Примерка пункта уходит мгновенно и ровно в одном месте** — `PreviewMenuDelegate`
   (`MinimizeMenu.swift:1011`), метод `menu(_:willHighlight:)` (`:1014`), одна строка
   `(item as? BlockMenuItem)?.preview?()`. Замыкание живёт на самом пункте (`BlockMenuItem.preview`, `:1103`).
3. **Делегат один на все меню и без состояния** — `PreviewMenuDelegate.shared`, вешается на «🎨 Оформление ▸»
   (`:531`), на список цветов (`:728`), на список размеров (`:827`) и на список шрифтов (`:859`); у «🖥 Всем
   окнам ▸» примерок нет вовсе (`item.preview = all ? nil : …`) и делегата там нет. Значит задержку достаточно
   завести в делегате — её получат разом все примеряемые пункты: цвета (`:740`, `:754`), свои темы (`:768`),
   рамка (`:802`), размеры (`:833`, `:845`), шрифты (`:864`, `:879`).
4. **`Timer.scheduledTimer` внутри открытого меню НЕ сработает**: меню крутится в
   `NSEventTrackingRunLoopMode`, таймер в `.default` во время трекинга не тикает — это уже ловили в WF14
   (комментарий `SliderMenuView`, `MinimizeMenu.swift:1028-1033`). Главная очередь в tracking-режиме
   обслуживается, поэтому берём `DispatchQueue.main.asyncAfter` (так сделан дебаунс ползунка, `:1090`).
   **Не «единственный» способ** (уточнено по находке критика М1): запрещён именно `Timer.scheduledTimer`
   (режим `.default`); `Timer`, добавленный в `RunLoop.main` `forMode: .common`, в трекинге живёт — так
   работает тик наведения (`:69-71`). Это наш запасной путь, если шаг 0 гейта покажет, что `asyncAfter`
   в трекинге не выполняется.
5. **`popUp` блокирующий, и это снимает гонки.** `show()` стоит на `menu.popUp(...)` (`:290`), а сразу после
   синхронно решает судьбу примерки: `if previewed && !committed && !MinimizeMenu.editorOpen
   { actions.endPreview(window: window) }` (`:297`). Флаги `previewed`/`committed` — локальные `var` (`:184-185`),
   их пишут замыкания пунктов ВНУТРИ цикла показа. Всё это главный поток: отложенный блок либо успел
   выполниться до возврата `popUp` (и `previewed` честно стал `true`), либо ещё лежит в очереди — и его
   достаточно отменить синхронно первой же строкой после `popUp`.
6. **Панель «Своя тема» уже развязана с меню**: пока она открыта, `hoverPaused` (`:60`) не даёт меню всплыть,
   а `stop()` (`:75-86`) её закрывает. Отдельной защиты не нужно — только отмена в этих же двух местах.
7. **У панели своя задержка** — `ThemeEditorModel.previewInterval = 0.5` (`ThemeEditorModel.swift:21`),
   троттлинг ползунков. Её не трогаем, константы не связываем.
8. **Подставное расписание в проекте уже принято**: `ThemeEditorModel` принимает `now` и `schedule`
   замыканиями (`ThemeEditorModel.swift:47-57`), так же живёт `CommandChannel` (`:90`). Новую задержку делаем
   тем же приёмом — тест ничего не ждёт.
9. **Канал**: `CommandChannel.minInterval = 0.6` (`CommandChannel.swift:50`), примерка пишется мимо очереди
   (`priority: .preview`, `:52-59`), лоадер читает `command.json` раз в 500 мс и берёт ПОСЛЕДНЮЮ запись.
   Сегодня проход по 24 темам — два десятка записей в файл, из которых до страницы доезжают единицы;
   пауза этот мусор убирает заодно.
10. **Тесты уже умеют звать наведение без AppKit**: помощник `highlight(_:_:)`

## Решения

### 1. Пауза перед примеркой

**1.1. Задержку получают ВСЕ примеряемые пункты одинаково, не только «Мои темы».** Обоснование:
(а) жалоба дословно про свои темы, но механика у всех списков одна (п. 2, 3), и проезд по 24 цветам стоит
ровно столько же; (б) выборочная задержка потребовала бы флага на каждом пункте и второго правила, которое
придётся помнить всем следующим воркфлоу; (в) WF25 («своя панель-меню») уже заложил, что рендерер обязан
звать делегата меню, а не примерку напрямую — задержка внутри делегата достанется панели даром;
(г) побочно исчезает мусор в `command.json` (п. 9).

**1.2. Задержка — 0,5 с, одной константой `PreviewMenuDelegate.defaultDelay`.** Обоснование: слово Элвиса —
«нужно секундочку подождать… только при долгом удержании», карточка #5452 записана как «~0,5 с»; проезд
мыши через пункт занимает меньше 0,2 с, системная задержка раскрытия подменю — около 0,3 с, так что 0,5
надёжно отделяет «проехал» от «остановился» и не спорит с раскрытием подменю. Ошибка в короткую сторону дороже:
паузу Элвис попросил сам, а «всё равно активируется» — это повторная задача. **0,4 с — первый кандидат, если
Элвис скажет «тормозит»**; правка — одна строка (оркестратор предлагал ~0,4 с, разница ровно в этой константе).

**Честное число «остановился → цвет» — от 0,5 до 1,0 с, в среднем ~0,75 с** (находка критика Б4). Константа
здесь одна, но к ней прибавляется доставка: примерка пишется в `command.json` сразу, мимо очереди
(`priority: .preview`, `CommandChannel.swift:50-59`), а лоадер читает файл раз в 500 мс — значит от записи
до экрана ещё 0…0,5 с. Это ровно та «секундочка», которую просил Элвис, но назвать её надо вслух и в
презентации: иначе после гейта разговор «стало тормозить» пойдёт про не ту константу (тюнить всё равно
можно только `defaultDelay` — шаг опроса лоадера трогать нельзя, это перепатч). Снятый довод: раньше здесь
стояло, что «0,5 = шаг опроса, значит при проезде мимо в файл ничего не уходит» — довод неверный, при
проезде мимо `preview()` вообще не зовётся при ЛЮБОЙ константе, шаг опроса ни при чём.

**1.3. Реализация — в `PreviewMenuDelegate`, через `DispatchQueue.main.asyncAfter`, с отменой по поколению
и с защитой от чужого `nil`.** `Timer` в меню не тикает (п. 4). Форма — ориентир, не буква:

```swift
final class PreviewMenuDelegate: NSObject, NSMenuDelegate {
    static let shared = PreviewMenuDelegate()
    /// Сколько курсор должен простоять на пункте, прежде чем окно перекрасится (#5452).
    static let defaultDelay: TimeInterval = 0.5
    /// Боевое расписание вынесено в константу, чтобы тесты могли вернуть его на место.
    static let liveSchedule: (TimeInterval, @escaping () -> Void) -> Void = { wait, block in
        DispatchQueue.main.asyncAfter(deadline: .now() + wait, execute: block)
    }
    var delay = PreviewMenuDelegate.defaultDelay
    /// Подставляется в тестах — как `schedule` у `ThemeEditorModel` (:47-57).
    var schedule = PreviewMenuDelegate.liveSchedule

    private weak var pendingMenu: NSMenu?
    private weak var pendingItem: NSMenuItem?
    private var generation = 0

    func menu(_ menu: NSMenu, willHighlight item: NSMenuItem?) {
        // «Подсветки нет» из ЧУЖОГО меню отложенную примерку не отменяет: родительское меню
        // гасит свою подсветку, пока мышь ушла в подменю, — иначе примерка не случилась бы никогда.
        if item == nil, let pending = pendingMenu, pending !== menu { return }
        // Тот же пункт (дрожь руки) таймер не перезапускает.
        if let item = item, item === pendingItem, pendingMenu === menu { return }
        generation &+= 1
        guard let preview = (item as? BlockMenuItem)?.preview else {
            pendingMenu = nil; pendingItem = nil; return
        }
        pendingMenu = menu
        pendingItem = item
        let mine = generation
        schedule(delay) { [weak self] in
            guard let self = self, self.generation == mine else { return }
            preview()
        }
    }

    /// Закрылось ТО меню, в котором мы ждём: подсветке уже некуда двигаться, отменяем сами
    /// (находка критика Б5 — иначе весь класс «примерка выстрелила в закрытое подменю»
    /// держался бы только на `cancel()` после `popUp`, а порядок событий AppKit при закрытии
    /// подменю — единственное место, где план гадает, см. риск 3).
    func menuDidClose(_ menu: NSMenu) {
        if menu === pendingMenu { cancel() }
    }

    /// Меню закрылось (выбором или мимо) — отложенная примерка отменяется.
    func cancel() { generation &+= 1; pendingMenu = nil; pendingItem = nil }
}
```

Что здесь важно и проверяется тестами: подсветка сменилась — старая отложенная примерка не выстрелит
никогда; подсветка на заголовке секции, разделителе, пункте с подменю («🎨 Цвет ▸») или «Сохранить…» —
отмена без своей примерки; `nil` из того же меню — отмена, `nil` из родительского меню при живом
подменю — НЕ отмена (иначе на реальном AppKit примерка могла бы не случаться вовсе).

**1.4. Отмена зовётся в трёх местах.** (1) В `MinimizeMenu.show()` — **синхронно, сразу после
`menu.popUp(...)` (`:290`) и ДО проверки `previewed && !committed`** (`:297`): иначе отложенная примерка

### Блокеры

1. **«Живая проверка паузы необязательна, а приложение при этом подменяется в `/Applications`».** Принято

   `MinimizeMenu.swift:69-71`), иначе — мгновенный вызов одной строкой и честное «пауза не сделана».
   Строка Элвису на утро тоже записана.
