### Как сделано в старом

Механика делится на четыре куска.

1) ПОЙМАТЬ ФАЙЛ НА ВХОДЕ. Из разметки File не достать — у картинки в плашке только blob-превью, у pdf/txt одно имя; сам File лежит в состоянии Claude (прямая цитата причины: /Users/elvis/_ElvisProjects/ElvisOS/Resources/claude-handoff-main.js:562-570). 2) РАЗЛОЖИТЬ ПО ПЛАШКАМ. Сборщик берёт превью КАЖДОЙ плашки (fetch blob: → размер) и просит у реестра файл парой (имя, размер), а не по имени: /Users/elvis/_ElvisProjects/ElvisOS/Resources/claude-handoff-main.js:571-640 и `matchEach` в claude-chat-cleaner-inject.js:246-320. - В композере файл живёт ТОЛЬКО в памяти страницы. Доказано замером старого проекта: после forciblyPurgeJavaScriptMemory набранный текст выживает, а вложение исчезает (claude-handoff-main.js:3059-3068).

## «Обкэшить» в ElvisOS (renew + fork) — что забрать в PimpMyClaude, что не брать

### Как сделано в старом

В ElvisOS было ДВЕ команды. (1) «Обкэшить» = фаза `renew` — новый чат в ТОМ ЖЕ окне. (2) «Форкнуться» — разговор уезжает в соседнее окно; тогда у Claude не было попапов, поэтому «соседнее окно» = ВТОРОЙ ПРОЦЕСС Claude, поднятый через NSWorkspace.

Шаги «Обкэшить» (renew):
1. Пункт меню → `runClaudeRenewWithContext` (Source/AppDelegate+ClaudeHandoff.m:770) с контекстом {frame окна из AX, pid}. Ни одной молчаливой развилки: нет рамки — говорит вслух (:773-780).
2. Пишется ОДИН файл команды `claude-handoff-command.json` (`writeClaudeHandoffCommand`, .m:622): `{id: UUID, phase:"renew", carry, bounds:{x,y,width,height}, sourcePid}`.
3. Файл читают ВСЕ живые экземпляры Claude. Адресация — `sourceWindow()` (Resources/claude-handoff-main.js:7269): свой pid → работа моя; чужой pid + у меня окно нужной геометрии → жду 1,5-2,7 с и подстраховываю, если адресат промолчал; перед этим смотрю реестр живых экземпляров (`bestInstanceForBounds`, :6876), чтобы не спорить с более близким по рамке.
4. Взявший работу СРАЗУ пишет метку `claude-handoff-claim.json` (`claimCommand`, :6504) — до всякой работы.
5. Сбор: `collectFrom` (:6396) → `COLLECT_SCRIPT` (:416). Забирает: последний ответ Claude (каскад из 8 селекторов, служебные узлы Epitaxy и сайдбар отсекаются), черновик поля ввода (уезжает ПОД ответ, между разделителями `composeText`, :6385), модель, усилие, режим разрешений Auto/Manual/Plan, папку проекта, вложения из поля (объекты File из реестра, который инжект набивает на входе) и картинки из ленты (data:/blob:, потолки 24 шт / 48 МБ, дедуп по хэшу содержимого). Если целевая страница ответила пустотой — перебирает ОСТАЛЬНЫЕ страницы того же окна (панель артефакта кода), общий потолок один на все заходы.
6. Новый чат: `newChatScript` (:1339) — клик по кнопке в том же окне, три стратегии поиска (акселератор ⌘N → точная подпись → href), защита от клика по строке списка чатов с именем «Новый чат»; ждёт смены href/обнуления счётчика сообщений, потом появления редактора, потом очистки чужого черновика.
7. Вставка: `pasteScript` (:855) — папка → модель → усилие → режим (промах ЛЮБОЙ настройки перенос НЕ отменяет, уезжает в статус), затем текст `ClipboardEvent("paste")` с проверкой доезда по нормализованному сравнению и запасным `execCommand("insertText")` (:1188-1213), затем вложения ПОСЛЕ текста с проверкой мультимножеством (имя,размер) до 40 проходов.
8. Весть инжекту о доставке (`announceDelivery`, :3561) — глобал + CustomEvent, чтобы окно развернуло поле по ФАКТУ доезда; плюс два своих прохода разворота.
9. Ответ — ЕДИНСТВЕННАЯ запись в `claude-handoff-status.json` в самом конце, числами: `attachedDone/attachedWanted/lost/imagesSkipped/lostSettings`. Obj-C опрашивает его раз в 0,4 с (`waitClaudeHandoffPhase`, .m:683) с потолком 500 попыток (200 с), но с ранним отказом по метке через 20 с (`RadugaHandoffClaimAttempts=50`, .m:681).
10. Enter НЕ жмётся никогда.

Что делалось со старым чатом и окном: НИЧЕГО. Старый чат остаётся в сайдбаре (это SPA-переход, а не удаление), окно не двигается и не меняет размер. Разворот окна «на четыре пятых экрана» был сделан (`expandClaudeWindowForRenew`, .m:738) и ОТКЛЮЧЁН по слову Элвиса — код мёртв за `if (NO && carry …)` (.m:797, Kaban 3028: «нажал обкэшиться, и окно раздулось почти на полэкрана — такого изменения размера при команде быть не должно»).

Закрытие старого окна и постановка нового на его место в ElvisOS СУЩЕСТВОВАЛО, но не в «Обкэшить», а в «Новое окно» (Kaban 2280): `launchClaudeInstanceIntoSlot:replacingProcess:sourceFrame:` (Source/AppDelegate+ClaudeWindows.m:933) ставит новый экземпляр в рамку старого и зовёт `retireClaudeWindowForProcess` (:409) — если у экземпляра одно окно, `terminate` + через 4 с страховочный `forceTerminate`; если окон несколько — закрывается только заменяемое окно, чужие чаты не теряются. Элвис от этой замены ОТКАЗАЛСЯ (Kaban 2518, комментарий ClaudeWindows.m:361-367): «пункт назван "Новое окно" и должен именно открывать новое, ничего не теряя». Порядок там правильный и нам полезный: старое закрывается ТОЛЬКО после того, как новое окно реально встало в ячейку (:1010-1015).

Форк (аналог сегодняшнего попапа): три фазы `fork-collect` → `fork-paste` → `fork-collapse` (:7693, :7793, :7761). Вложения между процессами едут через диск `Application Support/ElvisOS/fork-carry/<id>/` кусками по 1,5 МБ base64. Исходное окно портится ПОСЛЕДНИМ: поле ввода сворачивается отдельной фазой и только после того, как текст доехал в соседнее окно.

## ЗОНА 2 — окна, меню и общие функции: что взять из ElvisOS в PimpMyClaude

### Как сделано в старом

ElvisOS жил в мире «одно окно Claude = один процесс»: нативного нового окна у Claude тогда не было, и каждое окно поднималось отдельным экземпляром через NSWorkspace с createsNewApplicationInstance (Source/AppDelegate+ClaudeWindows.m:921-963). Отсюда почти вся его сложность: список живых экземпляров собирается ДВУМЯ независимыми способами и объединяется (NSRunningApplication + CGWindowList с proc_pidpath, Source/AppDelegate+ClaudeWindows.m:154-209); окно внутри экземпляра ищется по РАМКЕ с допуском (RadugaCopyClaudeWindowNear, Source/ClaudeWindows.m:234-277); имя чата достаётся точечным AX-хит-тестом заголовка (Source/ClaudeWindows.m:378-400), а состав чатов — из реестра, который пишет скрипт в main-процессе Claude (claude-instances/<pid>.json, Source/AppDelegate+Menus.m:908-931).

Работа с окнами через доступность у него такая. Рамка ставится тройкой «размер → позиция → размер» (RadugaForceAccessibilityFrame, Source/ClaudeWindows.m:788-802) и потом ДОБИРАЕТСЯ четырьмя отложенными проверками на 2.0/3.5/5.5/8.0 с (Source/AppDelegate+ClaudeWindows.m:1021-1026, settleClaudeWindowForProcess:1047-1058). Появления окна ждут опросом раз в 0,3 с до 60 попыток, и окно считается готовым только при ширине ≥ 320 и высоте ≥ 240 (Source/AppDelegate+ClaudeWindows.m:995-1046). Закрытие — нажатие красной кнопки через AX (RadugaCloseAccessibilityWindow, Source/ClaudeWindows.m:362-375), и только если у экземпляра больше одного окна; единственное окно закрывается завершением всего процесса с forceTerminate-страховкой через 4 с (Source/AppDelegate+ClaudeWindows.m:409-433). «Расставить» берёт окна ТОЛЬКО текущего стола из оконного сервера (kCGWindowListOptionOnScreenOnly, Source/ClaudeWindows.m:864-910), раздаёт ячейкам ближайшие окна с тройным весом по горизонтали, копит промахи и добирает их на 0.6 и 1.6 с, а в конце поднимает все окна (Source/AppDelegate+ClaudeWindows.m:521-641). Сетка при этом целится в самый большой ПУСТОЙ прямоугольник экрана, если пачка влезает туда целиком (RadugaLargestFreeRectInArea, Source/ClaudeWindows.m:1217-1290; занятость — любое чужое окно слоя 0 минус мелочь и прозрачное, Source/ClaudeWindows.m:1168-1194).

Меню на жёлтой кнопке: глобальный монитор движения мыши, кэш «зон» углов окон раз в 0,4 с, дешёвая проверка «курсор рядом с кнопкой» по зашитым смещениям Electron (47, 24, радиус 22 — Source/MinimizeHoverMenu.m:74-76, 643-657) и только потом дорогой AXUIElementCopyElementAtPosition с проверкой subrole (Source/MinimizeHoverMenu.m:660-712); пауза раздумья 0,16 с не перезапускается, пока курсор на ТОЙ ЖЕ кнопке (Source/MinimizeHoverMenu.m:713-742). Состав меню — в main.m:1828-1993: «Чаты ▸» первым пунктом, дальше Обкэшить/Форкнуться/Новый чат/Новое окно/переключалка высоты/поля ввода, и общий с меню Dock блок команд на все окна.

Тема доставляется НЕ инжектом, а отдельным mjs в main-процессе через insertCSS с cssOrigin:"user" (Resources/claude-theme-manager.mjs:213-236) — именно потому, что только пользовательская таблица перебивает инлайновый !important самого Claude.
