## Что выяснено (разведка 04.09, живьём; агенту заново не лезть)

1. **Рамка.** Оверлей `#myclaude-window-frame` рисует inject.js (константа `WINDOW_FRAME_RADIUS = 10`, инлайн-стиль
   `border-radius: 10px`). У окна macOS 26 (Tahoe; у Элвиса 26.5) радиус ≈ **17 pt** — замер по альфа-каналу скриншота окна;
   у macOS 13–15 радиус 10–11 pt. Отсюда «углы обрезаются неровно»: рамка круглее/квадратнее самого окна.
   **inject.js править не нужно**: лоадер вставляет живой файл `~/Library/Application Support/MyClaude/claude.css`
   как **user-origin** CSS (`insertCSS(text,{cssOrigin:"user"})`, файл перечитывается по mtime раз в секунду) — а user `!important`
   по правилам каскада бьёт инлайн-стиль автора. Значит радиус чинится строкой в claude.css без перепатча у команды.
2. **Поля по бокам.** В живом `claude.json` уже `sidePadding: 5`, но новая сборка Claude сменила классы: контейнер колонки чата
   теперь `mx-auto [--chat-column-gutter-start:var(--chat-gutter-start,var(--chat-gutter,32px))] [--chat-column-gutter-end:…]`,
   отступы 32/40 px берутся из переменных `--chat-column-gutter-start/end`. Правило лоадера
   (`[class*="ps-[var(--chat-gutter"]`, `.epitaxy-transcript-width`, `.epitaxy-composer-width`) по этим классам больше НЕ матчится —
   поэтому поля и «не слушаются». **Лоадер трогать нельзя** (смена лоадера = перепатч Claude у всей команды). Лечится тем же claude.css.
   В репозитории умолчание всё ещё 16: `claude-patch/claude.json`, `DEFAULTS` в `claude-patch/patch-claude.mjs:41`,
   `Patcher.configDefaults` в `app/Sources/Patcher/Patcher.swift:22`.
3. **Меню.** Верхний уровень — `MenuModel.entries` (8 пунктов) + `separatorsAfter`; сборка — `MinimizeMenu.build/themeItem/themeList/
   fontItem/sizeItem/sizeList/fontList/frameItem/autoPaintItem`. Автопокраска висит и в меню-баре (`AppDelegate.buildStatusItem`,
   `ax.autoPaintMenuItem()`). Каталог: 24 темы (15 тёмных, 9 светлых) в `claude-patch/themes.json`; шрифты — четыре категории
   `FontCategory` (serif/sans/hand/mono); кегли `Size.steps = [12,13,14,15,16,18,20]` (`FontCatalog.swift:49`).
   Тесты, которые упадут при перестановке: `testMenuKeysMatchReadme`, `testMenuItemsCarryKeyEquivalents`, `testMenuHasTwoThemeSubmenus`,
   `testHoverPreviewsThemeAndFont`, `testMenuHasSizeSubmenusWithChecksAndPreview`, `testMenuFrameToggleFlipsAndPreviewsOn`,
   `testAutoPaintMenuHasPresetsRandomAgainAndReset`, `testSkeleton` (число команд).
4. **Галки (#5363).** В `themeList/fontList/sizeList` пункт сброса получает галку только при `all && selected == nil` —
   у окна «Как у Claude» не отмечается никогда. Нужно: галка у окна, когда `windowXxx == nil && allXxx == nil`
   (нет своей записи и нет записи «всем»); если запись «всем» есть, а своей нет — галка стоит в «Всем окнам ▸», у окна пусто.
5. **Мои темы (#5364).** `MyThemesStore.add` всегда заводит новую запись (`makeID` по времени) — одинаковые имена плодятся,
   «изменить» невозможно. `appending` уже умеет вытеснять по id — не хватает совпадения по имени.
6. **Тумблер рамки** сейчас живёт внутри списка тем `scope:"all"` последним пунктом (`themeList`) — в новой структуре он переезжает
   в «🖥 Всем окнам ▸» отдельным пунктом.

## Решения

### 1. Контракт живого блока в claude.css (новый, обязателен побайтно)

Приложение владеет ОДНИМ блоком в `~/Library/Application Support/MyClaude/claude.css`, всё остальное содержимое файла
(правила Элвиса и правила из бандла) сохраняет дословно:

```css
/* PimpMyClaude:auto */
#myclaude-window-frame{border-radius:17px !important}
[class*="--chat-column-gutter-start"]{--chat-column-gutter-start:5px !important;--chat-column-gutter-end:5px !important}
[class*="ps-[var(--chat-gutter"],[class*="pe-[var(--chat-gutter"],.epitaxy-transcript-width,.epitaxy-composer-width{padding-inline-start:5px !important;padding-inline-end:5px !important;padding-left:5px !important;padding-right:5px !important}
/* /PimpMyClaude:auto */
```

- Маркеры ровно такие: открывающий `/* PimpMyClaude:auto */`, закрывающий `/* /PimpMyClaude:auto */`, каждый на своей строке.
- Есть оба маркера — заменить содержимое МЕЖДУ ними на месте (порядок строк файла не менять). Нет — дописать блок в КОНЕЦ файла
  (последний выигрывает при равной специфичности). Маркеры битые/один из двух — старый мусор вырезать по первому и последнему, записать блок в конец.
- `17` = радиус окна: `ProcessInfo.processInfo.operatingSystemVersion.majorVersion >= 26 ? 17 : 10`. На гейте сверить скриншотом, допуск 16–18.
- `5` = `sidePadding` из настроек приложения (см. п. 3).
- Пишется: при запуске приложения, после «Поставить» (оно копирует claude.css из бандла и затирает блок — дописать снова) и при каждом
  изменении ползунка (дебаунс ~150 мс). Запись атомарная (`CommandChannel.writeAtomic`), только при реальном изменении текста —
  лишний `write` дёргает mtime и заставляет лоадер переставлять CSS каждую секунду.

### 2. Один писатель на файл

- **`claude-patch/inject.js` в WF14 НЕ трогаем вообще** (там же идёт/только что прошёл WF13 — раздел 12б). Всё поведение WF14
  делается Swift-ом и живым claude.css. Константу `WINDOW_FRAME_RADIUS` не двигаем: правит claude.css, инлайн-стиль остаётся как был.
- Весь Swift — **один батч B**, один агент: `MenuModel`, `MinimizeMenu`, `ThemeCatalog`/`MyThemes`, `ClaudeActions`,
  `ClaudeAXController`, `AppDelegate`, новый `LiveStyle.swift`, тесты. Разбивать нельзя: пункты меню, галки и ползунок — один файл `MinimizeMenu`.
- `README.md` + `docs/TEAM.md` — тем же батчем B (у него уже все факты) либо отдельным батчем D (Opus max), если хочется параллели;
  тогда B в них не пишет.

### 3. Поля по бокам — ползунок (#5360)

- Значение живёт в `UserDefaults` приложения (`sidePadding`, Int, 0…24, по умолчанию **5**).
- Пункт меню «↔️ Поля по бокам» — `NSMenuItem.view` со своим `NSView`: слева заголовок, дальше `NSSlider` (min 0, max 24,
  `allowsTickMarkValuesOnly = true`, 25 делений), справа число. Ползунок таскается мышью прямо в открытом меню
  (`NSMenuItem.view` события мыши получает), клика «применить» нет.
- На изменение (дебаунс 150 мс): (а) переписать блок claude.css (п. 1); (б) merge-запись `sidePadding` в
  `~/Library/Application Support/MyClaude/claude.json` — **читать JSON, менять один ключ, писать обратно**, остальные ключи
  (`minWindowWidth`, `projectsRoot`) не терять; это для старых сборок Claude, где правило лоадера ещё матчится.
- Умолчание 5 поднять и в репозитории: `claude-patch/claude.json`, `DEFAULTS` в `patch-claude.mjs`, `Patcher.configDefaults`.

свечение не выпирает за угол окна: если выпирает — уменьшить внешний размытый слой у оверлея НЕ здесь, а задачей на WF15
(inject.js занят).

### 5. Структура меню (#5361) — вариант выбирает Элвис по макету

**Вариант А (рекомендую), верхний уровень:**

```
🪟 Новое окно           ⌥⌘N          ← из WF13
──────────────
⬆️ Развернуть           ⌥⌘↑
⬇️ Свернуть             ⌥⌘↓

```

Хоткеи всех четырёх спрятанных пунктов регистрируются и работают как раньше — прячем только из глаз.
**Вариант Б:** всё плоско как сейчас, меняется только порядок (Развернуть над Свернуть) и три подменю схлопываются в «🎨 Оформление ▸».

**Подменю «🎨 Оформление ▸» — одинаково для А и Б:**

```
МОИ ТЕМЫ                        ← disabled-заголовок; пусто — секции нет
  ✓ Ночная работа
    Тёплая
──────────────
🎨 Цвет ▸
🔤 Шрифт ▸
🔠 Размер ответов ▸
🔠 Размер вопросов ▸
✨ Неоновая рамка        ✓
↔️ Поля по бокам   ——●——   5      ← ползунок
──────────────
🖥 Всем окнам ▸
──────────────
💾 Сохранить как мою тему…
🗑 Удалить мою тему ▸
🧹 Всё как у Claude
```

- «🖥 Всем окнам ▸»: Цвет ▸ · Шрифт ▸ · Размер ответов ▸ · Размер вопросов ▸ · ✨ Неоновая рамка · ─ · 🌈 Раскрасить по кругу ▸
  (бывшая «Автопокраска», если Элвис её оставит — вопрос 1). Предпросмотра по наведению внутри «Всем окнам» по-прежнему нет.
- «🧹 Всё как у Claude» — сброс всех слоёв окна разом: `theme:null, font:null, size:null, frame:null`.
- «🎨 Цвет ▸»: первым `✓ Как у Claude`, разделитель, `ТЁМНЫЕ` (15), **разделитель**, `СВЕТЛЫЕ` (9) — секции разделены так же,
  как «МОИ ТЕМЫ» (прямой вопрос Элвиса «почему мои темы отделены полоской, а светлые от тёмных нет»).
  Вариант В: тёмные и светлые — двумя подменю (`🌑 Тёмные ▸` / `☀️ Светлые ▸`); список короче, но на уровень глубже.
- «🔤 Шрифт ▸»: первым `✓ Системный (как у Claude)`, дальше четыре категории. «🔠 Размер … ▸»: первым `✓ Как у Claude`,
  дальше 12…20, галка на текущем.
- **Автопокраска (#5362)** снимается с верхнего уровня меню окна и из меню-бара (`AppDelegate.buildStatusItem`); внутри
  «Всем окнам ▸» — по ответу Элвиса (вопрос 1).

### 6. Галки (#5363)

Единое правило для всех четырёх списков окна (цвет, шрифт, размер, рамка): галка у «Как у Claude»/«Системный» стоит, когда
`windowXxx == nil && allXxx == nil`. Есть запись «всем окнам» — у окна не отмечено ничего (окно наследует), галка в «Всем окнам ▸».
Для рамки то же: `windowFrame == false && allFrame == false` → тумблер погашен, это и есть «как у Claude».

### 7. Мои темы: сохранить / изменить / удалить (#5364)

- `MyThemesStore.add`: имя после `clean(name:)` совпало с существующей темой (регистронезависимо) → **перезаписать её слои,
  сохранив id и место в списке** (это и есть «изменить»: галка в меню не съезжает, применённая тема остаётся применённой).
  Не совпало — новая запись, как сейчас.
- Диалог «Сохранить как мою тему…» открывается с подставленным именем: если к окну применена своя тема — её имя, иначе пусто.
  Подсказка под полем: «Имя как у сохранённой — перезапишу её».
- «🗑 Удалить мою тему ▸» остаётся списком; пункт есть, только когда свои темы есть.

### 8. Версия и релиз

`app/Resources/Info.plist` → **1.4.0** (CFBundleVersion 8) до сборки. Релиз `tools/release.sh` (нотаризация, профиль `pimpmyclaude`) →
`dist/PimpMyClaude-1.4.0.zip`; WF13 «Новое окно» уезжает тем же релизом.

### 9. Не делаем в WF14

Свой редактор цветов; тему на папку/проект; перенос ползунка полей в меню-бар; правку inject.js (в т. ч. свечение рамки и
`WINDOW_FRAME_RADIUS`); настройку `minWindowWidth` ползунком.

## Открытые риски

- **Своё содержимое claude.css.** У Элвиса файл живой и правится руками; ошибка в разборе маркеров сотрёт его правила.
  Тест на «файл без маркеров», «файл с блоком в середине», «блок дважды» — обязателен.
- **Радиус окна.** 17 pt снят замером по одному скриншоту одной сборки macOS 26.5; у команды бывают 13–15 (10–11 pt).
  Порог по `majorVersion` грубый — если Apple снова сменит радиус, лечится одной строкой в claude.css без релиза (это плюс подхода).
- **Классы Claude снова сменятся.** Оба правила (новое и старое) живут в блоке одновременно; при следующей смене сборки поля опять
  «отвалятся» — тогда правится claude.css, а не лоадер. Стоит записать это в TEAM.md одной строкой.
- **`NSSlider` в `NSMenuItem.view`** не наследует подсветку строки и требует своей отрисовки; на macOS 26 меню рисует
  подложку иначе — на гейте посмотреть, не «висит» ли ползунок вне строки.
- **Перестановка меню ломает 8 тестов** (см. «что выяснено» п. 3) — это ожидаемо, ожидания переписываются в том же батче B;
  verify обязан проверить, что тесты именно переписаны, а не удалены.
- **«Ещё ▸» прячет хоткеи от глаз.** Клавиши остаются, но команда их не увидит — README и TEAM.md обязаны их перечислить.
- Сброс только одной половины размера по-прежнему невозможен (`size:null` снимает обе) — контракт не трогаем, хвост остаётся.
