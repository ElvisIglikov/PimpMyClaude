## Отдельно: ключи зеркала vs `writeKeys` страницы (пункт задания)

Сверил построчно `WindowThemeStore.keys` (`:331`) с `writeKeys` (`inject.js:1380`). **Постоянного расхождения,
которое красило бы окно чужим цветом, нет.** Расхождения такие:

1. Главное окно из меню (`applyTheme`, AX-заголовок «Claude») — страница пишет `id:` + `chat:<имя чата>` + `main`,
   зеркало только `main`. Строка 5 таблицы решения 2, возврат красит верно.
2. Главное окно из цвета проекта — `title:""` + `match`, зеркало пишет `main`, страница три ключа. Строка 3, верно.
3. Попап из меню — зеркало `chat:<заголовок>` (поле `chat` `applyTheme` не шлёт вовсе), страница `id:` + `chat:`.
   После переустановки у попапа id на инжекте ещё нет, читается `chat:` — цвет возвращается.
4. Попап из цвета проекта — ключи совпадают побайтно (`id:` + `chat:`).
5. Расхождение по полноте записи (страница переносит всю запись `migrateChatKey`, зеркало пишет слои одной
   команды) и по склейке половинок `size` — находки 3 и 5.

Все они самолечатся первым же ответом probe (`absorb`, `WindowThemeStore.swift:175`), пока включён тумблер
«🗂 Цвет по проекту» (см. находку 2).

## Находки

1. **Безымянный попап уносит ключ `main` (мелкая, не блокер).** `isMainWindowTitle` повешен на
   `ProjectPaint.windowKey(forTitle:)` (`ClaudeAXController.swift:94`), а тот отдаёт `main` любому окну с
   заголовком ровно «Claude» (`ProjectPaint.swift:544`). Выбор темы в попапе безымянного чата ложится в файл
   ключом `main` (`WindowThemeStore.swift:337-341`), и после переустановки возврат покрасит этим цветом **главное
   окно** — то есть цена ошибки ключа здесь «чужой цвет», а не «серое окно», как обещают решение 2 и риск 2.
   Узко (только буквальный заголовок «Claude»; «New chat» сюда не попадает) и лечится первым ответом probe:
   сама страница-попап в карту ничего не пишет (`writeKeys` пуст), поэтому `absorb` этот ключ снесёт.
   Правки не требует; на живом гейте достаточно посмотреть глазами (это же место назвал хвостом батч B).
2. **Тумблер «🗂 Цвет по проекту» выключен — решение 3 не работает вовсе.** `ChatProbe.tick` выходит первой
   строкой (`ChatProbe.swift:223-226`), `takeThemes()` всегда nil, файл живёт одним зеркалом и чужие правки не
   догоняет. Возврат при этом работает. План этого случая не разбирает; батч B назвал сам. Не блокер.
3. **Половинки `size` зеркало склеивает по-другому.** Страница берёт основу из всей цепочки приоритетов
   (`storedLayer("size")`, `inject.js:1546`), зеркало — только из записи того же ключа
   (`WindowThemeStore.swift:400`). Файл может получить более бедный размер, чем карта страницы. Лечится `absorb`.
4. **Возврат в легаси-запись плодит второй ключ.** `runThemesRestoreCommand` читает текущую запись через
   `mapEntry` (`inject.js:1663`, а он понимает `w:`), а кладёт результат под присланный ключ `chat:`
   (`inject.js:1675`) — старый `w:` остаётся рядом. Безвредно (`mapEntry` читает `chat:` первым), но карта
   немного растёт. Уборку карты WF35 и не обещал.
5. **Тень `id:` над более полной `chat:` — подтверждаю как хвост, не как поломку.** `chatEntry`
   (`inject.js:1082`) фолбэка на `chat:` при непустой записи `id:` не делает по построению. В главном сценарии
   плана недостижимо: страница пишет оба ключа разом (`writeKeys`), а перед записью зовёт `migrateChatKey`.

Отклонения батчей проверил отдельно, обе законны:
- **TDZ**: цепочка источников id переведена в объявления функций (`inject.js:4025`, `:4028`, `:4705`, `:4723`),
  `const CHAT_ID_KEY` переехал в блок ключей хранилища (`:346`). Тела и имена не менялись; без этого `chatIdKey`
  на инжекте ловил бы TDZ и окно моргало бы серым.
- **`try/catch` в `chatIdKey`** (`inject.js:1006`) нужен из-за `tests/wf16-new-window.test.mjs:98`: набор
  исполняет срез исходника (строки 68–1158) в отдельном vm-контексте без раздела «12в», и `myChatId` там нет.
  Деградация на ключ по имени — то же поведение, что у адресации WF29.
- **Чужой файл** `app/Tests/ClaudeAXTests/ClaudeAXTests.swift:3263` — одна строка (`themes-restore` в `pageOnly`
  сторожа контракта). Файл в таблице батчей не закреплён ни за кем, а сторож без этой строки красный; в доке
  самого теста написано «Дополняет тот, кто добавляет команду». Претензии нет.
