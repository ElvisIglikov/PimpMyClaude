## Решения

### 1. Контракт команды `new-window` (расширение WF13, побайтно; страница и Swift обязаны совпадать)

```
{"id","action":"new-window","at","scope":"window","title":<AX-заголовок окна>,"x":<число>,"y":<число>,
 "text":<первое сообщение>,"folder":<абсолютный путь|"">,"name":<имя чата|"">,
 "theme":{…}|null?,"font":{…}|null?,"size":{…}|null?,"frame":true|null?}
```

- Порядок полей ровно такой. `folder` и `name` — всегда есть, пустая строка = «не трогать» (полная совместимость с
  поведением WF13). Слои — по правилам команды `theme`: поля нет → слой не трогаем, `null` → сброс.
- Swift пишет только через `ClaudeActions.newWindowFields(title:x:y:text:folder:name:theme:font:size:frame:)` +
  `commands.write(action:fields:)`; сериализация слоёв — та же, что в `themeFields`.
- `popout-window` не меняется вовсе.
- **Безопасность превыше удобства:** `folder` непустой, а выбрать папку не удалось → **сообщение не отправляем и чат не
  создаём** (статус `no-folder-ui` / `folder-missing`, плашка). Иначе агент с авто-Allow стартанул бы в чужом проекте.

### 2. Список проектов — Swift, чистая функция (новый `RecentProjects.swift`)

- Источник 1: скан `~/Library/Application Support/Claude/claude-code-sessions/*/*/local_*.json` → `cwd`,
  `max(lastFocusedAt, lastActivityAt, createdAt)`, `isArchived`. Группируем по `cwd`, сортируем по времени вниз.
- Источник 2 (дозаполнение): ключи `projects` из `~/.claude.json`. Источник 3: подпапки `projectsRoot`
  (`claude.json`, по умолчанию `~/_ElvisProjects`) — тот же путь, что у `StatusFeed`.
- Дедупликация по нормализованному пути, папки без существующего каталога отбрасываем, потолок — **8 пунктов**
  (вопрос 3), имя пункта = имя папки, полный путь — во всплывающей подсказке (`item.toolTip`).
- Если WF15 успел дать свой реестр проектов — список берётся из него, а этот скан остаётся запасным путём;
  сигнатура одна: `RecentProjects.list() -> [Project]`.
- Никаких записей: файлы Claude только читаем.

### 4. Имя чата вместо «Привет»

- Первое сообщение = **имя проекта** (`PimpMyClaude`), а не «Привет»: заголовок авто-сессии — это и есть текст первого
  сообщения (п. 2 разведки). Константа `MenuModel.newWindowText` остаётся только для «Здесь же» (папка не выбрана).
- **Сразу после создания чат переименовывается тем же именем** — переименование делает заголовок `titleSource:"user"`,
  и приложение больше не перепишет его своей сводкой (иначе цвет окна «съедет» вместе с заголовком). Не нашли, чем
  переименовать (П3) — деградируем молча: имя всё равно правильное, просто не замороженное.
- Имя уже занято среди недавних строк сайдбара → добавляем номер: `PimpMyClaude 2` (иначе два окна одного проекта
  делят ключ темы `chat:` и путают адресацию `cashout`/`workflow` по заголовку — риск, заведённый ещё в WF13).
- В первом сообщении **только имя проекта**: никаких команд, путей и просьб что-то запустить — в этой сессии работает
  авто-Allow (правило WF13).

### 5. Цвет и размер нового окна «сразу»

- Страница ДО `openPopout` пишет в `myclaude-themes-v1` запись `chat:<имя чата>` со слоями из команды и только потом
  открывает окно — попап рисуется уже покрашенным (механика п. 3 разведки). Новых команд и новых ключей нет.
- Откуда Swift берёт слои (вопрос 2): 1) настройки проекта из WF15; 2) нет их — как у окна, из которого нажали;
  3) не берём вовсе (окно как у Claude).
- Слои уходят в команду ровно так же, как в `theme`: чего нет — то не трогаем.

### 6. Страница (inject.js, врезка в раздел 12б) — порядок шагов

1. Разбор команды: `folder`, `name`, слои. Всё остальное — как в WF13 (адресация заголовком, `isMainWindow()`,
   токен запуска, `busy`, страховка, плашки).
2. Дождаться `/epitaxy` и пустого композера — без изменений.
3. **Новый шаг «папка»** (только если `folder` непустой): выбрать папку способом, который даст микро-разведка (стор или
   DOM-кнопка), затем **прочитать выбранное обратно** и сверить с `folder`. Не сошлось за 5 с → статус `no-folder-ui`
   (не нашли, чем выбирать) или `folder-missing` (папки нет в списке), плашка, **возврат главного окна на `prev`,
   сообщение не отправляем**.
4. Вставка текста и отправка — без изменений.
5. Ожидание `/epitaxy/local_<id>` и строки сайдбара — без изменений.
6. **Новый шаг «имя»** (только если `name` непустой): имя занято среди строк сайдбара → `name 2`; переименовать чат
   найденным способом; не вышло — статус `no-rename`, дальше идём (плашки нет: чат создан и назван правильно).
7. **Новый шаг «цвет»**: записать слои под `chat:<итоговое имя>` (существующие функции карты, без своего JSON).
8. `openPopout` с этим же заголовком → возврат главного окна — без изменений.
9. Новые статусы в `state.newWindow`: `no-folder-ui`, `folder-missing`, `no-rename`, поле `folder` и `name`.
   `VERSION` (inject.js:34) поднять на `wf16-a-1` — иначе на гейте не отличить, доехал ли файл.

### 7. Не делаем в WF16

Своё хранилище настроек проекта (это WF15); выбор модели/эффорта для нового окна; «Другая папка…» с системным диалогом
(вопрос 4); правку лоадера; правку `popout-window`; тему на папку в обход WF15; запись в файлы Claude.

## Открытые риски

- **Недоверенная папка.** Первый чат в папке, где Claude ещё не работал, поднимает окно доверия — цепочка встанет.
  Прикрыто тем, что список строится из папок с уже существующими сессиями; «Другая папка…» — только по ответу Элвиса,
  и с честной плашкой.
- **Механика выбора папки не проверена живьём** — снимается П1/П2 ДО кодинга. Не найдётся ни стора, ни кнопки — пункты
  проектов в меню не строим вовсе (список пуст), «Здесь же» остаётся как в WF13.
- **Авто-заголовок приложение переписывает само** — цвет окна привязан к заголовку и «съедет». Лечится переименованием
  (П3). Не нашли переименования — записываем как принятый хвост и заводим задачу.
- **Два окна одного проекта** делят ключ темы `chat:` и путают адресацию `cashout`/`workflow` по заголовку — лечится
  номером в имени (решение 4), полностью проблема снимается только вариантом «имя со временем».
- **Выбор папки в главном окне меняет «последнюю папку»** — следующий ручной ⌘N Элвиса откроется в ней. Ожидаемо, но
  сказать в README одной строкой.
- **Смена сборки claude.ai** — селекторы домашнего экрана и жест переименования могут уехать; все отказы видимые
  (плашка), окна не ломаем.
- **Пересечение по `inject.js` с WF15 и WF18** — три воркфлоу на один файл; очередь фиксируется run-файлами, параллель
  запрещена.
- **Формат файлов сессий Claude — не публичный контракт**: поля `cwd`/`title` могут исчезнуть в новой версии. Скан
  обязан пережить битый и чужой JSON и молча отдать пустой список — тогда меню просто без списка проектов.
