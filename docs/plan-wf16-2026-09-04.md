## Решения

### 1. Контракт команды `new-window` (расширение WF13, побайтно; страница и Swift обязаны совпадать)

```
{"id","action":"new-window","at","scope":"window","title":<AX-заголовок окна>,"x":<число>,"y":<число>,
 "text":<первое сообщение>,"folder":<абсолютный путь|"">,"name":<имя чата|"">,
 "theme":{…}|null?,"font":{…}|null?,"size":{…}|null?,"frame":true|null?}
```

- Порядок полей ровно такой. `folder` и `name` — всегда есть, пустая строка = «не трогать» (полная совместимость с
  поведением WF13). Слои — по правилам команды `theme`: поля нет → слой не трогаем, `null` → сброс.
- Swift пишет только через `ClaudeActions.newWindowFields(title:x:y:text:folder:name:theme:font:size:frame:)` +
  `commands.write(action:fields:)`; сериализация слоёв — та же, что в `themeFields`.
- `popout-window` не меняется вовсе.
- **Безопасность превыше удобства:** `folder` непустой, а выбрать папку не удалось → **сообщение не отправляем и чат не
  создаём** (статус `no-folder-ui` / `folder-missing`, плашка). Иначе агент с авто-Allow стартанул бы в чужом проекте.

### 2. Список проектов — чистая функция В СОСТАВЕ `ProjectIndex` из WF15 (правка по критику, Б2)

- **Своего сканера WF16 не заводит.** WF15 (батч S, идёт первым) уже читает
  `~/Library/Application Support/Claude/claude-code-sessions/*/*/local_*.json` в `ProjectIndex.swift`. WF16 добавляет
  туда **одну чистую функцию** `ProjectIndex.recentProjects(limit:) -> [Project]`. Двух источников правды об одном
  каталоге быть не должно (WF21 добавил бы третий).
- Что делает функция: группировка по `cwd`, время = `max(lastFocusedAt, lastActivityAt, createdAt)`, сортировка вниз,
  архивные (`isArchived`) — вон, дедупликация по нормализованному пути, отсев несуществующих каталогов,
  потолок — **8 пунктов** (вопрос 3).
- Дозаполнение, если сессий мало: ключи `projects` из `~/.claude.json`; затем подпапки `projectsRoot`
  (`claude.json`, по умолчанию `~/_ElvisProjects`) — тот же путь, что у `StatusFeed`.
- Имя пункта = имя папки, полный путь — во всплывающей подсказке (`item.toolTip`).
- Тест называется `testProjectIndexRecentSortsDedupesAndCaps`.
- **Отдельный `RecentProjects.swift` заводится только в одном случае:** WF15 по какой-то причине не слился — тогда
  файл создаётся с той же сигнатурой и это отмечается в run-файле. Соседям (WF21, WF23) точка входа объявляется
  одна: `ProjectIndex.recentProjects(limit:)` — **в плане WF23 стоит `RecentProjects.list()`, там поправить имя.**
- Никаких записей: файлы Claude только читаем; битый и чужой JSON — молча пустой список.

### 4. Имя чата вместо «Привет»

- Первое сообщение = **имя проекта** (`PimpMyClaude`), а не «Привет»: заголовок авто-сессии — это и есть текст первого
  сообщения (п. 2 разведки). Константа `MenuModel.newWindowText` остаётся только для «Здесь же» (папка не выбрана).
- **Сразу после создания чат переименовывается тем же именем** — переименование делает заголовок `titleSource:"user"`,
  и приложение больше не перепишет его своей сводкой (иначе цвет окна «съедет» вместе с заголовком). Не нашли, чем
  переименовать (П3) — деградируем молча: имя всё равно правильное, просто не замороженное.
- **Уникальность имени считает Swift, а не страница (правка по критику, В4).** Страница видела бы только хвост
  сайдбара, а на диске лежат все сессии: через несколько дней у проекта наберётся несколько чатов с одинаковым
  `title`, и сработает правило WF15 (решение 2, п. 2) «заголовок встречается в индексе дважды — **папку не
  определяем**» — то есть WF16 своими руками сломал бы определение папки в WF15. Поэтому Swift проходит по тому же
  индексу сессий, который уже читает (**все** `title`, не только сайдбар), и кладёт в поле `name` **готовое
  уникальное имя** (`PimpMyClaude`, занято → `PimpMyClaude 2`, `PimpMyClaude 3`…). Страница номер не придумывает и
  сайдбар на совпадения не проверяет.
  Зачем вообще: два окна с одним заголовком делят ключ темы `chat:` и путают адресацию `cashout`/`workflow`
  по заголовку — риск, заведённый ещё в WF13.
  Если Элвис ответит на вопрос 5 «2 — имя со временем», эта правка не нужна: такое имя уникально само.
- В первом сообщении **только имя проекта**: никаких команд, путей и просьб что-то запустить — в этой сессии работает
  авто-Allow (правило WF13).
- **Проверить на гейте (правка по критику, М5):** WF13 слал инертное «Привет», а «PimpMyClaude» в папке
  PimpMyClaude уже похоже на задание, и агент с авто-Allow может сам полезть читать репозиторий. Ущерба нет
  (чтение), но чат откроется не пустым. Начинает работать по одному имени — **возвращаем текст «Привет»** и
  опираемся на переименование (П3): имя чата от этого не пострадает.

### 5. Цвет и размер нового окна «сразу»

- Страница ДО `openPopout` пишет в `myclaude-themes-v1` запись `chat:<имя чата>` со слоями из команды и только потом
  открывает окно — попап рисуется уже покрашенным (механика п. 3 разведки). Новых команд и новых ключей нет.
- **Пишем только запись нового чата и ничего больше (правка по критику, Б3).** Команду исполняет главное окно, и
  «очевидная» функция `writeLayers()` записала бы слои по `writeKeys()` — это `chat:<текущий чат>` **и `main`**,
  плюс `storeSessionLayers()` в sessionStorage: один клик по «Новое окно ▸ Dictatorik» перекрасил бы главное окно
  Элвиса и его сессию в чужой цвет. Разрешена ровно тройка `readThemeMap` → `setMapLayers` → `writeThemeMap`
  (побайтно — в решении 6, шаг 8).
- Откуда Swift берёт слои (вопрос 2): 1) настройки проекта из WF15; 2) нет их — как у окна, из которого нажали;
  3) не берём вовсе (окно как у Claude). **Вариант «2 — всегда как у текущего окна» после WF15 даст мигание**
  (правка по критику, В6): окно откроется в цвете исходного, а через 2–3 с `ProjectPaint` перекрасит его в цвет
  проекта — ровно та вспышка, ради которой пункт и затевался. Оговорка вписана в вопрос 2 и в макет.
