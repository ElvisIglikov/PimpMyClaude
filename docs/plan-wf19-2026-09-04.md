## Что выяснено по коду (04.09, только чтение; агенту заново не лезть)

1. **Размер — единственный слой с половинками.** Команда `theme` несёт `size:{answer?,question?}|null`; страница
   (`claude-patch/inject.js:1249`) дописывает недостающую половину из базы: у примерки база — экран (`themeState.size`),
   у закрепления — хранилище (`storedLayer("size")`, `inject.js:1087`, цепочка чат → сессия → main → «всем»).
   Поэтому «поставить 16 ответам» вторую половину не теряет.
2. **Снять половину нечем.** `normalizeSize` (`inject.js:709`) выбрасывает всё, что не число 11…24, и пустой объект
   возвращает как `null` — то есть `{"answer":null}` сегодня читается как «сбросить слой целиком». Пункт «Как у Claude»
   в `MinimizeMenu.sizeList` (`MinimizeMenu.swift:457`) шлёт `size:.reset` → `"size":null` и снимает обе половины;
   комментарий там честно это и признаёт («перефилдового null контракт не знает»).
3. **Хранение половин в Swift.** `struct Size` (`FontCatalog.swift:39`) — две необязательные половины, `merging` склеивает
   слой поверх запомненного, `commandValue` пишет только заданные (`answer` первым). `ThemeStore` держит `sizeByWindow`/
   `sizeAll` словарями (`ThemeCatalog.swift:187…218`), `ClaudeActions.remember` (`:339`) на `.reset` кладёт `nil` —
   и стирает ОБЕ половины. `CommandValue` умеет `.null` (`CommandChannel.swift:16`) — `{"answer":null}` выразим.
4. **Запись на странице.** `entryLayer` (`inject.js:834`) прогоняет хранимую запись через тот же `normalizeSize`, поэтому
   половина со значением `null` в localStorage читается как «слоя нет»: в карту такие ключи класть нельзя — только
   вычищенный объект либо маркер `"none"` (`setMapLayers`, `inject.js:1107`).
5. **«🎲 Случайно» всегда тёмное после автопокраски — арифметика, не случайность.** `paint` (`ClaudeActions.swift:491`):
   `light = preset.light ?? repeated ?? prefersLightWindows()`. У «Случайно» `preset.light == nil`, `repeated` есть только
   у «Ещё раз», а `prefersLightWindows()` (`:539`) считает галки тем окон — и покраска сама же их снимает
   (`themeStore.setWindowTheme(nil, …)`, `:501`). Пустой список даёт `0 > 0 == false` → тёмное. Второе и третье
   «Случайно» — тоже тёмное, пока Элвис руками не выберет светлые темы.
6. **«🔁 Ещё раз» повторяет гармонию нарочно.** `autoPaintAgain` (`:461`) передаёт `repeating: last?.scheme` в
   `AutoPaint.schemeIndex` (`AutoPaint.swift:153`), режим тоже из памяти (`AutoPaintStore`, `:389`). Так решал план WF10 п. 5
   («тот же набор, повёрнутый на +37°»); Элвису это читается как «ничего не изменилось».
7. **Случайность не инъектируется.** `autoPaint` (`:452`) зовёт `Int.random` прямо в теле, `schemeIndex` умеет принимать
   `pick`, но никто его не передаёт — тест на новое поведение будет флаки, пока в `ClaudeActions` не появится шов.
8. **Перепатча не будет.** Лоадер v6 рассылает `command.json` во все страницы без белого списка полей
   (`patch-claude.mjs:203`, `Loader.swift:79`) — расширение поля `size` доедет как есть; живой `inject.js` берётся по mtime.
   `VERSION` в `inject.js:36` сейчас `"wf13-a-1"` (WF14 в inject.js не пишет вовсе).
9. **Тесты по теме:** `testSizeAndFramePayloadMatchContract` (побайтно, `ClaudeAXTests.swift:377`),
   `testMenuHasSizeSubmenusWithChecksAndPreview` (`:657`), `testAutoPaintRemembersPresetStartAndScheme` (`:1377` — прямо
   утверждает, что «Ещё раз» повторяет гармонию и режим), `testAutoPaintMenuHasPresetsRandomAgainAndReset` (`:1427`),
   `testThemeStoreRemembersSizeAndFrame` (`:809`). Счёт тестов сейчас 51 + сколько добавит WF14 — фактическое число
   взять после слияния, в план не зашивать.

## Решения

### 1. Контракт `size` — половина снимается явным `null` (побайтно, страница и Swift)

```
"size": {"answer": 16, "question": null}
```

- Поля половины **нет** — половину не трогаем (как сейчас); число 11…24 — поставить; **`null` — снять именно эту половину**.
- `"size": null` (слой целиком) остаётся как был: снимает обе. Его шлёт «🧹 Всё как у Claude» из WF14.
- Порядок ключей внутри объекта прежний: `answer`, затем `question`.
- Мусор (строка, 0, 99) = поля нет (нынешнее поведение). Если после разбора не осталось ни одного значимого ключа —
  слой равен `null`, полный сброс (совместимость со старым `{}`).
- Деградация: страница старой версии прочитает `{"answer":null}` как полный сброс — то есть ровно как сегодня; поэтому
  на гейте `cp inject.js` идёт ДО подмены приложения.

**Страница (`inject.js`, раздел 2а, батч A-js):**
`normalizeSize` возвращает три состояния половины (нет ключа / `null` / число); в `runThemeCommand` (`:1249`) после слияния
с базой ключи со значением `null` **удаляются**, и если объект опустел — слой становится `null` (полный сброс:
`removeSize`, запись `"none"`/удаление по нынешним правилам `setMapLayers`). В localStorage и в sessionStorage половина
со значением `null` не пишется никогда. `applySize`/`sizeCss` не трогаем — они и так рисуют только заданные половины.
`VERSION` → `"wf19-a-1"`.

**Swift (батч A-swift):** `Size` (хранилище) не менять. Ввести слой команды с тремя состояниями у каждой половины —
`struct SizeLayer { var answer: Layer<Int> = .keep; var question: Layer<Int> = .keep }` (рекомендуемая форма; имя и место
на усмотрение батча, но `Size` остаётся типом ХРАНЕНИЯ, чтобы не тянуть тристейт в `MyThemes` и `ThemeStore`).
Затрагиваются: `ClaudeActions.themeFields` (`:291`, ветка `size`), `applyTheme`, `remember` (`:339`: на снятой половине
писать `Size` без неё, обе сняты → `nil`), `previewSize` (`:407`), `MenuConfig.apply`/`previewSize`
(`MinimizeMenu.swift:265,272`) и обе точки вызова (`:153`, `:178`), `sizeList` (`:440`).
Своя тема (`apply(myTheme:)`) и «всем окнам» переводятся адаптером `SizeLayer(size:)` — обе половины `.set`/`.keep`.

### 2. Пункт «Как у Claude» в списках размера

«Размер ответов ▸ → Как у Claude» шлёт `size:{"answer":null}`, «Размер вопросов ▸» — `{"question":null}`.
Примерка по наведению — та же команда с `preview:true` (база примерки — экран, вторая половина остаётся видимой).
Галка — по своей половине (см. «Что уже делает WF14»).

### 3. «🎲 Случайно» — режим больше не залипает на тёмном

Режим берётся **противоположным прошлой автопокраске** (`AutoPaintStore.last.light`), памяти нет — монетка
(шов `randomBool`). «Ещё раз» режим не меняет (память), наборы со своим режимом (Радуга, Пастель…) — как были.
`prefersLightWindows()` после этого никто не зовёт — удалить вместе с тестами на него, если такие есть.

### 4. «🔁 Ещё раз» после «Случайно» — новая гармония

`autoPaintAgain` для набора с `picksScheme` (только «Случайно») выбирает гармонию заново (`repeating: nil`), режим и
набор берёт из памяти, старт по-прежнему +37°. Для остальных наборов не меняется ничего.
`testAutoPaintRemembersPresetStartAndScheme` переписать (сейчас он утверждает обратное), добавить
`testAutoPaintAgainRerollsRandomScheme` и `testAutoPaintRandomAlternatesLightMode` — оба через шов случайности,
без `Int.random` в тесте.

### 5. Шов случайности

В `ClaudeActions` — два свойства с умолчанием (`var randomInt: (Int) -> Int = { Int.random(in: 0..<$0) }`,
`var randomBool: () -> Bool = { Bool.random() }`), через них идут старт, индекс гармонии и монетка режима.
Ничего кроме тестов их не подменяет.

### 6. Не делаем в WF19

Не трогаем: лоадер, `themes.json`, структуру меню WF14, живой `claude.css`/`LiveStyle`, «Всё как у Claude»,
хранение размеров в `MyThemes`, полоску прогресса, StatusFeed. Новых пунктов меню не добавляем.
Остальные хвосты AGENTS.md (живой «Снять → Поставить», обновления Claude, StatusFeed 9+ проектов, Lua-модули,
скретч-тесты) — другие воркфлоу, здесь их нет.

## Открытые риски

- **Старт до слияния WF14** = два писателя на пяти файлах. Проверять `git log main` и run-файл WF14 (`финиш`) до тега.

  деградация безопасная, но `cp inject.js` обязан идти до подмены приложения; при откате наоборот.

- **Живая проверка (е)/(ж)** требует 2–3 окон Claude на экране и 600 мс на окно — считать по `status()` окон, а не на глаз.
- **Если батч B WF14 переписал `sizeList` иначе** (например, размеры уехали в «Оформление ▸» отдельными пунктами),
  адреса из «Что выяснено» съедут — A-swift обязан перечитать `MinimizeMenu.swift` перед правкой, а не идти по номерам строк.
