## Что выяснено по коду (04.09, только чтение; агенту заново не лезть)

1. **Размер — единственный слой с половинками.** Команда `theme` несёт `size:{answer?,question?}|null`; страница
   (`claude-patch/inject.js:1249`) дописывает недостающую половину из базы: у примерки база — экран (`themeState.size`),
   у закрепления — хранилище (`storedLayer("size")`, `inject.js:1087`, цепочка чат → сессия → main → «всем»).
   Поэтому «поставить 16 ответам» вторую половину не теряет.
2. **Снять половину нечем.** `normalizeSize` (`inject.js:709`) выбрасывает всё, что не число 11…24, и пустой объект
   возвращает как `null` — то есть `{"answer":null}` сегодня читается как «сбросить слой целиком». Пункт «Как у Claude»
   в `MinimizeMenu.sizeList` (`MinimizeMenu.swift:457`) шлёт `size:.reset` → `"size":null` и снимает обе половины;
   комментарий там честно это и признаёт («перефилдового null контракт не знает»).
3. **Хранение половин в Swift.** `struct Size` (`FontCatalog.swift:39`) — две необязательные половины, `merging` склеивает
   слой поверх запомненного, `commandValue` пишет только заданные (`answer` первым). `ThemeStore` держит `sizeByWindow`/
   `sizeAll` словарями (`ThemeCatalog.swift:187…218`), `ClaudeActions.remember` (`:339`) на `.reset` кладёт `nil` —
   и стирает ОБЕ половины. `CommandValue` умеет `.null` (`CommandChannel.swift:16`) — `{"answer":null}` выразим.
4. **Запись на странице.** `entryLayer` (`inject.js:834`) прогоняет хранимую запись через тот же `normalizeSize`, поэтому
   половина со значением `null` в localStorage читается как «слоя нет»: в карту такие ключи класть нельзя — только
   вычищенный объект либо маркер `"none"` (`setMapLayers`, `inject.js:1107`).
5. **«🎲 Случайно» всегда тёмное после автопокраски — арифметика, не случайность.** `paint` (`ClaudeActions.swift:491`):
   `light = preset.light ?? repeated ?? prefersLightWindows()`. У «Случайно» `preset.light == nil`, `repeated` есть только
   у «Ещё раз», а `prefersLightWindows()` (`:539`) считает галки тем окон — и покраска сама же их снимает
   (`themeStore.setWindowTheme(nil, …)`, `:501`). Пустой список даёт `0 > 0 == false` → тёмное. Второе и третье
   «Случайно» — тоже тёмное, пока Элвис руками не выберет светлые темы.
6. **«🔁 Ещё раз» повторяет гармонию нарочно.** `autoPaintAgain` (`:461`) передаёт `repeating: last?.scheme` в
   `AutoPaint.schemeIndex` (`AutoPaint.swift:153`), режим тоже из памяти (`AutoPaintStore`, `:389`). Так решал план WF10 п. 5
   («тот же набор, повёрнутый на +37°»); Элвису это читается как «ничего не изменилось».
7. **Случайность не инъектируется, а `ClaudeActions` не тестируется вовсе (Б3).** `autoPaint` (`:452`) зовёт `Int.random`
   прямо в теле; `schemeIndex` умеет принимать `pick`, но никто его не передаёт. При этом ни один тест не создаёт
   `ClaudeActions` — в `ClaudeAXTests.swift` нет ни одного `ClaudeActions(`, а инициализатор требует живые `ClaudeApp`
   и `CommandChannel`. Значит шов обязан жить чистыми статиками в `AutoPaint`, иначе тестов на новое поведение
   не написать вовсе (см. решение 5).
8. **Перепатча не будет — подтверждено критиком по коду.** Лоадер v6 рассылает `JSON.stringify(cmd)` целиком, без белого
   списка полей (`patch-claude.mjs:203`, `Loader.swift:79` — обе копии совпадают), живой `inject.js` перечитывается по mtime
   (`fs.watchFile(injectPath,{interval:1000})`) — расширение поля `size` доедет как есть. Единственное требование —
   порядок доставки на гейте: `cp inject.js` ДО подмены приложения. `VERSION` в `inject.js:37` сейчас `"wf13-a-2"`
   (М1: не `-a-1`; к старту WF19 там будет метка WF16/WF18 — поднимать до `"wf19-a-1"`, каким бы он ни был).
9. **Тесты по теме:** `testSizeAndFramePayloadMatchContract` (побайтно, `ClaudeAXTests.swift:377`),
   `testMenuHasSizeSubmenusWithChecksAndPreview` (`:657`), `testAutoPaintRemembersPresetStartAndScheme` (`:1377` — прямо
   утверждает, что «Ещё раз» повторяет гармонию и режим), `testAutoPaintMenuHasPresetsRandomAgainAndReset` (`:1427`),
   `testThemeStoreRemembersSizeAndFrame` (`:809`). Счёт тестов сейчас 51 + сколько добавят WF14…WF18 — фактическое число
   взять после слияния, в план не зашивать.
10. **`normalizeSize` — общая функция команды И хранилища (В1).** Она стоит в карте `LAYER_NORMALIZE` (`inject.js:818`),
    которую зовёт `entryLayer` (`:838`) при каждом чтении записи карты и при проверке `entryLayer(all, layer)`
    в `setMapLayers` (`:1113`). Тристейт, вкрученный прямо в `normalizeSize`, потечёт в чтение записей — поэтому
    трогать её нельзя (см. решение 1, страница).
11. **Слой размера наследуется целиком, а не по половинам (М5, для verify — чтобы не завёл ложный баг).** `storedLayer`
    останавливается на первом уровне, где слой определён; поэтому снятие последней своей половины не роняет окно обратно
    на запись «всем окнам» — сегодня оно на неё и так не падало.
12. **`sendPreview` (`ClaudeActions:429`, на ветке `wf14` уже `:433`) тоже принимает `Layer<Size>`** — его в списке
    затрагиваемых мест забыли (М3).

## Решения

### 1. Контракт `size` — половина снимается явным `null` (побайтно, страница и Swift)

```
"size": {"answer": 16, "question": null}
```

- Поля половины **нет** — половину не трогаем (как сейчас); число 11…24 — поставить; **`null` — снять именно эту половину**.
- `"size": null` (слой целиком) остаётся как был: снимает обе. Его шлёт «🧹 Всё как у Claude» из WF14.
- Порядок ключей внутри объекта прежний: `answer`, затем `question`.
- **Дискриминатор «снять» строгий (правка В2):** снятие — это ровно `"answer" in value && value.answer === null`
  (и так же для `question`). Всё остальное идёт через `sizePx` (`inject.js:705`): число 11…24 — поставить, иначе поля нет.
  Иначе `{"answer":"abc"}` прочитается как снятие: сегодня мусор и `null` неразличимы, `sizePx(null)` даёт 0.
- Мусор (строка, 0, 99) = поля нет (нынешнее поведение). Если после разбора не осталось ни одного значимого ключа —
  слой равен `null`, полный сброс (совместимость со старым `{}`).
- Деградация: страница старой версии прочитает `{"answer":null}` как полный сброс — то есть ровно как сегодня; поэтому
  на гейте `cp inject.js` идёт ДО подмены приложения.
- Для verify: слой размера наследуется целиком, а не по половинам («Что выяснено», п. 11) — снятие последней своей
  половины не роняет окно на запись «всем окнам», это не баг.

**Страница (`inject.js`, раздел 2а, батч A-js) — правка В1:**
`normalizeSize` и карту `LAYER_NORMALIZE` **не трогать вовсе**: их же зовёт `entryLayer` при каждом чтении записи карты,
и тристейт потечёт в чтение хранилища. Вместо этого в `runThemeCommand` (`:1241`) — особый случай для размера:
`layers.size = normalizeSizeCommand(detail.size)` (новая функция, разбирает три состояния половины по строгому
дискриминатору В2). Чистка нулей — **ровно в одном месте**: сразу после слияния с базой и ДО `applyLayers`, `writeLayers`,
`storeSessionLayers` и `themeState.pending`. Ключи со значением `null` там удаляются; если объект опустел — слой
становится `null` (полный сброс: запись `"none"`/удаление по нынешним правилам `setMapLayers`). В localStorage и в
sessionStorage половина со значением `null` не пишется никогда. `applySize`/`sizeCss` не трогаем — они и так рисуют
только заданные половины. `VERSION` → `"wf19-a-1"`.

**Swift (батч A-swift) — правка Б1 (блокер):** `Size` (хранилище) не менять. Форма слоя команды —
**`enum SizeLayer { case keep; case reset; case halves(answer: Layer<Int>, question: Layer<Int>) }`**, а НЕ структура
из двух `Layer<Int>`: пара половин `{answer:null,question:null}` — это другие байты, а «🧹 Всё как у Claude» (WF14)
зовёт `config.apply(scope, .reset, .reset, .reset, .reset)`, и `testSizeAndFramePayloadMatchContract` (`:409`) требует
байт в байт `,"size":null}`. В `themeFields` (`:291`, ветка `size`): `.keep` → поля нет; `.reset` → `.null`;
`.halves` → объект (`answer` первым, половина `.keep` не пишется, `.reset` пишется как `null`), а если у `.halves`
обе половины `.keep` — поля `size` нет вовсе (это замена нынешней проверке `if case .set(let value) = size, value.isEmpty {}`).
`Size` остаётся типом ХРАНЕНИЯ, чтобы не тянуть тристейт в `MyThemes` и `ThemeStore`.
Затрагиваются: `themeFields`, `applyTheme`, `remember` (`:339`), `previewSize` (`:407`), `sendPreview` (`:429`, М3),
`MenuConfig.apply`/`previewSize` (`MinimizeMenu.swift:265,272`) и обе точки вызова (`:153`, `:178`), `sizeList` (`:440`).
Своя тема (`apply(myTheme:)`) и «всем окнам» переводятся адаптером `SizeLayer(size:)` — обе половины `.set`/`.keep`.

**`remember`, ветка окна (`:367`) — правка В4:** база слияния должна быть `themeStore.windowSize(title:) ?? themeStore.allSize
?? Size()`. Страница мержит по `storedLayer` (цепочка чат → сессия → main → «всем») и материализует унаследованную половину
в запись окна; Swift сегодня мержит поверх одной только `windowSize(title:)` — на снятии половины у наследующего окна
галки разъедутся с экраном. Ветку «всем окнам» не менять. На снятой половине пишем `Size` без неё, обе сняты → `nil`.

**`lastAppliedSize` (`:377`) — правка В5:** сейчас он только мержит новое поверх старого. Снятую половину надо из него
убирать, иначе «💾 Сохранить как мою тему…» запишет кегль, которого на экране уже нет.

### 2. Пункт «Как у Claude» в списках размера

«Размер ответов ▸ → Как у Claude» шлёт `size:{"answer":null}`, «Размер вопросов ▸» — `{"question":null}`.

Галка — по своей половине (см. «Что уже делает WF14»).

### 3. «🎲 Случайно» — режим больше не залипает на тёмном

Режим берётся **противоположным прошлой автопокраске** (`AutoPaintStore.last.light`), памяти нет — монетка
(`AutoPaint.nextLight(last:coin:)`, решение 5). «Ещё раз» режим не меняет (память), наборы со своим режимом
(Радуга, Пастель…) — как были.
`prefersLightWindows()` после этого никто не зовёт — удалить вместе с тестами на него, если такие есть.

### 4. «🔁 Ещё раз» после «Случайно» — новая гармония

`autoPaintAgain` для набора с `picksScheme` (только «Случайно») выбирает гармонию заново, режим и набор берёт из памяти,
старт по-прежнему +37°. Для остальных наборов не меняется ничего.
**Правка В3: не `repeating: nil`, а `avoiding: last?.scheme`** — гармоний всего четыре, и «случайный выбор из четырёх»
в четверти случаев вернул бы ту же самую: Элвис снова увидел бы «ничего не изменилось», а живая проверка (ж) стала бы флаки.
Выбор идёт из трёх оставшихся.
Тесты — поимённо под таблицей батчей (правка В7).

### 5. Шов случайности — статиками в `AutoPaint` (правка Б3, блокер)

Свойств `randomInt`/`randomBool` на `ClaudeActions` **не заводить**: класс нечем создать в тестах (нет ни одного
`ClaudeActions(` в `ClaudeAXTests.swift`, инициализатор требует живые `ClaudeApp` и `CommandChannel`) — заявленные тесты
в такой форме просто не напишутся. Обе решалки — чистыми статиками в `AutoPaint.swift`, рядом со `schemeIndex` (`:153`):

```swift
static func nextLight(last: Bool?, coin: () -> Bool = { Bool.random() }) -> Bool { last.map { !$0 } ?? coin() }
static func schemeIndex(for preset: AutoPaintPreset, repeating: Int? = nil, avoiding: Int? = nil,
                        pick: (Int) -> Int = { Int.random(in: 0..<$0) }) -> Int?
```

`autoPaint`/`autoPaintAgain` их только зовут; тесты бьют по статикам и подменяют `coin`/`pick` — без `Int.random`
в самом тесте.

### 6. Не делаем в WF19

Не трогаем: лоадер, `themes.json`, структуру меню WF14, живой `claude.css`/`LiveStyle`, «Всё как у Claude»,
хранение размеров в `MyThemes`, полоску прогресса, StatusFeed. Новых пунктов меню не добавляем.
Остальные хвосты AGENTS.md (живой «Снять → Поставить», обновления Claude, StatusFeed 9+ проектов, Lua-модули,
скретч-тесты) — другие воркфлоу, здесь их нет.

### [блокер]

**Б1. `SizeLayer` из двух `Layer<Int>` не умеет сказать `"size":null`.** «🧹 Всё как у Claude» (WF14) зовёт

*Правка решения 1:* `enum SizeLayer { case keep; case reset; case halves(answer: Layer<Int>, question: Layer<Int>) }`.
В `themeFields`: `.keep` → поля нет; `.reset` → `.null`; `.halves` → объект (`answer` первым; половина `.keep` не пишется,
`.reset` пишется как `null`); у `.halves`, где обе половины `.keep`, поля нет вовсе — это замена нынешней проверке
