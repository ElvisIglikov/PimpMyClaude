## Диагноз (снято живьём 20.09 ~21:20)

**Расстановка.** `ClaudeActions.arrange(mode:)` и `arrange(ids:mode:)` сгоняют ВСЕ окна на один экран
(`Screens.usableFrame(holding:)` — где центров больше) и перекладывают всех заново; автоматические пути (⌥⌘A,
«▦ Расставить», новое окно `PimpChannel.row`, CLI `arrange --layout last`) берут последнюю ПЛИТКУ
(`ThemeStore.arrangeMode`, у Элвиса сейчас `4`): окон больше ёмкости — хвост «болтается», окон меньше — окна встают
в четверть ширины с дырой справа; лента (`row`) на Odyssey режет до 10 столбцов (3008/280). Экраны Элвиса:
MacBook 1280×832 (рабочая 1205×802), Odyssey G91SD 3008×846 НАД ним (в перевёрнутых координатах y = −846…0).

**Зазор.** Сейчас окна Элвиса стоят в шестых долях Odyssey (ячейка 501): рамки x = −792/−290/210, ширина 495–497,
верх −842, высота 838. То есть от края экрана ≈4, между окнами ≈5. Наша сетка ставит окна встык.

**Проект окна.** Оба попапа называются «Ожидание задачи» (Элвис открывает каждый чат одной фразой — одинаковые
заголовки у него НОРМА). Попап узнаёт свой чат, спрашивая главное окно ПО ЗАГОЛОВКУ (`popoutChat`, раздел 12в
`inject.js`), ответ кэшируется в `sessionStorage`. В `probe-result.json` оба попапа назвали один чат
`local_abe07c3d…`, хотя React-волокно второго попапа держит `sessionId = local_a4c290f1…` (проба 20.09: у любого
узла попапа вверх по `fiber.return` есть пропс `sessionId`). Вторая половина беды — Swift: `ChatProbe.chat(forTitle:)`
берёт ПЕРВУЮ страницу с таким заголовком, и даже при верных ответах страниц два одноимённых окна получили бы один чат.
У страницы есть и рамка окна: `screenX/screenY/outerWidth/outerHeight` попапа совпали с рамкой Quartz точка в точку.

## Решения

1. **Умная расстановка — для всех автоматических путей**: ⌥⌘A, «▦ Расставить», новое окно (место `right` и
   умолчание), CLI/голос `arrange` с `layout: last`. Плитки «4», «5», «5×2» и «как сейчас» остаются явным разовым
   выбором рукой (и явным `--layout 4|5|5x2|row` в CLI). `ThemeStore.arrangeMode` продолжает помнить плитку — для
   подсветки в меню и для «💾 Сохранить раскладку»; автоматические пути его больше не читают.
2. **По экранам**: окна делятся по экрану, где лежит центр рамки (нет такого — экран с меню-баром); каждая группа
   расставляется на СВОЁМ экране. Окна между экранами не переезжают.
3. **Сетка экрана**: столбцы во всю высоту; потолок столбцов `cap = min(6, floor(ширина / minWindowWidth))`, не меньше
   1 (Odyssey — 6; MacBook при нынешних 280 — 4: пять столбцов по 241 Electron не сделает; Элвису сказать, что 5
   получится, если опустить `minWindowWidth` до 240). Окон `n ≤ cap` — один ряд; больше — рядов `r = ceil(n / cap)`.
   Кандидаты числа столбцов `k`: от `ceil(n / r)` до `cap`.
4. **Кто стоит на месте**: окно «сидит» в ячейке кандидата, если все четыре стороны рамки совпали с ячейкой (с
   учётом зазора) в пределах допуска 8 pt. Выбор `k`: у кого больше сидящих; `k > ceil(n/r)` берём только когда
   сидящих не меньше половины окон группы (одно случайно совпавшее окно сетку не диктует); ничья и «никто не сидит»
   — наименьший `k` (окна делят весь экран поровну). Сидящие не двигаются ВОВСЕ (даже на свои 1–2 pt); остальные
   по порядку `ArrangeLayout.order` занимают свободные ячейки слева направо, сверху вниз.
5. **Главное окно** — рядовое окно в общем ряду, особых правил нет (их и сейчас нет; в тест — закрепить).
6. **Новое окно слева / посередине** — порядок НАВЯЗАН: сетка выбирается тем же правилом, но окна кладутся по
   заданному порядку (сдвигаются все, кому надо). «Справа» и умолчание — новое окно просто «неприкаянное» и
   занимает свободную ячейку.
7. **Зазор**: ключ `windowGap` в живом `claude.json` (целое, pt; нет ключа или мусор — 5; зажим 0…40). Рабочая область
   экрана сжимается на `gap/2` с каждой стороны, каждая ячейка — ещё на `gap/2`: от края экрана и между окнами выходит
   ровно `gap`. Зазор живёт ВНУТРИ `ArrangeLayout.frames(…, gap:)` (умолчание параметра 0 — старые тесты и эталоны не
   двигаются), живьём его подставляют так же, как `cellWidth()`; поэтому плитки, `arrangeCells` и `LayoutsStore`
   (сверка ячейки по рамке, допуск 2 pt) остаются согласованными. `Patcher.ensureConfig` для ЧИСТОЙ установки дописывает
   `windowGap: 5`; готовые файлы не трогает (у команды сработает умолчание кода). Пункта меню нет — правка файла; пункт
   меню — отдельной задачей после макета, если Элвис попросит.
8. **Ответ канала**: у умной расстановки поле `layout` в ответе — `"row"` (эталоны `tests/fixtures/pimp/*` и тексты
   CLI не меняются). `windows` — все окна группы с итоговыми рамками (и сидящие тоже), `skipped` — 0.
9. **Окно знает свой чат** (страница): попап сперва читает `sessionId` из своего React-волокна (обход от узлов
   `.epitaxy-titlebar`/`.epitaxy-chat-panel` вверх по `return`, предел глубины, строка `local_…`); кэш
   `sessionStorage` годен, только если не спорит с волокном; вопрос родителю по заголовку остаётся запасным путём,
   когда волокно молчит. Значение `store` у такого ответа — `"ok"` (набор значений контракта не расширяем).
10. **Рамка в ответе probe**: в ХВОСТ ответа `chats()` (после `at`, перед необязательным `themes`) дописывается
    `frame: [screenX, screenY, outerWidth, outerHeight]` — у всех «наших» страниц. Контракт выше остаётся побайтно
    прежним; старое приложение поле игнорирует, новое приложение без поля работает по-старому.
11. **Swift: окно → чат по рамке**: `ChatPage` получает `frame: CGRect?`; `ChatProbe.chat(forTitle:frame:)`: страница с
    таким заголовком одна — она; несколько — та, чья рамка совпала с рамкой окна (допуск 8 pt по всем сторонам);
    несколько и ни одна не совпала (или рамки не прислали) — `nil`: «лучше не покрасить, чем покрасить чужим».
    Все места, где окно опознаётся заголовком (`ProjectPaint.writableFolder/target/windowKey` и цикл покраски,
    `ClaudeActions.cashoutRoute` ×3, `ClaudeAXController` ~365–390, `PimpChannel` поле `chat` у окон), получают рамку
    окна рядом с заголовком. Сигнатуры замыканий `chatForTitle` меняются на `(String, CGRect?) -> String?`.
12. **Чужие настройки не лечим**: тема, уже записанная не в тот проект, остаётся как есть — после выкладки Элвис
    выбирает цвет заново в каждом окне. Лоадер НЕ трогаем.

## Риски

- Electron зажимает ширину окна минимумом — «сидит ли окно» сверяем с допуском 8 pt, а не 2.
- Волокно React — чужая внутренность: имя пропса `sessionId` может смениться с релизом Claude; тогда попап падает на
  прежний путь по заголовку (не хуже, чем сейчас), а Swift при одноимённых окнах отвечает `nil`, а не чужим чатом.
- `screenX/screenY` у страницы — в тех же перевёрнутых глобальных координатах, что AX (проверено на Odyssey над
  MacBook); на втором масштабе экрана сверить на гейте.
- «💾 Сохранить раскладку» после умной расстановки с `k > n` (окна в шестых долях, окон три) сверяет рамки с сеткой
  запомненной плитки и может ответить `not-arranged` — известное ограничение, в DECISIONS; чинить отдельной задачей.
