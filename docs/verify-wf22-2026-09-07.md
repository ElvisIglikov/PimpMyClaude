## Находки

### 1. Важно · бейдж карточки не называет этап (буква Элвиса 22:50)
`claude-patch/inject.js:2576`. Сейчас `progressCardPill.textContent = "💭 идёт"`. План, раздел «Буквы
Элвиса»: «бейдж состояния называет этап — идёт план / идёт критик / идёт кодинг / идёт проверка
(готов — «готов ✅», ждёт — «ждёт тебя»)».
Правка: у `word === "идёт"` дописывать `stages.rows[stages.now]?.label`, у `"ждёт"` — «ждёт тебя».
Данные уже посчитаны рядом (`stages` в `progressTipShow`), правка на одну строку.

### 2. Важно · карточка растёт во всю ширину широкого окна (буква Элвиса 22:50)
`claude-patch/inject.js:2598` (`width: Math.max(120, innerWidth - 12)`, потолка нет) и `:2629`
(`left` жёстко `"6px"`). Буква: «в широком окне карточка не растёт — потолок ширины как у узкого окна
(≈ 400 px), прижата к левому краю поля».
Проверено живьём: окно 1600 px → карточка 1588 px; окно 367 px → 355 px (это верно).
Правка: `Math.max(120, Math.min(400, innerWidth - 12))` и `left = Math.max(6, Math.min(progressState.box.left, innerWidth - width - 6))`.
Тест `progress-card.test.mjs:176` пинит только узкое окно (355 px) — правке не мешает.

### 3. Важно · пустой контур ловит мышь и глотает клик
`claude-patch/inject.js:2712` (`reason` «пустой контур», `progressState.box` теперь выставляется и без
строки состояния) → `progressHit` (`:2794`) отвечает «да» → `onProgressMove` ставит курсор-руку, а
`onProgressDown` (`:2841`) делает `preventDefault` + `stopPropagation` и зовёт `progressTipToggle`,
который тут же выходит по `!info`. Итог: в новом чате над нижней кромкой поля курсор обещает клик,
клик ничего не открывает и не доходит до страницы под ним. До WF22 полоса пряталась и этой зоны не было.
Проверено: наведение над контуром в чате без строки состояния даёт `cursor: pointer`.
Правка: первой строкой `progressHit` — `if (!progressState.info) return false;`.

### 4. Важно · заливка и этапы врут, когда роли записаны разом (риск 1 плана, подтверждён живьём)
`claude-patch/inject.js:2264-2276` (`progressStages`: нет 💭 → идущим считается ПОСЛЕДНЯЯ записанная
роль). На настоящем `docs/status.md` блок `2️⃣2️⃣ 💭 идёт` перечисляет все роли сразу и без 💭, поэтому
полоса даёт **87,5 %**, а карточка — «✅ план ✅ критик ✅ кодинг 💭 проверка» при «шаги 0 из 3».
Это ровно тот воркфлоу, который Элвис увидит на своей полосе сейчас.
Дешёвая правка на гейте: дописать `💭` в конец строки идущей роли в `docs/status.md` (правило для
`AGENTS.md` — чужой файл чата Max, задача уже в плане). Страховка в коде (по желанию): в
`progressBlockFill` не считать этапы пройденными, когда `block.steps?.done === 0`.

### 5. Мелочь · `isBlockLine` теряет «о чём» без префикса (чужой файл, диагноз)
`app/Sources/ClaudeAX/StatusFeed.swift:215`. Строка блока едет, только если начинается с «о чём»/«шаги»,
со времени или содержит « · ». В живом `docs/status.md` блоки 1️⃣–3️⃣ пишут «- ручка над полем ввода…»
без префикса — `compact` их выбрасывает, и страница берёт за «о чём» первую роль, теряя её из этапов
(проверено моделью `compact` на настоящем файле). Сегодня не видно только потому, что срез с начала
эти блоки не довозит. Правка — в Swift (владелец файла — гейт) или «о чём:» в status.md.

### 6. Мелочь · шапка-список не попадает в подвал карточки
`claude-patch/inject.js:1972`: в `head` берутся только строки, начинающиеся с цифры. У
`VkusnoffKz/audit/status.md` и `VkusnoffKz-deploy` счётчики написаны пунктами («- 3 воркфлоу этого
чата»), и подвал карточки у этих проектов останется без счёта — только имя проекта.
Правка: разрешить в `head` и «- <цифра>…».

### 7. Мелочь · слитая полоса заливку по этапам не получает
`claude-patch/inject.js:2302`: в узком окне с многими воркфлоу `progressShares` отдаёт
`Math.max(8, info.total)`, а `info.total` считается по `pct ?? 0` (`:1842`), то есть `(wf−1)/of`.
Пункт C туда не доехал. Ветка редкая (сегменты уже сливаются), поэтому мелочь.

### 8. Мелочь · README не описывает новое поведение сводки
`README.md:703-706`: «≤ 6 КБ на проект» осталось, но не сказано, что приложение блоки **сжимает**,
режет **с начала** (живое доезжает) и шлёт проекты **свежими вперёд**.

## Хвосты (правок не требуют, к сведению гейта)

- После среза номера блоков идут с дырой: `22`, затем `26…41` — следствие правила «живые блоки едут
  всегда» (гейт, коммит 8e7ff78). На страницу это не влияет: готовые сегменты считаются с хвоста
  списка ✅, а не по непрерывности номеров.
- Пятая роль сводки («макет» у блока 22) в карточку не идёт — этапов по букве Элвиса ровно четыре;
  в старой однострочной подсказке она по-прежнему видна.
- `runStatusCommand` зовёт `placeProgress()`, а тот в конце сам зовёт `progressTipShow()` — и следом
  `runStatusCommand` зовёт его второй раз. Лишняя работа раз в минуту, вреда нет.
- `slice()` пересчитывает размер всего набора на каждого кандидата — O(n²) по строкам; на 41 блоке
  незаметно.
- `VERSION` стал `wf22-p-1` при `wf37-p-1` на `main` — это метка воркфлоу, сторож проверяет только вид.
