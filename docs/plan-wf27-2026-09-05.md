## Решения

### 1. Sparkle 2 как зависимость SwiftPM, пин точной версии

```swift
.package(url: "https://github.com/sparkle-project/Sparkle", from: "2.7.0")   // число — последнюю 2.x на день ветки
```
Продукт `Sparkle` подключается **только** к executable-таргету `PimpMyClaude`; `Patcher` и `ClaudeAX` остаются
без зависимостей (их тесты не должны тянуть XCFramework). `app/Package.resolved` коммитим — иначе у следующего агента
приедет другая версия фреймворка, чем та, что подписана и роздана.
Пакет отдаёт **бинарный XCFramework** (не исходники): первый `swift build` его скачивает, дальше он лежит в
`app/.build/artifacts/…`. Следствия: (а) без сети чистая сборка не поднимется — сказать в README; (б) путь к фреймворку
**искать, а не вшивать**: `find app/.build/artifacts -maxdepth 6 -name 'Sparkle.framework' -type d`.

### 2. Как фреймворк попадает в бандл (bundle.sh) и чем подписывается

`swift build` бандлов не делает — всё руками, порядок важен:

1. найти `Sparkle.framework` в артефактах (см. выше), `ditto` его в `"$APP/Contents/Frameworks/Sparkle.framework"`;
2. **удалить `XPCServices/`** внутри копии: службы `Installer.xpc`/`Downloader.xpc` нужны только сэндбоксовым
   приложениям, наше — несэндбоксовое (`PimpMyClaude.entitlements`: `app-sandbox = false`). Меньше кода — меньше подписи;
   если Sparkle на день ветки скажет иначе, оставляем и подписываем их первыми;
3. `install_name_tool -add_rpath @executable_path/../Frameworks "$APP/Contents/MacOS/PimpMyClaude"` — иначе приложение
   не найдёт фреймворк и не запустится (в `Package.swift` `unsafeFlags` не тащим);
4. подпись **изнутри наружу**, каждый шаг с `--options runtime --timestamp` и **нашим** Developer ID:
   `Versions/B/Autoupdate` → `Versions/B/Updater.app` → сам `Sparkle.framework` → потом, как сейчас, `$APP`.
   Своей подписью, а не `--deep`: hardened runtime с library validation не пустит фреймворк чужой команды —
   родная подпись Sparkle Project здесь не годится;
5. проверка прямо в `bundle.sh`: `codesign -dv --verbose=4` на фреймворке содержит `TeamIdentifier=F27N4S4NJ4` и `flags=…runtime`,
   `codesign --verify --strict --deep` на бандле чист. Не сходится — стоп до подписи, а не на нотаризации через 5 минут.

**Четыре места, где это упадёт (К9) — заложить сразу:**
1. `find` даёт 0 или >1 совпадение (слайсы XCFramework) — брать строго слайс macOS; при 0 или ≥2 — `die` с внятным
   текстом, «первый попавшийся» не брать;
2. `install_name_tool -add_rpath` на уже существующем rpath — **ошибка**, а скрипт под `set -euo pipefail`: добавлять,
   только если `otool -l "$APP/Contents/MacOS/PimpMyClaude" | grep -q '@executable_path/../Frameworks'` пуст;
3. вложенное (`Autoupdate`, `Updater.app`, сам фреймворк) подписывать **без `--entitlements`** — `PimpMyClaude.entitlements`
   предназначен только приложению (иначе агент повторит строку из конца скрипта);
4. подписывать версионный каталог `Sparkle.framework/Versions/B`, а не только символическую вершину.

### 3. Ключ EdDSA — заводит Элвис, агент его не видит

`generate_keys` из комплекта Sparkle кладёт **приватный** ключ в связку ключей входа и печатает **публичный** (base64, 44 символа).
Приватный ключ — это право поставить команде любой код: в репозиторий, в чат и в план он не попадает **никогда**.
Порядок: Элвис до волны выполняет `generate_keys`, публичный отдаёт в чат, батч S1 вписывает его в `Info.plist`
(`SUPublicEDKey`), бэкап приватного — в 1Password (потерян = обновлять команду больше нечем, только новая ручная раздача
с новым ключом). Подписывать релизы (`sign_update`) тоже Элвис/оркестратор на гейте — ключ читается из связки сам.
Инструменты (`generate_keys`, `sign_update`) искать в артефакте SPM (`find app/.build/artifacts -name sign_update`);
нет — скачать `Sparkle-<версия>.tar.xz` из релизов Sparkle. **Бинарники в репозиторий не коммитим**, `release.sh`
говорит словами, что и откуда взять.

### 4. Где живёт appcast

**`docs/appcast.xml` в ветке `main`, фид — `https://raw.githubusercontent.com/ElvisIglikov/PimpMyClaude/main/docs/appcast.xml`**
(рекомендация, В3). Плюсы: файл в репозитории — видно в диффе, кто и когда что выкатил; правится и откатывается коммитом;
никакой возни с ассетами. Кэш raw ≈ 5 минут — для суточной проверки не важно.
Сам zip остаётся ассетом GitHub Release: `https://github.com/ElvisIglikov/PimpMyClaude/releases/download/v<версия>/PimpMyClaude-<версия>.zip`.
Скелет файла обязателен целиком (К12) — без объявления пространства имён все поля `sparkle:*` молча игнорируются,
а `testAppcastIsWellFormed` на пустом канале этого не заметит:

```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
  <channel>
    <title>PimpMyClaude</title>
    <link>https://github.com/ElvisIglikov/PimpMyClaude</link>
    <description>Обновления PimpMyClaude</description>
    <!-- записи ниже, новая — первой -->
  </channel>
</rss>
```

Форма записи (побайтно, порядок полей менять только на гейте):

```xml
<item>
  <title>1.4.1</title>
  <pubDate>Fri, 05 Sep 2026 20:00:00 +0500</pubDate>
  <sparkle:version>9</sparkle:version>                        <!-- CFBundleVersion, целое, растёт -->
  <sparkle:shortVersionString>1.4.1</sparkle:shortVersionString>
  <sparkle:minimumSystemVersion>13.0</sparkle:minimumSystemVersion>
  <description><![CDATA[<ul><li>…</li></ul>]]></description>
  <enclosure url="https://github.com/…/PimpMyClaude-1.4.1.zip"
             sparkle:edSignature="…" length="581234" type="application/octet-stream"/>
</item>
```

Старые записи **не удаляем**, но обоснование честное (К11): Sparkle всегда предлагает **самую свежую** подходящую
запись — застрявшему на 1.3.0 старые `<item>` ничем не помогают, а понизить версию Sparkle не умеет: снятая из appcast
плохая сборка останется у всех, кто успел обновиться. Держим их ради `sparkle:minimumSystemVersion` для старых macOS
и ради истории в диффе; **откат плохого релиза — только новой версией** (см. «Открытые риски»). Сравнивает Sparkle по `sparkle:version` (это `CFBundleVersion`), значит билд обязан расти
на каждом релизе — проверка в `tools/test.sh`.

### 6. Проводка в приложении (executable, Sparkle только здесь)

`app/Sources/PimpMyClaude/SparkleUpdates.swift` — тонкий слой, вся логика без Sparkle лежит в `Patcher/Updates.swift` (решение 7):

- `SPUStandardUpdaterController(startingUpdater: true, updaterDelegate: self, userDriverDelegate: self)` — свойство
  `AppDelegate`, создаётся в `applicationDidFinishLaunching`. Проверка при старте — штатная работа Sparkle
  (по расписанию, с учётом `SUScheduledCheckInterval`), своего таймера не заводим;
- пункт меню **«⬆️ Обновить PimpMyClaude…»** между «История авто-Allow…» и «О программе» (вариант А макета, В6).
  Не «Проверить обновления…» (К5): выше в меню WF17 уже поставил **«⬆️ Обновить Claude…»** — две строки с одной стрелкой
  и почти одинаковым текстом читаются как ошибка. `isEnabled` в `menuWillOpen` берётся из `updater.canCheckForUpdates`;
- **`LSUIElement`**: перед показом окна Sparkle обязателен `NSApp.activate(ignoringOtherApps: true)` — то же правило,
  что для `popUp` меню (AGENTS.md, «Решения, о которых легко забыть»). Делаем в методе делегата пользовательского драйвера,
  который зовётся перед показом обновления; точное имя метода берём из заголовков Sparkle на день ветки;
- **не проверять во время операции патча**: пока `AppDelegate.busy == true` («Поставить»/«Снять» переписывают Claude),
  делегат апдейтера отвечает «сейчас нельзя» (метод-разрешение `updaterMayCheckForUpdates`-типа; имя сверить по заголовкам).
  Иначе Sparkle попросит перезапуск ровно в момент, когда мы держим asar;
- **гонка «установка ↔ патч» — три замка (К2, все обязательны)**: опасна не проверка, а установка. Обновление могло быть
  скачано десять минут назад, и человек жмёт «Установить и перезапустить» посреди патча; обрыв между записью `app.asar`
  и `codesign` оставляет **неработающий Claude**, который чинится только «Поставить» руками:
  1. `SPUUpdaterDelegate` откладывает перезапуск — метод вида `updater(_:shouldPostponeRelaunchForUpdate:untilInvokingBlock:)`:
     при `busy` сохранить блок, вернуть `true` и вызвать блок из `operationFinished()`; имя сверить по заголовкам Sparkle;
  2. `applicationShouldTerminate` при `busy` возвращает `.terminateCancel` и показывает однострочный алерт
     «Идёт установка патча, подожди 10 секунд» — этим же закрывается ⌘Q и любой другой путь выхода;
  3. «Поставить…»/«Снять…» гаснут в `menuWillOpen`, пока Sparkle качает или ставит (флаг из делегата пользовательского
     драйвера: поднимается в методе типа `standardUserDriverWillHandleShowingUpdate`, снимается по завершении или отмене).
  **WF26 к этому моменту чинит патч в фоне и молча** — тихая починка обязана поднимать тот же `busy` (или свой флаг,
  который видят эти три пункта), иначе Sparkle перезапустит приложение посреди автоперепатча;
- фид — из `Updates.feedURL(override:default:)`: штатный из `Info.plist`, а если в `UserDefaults` лежит **наш**
  ключ `PMCFeedURLOverride` с https-строкой, берётся он. Это единственный способ прогнать живой тест обновления,
  не публикуя ничего в `main` (решение 10). Не-https и мусор игнорируются. Подключается штатным путём Sparkle 2 —
  `SPUUpdaterDelegate.feedURLString(for:)` (К16); `setFeedURL` не звать.

### 7. Что можно проверить тестом — живёт в `Patcher`

`app/Sources/Patcher/Updates.swift` (Sparkle **не** импортирует, значит доступен тестам таргета `PatcherTests` —
новым классом `UpdatesTests`, К3):
имена ключей Info.plist, `feedURL(override:default:)`, `shouldRefreshLiveFiles(last:current:)`,
разбор appcast для тестов (минимальный, на `XMLDocument`). Всё остальное — проводка AppKit, её проверяет живой гейт.

### 8. Живые файлы после автообновления (без этого воркфлоу бессмысленен)

`applicationDidFinishLaunching` сравнивает `CFBundleVersion` с `UserDefaults` `lastRunBundleVersion`:

- **не совпало** (значит приложение только что обновилось или его заменили руками) → копируем в Application Support
  **`inject.js` и комплект `workflow/`**; **`claude.css` не трогаем** — блок `/* PimpMyClaude:auto */` и так вернёт
  `refreshLiveStyle`. Правило самого `claude.css` к этому моменту уже написал WF26 (пишется только при отсутствии живого
  файла) — WF27 **его не меняет и не дублирует** (К1);
- записываем новую версию в `lastRunBundleVersion`;
- если патч при этом «слетел» (сменился лоадер), человек и так получит красный «!» и баннер «Поставить снова» — это уже есть.

Список файлов параметризуется одной строкой: `func installLiveFiles(names: [String] = ["inject.js", "claude.css"], progress:)`,
автообновление передаёт `["inject.js"]` (плюс комплект `workflow/`) — правку не размазываем, чужого поведения не меняем.
Наружу открывается **один** метод, и он **не зависит от найденного Claude.app** (К6):
`public static func refreshLiveFiles(supportDirectory:resources:progress:)`. Причина: `ClaudePatcher` конструируется только
с `appURL`, а на машине без Claude `chosenClaude(askIfSeveral: false)` отдаёт `nil` — главная польза воркфлоу молча бы
не сработала. Зовём из `applicationDidFinishLaunching` **без** `chosenClaude`.
Второе правило оттуда же: копировать файл, только если бандловый **не старше** живого по mtime — на Маке Элвиса живой
`inject.js` во время гейтов кладётся `cp` из репозитория, и перезапуск с новым `CFBundleVersion` не должен вернуть
бандловую копию поверх свежей; пропуск — строкой в журнал.
Файл `Patcher.swift` в этой волне пишет **только** батч S2 и перед правкой перечитывает его заново (WF26 уже трогал).

### 9. `tools/release.sh` — три новых шага и флаг `--publish`

После нынешнего шага 6 (проверка распакованного zip):

- **7.** `sign_update dist/PimpMyClaude-<версия>.zip` → `sparkle:edSignature` и `length`;
- **8.** обновление `docs/appcast.xml`: новая `<item>` первой, старые на месте (маленький `python3` внутри скрипта —
  ни одной зависимости; XML правится разбором, а не `sed`). Заметки берутся из `docs/release-notes/<версия>.html`,
  файла нет — одна строка «Обновление PimpMyClaude <версия>»;
- **9.** публикация, и сначала три замка (К10): `[ "$(git rev-parse --abbrev-ref HEAD)" = main ] || die "публикуем только с main"`
  (фид смотрит в `main`: с ветки релиз уйдёт, а appcast — нет, и команда не увидит ничего при уже опубликованном zip),
  `gh auth status`, рабочее дерево чисто. Затем `gh release create v<версия> dist/PimpMyClaude-<версия>.zip --title … --notes-file …`
  и `git add docs/appcast.xml && git commit && git push`. Последним действием — **скачать опубликованный ассет и сверить
  `shasum` и размер с `length` в appcast**.

**Без ключа `--publish` шаги 7–8 выполняются, шаг 9 только печатает готовые команды.** Публикация — «публичное
содержимое» и делается руками оркестратора с явного разрешения Элвиса на прогон (WORKFLOW.md, дисциплина прогона).
Ещё две правки скрипта: `rm -f dist/PimpMyClaude-*.zip` в начале **оставляем**, но перед ним старый zip уезжает
в `dist/old/` (иначе после публикации нечем откатиться); в конце печатается, какой URL встал в appcast.

**Первый боевой `--publish` — не в WF27 (К7).** WF21 и WF25 отдают подъём версии гейту **последнего** воркфлоу марафона,
WF22 планирует 1.5.0 — публикация в середине очереди означала бы вторую публикацию после WF28. WF27 сдаёт готовый
механизм и проверяет его временным prerelease-ом; боевая публикация — на гейте WF28, когда версия поднята один раз.

### 10. Как это проверяется живьём, ничего не ломая

Собрать текущую версию, поставить её в `/Applications`, затем собрать версию на единицу больше **тем же `tools/release.sh`
без `--publish`** (К15: с нотаризацией и сшитым билетом — иначе живьём проверяется не тот путь), опубликовать её
**временным prerelease** (`gh release create wf27-test --prerelease`) и положить appcast **в ветку `wf27`**,
фид переключить через `defaults write com.elvis.pimpmyclaude PMCFeedURLOverride …` (решение 6). После проверки —
`gh release delete wf27-test`, тег снять, `defaults delete`. Команда в это время смотрит на `main`, где appcast старый,
и ничего не видит. Альтернатива «локальный http-сервер» хуже: ATS в hardened-runtime приложении режет http,
пришлось бы городить исключение в боевом `Info.plist`.

### 11. Не делаем в WF27

Дельта-обновления (нужны старые zip и `generate_appcast`), каналы «бета/стабильная», молчаливую установку без спроса,
свой сервер и GitHub Pages, обновление `inject.js` отдельно от приложения (это про WF26), автоперепатч Claude (WF26),
обновление самого Claude (WF17), подпись DSA (мертва), Sparkle в `ClaudeAX`/`Patcher`, правку `inject.js` и лоадера v7.

## Тесты (поимённо)

**Новые Swift — отдельным файлом `app/Tests/PatcherTests/UpdatesTests.swift`, класс `UpdatesTests: XCTestCase` без `setUp`**
(К3: `PatcherTests.setUpWithError` начинается с `XCTSkipUnless(… Claude.app …)` и копирования `app.asar` на каждый тест —
в его классе все семь проверок, к Claude отношения не имеющих, молча стали бы «skipped» на чистой машине, а гейт
видел бы выросший счёт). Корень репозитория считается локально по образцу `ClaudeAXTests.repositoryRoot`
(`URL(fileURLWithPath: #filePath)` + четыре `deletingLastPathComponent`); `PatcherTests.swift` не трогаем вовсе.
Файлы репозитория читаются по `#filePath` — так же, как WF24 читает `inject.js`:

- `testInfoPlistHasSparkleKeys` — все пять ключей решения 5 на месте: `SUFeedURL` начинается на `https://` и указывает
  на наш репозиторий; `SUPublicEDKey` — base64 длиной 44 и не заглушка; `SUEnableAutomaticChecks == true`;
  `SUScheduledCheckInterval >= 3600`; `SUAutomaticallyUpdate == false`; `CFBundleVersion` — целое.
- `testAppcastIsWellFormed` — `docs/appcast.xml` разбирается и **объявляет `xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle"`**
  (К12: без объявления все `sparkle:*` игнорируются, а на пустом канале тест иначе зелёный и слепой); у каждой записи есть `sparkle:version` (целое),
  `sparkle:shortVersionString`, `sparkle:minimumSystemVersion == 13.0`, `enclosure` с https-ссылкой на
  `github.com/ElvisIglikov/PimpMyClaude/releases/download/`, `sparkle:edSignature` (base64, 88 символов) и `length > 0`;
  версии уникальны и идут по убыванию.
- `testBundleVersionIsNotBehindAppcast` — `CFBundleVersion` из `Info.plist` **не меньше** самой свежей записи appcast
  (иначе приложение предложит «обновиться» на само себя или в прошлое). Пустой appcast — тест зелёный.
- `testFeedOverrideAcceptsOnlyHTTPS` — `Updates.feedURL(override:default:)`: `nil`, пустая строка, `http://…`,
  `file://…`, мусор → штатный фид; `https://…` → он.
- `testShouldRefreshLiveFilesOnVersionChange` — `nil` (первый запуск) → да; равные версии → нет; другая версия → да;
  пустая/мусорная запись → да (безопасная сторона).
- `testRefreshLiveFilesTouchesInjectOnly` (К1 — имя не про `claude.css`, чтобы V не счёл дублированием чужого
  `testInstallKeepsExistingClaudeCss` из WF26) — на временном каталоге: `refreshLiveFiles` кладёт `inject.js`
  и комплект `workflow/`, а подложенный руками `claude.css` остаётся **байт в байт** прежним.
- `testRefreshLiveFilesKeepsNewerLiveFile` (К6) — живой `inject.js` новее бандлового по mtime: остаётся нетронутым,
  в журнал уходит строка о пропуске.

**Сторожевые проверки в `tools/test.sh` (батч R):** appcast разбирается `python3` и объявляет `xmlns:sparkle` (К12);
`SUPublicEDKey` не заглушка;
`bundle.sh` содержит и копирование `Sparkle.framework`, и его подпись (пропало — релиз уедет без фреймворка и не запустится);
версия Sparkle в `Package.resolved` совпадает с пином в `Package.swift`.

**Сеть на тестах (К18).** После добавления зависимости `tools/test.sh` без интернета красный **целиком**, а не только
в Swift-части: SwiftPM качает XCFramework Sparkle. Записать в `docs/CHECKLIST.md` строкой «первый прогон после чистого
клона требует сети».

**Чего тестами не проверяем (только живой гейт):** пункт меню и его гашение, окно Sparkle, скачивание и установку,
перезапуск, сохранение разрешения Accessibility, поведение при `busy`.

## Открытые риски

- **Приватный ключ = ключ от машин команды.** Кто им подпишет zip, тому Sparkle поставит любой код у всех.
  Только связка ключей, только у Элвиса, бэкап отдельно; в репозиторий, чат и план не попадает. Потеря ключа —
  новая ручная раздача всей команде.
- **Нотаризация с фреймворком.** Самый вероятный красный шаг: чужая подпись, пропущенный `--timestamp`, забытый
  hardened runtime на `Autoupdate`/`Updater.app`. Смягчение — подпись изнутри наружу и проверки прямо в `bundle.sh`
  (решение 2, п. 5), а не «отправим и посмотрим».
- **Приложение не запустится без rpath** — и это будет видно только в собранном бандле, `swift build` промолчит.
  Отсюда шаг 3 гейта с `otool -l` и запуском.
- **Сеть на сборке.** Чистый клон без интернета больше не собирается: XCFramework скачивается. `Package.resolved`
  коммитим, в README пишем прямо.
- **Публичные релизы.** Репозиторий уже открыт, но zip станет качать кто угодно; если Элвис захочет приватность (В4),
  Sparkle к приватным ассетам без токена не ходит — придётся отдельный хостинг, это другой воркфлоу.
- **Гонка «обновление ↔ патч».** Sparkle просит закрыть приложение ровно тогда, когда мы держим `app.asar`.
  Лечится тремя замками решения 6 (К2: запрет проверки, отложенный перезапуск, `applicationShouldTerminate` и гашение
  «Поставить…»/«Снять…»); проверяется шагом 6 гейта. Тихая починка WF26 обязана поднимать тот же `busy`.
- **Разрешения после подмены бандла.** Accessibility и App Management привязаны к подписи; Developer ID и bundle id
  не меняются, значит должны пережить. Но это **гипотеза** — шаг 7 гейта существует именно ради неё; если разрешение
  слетит, обновление придётся сопровождать плашкой «включи снова», и это надо будет написать в TEAM.md.
- **Старая страница при новом приложении.** Без решения 8 команда получила бы новый Swift и старый `inject.js` —
  молчаливые «команда не сработала». Проверка — тесты `testRefreshLiveFilesTouchesInjectOnly`,
  `testRefreshLiveFilesKeepsNewerLiveFile` и шаг 8 гейта.
- **Версия Sparkle.** Числа в плане не вшиты намеренно: берём последнюю 2.x на день ветки. Если у неё изменились
  имена методов делегата (решение 6) — правит батч S2 по заголовкам, поведение остаётся тем же.
- **`sparkle:version` обязан расти.** Забыть поднять `CFBundleVersion` — значит выкатить обновление, которое никто
  не увидит. Ловит `testBundleVersionIsNotBehindAppcast` и сторож в `test.sh`.
- **Плохой релиз откатывается только новой версией** (К11): Sparkle не понижает версию, а снятая из appcast запись
  уже никого не вернёт назад. Отсюда правило в `docs/CHECKLIST.md` (батч D): публикуем только ту сборку, которая
  **сутки прожила у Элвиса**.
- **App Translocation** (К13): zip, распакованный в «Загрузки», macOS запускает из read-only копии — Sparkle оттуда
  обновиться не сможет. Лечится строкой в `docs/TEAM.md` («держи PimpMyClaude в Программах»), в коде ничего не городим.
- **Порядок с WF17 — не выбор, а данность** (К8): WF17 седьмой в марафоне, WF27 тринадцатый, 1.4.0 уедет без Sparkle.
  Вопрос остаётся один — собирать ли отдельную раздачу 1.5.0 сразу после WF27 или ждать конца марафона (В1).
- **Критик плана** — отдельным агентом Opus max перед презентацией; его находки вносятся сюда же с пометкой «правки по критику».

**К9. `tools/bundle.sh`: четыре точных места, где решение 2 как написано упадёт.**

**К11. Обоснование «старые записи в appcast» неверно, а отката у Sparkle нет.** Sparkle всегда предлагает **самую
