2. **Половина воркфлоу уже написана.** `ClaudePatcher.state()` (`Patcher.swift:270`) сверяет версию Claude и

3. **`install()` всегда открывает Claude** (`relaunchClaude()` — `/usr/bin/open -a`, строки 219/233). Для тихой починки

## Решения

### 1. Повод чинить — только «слетел», никогда «не стоит»

Автоперепатч включается на `ClaudeState.lost` и только с причинами из **белого списка** (Б3, находка 16): причины
перечисляются явно, всё незнакомое — не чиним.

| причина `state()` | что случилось на самом деле | чинить |
|---|---|---|
| «Claude обновился» | человек подменил Claude.app, лоадера в asar нет | да |
| «старый лоадер vN» | обновилось **наше** приложение, лоадер в нём новее | да |
| «хэш в Info.plist не сходится» | прошлая установка упала между записью архива и подписью | да |
| «app.asar не читается» | битый/чужой архив; `install()` сам падает на `Asar.status` | **нет** (строка в журнал) |
| любая новая причина | код разъехался с планом | **нет** (строка в журнал) |
| `.notInstalled` | патч сняли или не ставили никогда | **нет** |
| `.claudeNotFound` | Claude нет вовсе | нет |

Второй столбец — почему «старый лоадер» тут особенно важен: сегодня смена лоадера означает «Поставить снова» руками
у всей команды (AGENTS.md, слой 1). С WF26 это происходит само при первом же закрытии Claude. **Это и есть главная
ценность воркфлоу** — заголовок в `TEAM.md`/`README` (батч D) пишем про неё, а не про «Claude обновился» (критик).

**Чиним только ТОТ Claude, который патчили (Б1).** `installedRecord()` начинает читать `appPath`, и решение о починке
принимается, только если `recorded.appPath == appURL.path`. Сам `state()` не трогаем — иначе поедет поведение
«Claude переехал». Плюс: копий Claude больше одной и `UserDefaults.claudeAppPath` пуст → тихий путь запрещён вовсе,
показываем плашку «несколько копий Claude — выбери, какую чинить» (как в `install()`).

### 2. Два пути: тихий и по плашке

- **Claude НЕ запущен** → чиним молча: `install(relaunch: false)`, Claude не открываем (человек сам откроет, когда
  захочет — и увидит уже пропатченный). Успех — только строка в журнале; провал — плашка с текстом ошибки.
- **Claude запущен** → **никогда не закрываем сами**: в окнах Claude живут чаты и сессии Claude Code. Плашка-баннер
  «Claude обновился — поставить патч заново? Claude закроется и откроется, ~полминуты» с кнопкой «Поставить сейчас»
  (существующая категория `PatchLost`, текст поправить). Не нажали — ничего не происходит; **как только человек сам
  закроет Claude, чиним молча** (триггер ниже). То есть даже пропущенный баннер лечится сам.
- Тумблер **«Чинить патч сам»** в меню-баре рядом с «Авто-Allow» (по умолчанию включён). Выключен — остаётся сегодняшнее
  поведение: красный «!» и баннер с кнопкой.

**Тихо чиним, только если сошлось всё** (иначе — плашка, ничего не трогаем):

1. состояние `.lost`, причина из белого списка (решение 1);
2. `installed.json.appPath` совпадает с проверяемой копией; копий Claude не больше одной или выбор сохранён (Б1);
3. Claude не запущен, тумблер включён;
4. **наше приложение лежит в «Программах»** (`SetupWindow.isInApplicationsFolder`, находка 18) — иначе dev-сборка из
   `.build` молча перепишет рабочий Claude лоадером из ветки (В6);
5. не идёт выключение/засыпание системы (решение 3, точка 5);
6. предохранитель не исчерпан — попыток на пару «версия + причина» меньше двух (решение 11).

**Первую в жизни тихую починку говорим вслух (В5).** Флаг `repatchAnnounced` в `UserDefaults`: первая удачная тихая
починка (и только она) шлёт баннер «Патч Claude встал заново сам. Выключить — в меню → „Чинить патч сам“». Дальше —
только журнал. Иначе у команды приложение начинает править чужой бандл без единого слова.

### 3. Когда смотрим (новых сторожей файлов не заводим)

Хватает четырёх точек, все дешёвые:

1. **Старт приложения** + 5 с (`applicationDidFinishLaunching`) — обновили Claude, пока приложение не работало.
2. **Опрос раз в 60 с** — уже есть (`pollTimer`), ничего не добавляем.
3. **Claude закрылся** — `didTerminateApplicationNotification` по `Patcher.claudeBundleID`, пауза 3 с (Claude умирает
   не мгновенно, `runningClaude()` должен опустеть), потом проверка и тихая починка.
4. **Claude запустился** — `didLaunchApplicationNotification`: только проверяем состояние и, если слетел, показываем
   плашку. Ничего не закрываем.
5. **Выключение и сон — стоп-кран (В3).** Подписка на `NSWorkspace.willPowerOffNotification` и
   `willSleepNotification` взводит флаг `shuttingDown`: новую тихую починку не начинаем (начатую не бросаем),
   `didWakeNotification` флаг снимает. Иначе типичный случай «человек выходит из системы» = Claude закрылся первым →
   мы начали `codesign --force --deep` по 832 МБ → macOS убила нас на середине → следующий запуск Claude
   «программа повреждена». В журнал — строка «отложил: выключение».

FSEvents/`DispatchSource` на `Claude.app` **не заводим**: подмена бандла сносит вотчер вместе с папкой, а сторож на
`/Applications` шумит на каждую установку любой программы. Четырёх точек достаточно: сценарий «положил новый Claude и
сразу его открыл» ловится точкой 4 (плашка), «положил и не открыл» — точками 1–3 (тихо).

### 4. Гонка «Claude открыли посреди починки» (вопрос В2)

Между записью `app.asar` и переподписью Claude запускаться нельзя: не сойдётся `ElectronAsarIntegrity`, человек увидит
крэш или «программа повреждена». Окно — десятки секунд (замер 9).

**Рекомендуемое поведение:** на время тихой операции подписываемся на `didLaunchApplicationNotification`; Claude
успел стартовать — закрываем его существующим `quitClaude` (`terminate` → `forceTerminate`, находка 19), **сразу**
шлём баннер «Чиню патч — открою Claude через полминуты», в журнал строку, доделываем починку и **открываем Claude
заново сами** (`relaunch: true` в этом случае). Альтернатива (В2, вариант Б) — бросить починку и откатиться к плашке;
тогда Claude остаётся с недописанным патчем, что хуже.

Две уточняющие детали от критика (В4): баннер уходит **в момент закрытия**, а не после починки — иначе человек
полминуты смотрит, как только что открытый им Claude подпрыгнул в доке и умер, без объяснений. И наблюдатель
`didLaunch` держится **до конца операции**: второй запуск обрабатывается так же, а не проскакивает.

### 5. Живые файлы: `claude.css` существующий не трогаем (вопрос В5)

**Предусловие (Б4): сперва смотрим, что уже лежит в `main`.** План WF17 (пп. 98–101) прямо допускал, что его батч S
чинит `installLiveFiles` **слиянием по маркерам** и тогда владеет `Patcher.swift`. WF17 идёт седьмым, WF26 —
двенадцатым. Проверка до резки ветки: `git log -p main -- app/Sources/Patcher/Patcher.swift | grep -n "installLiveFiles"`
плюс глазами тело метода в `main`.

- **Слияние по маркерам уже есть → решение 5 отменяется целиком**: батч A правило `claude.css` не трогает, тест
  `testInstallKeepsExistingClaudeCss` переписывается под маркерное слияние. Второй контракт на тот же файл за неделю
  (часть команды получила бы оба) не заводим. Результат проверки — строкой в run-файл.
- **Слияния нет** → делаем ниже.

`installLiveFiles` меняется одной строкой правила: **`claude.css` из бандла пишется, только если живого файла нет**;
существующий не перезаписывается никогда — ни при тихой починке, ни по кнопке «Поставить».

**Умное исключение (В7, ~15 строк, батч A):** если часть живого файла **вне** маркеров `/* PimpMyClaude:auto */`
побайтно равна той же части бандлового — человек ничего не правил, файл можно обновить; отличается хоть на символ —
не трогаем. Так базовые правила (сегодня их два: стрелки «назад/вперёд» и строка действий) продолжают доезжать до
тех, кто не правил ничего, а правки не теряются ни у кого. Две строки-константы маркеров дублируются в `Patcher`
осознанно (находка 12: `LiveStyle` — из другого таргета). Вариант выбирает Элвис (вопрос В5).
Минимум, обязательный при любом варианте: строка в `AGENTS.md` («живой `claude.css` больше не обновляется установкой
целиком; новое общее правило едет блоком `PimpMyClaude:auto` или разовой миграцией») и пункт в `CHECKLIST.md`.

- Ничьи правила не теряются, новых маркеров и переноса старых файлов не нужно (решение 12: сливать в `Patcher`
  всё равно нечем — `LiveStyle` из другого таргета).
- `inject.js` и комплект `workflow/` — наши, перезаписываются как раньше: лоадер и `inject.js` обязаны совпадать по
  версии, иначе починка бессмысленна.
- Базовых правил в бандловом `claude.css` всего два (стрелки «назад/вперёд» и строка действий) — если когда-нибудь
  понадобится довезти новое правило всем, оно едет в блоке `/* PimpMyClaude:auto */`, который `LiveStyle` переписывает
  на каждом запуске приложения.
- После починки (обоих путей) по-прежнему зовём `ax.refreshLiveStyle()` — радиус рамки и поля на месте.
- Заодно закрывается предусловие 1а плана WF17: «заменить .app → Поставить» больше не сбрасывает правки.

### 6. Бэкапы: держим три последних (вопрос В4)

После **удачной** установки: смотрим `backups/*`, оставляем три самые свежие по mtime **и обязательно версии всех
установленных копий Claude** — не одной текущей, а каждой из `Patcher.locateClaude()` (В8: иначе удалим бэкап версии
из второй копии, и «Снять» для неё сломается насмерть — `restore()` без бэкапа только бросает `noBackup`,
`Patcher.swift:248`). Удаляем, только когда бэкапов больше трёх; каждая удалённая — строка в журнале. И парная защита от
находки 11: **`makeBackup` перед записью проверяет asar на маркер `[MyClaude:v*:start]`; маркер есть — в бэкап уезжает
очищенная копия (`Asar.removeLoader` на временном файле), а не патченый архив.**

### 7. Журнал

Файл `~/Library/Application Support/MyClaude/repatch.log`, дописывается строками, потолок **200 строк** (лишнее
срезается с начала). `RepatchLog` принимает директорию — `init(directory: URL = Patcher.defaultSupportDirectory)`
(М2), иначе тест полезет в живой `~/Library/Application Support/MyClaude/`. Формат строки — одна на событие,
читается глазами:

```
2026-09-05 19:41 · Claude 1.46388.1 → 1.47010.2 · «Claude обновился» · сам · ok · 34 с · лоадер v7
2026-09-06 08:12 · Claude 1.47010.2 · «старый лоадер v7» · по кнопке · ok · 29 с · лоадер v8
2026-09-06 09:03 · Claude 1.47010.2 · «Claude обновился» · сам · не вышло: нет разрешения «Управление приложениями»
2026-09-06 09:04 · чистка бэкапов: удалён 1.40609.1 (38 МБ)
2026-09-06 21:30 · Claude 1.47010.2 · «Claude обновился» · отложил: выключение
2026-09-07 10:00 · Claude 1.47010.2 · «Claude обновился» · пропустил: чинили дважды, жду кнопку
2026-09-07 10:01 · Claude 1.47010.2 · «app.asar не читается» · пропустил: причина не наша
```

Показываем разделом **«Последние починки»** в существующем окне «Статус…» (вопрос В3) — новых пунктов меню не заводим,
их и так прибавляют WF17 и WF21. Журнал никуда не отправляется, читается только на этом Маке.

### 8. Кэш разбора asar (находка 10) — только статический, за замком (Б2)

`state()` запоминает `(mtime, size)` файла `app.asar` вместе с результатом разбора; ключ не изменился — asar не
трогаем. Иначе в состоянии «слетел» приложение раз в минуту вечно читает 41 МБ.

Как именно (в поле экземпляра нельзя — находка 17: `ClaudePatcher` структура, `state()` не `mutating`, экземпляр
живёт один вызов):

- кэш — `static` в `ClaudePatcher`, ключ `(asarURL.path, mtime, size)`, значение — `AsarStatus`;
- доступ через `NSLock` (или свою serial-очередь): читают два потока — `refreshState` с `DispatchQueue.global`
  и `menuWillOpen` с главного. «Просто `static var`» — гонка;
- счётчик разборов для теста — там же, `static`, со `static func resetForTests()`, который зовётся в `setUp`:
  XCTest гоняет все классы в одном процессе, иначе `testStateReusesAsarProbeWhileUnchanged` ловит чужие вызовы.

### 9. Что WF26 НЕ делает

Не трогает `claude-patch/inject.js`, лоадер v7 и контракт `command.json`; не качает Claude и не ходит в сеть; не
возвращает подпись Apple; не бэкапит Claude.app целиком (832 МБ); не глушит проверку обновлений Claude; не делает
Sparkle (WF27); не закрывает работающий Claude по своей воле (кроме гонки, решение 4); не поднимает версию в
`Info.plist` и не выпускает релиз (это WF17/WF27).

### 10. Если WF17 не сделал батч S

WF26 идёт после WF17 по очереди, но батч S у WF17 зависит от ответа Элвиса (их вопрос В1).

- **Сделал** — WF26 переиспользует `ClaudeUpdates.swift` и вторую категорию уведомлений, свои не заводит; в плашке
  «Claude обновился» показывает и дату из лога, если она есть.
- **Не сделал** — WF26 работает на своей единственной категории `PatchLost` (существующей), `ClaudeUpdates` не
  появляется; текст плашки берётся из решения 2 без даты.

Проверок перед стартом **две**, обе до резки ветки, обе результатом в run-файл (Б4):

1. `git log main -- app/Sources/Patcher/ClaudeUpdates.swift` — есть ли файл WF17 и вторая категория уведомлений;
2. `git log -p main -- app/Sources/Patcher/Patcher.swift | grep -n "installLiveFiles"` плюс тело метода в `main` —
   не переписал ли батч S правило `claude.css` слиянием по маркерам (тогда решение 5 отменяется целиком).

**Правило `setNotificationCategories` из WF17 действует и здесь:** набор категорий регистрируется ОДНИМ
вызовом массивом, а в делегате сперва ветка по `categoryIdentifier` — иначе клик по чужому баннеру закроет человеку
Claude.

### 11. Предохранитель: не больше двух тихих попыток (Б3)

Без него неудачная тихая починка повторяется вечно: `pollTimer` (`AppDelegate.swift:56`) дёргает `refreshState()`
раз в 60 с, состояние осталось `.lost`, `busy` снят — и мы снова гоняем `codesign --force --deep` по 832 МБ, снова
пишем строку в журнал. За три часа журнал (200 строк) состоит из одной ошибки, а батарея — из `codesign`. Живее
всего это на отказе «Управление приложениями».

- `RepatchGuard`: не больше **двух** тихих попыток на пару `(версия Claude, причина)`. Счётчик — в `UserDefaults`.
- Сбрасывается: при смене версии или причины, при удачной починке, при ручном «Поставить…», при переключении тумблера.
- Исчерпали — переходим на плашку с текстом ошибки и больше ничего не трогаем; в журнале строка «пропустил: чинили
  дважды, жду кнопку» (одна, не каждую минуту).
- Белый список причин из решения 1 — часть того же предохранителя: незнакомая причина = `.nothing` + одна строка.

## Открытые риски

- **Мы молча правим чужое приложение.** Это главный риск воркфлоу. Ограничения жёсткие: только `.lost` с причиной из
  белого списка, только тот Claude, чей путь записан в `installed.json`, только при закрытом Claude, только когда
  приложение в «Программах», тумблер выключаемый, разрешения не выпрашиваем, каждое действие — строкой в журнале,
  первая тихая починка объявляется баннером. Остаточный риск: человек забыл, что ставил патч, и удивился.
- **Вторая копия Claude** (Б1) — самый коварный из закрытых: `.lost` появляется из ничего, потому что `chosenClaude`
  без сохранённого выбора берёт `copies[0]`. Закрыто сверкой `appPath` и запретом тихого пути при нескольких копиях;
  живой сценарий (ж) обязателен.
- **Вечный цикл починок** (Б3) — закрыт предохранителем на две попытки и белым списком причин; если предохранитель
  выпадет из реализации, симптом тихий: греется процессор и распухает журнал. V проверяет отдельным пунктом.
- **Выключение системы посреди тихой починки** (В3) — самый реальный способ получить «программу повреждена»:
  закрыть Claude и сразу выйти из системы люди делают каждый день. Закрыто флагом `shuttingDown`; остаточный риск —
  жёсткое выключение по кнопке, от него защиты нет.
- **Dev-сборка патчит рабочий Claude** (В6) — на Маке Элвиса приложение подменяется из `.build` посреди волны.
  Закрыто проверкой «мы в Программах».
- **Гонка с запуском Claude** (решение 4) — окно в десятки секунд, за которое Claude может стартовать с несведённым
  хэшем. Смягчение выбрано, но живой сценарий (г) обязателен: это единственное место, где можно показать человеку
  «повреждённый Claude».
- **Промпт «Управление приложениями» в тихом пути.** Просить разрешение молча нельзя; отказ фиксируется в журнале и
  плашкой. Если TCC когда-нибудь потребует подтверждение заново (смена подписи, чистая система) — автоперепатч честно
  выключится сам до первого ручного «Поставить».
- **Тихий путь трёт живой `inject.js`.** На гейте это ловушка: агент кладёт свежий `inject.js` в Application Support
  руками, приложение в момент починки возвращает бандловый. Правило гейта: сперва bundle/подмена приложения, потом
  живые файлы.
- **Бэкап-отравление и чистка** (находки 11, решение 6) — самая тихая из возможных поломок: «Снять» вернёт патченый
  архив, и никто не заметит. Тест `testBackupIsNotPoisonedByOldLoader` и сценарий (е) — обязательны.
- **Пересечения по файлам.** `AppDelegate.swift` и `Notifier.swift` пишут WF17, WF21, WF22, WF27. Разводится очередью
  марафона (WF26 — двенадцатый); ветку резать от свежего `main`, состав меню и категорий брать **фактический из кода**,
  а не из этого плана.
- **Зависимость от WF17** (решение 10): состав уведомлений и наличие `ClaudeUpdates.swift` определяется его батчем S,
  а правило `claude.css` в `Patcher.swift` он мог переписать слиянием по маркерам (Б4) — тогда решение 5 отменяется.
  Обе проверки — командами перед стартом, результат в run-файл.
- **Заморозка базового `claude.css`** (В7): при варианте «не трогать никогда» третье базовое правило не доедет ни до
  кого. Смягчение — умное исключение (побайтная сверка вне маркеров) плюс строка в `AGENTS.md` и пункт в `CHECKLIST.md`.
- **До Sparkle (WF27) сам WF26 не доедет до команды автоматически** — только ручной раздачей zip; в презентации
  Элвису сказать честно.
- **Claude 832 МБ.** Переподпись на батарее и при загруженном процессоре может занять заметно дольше «полминуты»;
  в текстах не обещаем секунд, в журнале пишем фактическую длительность.
- **macOS 13–15 у команды.** Поведение «Управления приложениями» там иное, живьём не проверено (общий хвост проекта,

- **Тесты патчера зависят от живого Claude.app** (копируется в temp): на машине без Claude весь набор пропускается —
  красное там не покажется. Гейт гоняется на Маке Элвиса, где Claude есть.
- **Критик плана**: обязателен до запуска (отдельный агент, Opus max, свежий контекст) — WORKFLOW.md п. 2.

### [блокер]

**Б1. Вторая копия Claude.app делает `.lost` из ничего — и мы молча патчим Claude, который никто не выбирал.**
Главный довод плана («чиню только `.lost`, значит патч уже ставили руками») по коду неверен. `installedRecord()`
(`Patcher.swift:525`) читает из `installed.json` только `version`/`headerSHA256`/`loaderVersion` — поле `appPath`
туда пишется (`writeInstalled`, :535), но **не сверяется никогда**. А `refreshState()` (`AppDelegate.swift:122`)
берёт копию через `chosenClaude(askIfSeveral: false)`, который без сохранённого `claudeAppPath` отдаёт
**`copies[0]`** (:198) — не обязательно ту, что патчили. Итог: непропатченная вторая копия (`~/Applications/Claude.app`,
свежескачанный Claude рядом со старым) даёт `recorded != nil` + несовпадение хэша → разбор asar → `loaderVersion == 0`
→ **`.lost («Claude обновился»)`** (`Patcher.swift:285,288`). Сегодня это стоит красного «!», с WF26 — тихий патч
чужого приложения без единого клика. Это ровно тот сценарий, от которого план защищается словами.
**Правка (батч A + B, обязательна):**
1. `installedRecord()` читает `appPath`; `RepatchDecision` получает его отдельным параметром и возвращает `.nothing`,
   если `recorded.appPath != appURL.path` (сам `state()` не менять — иначе поедет поведение «Claude переехал»).
2. Тихий путь запрещён, когда `Patcher.locateClaude().count > 1` **и** `UserDefaults` `claudeAppPath` пуст:
   в этом случае только плашка «несколько копий Claude — выбери, какую чинить», как в `install()`.
3. Тест `testRepatchRefusesForeignClaudeCopy`: `installed.json` с чужим `appPath` → `.nothing` при любом `.lost`.

**Б2. Кэш разбора asar (решение 8) в нынешнем виде не заведётся: `ClaudePatcher` — структура, и её создают заново
на каждый опрос.** `AppDelegate.refreshState()` пишет `ClaudePatcher(appURL: url).state()` (`AppDelegate.swift:126`),
`state()` объявлен `public func` (не `mutating`) на `struct` (`Patcher.swift:270`) — запомнить `(mtime, size)` в
поле экземпляра нельзя, а если бы и можно — экземпляр живёт один вызов. Находка 10 (41 МБ mmap раз в 60 с в
состоянии «слетел») при этом верная, чинить надо.
**Правка (батч A):** кэш — **статический**, за замком, ключ `(asarURL.path, mtime, size)`, значение — `AsarStatus`;
счётчик разборов для теста — там же, `static` , со `static func resetForTests()`, который зовётся в `setUp`
(иначе `testStateReusesAsarProbeWhileUnchanged` будет ловить чужие вызовы: XCTest гоняет все классы в одном
процессе). Читают кэш два потока (`refreshState` — `DispatchQueue.global`, `menuWillOpen` — главный), значит
`NSLock` или своя serial-очередь обязательны, «просто static var» — гонка.

**Б3. Предохранителя нет: неудачная тихая починка повторяется вечно раз в 60 с.** `pollTimer`
(`AppDelegate.swift:56`) дёргает `refreshState()` каждую минуту; при неудаче состояние остаётся `.lost`, `busy`
уже снят — и через 60 с мы снова закрываем Claude (в ветке гонки), снова гоняем `codesign --force --deep` по
832 МБ и снова пишем строку в журнал. Через три часа журнал (200 строк) состоит из одной и той же ошибки, а
батарея — из `codesign`. Особенно живо это на отказе «Управление приложениями» и на нечитаемом `app.asar`
(`state()` :278 отдаёт четвёртую причину «app.asar не читается», которой нет в таблице решения 1; `install()`
на ней падает ещё на `Asar.status` :199 — то есть чинить её бессмысленно).
**Правка (батч A + B):**
1. `RepatchDecision` берёт **список разрешённых причин** явным перечислением (три из таблицы решения 1);
   «app.asar не читается» и всё незнакомое → `.nothing` + одна строка в журнал.
2. `RepatchGuard`: не больше **двух** тихих попыток на пару `(версия Claude, причина)`. Счётчик — в `UserDefaults`,
   сбрасывается при смене версии/причины, при удачной починке, при ручном «Поставить…» и при переключении тумблера.
   Исчерпали — переходим на плашку с текстом ошибки и больше не трогаем.
3. Тест `testRepatchGuardStopsAfterTwoFailures` и `testRepatchIgnoresUnknownLostReason`.

**Б4. Проверка перед стартом ловит не тот файл: правило `claude.css` могло быть переписано ещё в WF17.**
Решение 10 велит проверить `git log main -- app/Sources/Patcher/ClaudeUpdates.swift`, но опаснее другое: план WF17
(строки 98–101) прямо допускает, что **батч S чинит `installLiveFiles` слиянием по маркерам** и тогда «S владеет
ещё и `Patcher.swift`». WF17 идёт седьмым, WF26 — двенадцатым. Если S выбрал вариант (а), в `main` уже лежит

контракт на тот же файл за одну неделю, и часть команды получит оба.
