## Решено (не переспрашиваем)

- **Одно меню везде.** Клик по значку в строке меню открывает ТО ЖЕ меню, что жёлтая кнопка окна (`MinimizeMenu.build`),
  для окна Claude в фокусе (нет фокуса — первое видимое). Служебное — «⚙️ Пимп ▸» последним пунктом в ОБОИХ меню.
  Окон Claude нет вовсе — по клику на значок меню из служебных пунктов (как сегодня) + «📊 Статистика» и «📄 Отчёты».
  Меню со значка работает и при выключенном тумблере «Меню на жёлтой кнопке» (он гасит только наведение).
- **Служебное подменю «⚙️ Пимп ▸»**: строка состояния патча (серая, как сейчас) · Поставить… · Снять… · Статус… · ─ ·
  Авто-Allow · Меню на жёлтой кнопке · «⌘Q не закрывает Claude» (бывший «Блок ⌘Q» — Элвис его не понял) ·
  Запускать при входе · ─ · Настроить разрешения… · История авто-Allow… · О программе · ─ · Выйти из PimpMyClaude.
- **«📊 Статистика» и «📄 Отчёты»** — два пункта верхнего уровня после «🧹 Всё как у Claude», перед «⋯ Ещё ▸»:
  открывают окно Пимпа на нужной вкладке. Клавиш у них нет (хоткеи — по `MenuModel.entries`, он не меняется).
- **Значок** — своя вспышка-звезда по мотивам Claude (9 лучей разной длины, скруглённые), на месте десятого луча
  внизу справа — точка состояния: 🟢 патч стоит · 🔴 слетел · серая — не стоит · Claude не найден — звезда
  вполсилы без точки. Рисуется кодом (`StatusIcon.swift`); картинка Астры (промт — `audit/astra-prompt-icon-2026-09-17.md`)
  встанет на место звезды, когда будет, — слот под неё сейчас не заводим (раздувание). Иконку приложения
  (Dock/Finder, `AppIcon.icns`) Астра рисует той же просьбой.
- **Окно Пимпа** — одно окно, две вкладки (📊 Статистика · 📄 Отчёты), WKWebView; встаёт СПРАВА от окна Claude в
  фокусе на всю его высоту, ширина 520 (места справа нет — прижать к правому краю экрана поверх); повторный вызов —
  переключить вкладку и поднять. Оно же — будущая «админка чатов» (#5433) и «Разборщик» (#5635): третьей вкладки нет.
- **Статистика — по решениям Радуги, без её кода** (`docs/raduga-stats-2026-09-17.md`): периоды «Сегодня · 7 дней ·
  30 дней · Всё» (умолчание 7 дней), шапка «N токенов · если бы по API — $X», полоса долей проектов в их цветах,
  топ-3 колонками, столбики по дням с подписями сверху и снизу, список проектов свёрнутыми строками. Круговая и
  «деньги подписки как доля платежа» — НЕ в этом плане (Элвис сам покажет, как было в других проектах). Ни одного
  выдуманного числа: нет данных — пусто и слово «пока пусто».
- **Цвет проекта в окне — тот же, что у его окон** (критик): цвет отдаёт приложение замыканием `colorOf(folder)` —
  акцент темы из `.pimpmyclaude.json` через `ProjectPaint.wanted` (Dictator — «Матрица» зелёная, TrelvisBot — «Дракула»),
  `"theme": null` → нейтральный серый, файла нет — авто-тон FNV-1a → hsl (тот же `AutoPaint`). В контракте окна поле
  `color` (hex), не `hue`.
- **История копится с установки.** Claude хранит транскрипты только открытых чатов (на Маке Элвиса 17.09 — 13 файлов
  чатов, ~15 тысяч ответов с агентами, все за 16–17.09; закрытый чат уносит свой файл). Приложение раз в 5 минут
  дочитывает хвосты и складывает ЗАПИСИ ОТВЕТОВ в `MyClaude/stats/ledger.json` — прошлое до установки не восстановить,
  об этом строка в окне.
- **Цена — по прайсу API** (`claude-api`, срез 24.06.2026; критик сверил — совпадает): Fable 5 / 5.1 — $10 / $50 за 1M
  (вход / выход); Opus 5, 4.8, 4.7, 4.6 — $5 / $25; Opus 5 в быстром режиме (`usage.speed == "fast"`) — $10 / $50;
  Sonnet 5 — $2 / $10; Sonnet 4.6 — $3 / $15; Haiku 4.5 — $1 / $5. Кэш: чтение 0,1 × вход (Fable 5.1 — 0,025 ×),
  запись 5 мин 1,25 ×, запись 1 ч 2 ×. Незнакомая модель — ставка Opus и пометка «≈». Таблица датирована в коде;
  старше 120 дней — слово «прайс устарел» в окне, не молчание. `usd` в леджере НЕ хранится — считается на показе из
  токенов: правка прайса задним числом честная. (В данных Элвиса сегодня `speed` — `standard` или нет; `fast` — 0 из
  15 138 ответов: фикстуру с `fast` держим, ожиданий на него не строим.)
- **Один ответ — один раз.** Ответ модели лежит в jsonl несколькими строками с `usage` (грабля Радуги, ×1,9):
  ключ дедупа — `message.id`, ПОСЛЕДНЯЯ строка с этим id побеждает (критик проверил на 5 193 id: у последней всегда
  наибольший `output_tokens`, остальные поля равны; расходятся в половине случаев — замена «старое вычесть, новое
  прибавить» обязательна). Строки `<synthetic>` с нулевым usage — пропуск, не пометка «≈».
- **Цена воркфлоу на карточке — по ПРОГОНАМ, не по окну времени** (критик: окно + mtime врёт при параллельных
  воркфлоу — сейчас их два в VkusnoffKz — и в многодневных чатах). Данные, которые есть точно:
  `<sessionId>/workflows/wf_<runId>.json` (`startTime`, `durationMs`, `agentCount`, `totalTokens`) и агенты прогона в
  `<sessionId>/subagents/workflows/wf_<runId>/agent-*.jsonl` — их цена принадлежит прогону ТОЧНО. Правило:
  прогон относится к блоку status.md, в чьё окно «ЧЧ:ММ → ЧЧ:ММ» попадает его старт; день блока — последний день,
  в который у сессий проекта есть прогон в этом окне (нет ни прогона, ни ответов — цены НЕТ: узел пуст, никакого «≈»
  на пустом месте); ходы самого оркестратора (главный jsonl сессии) в окне блока делятся поровну между блоками с
  перекрывающимися окнами. Парсер времени принимает «22:15 → закончит завтра · идёт 40 мин», «20:25 → 01:40 · 5,2 ч
  (в т.ч. …)», переход через полночь. Число на карточке всегда с «≈». Точнее станет только с датой в строке времени
  шаблона status.md (правка SkilZZZ/AGENTS.md — слово Элвиса, не в этом плане).
- **Контракт `status` расширяется полем `costs`** у проекта:
  `{"name":"…","text":"…","costs":[{"n":1,"usd":4.20,"tokens":1234567}]}` — порядок ключей побайтно; `usd` — JSON-число
  РОВНО с двумя знаками после точки (`%.2f`), `n` и `tokens` — целые; `costs` есть только у проектов, где посчиталось,
  и только для блоков с ценой. Канал сегодня пишет только `Int` (`CommandValue.number`) — волна 2 добавляет
  `CommandValue.decimal(String)` с этим форматом. Страница без `costs` работает как раньше; старая страница поле не
  заметит.
- **Отчёты** — все `*.html` в `<projectsRoot>/*/{docs,audit,work,reports}/` и на одну папку глубже (без `node_modules`,
  `.build`, `dist`, скрытых), свежие сверху, у каждого: проект (точка в его цвете), заголовок (`<title>` → первый `<h1>` →
  имя файла), дата и время. Просмотр — в правой части окна (свой WKWebView с доступом только к папке файла). Кнопки над
  файлом: «🌐 Открыть в Chrome» · «📋 Копировать» (файл в буфер, как WF69) · фильтр по проекту. Внизу списка —
  «❓ Как это работает?» → страница-объяснение (в бандле) в той же правой части. Кнопок ◀ ▶ и поля поиска в этом
  прогоне нет (критик: у одиночного файла истории нет).
- **Страница «Как это работает»** — для людей, открывается и в Chrome («Открыть в Chrome» на ней работает): что за
  файлы, откуда берутся, три шага «как получать такие же» (поставить PimpMyClaude → подключить правила SkilZZZ →
  скопировать промт своему агенту), окошко с промтом и кнопкой «Скопировать», надпись «Скилы должны быть подключены»
  ровно этими словами, и пример. Ссылка на SkilZZZ ведёт на `github.com/ElvisIglikov/SkilZZZ` — репозиторий сегодня
  ПРИВАТНЫЙ; сделать публичным — слово Элвиса (в презентации).
- **HEIC (#6365)** в этот план не входит — отдельная задача, названа Элвису как «то важное, что забыл» (кандидат).
- Версия приложения не поднимается в волне; на гейте после стыковки — `1.6.0 (11)`, сборка, подмена без простоя.
  Команде выпуск — отдельно (у них 1.3.0 и старая инструкция, #5381).

## Сборка: правило волны 1 (критик — «один build на волну»)

Три Swift-батча в одном SwiftPM-пакете: `swift test` на macOS — один xctest-бандл на пакет, и один не компилирующийся
файл в чужом таргете валит его всем. Поэтому:
- **До волны оркестратор** правит `app/Package.swift`: `.target(name: "UsageStats", path: "Sources/UsageStats")`,
  `.target(name: "PimpPanel", path: "Sources/PimpPanel")`, `.testTarget(name: "UsageStatsTests", dependencies: ["UsageStats"],
  path: "Tests/UsageStatsTests")`, `.testTarget(name: "PimpPanelTests", dependencies: ["PimpPanel"], path: "Tests/PimpPanelTests")`
  + по одному компилирующемуся файлу-заглушке в каждом из четырёх каталогов (`public enum UsageStats {}` / `public enum
  PimpPanel {}` и тривиальный тест), `swift build` и `swift test` зелёные — это и есть точка отката `wf72-start`.
- **В волне** каждый Swift-батч держит свои файлы компилирующимися постоянно; быстрые проверки — `swift build --target
  <свой>` и `swift test --filter <свои тесты>`; полный `swift test`, `tools/test.sh` и `tools/bundle.sh` — только гейт.
  Владелец сборки волны 1 — гейт (оркестратор). Фикстуры jsonl — `tests/fixtures/usage/` от корня через `#filePath`,
  как у всех тестов проекта (без `resources:` в Package.swift).
- Волна 2: `ClaudeAX` получает зависимость `UsageStats`; `PimpMyClaude` — `PimpPanel` и `UsageStats`; `ClaudeAXTests` —
  `UsageStats`. Циклов нет: `UsageStats` и `PimpPanel` ни от чего не зависят.

   `AppDelegate` показывает служебное меню сам (пункты «📊 Статистика», «📄 Отчёты», ─, служебные, ─, Выйти) тем же

- C1 + C2 — окно, мост, политика навигации, страницы на 420 px.
E проверяет гейт волны 2 полным `tools/test.sh` и probe.

## Что может пойти не так

- Атрибуция прогонов к блокам — эвристика по времени старта; параллельные воркфлоу с одинаковым окном делят ходы
  оркестратора поровну. На карточке всегда «≈»; нет данных — нет числа.
- WKWebView и `file://`: доступ только к папке файла и подпапкам; права копятся между загрузками в одном процессе
  страницы — для чужого html это чтение своих же папок проектов, сеть закрыта политикой навигации.
- `~/.claude` может отсутствовать у команды — пусто, без ошибок; леджер тогда не пишется.
- Два новых таргета — `swift build` дольше на ~10 с; `tools/test.sh` гоняет `swift test` целиком — новые тесты
  попадают сами.
