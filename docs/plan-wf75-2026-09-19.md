# План WF75 «Голосовой Пимп» — 19.09.2026

Слово Элвиса 19.09.2026 ~22:50 и 23:30 (задачи #6540–#6548, приоритет максимальный): «Пимп, …» голосом из
Диктатора → дешёвая быстрая модель → команды окнам Claude. «Просто сделай, как я сказал… побыстрее… в режиме
Workflow, опусов преимущественно, эффорты можешь подснизить». Одобрение на план — этим словом; макета нет: экранов
не добавляется, только тексты плашки HUD и ответы CLI.

Сложность: сложный (два модуля + внешний сервис DeepSeek). Оркестратор — Fable 5.1 high. Критик — Opus xhigh,
кодинг Swift — Opus max, кодинг CLI — Opus xhigh, проверка — Opus xhigh (эффорты снижены по слову Элвиса).

## Замысел

1. **Диктатор** (чужой проект, задача #6548, делает чат Диктатора — НЕ этот прогон) вырезает из расшифровки кусок
   от слова «Пимп» до конца или до второго «Пимп» и отдаёт его текстом на stdin команде
   `python3 <репо>/tools/pimp.py say -`. Сети у Диктатора нет — в сеть ходит только Пимп.
2. **`pimp.py say`** (CLI, полоса 3) — мозг: шлёт фразу в DeepSeek (`deepseek-v4-flash`, рассуждения выключены,
   `response_format: json_object`, таймаут 8 с; замер 19.09: 1,2–1,3 с на команду) вместе с каталогом команд и
   живым списком проектов, получает `{"steps":[…],"say":"…"}`, проверяет шаги по белому списку и исполняет их ПО
   ОЧЕРЕДИ через существующий канал `pimp/` (ответ «busy» — ждать и повторить, как в скилле). Итог — одной
   строкой в stdout и плашкой HUD (действие `hud`).
3. **Приложение** (Swift, полоса 2) получает в канал пять новых действий (ниже). Лоадер и `inject.js` НЕ трогаем.

Ключ: `~/Library/Application Support/MyClaude/pimp-voice.env`, строка `DEEPSEEK_API_KEY=` (уже заполнена Элвисом,
0600). Значение не печатать, не логировать. Необязательные `DEEPSEEK_MODEL`, `DEEPSEEK_BASE_URL` там же.

## После критика (Opus xhigh, 12 блокеров, 17 замечаний — `docs/critic-wf75-2026-09-19.md`, ЧИТАТЬ исполнителям)

Принято всё, кроме трёх мест, решённых оркестратором иначе (по слову Элвиса):
- **Адрес вставки**: критик убрал «переднее окно». Оставлено ЯВНЫМ ключом `front:true` — Элвис жмёт F5 в том чате, куда
  хочет вставить, это то же, что его собственное ⌘V. Условие: Claude — передняя программа (`NSWorkspace.frontmostApplication`),
  цель — его окно в фокусе; иначе `no-windows`. Без `front` — адрес `from` или `project`, как у критика.
- **`close` в `say`** остаётся (Элвис просил), но с воротами в КОДЕ: во фразе есть слово «закр…»/«убери окно»; защита канала
  (`ambiguous`, `main-window`, только `AX.close`) — по критику.
- **«Вчера» (снимок дня) вынесен в следующий круг WF76** целиком (задача #6545 остаётся открытой) — по критику.
Выкинуто по критику: `last-chats.json` (чат даёт `ProjectIndex`), два paste-действия → одно `paste`, журнал на 500 записей →
mtime последней вставленной фотки, правило «Вкуснофф первым» — в `tools/voice_prompt.md`, не в коде.
Приватность, сказано вслух: фраза после слова «Пимп» и ИМЕНА проектов (не пути) уходят в DeepSeek — это слово Элвиса 19.09.

## Контракт новых действий канала (эталоны батча 0 написаны: `tests/fixtures/pimp/`, раздел WF75 в README там)

Порядок ключей запроса: `id, at, action, from`, затем поля действия. Ответ: `id, at, ok, error, fromResolved, screen`, затем
поля действия. Старые эталоны побайтно прежние. Новые ошибки: `chat-missing`, `ambiguous`, `main-window` (и в `ERRORS` CLI).
CLI на `busy` повторяет запрос с НОВЫМ `id` и свежим `at`.

- **`new-window` + `chat`** — необязательный ключ ПОСЛЕ `place`: `"last"`; любое другое значение — `bad-request`. «Последний» =
  `ProjectIndex`: свежайшая по `lastFocusedAt` не архивная сессия с этой папкой; нет — `chat-missing`. Чат уже открыт окном —
  окно поднимается (новое сиденье `PimpSeats.raise` В КОНЕЦ структуры) и ставится на место, `opened:false`. Закрыт — выносится
  путём «↩︎ Вернуть эти чаты»: `seats.openChat` → `popout-window`; ждём новое окно ИМЕННО ЭТОГО чата 15 с
  (`restoreWindowSeconds`, фильтр как `PimpChannel.accepts`, в `Job` поле `chat`), не дождались или главного окна нет —
  `window-missing`. Ответ: прежние `window`, `layers`, `skipped` (как сегодня), ПОСЛЕДНИМ `opened` — только когда в запросе
  был `chat`.
- **`close-window`** — `…, project`. Окна проекта — по папке окна (`PimpChannel.matches`, живая карта probe; молчит —
  `window-missing`). Закрываем ТОЛЬКО `AX.close` конкретного окна; ⌘W не шлём никогда (#5734). Из кандидатов выбывают: окно
  `isMainWindow`, окно с пустым заголовком или заглушкой (`ProjectIndex.isStub`). Дальше: кандидатов ноль, а главное окно
  принадлежало проекту — `main-window`; ноль совсем — `window-missing`; два и больше ИЛИ главным опознаны два окна —
  `ambiguous` + `windows:[заголовки]`; `AX.close` вернул false — `window-missing`. Ответ: `closed`. Чат не удаляется.
- **`paste`** — `…, front?, project?, paths?:[абс. пути]` (порядок ключей именно такой; 0…20 путей). `paths` нет — вставляем
  буфер как есть (`pasted:0`); есть — `NSPasteboard.writeObjects([NSURL])`, прежний буфер НЕ восстанавливаем. Окно: `front:true`
  (условие выше) → иначе чат `from` → иначе единственное окно `project` (`ambiguous`/`window-missing`). Порядок: `app.focus(window:)`
  → `focusDelay` → ⌘V (`kVK_ANSI_V` 0x09) → ответ ПОСЛЕ нажатия. **Enter канал не шлёт никогда.** Путь не абсолютный, нет на
  диске, не файл, больше 20 — `bad-request`. Ответ: `pasted`, `window`. Зависимость: в поле ввода вставку приводит страница
  (WF64) — без свежего патча ⌘V уйдёт туда, где курсор.
- **`hud`** — `…, text` (1…200 знаков, длиннее — обрезать, пусто — `bad-request`). Штатное сиденье `PimpSeats.notice`. Ветка в
  `PimpChannel.answer` стоит ВЫШЕ `guard !isBusy`. Ответ без полей.

## Батчи (одна волна, две полосы; эталоны батча 0 готовы)

### A · CLI и мозг — Opus xhigh
Файлы: `tools/pimp.py`, `tests/pimp_cli_test.py`, новый `tools/voice_prompt.md` (системный промпт = каталог команд; читается

- Подкоманды: `open … --last`, `close <проект>`, `paste-airdrop`, `paste-clipboard`, `hud <текст>`.
- `paste-airdrop`: картинки `~/Downloads` (jpg, jpeg, png, heic, heif, gif, webp); порция = свежайшая и все цепочкой назад с
  разрывом ≤ 120 с, но только СВЕЖЕЕ отметки `voice-pasted.json` `{"mtime":…}` (mtime последней вставленной); свежайшая
  старше 30 минут → «свежих фоток нет»; всё вставлено → «новых нет»; не больше 20, порядок по времени; запрос `paste` с
  `front:true`; после `ok` — обновить отметку. Каталог загрузок — переменная `MYCLAUDE_DOWNLOADS` (для тестов).
- `say <текст|->`: DeepSeek `POST {base}/chat/completions`, модель `DEEPSEEK_MODEL` или `deepseek-v4-flash`,
  `thinking:{type:disabled}`, `response_format:{type:json_object}`, `max_tokens` 400, таймаут 8 с, ключ только заголовком
  `Authorization`. 400 «model not found» → «Пимп: модель <имя> не принята». Пути ключа и журналов — из переменных
  (`MYCLAUDE_VOICE_ENV`, каталог рядом с `MYCLAUDE_PIMP_DIR`); при `MYCLAUDE_VOICE_FAKE` (путь к JSON-ответу) сеть и ключ
  не трогаются ВООБЩЕ (проверка до чтения ключа). В модель уходят только ИМЕНА проектов.
  Белый список шагов: `open{project,place?,chat:new|last}`, `arrange{layout?,order?}`, `close{project}`,
  `layout_save{name}`, `layout_restore{name,fresh?}`, `paste_airdrop`, `paste_clipboard`, `projects`, `windows`,
  `none{say}`. Проект вне списка `projects` → шаг отклонён («не знаю проект …»). Не больше 5 `open`; после нескольких `open` —
  один `arrange --order <как вернула модель> --layout last`. Ворота в коде: `close` — только если во фразе «закр»/«убери окно»;
  `paste_airdrop` — только если «фот»/«картин»/«эйрдроп»/«airdrop». Общий бюджет 3 минуты, частичный итог («сделал 2 из 3»).
  Итог — строкой в stdout и плашкой `hud`; ошибка сети/JSON → плашка «Пимп не понял: …», код 1.
- `voice-log.jsonl` (0600): at, фраза, шаги, итог, мс, имя модели; без ключа; ротация 1000 строк.
- `tools/voice_prompt.md`: команды словами с примерами фраз Элвиса из задач #6540–#6547; правила порядка («VkusnoffKz всегда
  первым слева, остальные как названы», «чем левее, тем важнее»); «открой чаты» без слова «последние» = новые; словарь имён

## Риски
- ⌘V в чужое окно: `paste-*` обязан проверить, что впереди Claude, иначе отказ.
- Снимок дня может вытеснить ручные раскладки (лимит 30) — свой лимит 7 и отдельный префикс.
- `close-window`: двусмысленность → отказ, главное окно не закрывать.
