## Решения

### Р1. Раскладка — перечисление `ArrangeLayout.Mode`, чистая арифметика

```swift
enum Mode: String, CaseIterable { case ribbon = "row", four = "4", five = "5", tenGrid = "5x2" }
static func frames(count: Int, in area: CGRect, mode: Mode = .ribbon, minCellWidth: CGFloat = minCellWidth) -> [CGRect]
static func capacity(of mode: Mode) -> Int?      // ribbon → nil (сколько окон, столько ячеек); 4 → 4; 5 → 5; 5x2 → 10
```

- `ribbon` — ровно сегодняшний счёт; существующие тесты и вызовы (`mode` по умолчанию) не меняются.
- `four`/`five` — N столбцов во всю высоту, ширина ячейки `area.width / N` **без оглядки на `minCellWidth`**; окон
  меньше N — первые ячейки слева направо, остальные пустые (окна НЕ растягиваем: сетка «остаётся», пустые ячейки ждут
  новые окна). Ячейка уже `minCellWidth` (у Элвиса 280) → раскладка невозможна: меню пункт серый с подсказкой «экран
  уже», канал — `too-small`.
- `tenGrid` — 5 столбцов × 2 ряда, заполнение слева направо, сверху вниз; окон ≤ 5 — только верхний ряд, вполовину
  высоты (это и есть «в два ряда» по слову Элвиса: сетка остаётся).
- Окон больше ёмкости — **лишние не трогаем**: берём первые `capacity` по `ArrangeLayout.order` (слева направо, сверху
  вниз), остальные стоят где стояли. Ответ канала перечисляет ТОЛЬКО переставленные плюс поле `skipped:<число>`.
- Границы ячеек — как сегодня (`floor(x + 0.5)`), плитки без щелей.

### Р2. Последняя раскладка — `UserDefaults` ключ `arrangeMode` (строка `Mode.rawValue`)

- ⌥⌘A и «▦ Расставить» в «⋯ Ещё ▸» применяют последнюю (по умолчанию `row`). Картинка в меню закрепляет выбор.
- Канал: `layout:"last"` — тоже последняя; `layout:"row"|"4"|"5"|"5x2"` — конкретная, и она же становится последней.
  Читать/писать через тот же протокол настроек, что у тем (`ThemeDefaults`), чтобы тесты не трогали живые настройки.

### Р3. Полоса картинок — первый пункт меню жёлтой кнопки

- `NSMenuItem` с `view = LayoutPickerView` (новый файл `LayoutPicker.swift`): четыре плитки «4», «5», «5×2», «как
  сейчас» — мини-схемы столбиками, рисуются кодом (`NSBezierPath`), без картинок; выбранная — подсвечена цветом акцента;
  наведение — подсветка; клик — `config.arrange(mode)` и закрытие меню (как `BlockMenuItem`). Пункт стоит ПЕРВЫМ, до
  «🚀 Workflow»; после него разделитель. Ширина плитки ~54 pt, высота ~40, полоса не шире меню.
- Недоступная раскладка (ячейка уже `minWindowWidth`) — плитка серая, подсказка «экран уже».
- «▦ Расставить ⌥⌘A» в «⋯ Ещё ▸» остаётся: текст пункта дополняется последней раскладкой («Расставить · 5 в ряд»).
- Примерки (`PreviewMenuDelegate`) полоса не трогает; тесты меню (`testMenuKeysMatchReadme`, `testSkeleton` и
  структура «Ещё ▸») правятся минимально: +1 пункт с view на верхнем уровне.

### Р4. Канал «Пимп» — расширение `arrange` (WF21) и новые действия (WF41), эталоны до старта

Эталоны `tests/fixtures/pimp/` пишет оркестратор ДО волны, оба конца на них стоят; порядок ключей ответа прежний
(`id, at, ok, error, fromResolved, screen`, потом поля действия).

WF21:
- Запрос `arrange`: `{"id","at","action":"arrange","from","layout":"row"|"4"|"5"|"5x2"|"last"}` (умолчание CLI — `row`,
  как сегодня; `--layout` в CLI). Ответ: `…,"screen","layout":"<применённая>","windows":[…],"skipped":<число>,"minimized"`.
  Ошибка `too-small` — ячейка уже `minWindowWidth`; `bad-request` — незнакомая `layout`.

WF41:
- `arrange` получает необязательное `"order":["VkusnoffKz","SkilZZZ","PimpMyClaude"]` (имена папок проектов, как в
  `projects`): окна этих проектов встают в этом порядке первыми (проект без окна — пропуск, `missing:[…]` в ответе),
  остальные окна — за ними в прежнем порядке; раскладка — `layout` как выше.
- `layouts` — список сохранённых: `{"layouts":[{"name","at","cells":<число>}]}`.
- `layout-save` `{…,"name":"Утро"}` — запомнить текущее: на каждое окно `{project, chat, title, cell}` (ячейка по
  текущей раскладке; окно вне сетки — `cell:null`), ответ `{"name","cells"}`. Имя есть — перезапись.
- `layout-restore` `{…,"name":"Утро","fresh":false}` — вернуть: **`fresh:false` — те же чаты** (окно с таким чатом уже
  открыто → просто ставим в ячейку; закрыто → главное окно выбирает чат по id строкой сайдбара и выносит попапом
  `popout-window` в ячейку; чат пропал из индекса → новый пустой по тому же проекту); **`fresh:true` — новые чаты по тем же
  проектам** через сегодняшний `new-window`. Окна открываются ПО ОДНОМУ (цепочка «Новое окно» до 40 с каждая), ответ
  канала уходит после последнего; CLI ждёт до `MYCLAUDE_PIMP_WAIT` × число окон. Ошибки: `layout-missing`, `busy`.
- `projects` получает `"status":true` → у каждого проекта поле `"state":"<строка состояния>"` (последняя строка вида
  `💭⚪[…] · WF N из M · идёт💭` из `docs/status.md`/`audit/status.md` проекта, значки и слово; нет файла — `""`).
  Так «какие проекты и что в них» отвечает одной строкой на проект.
- Хранилище раскладок — `LayoutsStore.swift`, файл `~/Library/Application Support/MyClaude/layouts.json`
  (`{"version":1,"layouts":[{name,at,mode,cells:[{project,chat,title,cell}]}]}`), лимит 30, атомарная запись,
  по образцу `ProjectsStore`. Поле `pos` в `window-themes.json` НЕ используется (владелец геометрии — этот файл).

### Р5. Меню «раскладки проектов» — подменю в полосе картинок? Нет: пункт «🗂 Раскладки ▸» в «⋯ Ещё ▸»

`💾 Сохранить эту раскладку…` (диалог имени как у «Мои темы»), список имён, у каждого подменю: `↩︎ Вернуть эти чаты`,
`✨ Новые чаты по этим проектам`, `🗑 Удалить`. Полосу картинок не перегружаем — в ней только четыре плитки (макет).

### Р6. Страница (inject.js) — одна новая ступень для `layout-restore`

`popout-window` получает необязательные поля после `y`: `"chat":"local_<id>"` — главное окно **сначала выбирает чат по
id** (строка сайдбара, как «возврат на прежний чат» в 12б; нет строки — ошибка `chat-missing` в `status().popout`), потом
выносит его окном по `x,y`. Порядок ключей побайтно `scope,title,match?,x,y,chat?`. Никаких других правок страницы;
VERSION → `wf41-a-1`. Один писатель `inject.js` — батч E.

### Р7. Слова (скилл `pimp`) — словарь одним разделом

| Элвис сказал | вызов |
|---|---|
| «расставь», «в ряд», «как было/как сейчас» | `arrange` (`--layout row`/`last`) |
| «четыре в ряд», «пять в ряд», «в два ряда», «десять» | `arrange --layout 4` / `5` / `5x2` |
| «Вкуснофф первым, потом Скиллз, потом Пимп» | `arrange --order VkusnoffKz,SkilZZZ,PimpMyClaude [--layout …]` |
| «запомни раскладку как Утро» | `layout save Утро` |
| «открой окна, как стояли», «верни Утро» | `layout restore Утро` |
| «новые чаты по Утру» | `layout restore Утро --new` |
| «какие раскладки» | `layouts` |
| «какие проекты и что в них» | `projects --status` |

Имена проектов — из `projects`; нечёткое слово («Скиллз» → `SkilZZZ`) сопоставляет скилл, а не CLI (как сегодня).

## Риски

1. Ячейка 294 pt при пяти окнах: Electron не даст окно уже `minWindowWidth` — у Элвиса 280, у команды 360 → у них «5» будет
   серой с подсказкой; в TEAM.md — строка про `claude.json`.
2. `setFrame` спит на главной нити до 2 с при 4 окнах (#5557) — при десяти окнах до 5 с; в этот прогон не чиним, но
   `arrange` шлёт HUD «расставляю…» до цикла.
3. `layout-restore` тех же чатов зависит от строки сайдбара главного окна (`row` = null в главном окне, #5537): батч E
   ищет строку по id в DOM сайдбара, не по `status().chat.row`; не нашёл — честный `chat-missing`, новый пустой чат
   по проекту НЕ подставляется молча (как #5455).
4. Меню с custom view и примерка: `PreviewMenuDelegate` гасит примерку на закрытии — клик по плитке идёт тем же путём,
   что `BlockMenuItem` (закрыть меню → выполнить на ход вперёд), иначе «Расставить» сработает под открытым меню.
5. Пересечение по файлам с чужими прогонами: других run-файлов в `идёт` на 08.09 нет (WF22 и WF37 — финиш).
