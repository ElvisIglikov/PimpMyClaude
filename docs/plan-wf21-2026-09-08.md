## Решения

### Р1. Раскладка — `ArrangeLayout.Mode`, чистая арифметика

```swift
enum Mode: String, CaseIterable { case ribbon = "row", four = "4", five = "5", tenGrid = "5x2" }
static func capacity(of mode: Mode) -> Int?                                   // ribbon → nil; four → 4; five → 5; tenGrid → 10
static func frames(count: Int, in area: CGRect, mode: Mode = .ribbon, minCellWidth: CGFloat = minCellWidth) -> [CGRect]
static func fits(_ mode: Mode, in area: CGRect, minCellWidth: CGFloat) -> Bool  // ширина ячейки ≥ minCellWidth
```

- `ribbon` — ровно сегодняшний счёт; вызовы без `mode` и тесты `testColumnsKeepOneRowWhileCellsAreWideEnough`,
  `testFramesTileAreaWithoutGaps`, `testFramesFillRowsTopDown` не меняются.
- `four`/`five` — N столбцов во всю высоту, ячейка `area.width / N`; `tenGrid` — 5×2, заполнение слева направо, сверху
  вниз (при ≤ 5 окнах — только верхний ряд вполовину высоты; Элвису это сказано словами в презентации).
- **`frames` возвращает ровно `min(count, capacity)` рамок** в порядке ячеек; окон меньше — остальные ячейки пустые
  (окна не растягиваем, «сетка остаётся»). Окон больше — первые `capacity` по `ArrangeLayout.order`, остальные не трогаем.
- `fits` ложно (ячейка уже `minCellWidth`) → плитка серая в меню, канал — `too-small`.
- Границы ячеек — как сегодня (`floor(x + 0.5)`).

### Р4. Канал «Пимп» — контракт побайтно (эталоны `tests/fixtures/pimp/`, README там же)

**WF21** (эталоны написаны 08.09 01:30):
- Запрос `arrange`: `id, at, action, from, layout` — `layout` ∈ `row | 4 | 5 | 5x2 | last` (умолчание CLI `row`, как сегодня).
- Ответ `arrange`: `id, at, ok, error, fromResolved, screen, layout, windows, skipped, minimized` — `layout` применённая
  (`last` разрешается в конкретную), `windows` — только переставленные, `skipped` — сколько не тронули.
  Ошибки: `too-small` (ячейка уже `minWindowWidth`), `bad-request` (незнакомая `layout`), `no-windows`.
- `new-window` (`PimpChannel.row`): `arrange(ids:mode:)` с **последней раскладкой**; нет свободной ячейки → окно остаётся
  где родилось, ответ `ok:true`, `frame` как есть, `"skipped":1` ПОСЛЕ `layers` (эталон new-window.result.json — случай с
  ячейкой, без поля). Есть ячейка — новое окно занимает место по `at` (`insertIndex`), остальные сдвигаются в пределах ёмкости.
- CLI: текст `too-small` — по действию (`arrange` → «Экран уже: столько окон по <ширина> не влезает», `new-window` — прежний).

**WF41** (эталоны пишет оркестратор ПЕРЕД второй волной):
- `arrange` + необязательное `order` ПОСЛЕ `layout`: `id, at, action, from, layout, order` — список ПАПОК проектов
  (абсолютные пути; CLI переводит имена из `projects` в папки). Окна этих проектов встают первыми в этом порядке (папка
  окна — `index.folder(for: chat)` / `ProjectPaint`), проект без окна — пропуск, остальные опознанные — за ними в прежнем
  порядке, **неопознанные — в хвост**; ответ получает `unknown:<число>` после `skipped` и `missing:[папки]` после `unknown`.
- `layouts`: запрос `id, at, action, from`; ответ `…, screen, layouts:[{name, at, mode, cells}]`.
- `layout-save`: запрос `id, at, action, from, name`; ответ `…, screen, name, mode, cells:<число>`. Ячейка каждого окна —
  индекс по текущему `mode` со сверкой `frameMatches` (допуск 2 pt), иначе `null`; **окно с неопознанным чатом → ошибка
  `chat-unknown`, поле `windows:[заголовки]`, файл не пишется** (иначе restore выродился бы в новые чаты — #5455).
  Главное окно пишется как `{folder, chat:"main", title, cell}` — при restore ему ставится только рамка, чат не меняется.
- `layout-restore`: запрос `id, at, action, from, name, fresh`; ответ `…, screen, name, placed, opened, missing:[заголовки]`.
  `fresh:false` — те же чаты: окно с таким чатом открыто → ставим в ячейку; закрыто → главное окно выносит его попапом
  (`popout-window` с `chat`+`name`, Р6) в ячейку; чата нет в индексе или страница ответила `chat-missing` → ячейка ПУСТАЯ,
  заголовок в `missing`, новый чат НЕ подставляется. `fresh:true` — новые чаты по тем же папкам через сегодняшний
  `new-window` (⌘N в главном окне по числу окон, 10–40 с каждое — Элвису сказано). Окна открываются ПО ОДНОМУ:
  `Job` становится очередью шагов с текущим окном; **после каждого окна приложение перезаписывает `<id>.taken`
  (heartbeat)**, CLI считает `MYCLAUDE_PIMP_WAIT` от mtime `taken`, а не от запроса. Ошибки `layout-missing`, `busy`.
- `projects` + `status:true` ПОСЛЕ `from` (ключ только когда просили): у каждого проекта после `lastUsed` — `chats:[заголовки
  открытых окон проекта]` и `state:"<N воркфлоу · M готово · Сейчас: …>"` из шапки и строки «Сейчас:» его `docs/status.md`
  или `audit/status.md` (нет файла — `""`). Разбор — три строки в `PimpChannel`, `StatusFeed` не трогаем.
- Хранилище `LayoutsStore.swift`: `~/Library/Application Support/MyClaude/layouts.json` =
  `{"version":1,"layouts":[{"name","at","mode","cells":[{"folder","chat","title","cell"}]}]}`, лимит 30, атомарная запись,
  по образцу `ProjectsStore`. Зависимость: чаты попапов известны только при включённом «🗂 Цвет по проекту» и свободном
  `probe.js` — иначе `chat-unknown`, CLI говорит это словами.
