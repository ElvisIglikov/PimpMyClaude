### Часть B — «Обкэшить» из попапа рождает новое окно (#5575, #5535 для `cashout`)

**B1 Swift** (`ClaudeActions.cashout`). Окно — попап, если его AX-заголовок не заглушка (`ProjectIndex.isStub`)
ИЛИ карта probe знает попап с таким заголовком (`chatForTitle`); иначе — главное. **Главное: как сегодня**
(команда + ⌘N в него, вставка на домашнем экране). **Попап**: фокус → команда `cashout` полями
`scope:"window", title, chat?` (новый `cashoutFields`; `chat` — id из карты probe для этого заголовка, только
если страница сама его назвала; `match` не шлётся никогда) → через `cashoutNewChatDelay` вместо `newChat(popout)`
— **`newWindow(popout, project:, origin:)`**: проект — по папке чата попапа (`index.folder(for: chat)` →
`Project(folder:name:lastFocusedAt:)`, тем же путём, что «▸ проект»: имя `chatName(project)`, слои проекта и
авто-цвет, запись в `projects.json`), папки нет — «Здесь же» (`newWindow(popout)`); место —
`popoutOrigin(near: рамка попапа)`. Хоткей ⇧⌘N при попапе в фокусе идёт той же веткой.
**B2 Страница.** Обработчик `cashout` адресует через `addressed(detail)` (match → chat → заголовок/фокус) вместо
своей проверки. `runCashout()` в попапе (`!isMainWindow()`) пишет запись `{at, text, to:"pending"}` и **свой
сторож не заводит**; в главном — прежняя `{at, text}` и сторож. `runNewWindowCommand` на шаге 5 (id сессии
известен): свежая запись с `to === "pending"` → `to = id` (`at` не трогаем). `tryPasteCashout`: у записи есть
строка `to` → вставляем ТОЛЬКО когда `to !== "pending"` и `myChatId() === to`, поле пусто, `isFreshChat()` не
требуем (первое сообщение — локальная команда, чат не «свежий»); записи без `to` — прежнее правило. Новый попап
заводит сторож на инжекте (`:5410`, уже так), id ему приходит из кэша родителя (`syncChatTheme`) — 90 с
(`CASHOUT_FRESH_MS`) на это хватает с запасом (цепочка «Нового окна» ≤ 40 с). `status().cashout` →
`{record:bool, to:string|null}` (сегодня — bool).
**Контракты:** `cashout` = `{"id","action":"cashout","at","scope":"window","title":<AX>,"chat"?:<id>}`,
порядок `scope, title, chat?` (главное окно — `scope, title`); localStorage `myclaude-cashout` =
`{at, text, to?}`, `to` ∈ `"pending"` | `local_<id>`. Занятая цепочка (`state.newWindow.busy`) → команда
`new-window` отвечает `busy` как сегодня, запись протухает сама.

### Часть C — цвет за папкой сразу (#5576)

**C1 Страница.** Ответ `chats()` получает поле `folder` (string | null) **после `store`, перед `themes`** —
только у главного окна (`isMainWindow()`): `newWindowFolderNow(newWindowFolderStore)`, когда стор папки уже
найден; не найден — один раз запускаем `newWindowFindFolderStore(newWindowToken)` в фоне (промис в
`chatsFolderScanInFlight`, второй не заводим) и в этом круге отвечаем `null`; срыв скана (токен сменился
«Новым окном») — `null`, следующий круг. Попапы и чужие страницы — `null`. То же поле в `status().chat.folder`.
**C2 Swift.** `ChatPage` получает `path: String` и `folder: String?` (`folder` принимается только у `kind ==
.main`, абсолютный путь ≤ 1024 знаков, иначе nil). `ProjectPaint.targets()`: у главного окна папка — из свежего
(`isRecent`) ответа, если `folder` есть (через подъём к корню `ProjectFolder.root(for:…)` — новый
`index.root(of: URL)`; чип может показывать подпапку), иначе как сегодня (чат → сессия → `cwd`); **`mainWindow()`
= nil (домашний экран), а свежий ответ с папкой есть → цель всё равно строится**, `match` = `path` ответа
(`/epitaxy`; страница сверяет `location.pathname`, `addressed()`), ключ `main`. `writableFolder(for:)`
(ручной выбор → `.pimpmyclaude.json`) предпочитает ту же папку из ответа. Ответа с папкой нет — поведение
побайтно прежнее (тесты WF29/WF35 зелёные без правок).
**C3 Частота.** `ChatProbe.askInterval` 15 с остаётся полом в фоне; новый `frontInterval = 3` с, когда
Claude впереди: `tick(windowTitles:indexRevision:frontmost:)`, контроллер передаёт `claudeFrontmost`
(`ClaudeAXController.swift:278`). Круг без `scan` для страницы дёшев; цена — `probe-result.json` (~300 КБ)
раз в 3 с, пока Claude впереди. Альтернатива «страница красит себя сама по смене стора» отклонена: ей нужна
таблица палитр проектов на странице — новый контракт и второй источник правды о цвете.
**Диагностика:** `statusText` `project=…` дополняется папкой из ответа: `on/<папка>/<painted>/<known>/probe:<имя папки|—>`.

## Риски

1. Разведка красная — часть A выпадает, B/C делаются; «Привет» остаётся до пути 2 (задача-продолжение #5447).
2. Попап не знает свой id (`store:none`) → перенос не вставится, новое окно пустое; запись протухнет за 90 с.
   Пометка `status().cashout` — для гейта; плашки нет (B-цепочка молчит, как «Новое окно» при `busy`).
3. `selectedFolder` — подпапка проекта → подъём к корню; корня нет — сама папка (как у сессий).
4. Probe раз в 3 с при Claude впереди — вес `probe-result.json` (#5536) растёт в нагрузке на диск; если критик
   считает дорого — 5 с.
5. `addressed()` у `cashout` с `chat`: страница, что своего id не назвала, команду не берёт; приложение по
   правилу WF29 `chat` ей и не шлёт (только назвавшей себя странице) — иначе заголовком.
6. `isStub` у AX-заголовка попапа «Claude» без ответа probe → ветка главного окна → старая болезнь у
   безымянного попапа (#5534). Принято: безымянный попап без probe — редкость, лечится именем чата.
