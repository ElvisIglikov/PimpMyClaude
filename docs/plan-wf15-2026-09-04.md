## Решения

### 1. Архитектура: почти всё делает Swift, на странице — три строки (правка по критику Б1)

**Вариант Б+ (рекомендую).** Приложение само определяет папку каждого окна (решение 2), читает настройки из папки
(решение 3) и шлёт уже существующую команду `theme` (`scope:"window"`). Плюс **одна необязательная правка страницы**:
в `addressed()` (inject.js:1217) добавляется поле `match` —
`if (typeof detail.match === "string") return location.pathname === detail.match;`
(поле есть — сверяем путь страницы, поля нет — старое поведение побайтно). Главное окно адресуем
`match:"/epitaxy/local_…"` из `status.json`, попапы — заголовком, как и было. Почему без этого нельзя — п. 11
«Что выяснено»: заголовок главного окна «Claude» носят и безымянные попапы, команда «покрасить главное»
покрасила бы их все и записала бы им `w:Claude` в sessionStorage.
Цена: ~10 строк в `inject.js` + `VERSION` → `wf15-a-1`; **перепатча у команды НЕТ** — перепатч только у
`Loader.swift`/`patch-claude.mjs` (решение 7). Конфликта с WF16 нет: марафон идёт последовательно, ветка на каждый
воркфлоу. Минус остаётся один: цвет догоняет чат за 2–3 с (шаг `status.json`).

**Запасной без правки страницы** (если Элвис страницу трогать не хочет, вопрос 5 макета): красим ТОЛЬКО попапы
с непустым уникальным заголовком, главное окно не красим и пишем это прямо в пункте меню
(«🗂 Проект: PimpMyClaude — главное окно не крашу»). Молчаливой покраски «по площади» быть не должно.

**Вариант А (не берём).** Пятый слой «проект» на странице: `inject.js` берёт папку из чипа композера, Swift шлёт
широковещательную команду `projects`, цепочка становится `chat:` → сессия → **проект** → `main` → `*`. Плюс:
красит мгновенно. Минусы: новая команда и новый уровень в самом запутанном разделе страницы, обязательная разведка
чипа. **Берём А только если разведка (раздел 0, Ш1/Ш2) покажет, что индекс сессий или `status.json` не годятся.**

### 2. Как приложение узнаёт папку окна — три источника, в этом порядке

1. **Главное окно:** `status.json` → единственная запись `webContents` с `url` вида `https://claude.ai/epitaxy/local_…`
   → `sessionId` → индекс сессий → `cwd`. Читаем раз в 2 с (файл всё равно переписывается лоадером) — на общем
   таймере `ClaudeAXController`, своего не заводим (критик М2). **Адресуем командой с `match:"/epitaxy/local_…"`,
   не заголовком** (решение 1, критик Б1): заголовок главного окна — заглушка «Claude», по ней команда уйдёт
   веером всем безымянным попапам.
2. **Попап-окна:** AX-заголовок окна == `title` сессии в индексе → `cwd`, команда адресуется заголовком, как и было.
   Заголовок встречается в индексе дважды или он пустой — **папку не определяем** (лучше не покрасить, чем
   покрасить чужим цветом). Заголовок-заглушка («Claude», «New chat») в сопоставление не идёт вовсе.
3. **Запасной:** страниц `claude.ai` оказалось две (WF13 честно называл это допущением) — берём сессию с
   наибольшим `lastFocusedAt` и красим только её окно; не сошлось — не красим ничего и пишем в `status()`-подобную
   диагностику приложения.

Индекса нет (не Claude Code, старая сборка, чужая машина) — WF15 просто молчит: ни команд, ни предложений, ни ошибок.

### 3. Хранилище настроек проекта — три варианта

- **Вариант 1 (рекомендую): файл `.pimpmyclaude.json` в папке проекта.** Машиночитаемо, пишется атомарно
  (`CommandChannel.writeAtomic`), ничей чужой файл не портит, едет вместе с папкой к команде, руками правится.
  Минус: в репозитории появляется неотслеживаемый файл — лечится одной строкой в глобальном игноре Элвиса
  (`~/.config/git/ignore`, делает оркестратор на гейте, приложение в чужие настройки git не лезет).
- **Вариант 2: строка-маркер в `AGENTS.md` проекта** — ровно то, что предложил Элвис («в агентский файл, коротенько»):
  одна строка `<!-- pimpmyclaude: {"theme":"indigo","font":"inter","size":{"answer":16},"frame":true} -->`,
  в отрисованном markdown невидима, агент проекта её видит. Минус: приложение правит файл, который правят и Элвис,
  и агенты; каждая смена цвета — дифф в git и грязное дерево посреди чужого воркфлоу.
- **Вариант 3: реестр `projects.json` в `Application Support/MyClaude`** (ключ — путь папки). Минус один, зато
  тяжёлый: настройки не едут с папкой и Элвисово «в каждой папке хранить» не выполняется. Оставляем как
  **автоматический запасной** для папок, куда писать нельзя (нет прав, том только для чтения).

**Хранилище ровно одно (правка по критику М4).** Читаем настройки ТОЛЬКО из `.pimpmyclaude.json`. Строка в
`AGENTS.md` — памятка агенту проекта: пишем по клику, назад НЕ читаем, «Убрать настройки» её не трогает (только
говорим о ней в HUD). Реестр — не второе хранилище, а сообщение «в папку писать нельзя». Иначе verify «побайтно»
не на что опереть, а расхождение двух источников Элвис увидит как «цвет не тот».

**Папка проекта ≠ `cwd` сессии (правка по критику В2).** Claude Code запускают и из подпапки
(`…/PimpMyClaude/app`) — тогда файл лёг бы в подпапку и у двух чатов одного проекта были бы разные цвета.
Правило: папка проекта = подъём от `cwd` вверх до первой папки с `.git` или `AGENTS.md`; потолок подъёма —
`projectsRoot` из `claude.json` и домашняя папка; ничего не нашли — берём сам `cwd`. Тест на подпапку обязателен
(`testProjectRootClimbsToGitOrAgents`).

**Контракт файла (побайтно; порядок ключей такой, отступ 2 пробела, перевод строки в конце):**

```json
{
  "pimpmyclaude": 1,
  "name": "PimpMyClaude",
  "theme": {
    "id": "indigo",
    "name": "Индиго",
    "type": "dark",
    "palette": { "accent": "#7c8cff", "background": "#171a2b", "foreground": "#e8e9f5",
                 "sidebar": "#12142230", "panel": "#1e2238", "muted": "#9aa0c0" }
  },
  "font": { "id": "inter", "family": "Inter, -apple-system, sans-serif", "mono": false },
  "size": { "answer": 16, "question": 14 },
  "frame": true
}
```

- Слоя нет в файле — слой не трогаем (ровно как «поле есть/нет» в команде `theme`). `null` — сброс слоя
  («в этом проекте как у Claude»).
- Палитра копируется целиком, как в `my-themes.json`: файл переживёт смену каталога тем. `id` нужен только для галки
  в меню; каталога с таким id нет — работаем по палитре.
- Битый JSON, чужой `pimpmyclaude` ≠ 1, лишние ключи — читаем что смогли, остальное игнорируем; файл НЕ переписываем
  сами (перезапись только по явному пункту меню).
- Чтение: при старте приложения, при смене папки окна и по mtime (опрос 5 с, хэш как в `StatusFeed`). Правку файла
  руками приложение подхватывает без перезапуска — это и есть «настройки живут в папке».

### 4. Когда красим и чего не трогаем

- Поводы покрасить: (а) приложение запустилось; (б) главное окно сменило сессию (URL в `status.json`);
  (в) появилось новое окно Claude; (г) файл настроек проекта изменился; (д) пункт меню «Взять цвет проекта».
- **Сменилась папка — сперва снимаем прошлое (правка по критику Б2).** На окно держим отпечаток
  `{адрес окна → путь папки + хэш настроек}`. Папка сменилась: одной командой СНЯТЬ слои, которые ставил прошлый
  проект (`"theme":null`, `"font":null`, …), потом применить новые. Проект без `.pimpmyclaude.json` = только снятие.
  Без этого переход в проект без настроек оставлял бы окно в чужом цвете, а у главного окна — навсегда: страница
  пишет слои в ключ `main` (`themeKey()`, inject.js:797), он переживает перезапуск и затирает ручную тему.
  Тумблер «Красить чаты по проекту» при выключении делает то же снятие для окон, которые красил проект.
  Тесты `testProjectPaintResetsLayersWhenProjectHasNoSettings`, `testProjectPaintClearsOnToggleOff`.
- **Ручной выбор сильнее — но источников «окно занято» три, а не один (правка по критику Б3).** Одного
  `ThemeStore` мало: автопокраска сама его чистит (`themeStore.setWindowTheme(nil, title:)`, ClaudeActions.swift:499),
  и покрашенное «по кругу» окно выглядело бы нетронутым. Проект красит окно, только если его нет ни в одном из:
  (1) `ThemeStore` — ручной выбор из меню; (2) `autoPaintedThemes` — память автопокраски в `ClaudeActions`;
  (3) собственный отпечаток проекта; плюс (4) запись «всем окнам» (`allThemeID`/`allFontID` ≠ nil) проект не
  перебивает. Исключение — окно, которое он же и красил в прошлый раз: его перекрашивать можно.
  Тест `testProjectPaintSkipsManuallyAndAutoPaintedWindows`.
- Одинаковый цвет второй раз не шлём: отпечаток совпал — молчим. Иначе очередь команд (0,6 с на запись) забьётся,
  а лоадер будет дёргать страницу. Тест `testProjectPaintFingerprintSkipsRepeat`.
- **Пока открыто меню — не красим (правка по критику В1).** Наши команды идут как `.normal`, а не-preview команда
  вызывает `endPreviewExcept` (inject.js:1230) и гасит примерку темы мышью. Правило: покраска не шлётся, пока меню
  открыто и пока не прошло 2 с после последней команды меню (флаг у `MinimizeMenu`/`ClaudeActions`). Приоритет

### [блокер] Б1. Адресация по заголовку — широковещательная, главное окно ею не адресуется

`inject.js:1217` `addressed()`: `title` есть → страница сверяет `document.title === title`, пусто → `document.hasFocus()`.
То есть команда прилетает КАЖДОЙ странице с таким заголовком. У главного окна на вкладке Claude Code заголовок —
заглушка «Claude» (сам план, п. 4 «Что выяснено»), и такой же заголовок носят все безымянные попапы: одна команда
«покрасить главное окно» покрасит их все (и запишет им `w:Claude` в sessionStorage). Правило плана «два совпадения
в индексе — не красим» этот случай не ловит вовсе: заглушки в индексе нет, а обычный чат claude.ai с тем же именем
в индексе не лежит и проверку проходит.

**Правка решений 1 и 2.** Довод «вариант А = конфликт с WF16» неверен: марафон идёт последовательно (15, 16, 17…),
ветка на каждый воркфлоу, параллельных писателей `inject.js` нет. И правка `inject.js` **перепатча не требует** —
перепатч только у `Loader.swift`/`patch-claude.mjs`. Поэтому берём Б+: всё в Swift, плюс три строки на странице —
в `addressed()` добавить необязательное поле `match`: `if (typeof detail.match === "string") return location.pathname === detail.match;`
(поле есть — сверяем путь, нет — старое поведение побайтно). Главное окно адресуем `match:"/epitaxy/local_…"`
из `status.json`, попапы — заголовком, как и было. `inject.js` в WF15 становится вторым батчем (A-js, ~10 строк
и `VERSION` → `wf15-a-1`), `AGENTS.md` → «Контракты» дописывается полем `match`.
Если Элвис страницу трогать не хочет — запасной вариант без правок: красим ТОЛЬКО попапы с непустым уникальным
заголовком, главное окно не красим и честно пишем это в пункте меню. Молчаливой покраски «по площади» быть не должно.

### [блокер] Б2. Сменили проект — цвет прошлого проекта остаётся

Решение 3 («слоя нет в файле — слой не трогаем») + решение 4 (повод покрасить — смена сессии) дают дыру: перешли из
проекта с цветом в проект без `.pimpmyclaude.json` — команда не шлётся, окно остаётся в чужом цвете. Для главного окна
